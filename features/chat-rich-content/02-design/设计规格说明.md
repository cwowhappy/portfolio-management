# 对话流富内容（chat-rich-content）· 设计规格说明

> 状态：已确认设计（2026-09-10）；2026-09-11 澄清：四工具图表映射与双通道范围收敛、单一 ChartSpec 契约（详见[需求规格澄清决策](../01-requirement/需求规格说明.md#澄清决策2026-09-11对照真实代码核实后收敛)）。
> 本规格只写「做什么、怎么改、怎么验收」；字段级出处、体积实测、字节码/源码证据链全部在技术依据 [05-富文本场景技术方案.md](../../../docs/technology/research/05-富文本场景技术方案.md)，两处不重复维护细节，冲突时以 05 为准并回改本文件。

## 一、总体链路

```
后端 @Tool（get_kline 等）
  ├─ emitter.emit(TextBlock(ChartSpec 全量 JSON))  ──只进 SSE──▶ TOOL_CALL_RESULT.content
  └─ return ToolResultBlock.text(摘要)              ──只进 LLM──▶ Msg/stateStore（token 省）
SSE → @ag-ui/client 把 TOOL_CALL_RESULT 转成 role:"tool" 消息
前端 AssistantMessage 内 renderToolCall({toolCall, toolMessage}) 配对（★前置修复）
  → useRenderTool 按工具名精确匹配 → ChartCard（状态机 + JSON.parse + 降级）
     → EChart（echarts 按需 + app 主题）/ DataTable（TanStack v9）
     → 其余工具 → useDefaultRenderTool → ToolCallCard 兜底（现状不动）
文字：TEXT_MESSAGE_* → react-markdown + remark-gfm（现状）；图片：定制 img 组件
```

**前置修复（FR-7，先于一切图表工作）**：`ThreadArea.tsx:212` 现在调 `renderToolCall({toolCall: tc})` 没传 toolMessage——后端工具卡片永远 inProgress、`result` 恒 undefined。修法按官方 `CopilotChatToolCallsView` 范式建 `toolCallId → tool 消息` Map 配对（代码见 05 §4.2）。

## 二、后端设计

1. **ChartSpec Java record**（`backend/.../agent/chart/ChartSpec.java`，单一 sealed interface + records——含 table 变体，与前端 zod 一一对应）：K 线数据顺序 **[开,收,低,高]**；数字一律 JSON number；**null 字段省略**（`@JsonInclude(NON_NULL)`——注意 Jackson 只省 null 不省空数组，zod 的 dates/categories 是必填数组，空数组照常发送）。契约由双端共享 fixtures 钉住。
2. **双通道（FR-4，仅四个配图工具）**：工具方法加 `ToolEmitter emitter` 参数（自动注入），`emit` 全量 ChartSpec、返回摘要文本——机制已核实：emit 的块只进 SSE 事件流永不进 LLM，emit 过则返回值 delta 被 skipSet 跳过（05 §3.2）。**注意**：只 emit 一次（多次会拼接）= 一次调用只出一张图；返回 `ToolResultBlock` 而非 String（String 会被 Jackson 二次包装，现状 InvestTools 7 个工具全踩此坑）。
3. **迁移顺序与映射（2026-09-11 澄清）**：`get_kline` → candlestick 先行；`get_valuation` → line（全A PE/PB 中位数双系列，ERP/指数估值/温度计入摘要）；`get_market_overview` → bar（仅涨跌幅，点位入摘要）；`get_financials` → table。`search_stock`/`get_quote`/`get_news` **维持现状不动**（search_stock 的候选代码是 LLM 后续工具调用的依据，不可摘要化）；写工具不配图表（非目标）。

## 三、前端设计

**文件布局**（05 §4.3）：

```
frontend/lib/echarts-setup.ts        # 唯一 echarts 注册点（按需 use()，ESLint 禁裸入口）
frontend/lib/chart-theme.ts          # CSS 变量运行时解析（canvas 不认 var()）+ app-dark/app-light
frontend/lib/chart-spec.ts           # zod 契约（前端权威）
frontend/components/charts/          # 共享基建：useECharts / EChart / optionBuilders（纯函数）
frontend/components/chat/charts/ChartCard.tsx  # 状态机壳（P2 终审勘误：与 05 §4.3 一致，DataTable 在 P4）
frontend/components/chat/toolRenderers.tsx  # useRenderTool 注册集合
```

1. **渲染器注册（FR-2）**：`useRenderTool({name, parameters(zod), render})`——精确名永远压过通配，`useDefaultRenderTool` + ToolCallCard 兜底不动；headless 下**不传 agentId**（查询值恒 "default"）。
2. **EChart/主题（FR-8）**：按需注册（页面期 pie/bar/line；聊天期补 candlestick+dataZoom，gzip 218KB）；`registerTheme` 前必须 `getComputedStyle` 把 `--color-*` 解析成具体色值；K 线涨红跌绿四色 itemStyle 对齐 `--color-up/--color-down`。
3. **ChartCard 状态机（FR-9）**：inProgress 骨架（复用 `.tool-card` 样式）→ complete `JSON.parse` + zod 校验 → 失败/错误内容降级折叠卡；option 必须 `useMemo`。
4. **表格（FR-5）**：TanStack Table **v9**（`useTable` + `tableFeatures`，非 v8 的 `useReactTable`）；固定表头用原生 sticky CSS；虚拟滚动留到行数上千。
5. **图片（FR-6）**：react-markdown `components.img/a` 定制（懒加载/no-referrer/尺寸约束），外域白名单走 `urlTransform`（默认已拦 `javascript:`/`data:`）。
6. **历史重放**：不做（非目标）；ADR-0004 维持。

## 四、错误处理

- 工具异常 → 后端 `ToolResultBlock.error("Tool execution failed: ...")` → SSE content 为错误文本（事件无 error 标志字段）→ 前端内容嗅探降级（沿用 ToolCallCard `/error/i` 模式，扩展关键词）。
- ChartSpec 解析/校验失败 → 折叠 JSON 文本卡，聊天流不崩。
- `RUN_ERROR`（流级）→ 现有 `onRunErrorEvent` 错误横幅；已挂卡片停留 inProgress。

## 五、已知限制（接受并记录）

1. 刷新/切线程后图表卡不重放（ADR-0004 前端精简持久化）。
2. 暗亮主题切换后**已挂**图表色值不自动重绘（需触发重渲染；P1 记录的后续优化项）。
3. 审批续跑轮（HITL resume）不重放工具事件——图表只配 readOnly 行情工具。
4. jsdom 无 canvas：ECharts 不能真渲染，测试集中在 optionBuilders 纯函数 + mock EChart 壳。
