## 交付范围回顾

按需求规格 FR A/B/C/D 全量交付（subagent-driven 10 任务逐审 + 整分支终审 + 修复波）：

- **注册邮箱验证**：三段式表单（60s 冷却倒计时）+ 发码预检（用户名规则与占用/邮箱格式与未绑定/密码策略）+ 码前置注册（`email_verified=true` 创建 PENDING，审核状态机零改动）；验证码 5 分钟有效、错 5 次作废、用后即焚、同邮箱 60s 冷却 + 日限 10。
- **自助找回**：`/forgot-password` 两步状态机（用户名或邮箱定位 APPROVED 且 enabled 的 USER 账号）；重置成功经 `RememberMeTokenStore.removeUserTokens` 吊销全部 remember-me 令牌。
- **管理员代填**：AdminBoard 邮箱列（仅 USER 行）幂等保存（绑定即验证）+ 告知邮件尽力而为。
- **发信设施**：`infrastructure/mail/` SmtpMailSender（465 SSL）opt-in——未配置返回 503 明确报错，不做静默回退双路径。
- **域与数据**：Flyway V21（`app_user` email 列 + 部分唯一索引 + `verification_code` 表）；VerificationCode 聚合（BCrypt 哈希落库）；EmailCodeService（消费型验码 + 邮箱小写归一化）；User 域增量重载（旧签名委托新实现，既有调用点零改动）。
- **前端配套**：/api/auth catch-all 反代（e2e 实测 404 逼出的真缺口）。

**质量证据**：gradlew check 全绿（JaCoCo 81.8%）；vitest 777/777；e2e `E2E_FRESH_BUILD=1` 全量 70 过 + 2 门控跳过（auth 8/8 含注册/找回/代填三新流程）；`make smoke` §1~§5 绿 + **§6 真实 SMTP 实证**（235 认证 + register-code 真发至 account-manager@cwowhappy.cn）。

## 做得好的

1. **通道选型裁决留痕**：四候选对照表进需求规格（短信因签名实名制报备制度性出局 / 个人 SMTP 限额易风控 / DirectMail 需另配发信域名 / 企业邮箱复用自有域名采用）——「为什么不是短信」永久可考。
2. **增量重载控爆炸半径**：User 域旧签名委托新实现而非改签名扩散，既有调用点零改动。
3. **测试后门的门控设计**：`MAIL_TEST_FIXED_CODE` 仅在 `MAIL_TEST_MODE=1`（e2e 后端脚本/CI 设置）下可配，生产误配启动 fail-fast——封死「已知码接管任意 USER」向量；smoke §6 对固定码残留环境跳过并显式声明不构成 SMTP 证据。
4. **断言覆盖机械证明**：验证码全生命周期（isUsed/used/exhausted 分支）设变异实证哨兵——删任一分支测试即红，覆盖被证明而非声称。
5. **环境问题归因到环境**：SMTP 526 拒登不迁就代码，归因企业邮箱侧「三方客户端安全密码」未开通，开通后 235 认证真发成功——非直觉契约记录在案避免重查。
6. **e2e 逼出真缺口**：/api/auth catch-all 反代缺失由 e2e 404 实测发现（mock 层全盲）——「关键前端改动须真浏览器兜底」在本特性的又一实证（与 MS-08 反代 catch-all 同型复发）。

## 教训

1. **验收工具自身也会坏**：smoke §6 两处缺陷在验收期才暴露——①收件人非真实邮箱（阿里企业邮箱无 catch-all，不可投递地址不能作为收证，改发 `MAIL_FROM` 本身）②全角括号相邻变量 shell 展开须花括号。验收脚本与被测代码同等对待审查。
2. **固定码生产误配是安全向量**：终审阻塞级发现——e2e 便利设施若无环境门控，等于给生产留已知后门；fail-fast 是唯一正确姿势。
3. **阿里云企业邮箱两条非直觉契约**：收件人必须真实存在（无 catch-all）；SMTP 登录须开通「三方客户端安全密码」（标准密码 526 拒登）。
