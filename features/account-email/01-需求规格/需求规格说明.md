# 邮箱验证与找回密码（account-email）需求规格说明

- **版本**：v1.0（2026-09-27，brainstorming 阶段产出，用户已确认）
- **关联**：M01 用户与认证 F06（三期 MS-15 最后 1 点）｜[M01 模块文档](../../docs/function/modules/01-用户与认证.md)｜[ADR-0007 用户认证](../../docs/technology/decisions/0007-user-auth.md)
- **实施节奏**：单期交付（范围小，不分期）

## 一、背景与目标

**现状**：`app_user`（V1）无 email 列，注册仅用户名+密码 → PENDING → 管理员审核（F03）；密码找回唯一路径是管理员代重置（F04）；SMTP 自 MS-15 规划起一直「⏳ 待决策」。

**通道决策（2026-09-27，用户裁决）**：SMTP · **阿里云企业邮箱**。选型依据——

| 候选 | 结论 |
|---|---|
| 短信（阿里云） | **制度性出局**：签名实名制报备后仅企业资质可报备发送，个人认证账号不可行 |
| QQ/163 个人 SMTP | 可行但限额低（约 200 封/日）易风控，生产不体面 |
| 阿里云邮件推送 DirectMail | 可行，需另配发信域名 SPF/DKIM，免费 200 封/日 |
| **阿里云企业邮箱（采用）** | 复用自有域名、标准 SMTP（`smtp.qiye.aliyun.com:465`）、发件量远超需求（本系统月均个位数封） |

**目标**：注册即验证邮箱（每个 USER 账号必有已验证邮箱锚点）；USER 账号自助找回密码；收齐 M01-F06 → 三期门槛 14/14、全系统 **115/115**。

## 二、需求澄清汇总（决策表，均经用户确认）

| # | 议题 | 决定 |
|---|------|------|
| 1 | 邮箱验证介入点 | **验证码前置**：注册表单三段式，验证通过才创建 PENDING 账号（`email_verified=true`），状态机零改动，管理员审核仍是第二道闸 |
| 2 | 找回范围 | **仅 USER 角色**——ADMIN 不绑邮箱、不走邮件找回（忘密码走 `.env`/DB 运维路径，与 F04「内置管理员不可被重置」保护一致）；找回仅对 APPROVED 且 enabled 账号生效 |
| 3 | 凭证形态 | **统一 6 位数字验证码**（注册/找回同机制同表同前端组件）；不做重置链接 |
| 4 | 存量回填 | **/admin 代填**：用户列表加邮箱可编辑列，代填即视为已验证 + 发告知邮件 |
| 5 | 防枚举 | 不做——账号不存在/非 USER/停用**明确报错**（单机熟人系统，换实现与调试简单） |
| 6 | 改邮箱/解绑 | 不做（管理员代填覆盖，YAGNI） |

## 三、功能需求

### A. 注册邮箱验证（`/register` 改造）

- **FR-A1 三段式表单**：用户名/密码/邮箱 +「获取验证码」按钮（60s 冷却倒计时）。发码前预检：用户名规则与占用（REJECTED 复用语义与现状一致，见 `User.reRegister`）、邮箱格式、邮箱未被绑定、密码策略——任一不过不发码，返回对应错误。
- **FR-A2 验证码发送**：`POST /api/auth/email-code`（purpose=REGISTER）→ 邮件含 6 位数字码。**5 分钟有效、错 5 次作废、用后即焚**；同邮箱 60s 冷却 + 每日 10 条上限，超出明确提示。
- **FR-A3 注册落库**：`/api/auth/register`（`RegisterCommand`）扩展 email + code 字段 → 校验通过创建 PENDING 账号且 `email_verified=true` → 走既有审核流。
- **FR-A4 审核流零改动**：待审列表/通过/拒绝语义不变（邮箱验证是注册的前置步骤，不进入状态机）。

### B. 自助找回密码（新页 `/forgot-password`）

- **FR-B1 入口**：登录页加「忘记密码？」链接。
- **FR-B2 发码**：输用户名**或**邮箱 → 定位 APPROVED 且 enabled 的 USER 账号 → `POST /api/auth/email-code`（purpose=RESET），同 FR-A2 频控；不满足条件明确报错（决策 #5）。
- **FR-B3 重置**：输码 + 新密码（同密码策略）一次提交 `POST /api/auth/reset-password` → 成功后作废该码 + 经 `RememberMeTokenStore.removeUserTokens(username)`（端口已有，javadoc 即为本场景预留）吊销该账号全部 remember-me 令牌 → 跳登录页。

### C. 管理员代填（`/admin` 扩展）

- **FR-C1 邮箱列**：用户列表加「邮箱」可编辑列，**仅 USER 行**（ADMIN 行不提供，决策 #2）；保存 = email 落库（UNIQUE）+ `email_verified=true`。
- **FR-C2 告知邮件**：保存后发一封「邮箱已绑定」告知邮件（纯告知无动作）；SMTP 未配置则只存库 + warn 日志。

### D. 发信设施与配置

- **FR-D1 MailSender**：backend 新增 `infrastructure/mail/`（Spring Mail/JavaMailSender，465 SSL）；中文固定模板两类——验证码、绑定告知。
- **FR-D2 配置组**：`InvestProperties` 新增 `invest.mail.*`（smtp-host/port/username/password/from）；env 五变量 `MAIL_SMTP_HOST/PORT/USERNAME/PASSWORD/FROM`，`.env.example` 同步。
- **FR-D3 未配置行为**：注册/找回发码与 admin 代填发信（共三类发信入口）在未配置时返回明确错误「系统未配置邮件服务」——**不做静默回退双路径**；其余全部功能现状零影响。

## 四、非功能需求

| # | 需求 | 说明 |
|---|------|------|
| NFR-1 | **opt-in 零回归** | MAIL 五变量未配置时，除 FR-D3 三类发信入口外，全部行为与现状完全一致；现行测试全绿 |
| NFR-2 | 发信尽力而为 | 发信失败不影响既有业务语义；注册/找回发码失败返回可重试错误，不吞不炸 |
| NFR-3 | 凭证安全 | 验证码**哈希落库**（不存明文）；SMTP 凭证仅走 env；邮件不含明文密码等敏感信息 |
| NFR-4 | 会话安全 | 重置成功吊销全部 remember-me 令牌；服务端会话不主动踢出（重启/过期自然失效） |
| NFR-5 | 测试口径 | 单测 mock JavaMailSender；集成测试用 testFixtures 自建 RecordingMailSender 记录桩断言（Boot 4 `spring-boot-starter-mail-test` 无内嵌 SMTP 测试服务，已核实——零新依赖，不真发外网）；e2e 验证码取 `MAIL_TEST_FIXED_CODE` 固定码（e2e 后端脚本默认 123456，生产严禁设置）；覆盖率 ≥80% + ArchUnit（`infrastructure.mail` 自动被前缀覆盖无需登记，已核实） |
| NFR-6 | 密钥管理 | SMTP 密码 env 明文（现状惯例，同飞书 secret 口径）；~~P1-10 加密设施落地后统一收纳~~ **已关单（2026-10-03）**：P1-10 以独立小特性交付（features/mcp-token-encryption/），拍板裁定 env 类密钥维持 env 口径（同机同文件加密无增益，加密设施仅收库内 MCP token） |

## 五、验收标准

**人工验收清单（真实企业邮箱端到端）**：

1. `/register` 新流程：填表 → 真实邮箱收码 → 注册成功（PENDING）→ `/admin` 审核通过 → 登录；
2. 连错 5 次码 → 该码作废，须重新获取；
3. `/forgot-password`：输用户名 → 收码 → 重置 → 新密码登录成功；另一浏览器旧的「记住我」自动登录失效（令牌已吊销）；
4. `/admin` 代填存量 USER 邮箱 → 该邮箱收到告知邮件；
5. 不配置 MAIL 五变量启动：登录/行情如常，注册发码报「系统未配置邮件服务」。

**工程验收**：`make test` 三端全绿；Playwright e2e 覆盖注册-审核-登录与忘记密码两链路；`make smoke` 新增邮件段（opt-in 真发，未配置跳过并标注）。

**挂接**：交付时更新 M01 模块文档（F06 ✅，5/6→6/6）、00 概览（115/115）、落地计划（三期门槛收口 + 变更记录 + 风险表 SMTP 行置 ✅）。

## 六、明确不做（YAGNI）

- 用户自助改邮箱/解绑（管理员代填覆盖）
- 重置链接与落地页路由（统一验证码，决策 #3）
- 防枚举模糊提示、图形验证码/人机校验（单机熟人系统 + 每日 10 条频控兜底）
- ADMIN 账号邮箱绑定与邮件找回（决策 #2）
- 多邮箱、邮箱变更二次确认邮件
- 短信通道（个人资质制度性出局，见 §一）
- PENDING/REJECTED 账号的找回（PENDING 等审核后自然可用；REJECTED 可重新注册）

## 七、依赖与风险

| 事项 | 说明 | 状态 |
|------|------|:----:|
| 自有域名落定 | 首次发布方案中 `server_name` 仍为占位符——企业邮箱绑域名的前置 | ⏳ 用户侧 |
| 阿里云企业邮箱开通 | 标准版 + 发件账号（如 `noreply@<域名>`）+ SMTP 密码 | ⏳ 用户侧 |
| 送达率 | 新域名无信誉，首日发 QQ/163 等主流邮箱可能进垃圾箱；低频场景可接受，人工验收时留意 | 低风险 |
| Flyway 版本位 | `app_user` 加 `email`/`email_verified` + 新表 `verification_code`；下一空位 **V21**（现最高 V20，已核实） | ✅ 已核实 |
| 注册接口语义变更 | `/api/auth/register` 请求体扩展（email+code）——前端同步改，无第三方消费方 | 低风险 |
