## 一、交付结果

- **25 个提交**（分支 feature/industry-tools-extension，不含本收尾）：特性文档 1 + 计划勘误 2 + P1 批量导入 8 + P2 行业对比 5 + P3 ETF 筛选 9（含探测报告与勘误 2）。严格 TDD（inline executing-plans，P1 Task 1~7 / P2 Task 8~12 / P3 Task 0+13~18），每任务独立评审后合入。
- **P1 批量导入（M08-F12）**：六类行（BUY/SELL/CASH_DIVIDEND/STOCK_DIVIDEND/DEPOSIT/WITHDRAW）**全量预检 all-or-nothing**——五层校验管线（L1 解析 / L2 格式 / L3 引用（分组存在且 ACCOUNT 类型、证券代码存在性）/ L4 日期 / L5 模拟重放（按「分组,日期,行序」排序、组内首错即停防连锁误报、现金与数量逐事件演化））全部通过才单事务落库，行错误 200 返回行号+原因清单、零写入；执行阶段走领域实体演化（`applyBuy`/`applySell` 等，与手工录入/`replay()` 同一方法口径，零行情调用，2000 行不超时）。两端点 `GET /api/portfolio/import/template`（UTF-8 BOM 模板）/ `POST /api/portfolio/import`（multipart ≤2000 行 ≤1MB）；前端上传对话框 + Next proxy multipart 透传。单笔录入五用例同步收紧未来日期校验（决策 #9 存量缺口一并补齐）。
- **P2 行业对比（M10-F12）**：V17 `industry_watch`（user_id+industry_code 唯一、幂等）+ `domain/industry` 关注记录实体与仓储（该域首个写模型）+ 独立前缀 `/api/industry-watch` 三端点（list/watch/unwatch，需登录——避开 `/api/industry/**` 公开段，照 WatchlistController 先例）；前端 `/industry` 榜单/对比视图切换，对比维度固定集（PE/PB/ROE/股息率/5y 分位/景气）**零新增数据端点**消费既有 board；⭐ 关注集默认勾选、刷新后保持。融资热度/推送剔除（决策 #4）。
- **P3 ETF 筛选（M09-F06）**：数据面四任务——`etf_basic`（V18，目录/费率/规模/跟踪指数/类别六桶，新浪目录主源 + 天天基金逐只 enrich，周更）；ETF 与跟踪指数日线**复用 `index_close_history`**（`fund_daily` 全市场单次模式 + 指数 `index_daily` 后缀规则探测缓存，日更 15:55 对齐可得时点）；跟踪误差 collector DB→DB 近 1 年自算（收盘价口径 `std(ETF−指数日收益)×√252`，样本 <120 置 null，照 `industry_valuation_backfill` 先例）。后端并入 `domain/screening`（`FundScreeningCriteria` 平移个股模式，仓库端口扩 `findFunds`/`existsFund`）——`GET /api/screening/funds` + `/funds/export` 两端点；自选复用 watchlist（ETF 代码直存，存在性校验为股票快照 ∪ etf_basic 目录并集），顺带修复沪 ETF 行情三源连挂存量缺陷（`StockRef.Exchange.of` 缺 5→SH 分支）。前端 `/screener` 第三 tab「基金」。
- **数据面落地数字（本地 dev 库）**：etf_basic **1685 只**（宽基 675 / 行业 663 / QDII 252 / 债券 53 / 商品 42）；近 1 年日线 ETF **356,349 行** + 跟踪指数 **95,473 行**（合计 ≈45 万行，`index_close_history` 总量 550,468）；跟踪误差参与 1650 只、**非 null 1227 只**（null 分解：235 只指数码无日线行 + ~188 只样本 <120），中位 TE 4.1%；对齐性 sanity：510300 vs 000300 近 1 年 241 个交易日 EXCEPT 差集 = 0。
- **测试规模增量**（MS-13 基线 758+113+15 / 638 / 222 → 本期）：后端单测 **118 套件 854 用例（+96）**、集成 **37 套件 122 用例（+9）**、BDD 15 用例（持平），JaCoCo（test 报告口径）指令 83.2% / 分支 81.5%（门槛 ≥80%）；前端 vitest **103 文件 696 用例（+58）**语句 94.2% / 分支 87.14%；collector **245 用例（+23）**覆盖率 95.01%（门槛 ≥80%）。

## 二、经验（做对了什么）

1. **范围先裁决再动工**：grilling 三轮把 MS-14「4 点」收敛为「3 点交付 + F11 随 MS-10」——天眼查阻塞的产业链图谱不硬等（决策 #1）、ETF 对象口径收窄仅场内（决策 #2）、对比维度固定集剔除融资热度（决策 #4）。三点全部数据源已实证或既有，零外部阻塞交付。
2. **复用优先，包数不膨胀**：ETF 日线复用 `index_close_history`（零新表）、TE 重算照 `industry_valuation_backfill` DB→DB 先例、ETF 筛选并入 `domain/screening`（`FundScreeningCriteria` 平移个股模式）、行业关注照 watchlist 全套先例入 `domain/industry`、⭐ 复用 `/api/watchlist`——全程**零新领域包**，DDD 分包规范只需两行登记（screening/industry 各一行），ArchUnit 白名单零改动。
3. **已知答案测试拦下 brief 数学错误**（计划不是事实源的第三次实证）：T15 brief 构造「ETF 恒定偏离指数 0.1%」期望非零 TE——恒定差的 std=0，实现者识破后改为交替 ±0.1% 构造（期望 ≈`0.001×√252`）；MS-13 复盘「计划期数值口径笔误」教训的同源复发与同法拦截。
4. **探测结论也要可复现**：Task 0 首版报告的 ISEXCHG 字段（判场内/场外）复测不可复现，当日勘误剔除（`3b9383c`）并改为「新浪 ETF 目录天然全场内，无需过滤」——避免了下游 T13 带着幻影字段实现。
5. **存量缺陷顺手修 + 实测钉死**：T17 发现 `StockRef.Exchange.of` 缺 5→SH 分支致沪 ETF 行情三源连挂（P0 探测顺带暴露的既有缺陷）——一行修复 + 518880 实测 8.788 与腾讯直连价一致，深市无 5 开头段无回归面。
6. **e2e 门控范式第三次复用 + 真链路断言**：空库 CI 与本地真库分叉用探测门控（照 MS-09 `boardHasData`）跳过数据态用例；数据态用例本身走真后端反代链路且只断言「≥1 行 + TE 列格式」不断言具体行数——既覆盖 mock 盲区（fundScreeningApi 的 zod 边界/反代透传）又对数据漂移免疫。

## 三、不足

1. **TE 收盘价口径系统性偏高**：510300 实测 3.18% vs 官方 NAV 口径 ~0.5%（除息占方差 67%），1227 只中 ~70 只 >30% 系拆分/折算事件污染——本轮只做前端口径标注（「与官方净值口径不可直接对比」）未根治，复权口径后续。
2. **category 关键词法个位数误判**：黄金产业**股票**指数因含「黄金」误入商品桶、一带一路/央企等主题未列举归宽基——规则常量化+测试钉住，误判可增量修正但精度天花板在。
3. **fund tab ⭐ 继承个股 UX 缺陷**：⭐ 失败反馈复用 setError 只在个股分支渲染（失败不可见）；⭐ 已自选不能从基金 tab 移除（个股先例逐字继承）。
4. **三个 collector 文件漏跑 ruff format**（plugins.py / test_plugins.py / test_writer_idempotency.py）——任务级验证只跑了 pytest，格式门在收尾 `make test` 才暴露，返工一次格式化（无行为差异）。
5. **CI e2e 测不到数据态**：门控跳过让 CI 永远走空态分支——基金 tab 数据链路（真后端筛选/⭐ ETF 自选/现价列）只靠本地真库 e2e + 后端集成测试兜底（与 MS-13 不足 #2 同象，两库数据面分叉未收敛）。

## 四、优化建议

1. **TE 复权口径根治**：ETF/指数日线改前复权（qfq）或对分红日做收益修正，消除去息方差与拆分污染（污染只多不少、当前偏保守）。
2. **⭐ 移除 UX 补齐**：基金 tab 结果行支持已自选 → 移除（与自选 tab「移除」按钮对齐），失败反馈在基金分支渲染。
3. **category 分类源升级**：关键词表增量维护为短期方案；中期换基金公司官方分类或交易所分类字段（探测报告 §7 已列候选）。
4. **collector 提交前格式门**：任务验证命令固定含 `ruff format --check`（或 pre-commit hook），避免收尾期才暴露。
5. **`sortDirection` null 直构 NPE 面**（个股同构继承）：`FundScreeningCriteria` 构造前校验 null 直构路径，与个股筛选一并加固。
6. **smoke §5 共享 threadId 改按次唯一（或跑前清理 state）**：固定 `smoke-ms12` 一旦残留未应答中断即把整个 thread 永久卡死（重启不自愈，state 落盘 `.agentscope/state/`），三次复跑不可自愈只能人工清（本轮实证；同机 `smoke-ms12b/c` 残目录显示此前已发生过）。
