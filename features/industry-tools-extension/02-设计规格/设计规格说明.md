## §1 P1 · CSV 批量导入（M08-F12）

### 1.1 CSV 格式（模板即权威口径）

- 编码 UTF-8（带或不带 BOM 均可读，写入模板时带 BOM——对齐 `ScreeningCsv` 导出口径）；RFC 4180（Commons CSV `CSVFormat.DEFAULT.builder().setHeader().setSkipHeaderRecord(true)` 解析）。
- 九列固定顺序，首行表头：

```
日期,类型,证券代码,证券名称,分组名称,价格,数量,费用/金额,备注
2024-01-05,BUY,600519,贵州茅台,主账户,1680.00,100,5.00,首次建仓
2024-06-20,SELL,600519,贵州茅台,主账户,1750.50,50,5.00,
2024-07-01,CASH_DIVIDEND,600519,贵州茅台,主账户,25.63,,,
2024-07-01,STOCK_DIVIDEND,600519,贵州茅台,主账户,0.05,,,
2024-01-03,DEPOSIT,,,,主账户,,,200000.00,初始入金
2024-08-10,WITHDRAW,,,,主账户,,,10000.00,出金买房
```

- 列语义按类型：
  | 类型 | 日期列 | 证券代码/名称 | 分组名称 | 价格列 | 数量列 | 费用/金额列 |
  |---|---|---|---|---|---|---|
  | BUY/SELL | trade_date | 必填 | 必填 | 单价（>0） | 股数（>0） | 费用（≥0，可空=0） |
  | CASH_DIVIDEND | ex_date | 必填 | 必填 | 每股现金（>0） | 空 | 空 |
  | STOCK_DIVIDEND | ex_date | 必填 | 必填 | 每股送股比例（>0） | 空 | 空 |
  | DEPOSIT/WITHDRAW | tx_date | 空 | 必填 | 空 | 空 | 金额（>0） |
- 备注 ≤255 字符（落 `cash_transaction.note` / 导入忽略行级备注对 trade 不落库——trade 无 note 列，备注仅辅助人读）。
- 类型枚举即模板第二列白名单，大小写敏感（全大写）。

### 1.2 校验管线（五层，全部通过才执行）

| 层 | 校验内容 | 错误示例（行号+原因） |
|---|---|---|
| L1 解析 | 编码/列数=9/表头匹配/行数 ≤2000 | 第 3 行：列数不符（期望 9 列，实际 8 列） |
| L2 格式 | 类型枚举合法；日期 yyyy-MM-dd 且可解析；数值列可解析且符合各类型正负约束（§1.1 表） | 第 5 行：类型无效 FOO（允许：BUY/SELL/CASH_DIVIDEND/STOCK_DIVIDEND/DEPOSIT/WITHDRAW） |
| L3 引用 | 分组名称在该用户 portfolio 下存在（决策 #14）；证券代码在 `stock_valuation_daily` 最新快照或该用户历史持仓中出现过 | 第 2 行：分组不存在「主账户」，请先在页面创建或修改 CSV |
| L4 日期 | 任何行日期 > 今日 → 行错误（决策 #9） | 第 7 行：日期不能晚于今日（2026-09-26） |
| L5 模拟重放 | 按（分组, 日期, 文件行序）排序后逐行作用到**当前库态之上**：组现金（起点=现 `cashBalance`）逐事件演化，BUY 需现金充足、WITHDRAW 后现金 ≥0（比单笔严：批量错行影响大）、SELL/分红数量 ≤ 当时持仓数量 | 第 12 行：现金不足——排序重放后该分组可用 85000.00，本行需 168005.00（含费） |

- L5 与既有用例校验同构（`PortfolioApplicationService.buy` 的 INSUFFICIENT_CASH / `Position.applySell` 的 SELL_EXCEEDS_QUANTITY），语义一致但**在内存模拟器中先算**（不写库）；全部通过后执行阶段落库（§1.4）。
- 执行阶段**不逐条调 `buy()/sell()` 用例**——它们返回 `PositionView` 时每笔触发一次 `quoteQuietly` 行情调用（`buy` :168 / `sell` :180 → `positionView`），2000 行上限会串行打满行情源且必然超出前端 proxy 15s 超时。改为：对每个受影响 `(groupId, stockCode)` 取/建 `Position` 实体后按行序调**领域实体方法** `applyBuy/applySell/applyCashDividend/applyStockDividend`（领域校验完整保留——INVALID_INPUT/SELL_EXCEEDS_QUANTITY 抛点就在实体内），演化完 savePosition；Trade/Dividend/CashTransaction 记录逐行落库。模拟器与执行演化的一致性用同构测试对拍（执行后库内持仓=模拟器终态）。
- 同日多行：文件行序即稳定序（决策 #8 的「文件行序」项）；与 `replay()` 的「同日先交易后分红」不冲突——导入按行序执行，replay 重建时按其自身口径。

### 1.3 端点与契约

| 端点 | 方法 | 说明 |
|---|---|---|
| `/api/portfolio/import/template` | GET | 模板下载：含表头+六类示例行的 CSV（UTF-8 BOM），`Content-Disposition: attachment; filename=import-template.csv`（照 `ScreeningCsv` 口径手写，无需 Commons CSV 写侧） |
| `/api/portfolio/import` | POST | multipart/form-data，字段名 `file`；需登录；上限 2000 数据行 + 1MB 文件 |

- POST 响应（HTTP 200，行级错误不走异常——错误清单是多行结构，不适合 GlobalExceptionHandler 单 message）：

```json
{ "importedCount": 0, "rowErrors": [ { "row": 3, "reason": "分组不存在「主账户」，请先在页面创建或修改 CSV" } ] }
```

- `importedCount > 0 && rowErrors == []` = 全部成功；`importedCount == 0 && rowErrors 非空` = 全量拒绝（all-or-nothing，决策 #7）。
- 文件级错误（空文件/非 CSV/超行数上限/超大小）→ 400 异常 message（单条语义，走既有异常通道，错误码复用 `INVALID_INPUT`）。

### 1.4 分包与组件

```
application/portfolio/
  PortfolioImportService.java      编排：解析→五层校验→同事务执行（实体方法演化落库，零行情调用，见 §1.2）
  CsvImportParser.java             Commons CSV 解析 + L1/L2（产出 List<ImportRow> 或行错误）
domain/portfolio/
  ImportRow.java                   已解析行 record（type/date/code/name/group/price/qty/amount/fee/note/原始行号）
  ImportSimulator.java             L5 纯函数：起点态(组现金+每股数量) + 排序行 → 行错误或「按行序的规范化操作序列」
  ImportSimulationState.java       模拟态（groupId→cash、(groupId,stockCode)→qty；初始从 repository 快照装载）
web/PortfolioController.java       挂两端点（import 用 @RequestParam MultipartFile）
```

- Commons CSV 仅在 application 层（domain 零第三方依赖惯例不变）；`build.gradle` 加 `implementation 'org.apache.commons:commons-csv:1.11.0'`。
- 执行阶段寻址：按（groupId, stockCode）查 `findPositionByPortfolioIdAndGroupIdAndStockCode`，不存在则 `Position.create`（含已清仓行——写路径可寻址，`PortfolioApplicationService` 注释 :426-427 已确认）；导入器维护 (groupId, stockCode) → positionId 映射供 SELL/分红行寻址。
- L3 追加：分组类型必须 `GroupType.ACCOUNT`（TAG 标签组不可交易/不可挂现金——`BuyForm` 前端「仅 ACCOUNT 类型」既定口径，后端补齐）。
- 未来日期收紧（决策 #9）：`buy`/`sell`/`addCashDividend`/`addStockDividend`/`addCashTransaction` 五用例开头统一加 `if (cmd 日期().isAfter(LocalDate.now())) throw INVALID_INPUT("日期不能晚于今日")`；今日=服务器默认时区（部署于 Asia/Shanghai 口径，dev/CI 一致）。

### 1.5 前端

- `components/portfolio/ImportDialog.tsx`：`<input type="file" accept=".csv">` + 提交 + 结果态（成功 N 笔 / 错误行表）；挂 `PortfolioBoard` 工具区「批量导入」按钮；模板下载 `<a download>` 直连模板端点（照筛选器导出先例）。
- `lib/proxy.ts` relay 改造：`body instanceof FormData` 时不设 Content-Type（浏览器自动生成 boundary）；`app/api/portfolio/[...path]/route.ts` POST 从 `await req.text()` 改 `await req.arrayBuffer()` 并透传入站 `content-type`（CSV 文本 text() 虽可，arrayBuffer 对 multipart 通用且无编码歧义）。
- 成功后触发 PortfolioBoard 既有 `reload()`（六接口全量重拉复用）。

## §3 P3 · ETF 筛选（M09-F06，仅场内）

### 3.1 数据面（Task 0 探测先行，不可得维度降级）

| 数据 | 主源（探测确认） | 落库 | 降级 |
|---|---|---|---|
| ETF 目录+跟踪指数+类别 | akshare `fund_etf_category_sina`（新浪）/ 东财 ETF 列表 | `etf_basic` | 目录不可得→里程碑降级拍板（无目录=无筛选） |
| 费率（管理+托管） | 天天基金 `fundf10.eastmoney.com/jjfl_*.html`（已实测 200） | `etf_basic.fee_rate` 合计年化% | 不可得→费率列「—」，筛选项隐藏 |
| 规模 | akshare `fund_scale_change_em` / 目录接口字段 | `etf_basic.scale` 亿元 | 不可得→规模列「—」 |
| ETF 日线收盘 | tushare `fund_daily`（已实证单代码；探测 `trade_date=` 全市场模式行数/限频） | `index_close_history` 加行（照 518880 先例，index_code=六位基金代码） | — |
| 跟踪指数日线 | tushare `index_daily`（既有） | `index_close_history` 加行 | — |
| 跟踪误差 | 自算（collector 日任务） | `etf_basic.tracking_error_1y` | 样本 <120 交易日→null 显示「—」 |

```sql
-- V18__etf_screening.sql
CREATE TABLE etf_basic (
    fund_code             VARCHAR(16) PRIMARY KEY,   -- 6 位无后缀，与 index_close_history.index_code 同格式
    fund_name             VARCHAR(64) NOT NULL,
    fee_rate              NUMERIC(8,4),              -- 管理费+托管费合计（年化%），null=未知
    scale                 NUMERIC(18,4),             -- 亿元，null=未知
    tracking_index_code   VARCHAR(16),               -- 跟踪指数 6 位码，null=未知
    tracking_index_name   VARCHAR(64),
    category              VARCHAR(32) NOT NULL,      -- 宽基/行业/商品/债券/QDII/其他
    tracking_error_1y     NUMERIC(10,6),             -- 近1年日频差值 std×√252，null=样本不足
    updated_at            TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

- 跟踪误差口径（决策 #3）：窗口=近 1 年（250 交易日，<120 有效样本置 null）；`std_t(etf日收益 − 指数日收益) × √252`，日收益=收盘价环比（**收盘价口径**而非单位净值——fund_daily 与 index_close_history 同为市场价口径，序列对齐天然；探测若发现 tushare `fund_nav` 积分可得可升级净值口径，非本轮依赖）。收益差对齐：两序列按 trading_day inner join；指数缺失日的 ETF 收益跳过（不插值）。计算在 collector（pandas，日任务全量重算——数千只×250 日在 collector 批处理可接受；读侧请求时算被否）。
- collector 任务：`etf_basic`（周更目录/费率/规模）+ `etf_close`（日更，fund_daily）+ `tracking_index_close`（日更，指数日线——依赖 etf_basic.tracking_index_code 全集去重）+ `etf_tracking_error`（日更重算回写 etf_basic.tracking_error_1y）；均 YAML 声明式 + plugins.py 源类 + jobs.py 注册（照 gold_etf_close 全套先例）。
