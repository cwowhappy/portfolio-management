# 投资决策记录需求规格说明

- 日期：2026-09-02
- 状态：待实施
- 范围：MS-06 投资决策记录（M11-F01 买入备忘录 + F02 卖出备忘录 + F03 研究笔记 + F04 定期复盘 + F05 投资时间线视图 + F06 与持仓联动），全部 6 个功能点本里程碑交付，无后置
- 依据文档：[产品落地计划](../../../docs/plans/2026-08-27-产品落地计划.md) · [功能模块概览](../../../docs/function/00-功能模块概览.md) · [M11 投资决策记录](../../../docs/function/modules/11-投资决策记录.md) · [M08 持仓组合管理](../../../docs/function/modules/08-持仓组合管理.md)

## 一、背景与目标

一期投研信息获取闭环、估值仪表盘（MS-02）、持仓组合管理（MS-03）、资产配置基础（MS-04）、价值筛选与行业估值（MS-05）均已交付。进入二期「决策闭环」，**投资决策记录**回答「我为什么买这只股票、什么时候该卖、事后复盘对不对」，把买卖决策、研究过程与定期复盘沉淀为结构化记录，形成可回溯的投资决策闭环。

**交付物**：

1. 新增后端 `domain/journal` 域（纯 POJO，零 Spring/JPA 注解）+ `/api/journal/**` 接口（需登录）；
2. 新增前端 `/journal` 页面：时间线视图 + 备忘/笔记/复盘列表与编辑器；
3. 与 M08 持仓联动：买卖备忘录关联单笔交易（tradeId），时间线聚合买/卖/分红/备忘/复盘事件。

## 二、需求澄清汇总

| # | 需求点 | 决策 |
|---|---|---|
| 1 | 数据模型 | 统一 `JournalEntry` 聚合根 + `type` 枚举区分四类记录，单表存储；类型特有字段（目标价/止损价/期间）可空 |
| 2 | F06 联动粒度 | 备忘录关联到具体交易 `trade_id`（可选外键）+ 冗余 `stock_code`；归属校验在应用层 |
| 3 | F04 复盘结构 | Markdown 正文 + 元数据（`period_type` + `period_start` + `period_end`），非固定字段模板 |
| 4 | F05 时间线聚合位置 | 后端 application 层统一聚合一个 timeline 接口，前端只消费一个端点 |
| 5 | 时间线事件类型 | 精确 7 类：买/卖/分红（M08）+ 买入备忘/卖出备忘/研究笔记/复盘（journal）；模块 F05 原文「五类」为粗分组，研究笔记单列 |
| 6 | Flyway 迁移 | `V8__journal.sql`（当前已到 V7） |
| 7 | 特性目录 | `features/journal/`（对应路由 `/journal`） |
| 8 | 访问权限 | `/journal` 需登录；后端按登录用户隔离，非本人记录返回 404 |
| 9 | 时间线定位日期 | 引入显式 `eventDate`（LocalDate），创建默认今天、可回填；时间线按事件日排序 |
| 10 | 股票名存储 | `journal_entry` 反规范化存 `stock_name`（写入时从行情/M08 解析），时间线零实时查询 |
| 11 | 研究笔记行业 | 不引入结构化行业字段，行业标注写进 `title`/`content` 自由文本 |
| 12 | 联动可编辑性 | `tradeId` 可编辑（PUT 可设置/清除），每次变更做归属校验 |
| 13 | 删除语义 | 硬删除（与 M08 一致） |
| 14 | 时间线形态 | 扁平倒序 + 日期范围过滤，MVP 不分页 |
| 15 | 复盘唯一性 | 允许同期间多条，不设唯一约束 |
| 16 | 时间线事件类型 | 7 类（买/卖/分红 + 买入备忘/卖出备忘/研究笔记/复盘） |

## 三、功能需求

### A. 领域记录模型（F01–F04 共通）

**FR-A1 统一记录模型**

四类记录统一建模为 `JournalEntry` 聚合根，`type` 枚举区分：

| type | 中文 | 特有字段 |
|------|------|---------|
| `BUY_MEMO` | 买入备忘 | `targetPrice` / `stopLoss` |
| `SELL_MEMO` | 卖出备忘 | —（理由与收益回顾写入 content） |
| `RESEARCH_NOTE` | 研究笔记 | —（Markdown content） |
| `REVIEW` | 定期复盘 | `periodType` / `periodStart` / `periodEnd` |

共通字段：`id` / `userId` / `type` / `stockCode`（可空，关联股票）/ `stockName`（可空，股票名反规范化）/ `tradeId`（可空，关联 M08 交易）/ `title`（必填）/ `content`（Markdown，必填）/ `eventDate`（事件日，必填，创建默认今天、可回填）/ `createdAt` / `updatedAt`。

**FR-A2 CRUD（F01–F04 通用）**

- 四类记录共用同一套「列表 / 创建 / 详情 / 编辑 / 删除」操作，按 `userId` 隔离；删除为硬删除。
- 列表支持按 `type` 过滤（`GET /api/journal/entries?type=BUY_MEMO`），按 `updatedAt` 倒序。
- `eventDate` 默认取创建当天；关联 `tradeId` 的备忘前端可预填交易 `tradeDate`、复盘前端可预填 `periodEnd`，用户均可改。

### B. 买入 / 卖出备忘录（F01 / F02）

**FR-B1 买入备忘录（F01）**

- 记录买入理由、目标价（`targetPrice`）、止损价（`stopLoss`）；理由写入 `content`（Markdown）。
- 校验：`stockCode` 必填（除非提供 `tradeId`，此时 `stockCode`/`stockName` 由交易回查并冗余）；`targetPrice` / `stopLoss` 可选，若提供须 > 0。
- `stockName`：有 `tradeId` 时取交易所属 `Position.stockName()`；无 `tradeId` 时由客户端经行情 `search`/`quote` 解析后传入。

**FR-B2 卖出备忘录（F02）**

- 记录卖出理由与收益回顾，均写入 `content`（Markdown）；无 `targetPrice` / `stopLoss` 语义。

**FR-B3 与持仓联动（F06）**

- 备忘录可选关联单笔 M08 交易（`tradeId`）；`tradeId` 可编辑（创建或更新均可设置/清除），每次变更都做归属校验。
- 提供 `tradeId` 时：
  - 应用层校验该交易归属当前用户（trade → position → portfolio → user），非本人交易拒绝（错误码 `TRADE_NOT_FOUND`，不泄露存在性）；
  - `stockCode`/`stockName` 以交易所属 `Position` 为准（客户端传值须一致，否则拒绝）。
- 不提供 `tradeId` 时，备忘录独立存在（如「计划买入但未成交」的备忘）。

### C. 研究笔记（F03）

**FR-C1 研究笔记**

- Markdown 格式的个股/行业深度研究笔记。
- `stockCode` 可选（行业级笔记可不绑定个股）；`title` + `content` 必填。

### D. 定期复盘（F04）

**FR-D1 定期复盘**

- Markdown 正文 + 元数据：`periodType`（`QUARTERLY` 季度 / `ANNUAL` 年度）、`periodStart`、`periodEnd`。
- 校验：`periodType` / `periodStart` / `periodEnd` 必填；`periodStart ≤ periodEnd`；不绑定个股（`stockCode` 为空）。

### E. 投资时间线视图（F05）

**FR-E1 时间线聚合**

- 后端统一接口 `GET /api/journal/timeline`，合并两类数据源为一个按事件日倒序（journal 取 `eventDate`，M08 取 `tradeDate`/`exDate`）的事件流：

| 事件类型 | 来源 | 日期字段 |
|---------|------|---------|
| `BUY` / `SELL` | M08 `Trade` | `tradeDate` |
| `DIVIDEND` | M08 `Dividend` | `exDate` |
| `BUY_MEMO` / `SELL_MEMO` / `RESEARCH_NOTE` / `REVIEW` | journal `JournalEntry` | `eventDate` |

**FR-E2 事件字段**

- 每个事件返回：`type`（上表 7 类）、`date`（事件日：journal 取 `eventDate`，M08 取 `tradeDate`/`exDate`）、`title`、`description`（摘要）、`stockCode` / `stockName`（股票类事件）、`refId` / `refType`（跳转回源记录）。
- 支持日期范围过滤 `?from=` / `?to=`。

### F. 接口清单

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/journal/entries` | 记录列表（可选 `?type=` 过滤） |
| POST | `/api/journal/entries` | 创建记录 |
| GET | `/api/journal/entries/{id}` | 记录详情 |
| PUT | `/api/journal/entries/{id}` | 编辑记录 |
| DELETE | `/api/journal/entries/{id}` | 删除记录 |
| GET | `/api/journal/timeline` | 时间线聚合（journal + M08） |

所有接口需登录，按当前用户隔离，非本人记录 404。

## 四、非功能需求（NFR）

| 类别 | 要求 |
|---|---|
| 数据一致性 | 备忘录 `tradeId` 归属校验正确；`stockCode`/`stockName` 与交易一致；复盘 `periodStart ≤ periodEnd`；`eventDate` 非空 |
| 安全 | `/journal` 需登录；按用户隔离，非本人记录 404 不泄露存在性 |
| 分层 | `domain/journal` 纯 POJO 零 Spring/JPA 注解、零跨域依赖；`application.journal` 消费 `domain.portfolio` 读接口做联动与时间线 |
| 性能 | 时间线聚合 M08 交易/分红按持仓批量读取，不逐交易串行查行情 |

## 五、验收标准

- 四类记录创建/编辑/删除/列表正确，类型特有字段校验到位；
- 备忘录关联 `tradeId` 时归属校验正确（非本人交易拒绝、stockCode/stockName 自动冗余一致）；`tradeId` 可增改删；
- 时间线正确聚合 7 类事件并按事件日倒序，日期范围过滤有效；
- `/journal` 未登录跳转登录；非本人记录不可见；
- `make test`（覆盖率 ≥80%）+ `make smoke` + Playwright e2e 通过。

## 六、明确不做（YAGNI）

- 备忘录与交易的强外键/级联（交易在 M08 删除后，备忘保留为独立记录，`tradeId` 悬空不级联）；
- 复盘结构化模板字段（本期操作回顾/得失/下一步拆字段）——Markdown 承载；
- AI 决策记录工具（属 MS-12，不在本里程碑）；
- 决策记录的收益对账（复盘对照 M12 收益数据，属二期 MS-07 之后）；
- 复盘提醒/定时任务（三期）；
- 备忘的「预期持有期」结构化字段——写入 content 自由文本；
- 软删除 / 审计留存——硬删除即可；
- 研究笔记的结构化行业标签——写进标题/正文自由文本；
- 时间线分页与按月/季分组——MVP 扁平全量 + 日期范围过滤。

## 七、依赖与风险

**依赖**

- M08 持仓组合管理：`domain.portfolio.PortfolioRepository` 提供交易/分红/持仓读取（时间线聚合 + `tradeId` 归属校验）；
- 认证体系（M01）支撑 `/journal` 私有与用户隔离。

**风险**

| 风险 | 影响 | 应对 |
|---|---|---|
| `tradeId` 归属校验需跨 trade→position→portfolio→user 多跳 | 联动校验实现较绕 | 应用层封装为单一校验方法，集成测试覆盖「非本人交易拒绝」 |
| 时间线聚合 M08 侧 N+1（逐持仓查交易/分红） | 持仓多时时间线慢 | 按 `findPositionsByPortfolioId` 一次取持仓，逐持仓批量查交易/分红；持仓量小可接受 |
| M08 交易删除后 `tradeId` 悬空 | 备忘仍展示但关联交易消失 | 明确「不级联、悬空保留」，时间线跳过无效 tradeId（防御性 null 处理） |
