# MCP 数据源接入 · 需求规格说明

> 状态：已确认需求（2026-09-06，统一重写版）。背景调研见 [docs/technology/research/03-金融机构MCP服务参考.md](../../../docs/technology/research/03-金融机构MCP服务参考.md)。
> 设计见 `02-design/设计规格说明.md`。P0 技术验证结论见 `03-plan/验证记录.md`。

## 背景与目标

当前投研 Agent 只有 7 个内置 `@Tool`（行情/K线/财务/新闻/大盘/估值），数据能力由开发者硬编码。2026 年国内金融机构官方 MCP 服务已成型（东财妙想、Tushare 官方、Wind AIFin 等），可作为内置工具的补充数据源，扩展对话能回答的问题范围（宏观、公告、研报、港美股、债券等）。

**目标**：以**系统内置 MCP 目录**（provider + domain 两级）接入这些官方数据源，系统统一管理 Token，用户按 provider 选择启用，对话时按用户动态装配工具集；并在其上叠加 **agentscope-harness** 提供长期稳定运行的工程能力（记忆、压缩、会话持久化等）。

## 关键决策（已确认，2026-09-06）

1. **系统内置目录，两级 provider + domain**：数据源以「provider（鉴权/Token 维度）→ endpoint（domain 维度，一个 provider 下 1..N 个）」两级组织，一期内置 3 provider（妙想/Tushare/Wind）+ 8 endpoint（Wind 6 域）。用户不可自定义服务器/工具。
2. **Token 系统全局，非 per-user**：一个 provider 一个系统 Token，全员共享；一期经数据 INSERT 预置，二期在 admin UI 配置（届时加密存储）。用户不再填自己的 Token。
3. **用户按 provider 选择**：用户对每个 provider 做「启用/停用 + 工具级开关」，无需配置 Token。
4. **一期只收官方远程 HTTP（Streamable HTTP）**：妙想（HEADER）、Tushare（BEARER）、Wind（BEARER）；不支持 stdio。
5. **本地内置工具优先**：7 个内置工具仍是行情类问题首选；MCP 工具定位是扩展能力，提示词写明分工规约。
6. **不接交易类 MCP**：本系统是投研问答，无交易场景；一期不识别「是否含写工具」。
7. **叠加 agentscope-harness（完整能力）**：`HarnessAgent` 取代裸 `ReActAgent`，启用工作区上下文注入、双层持久记忆、对话压缩、会话持久化、文件系统/沙箱、子 agent 编排、技能加载。历史模型切换为**服务端持久化**（`server-side-memory: true`，前端只发最新一条消息）。

## 用户故事

- 作为**用户**，我在「MCP 设置」看到系统内置的 3 个 provider（妙想/Tushare/Wind），选择启用 Wind，对话即可使用 Wind 的股票/基金/指数/债券/宏观/分析数据。
- 作为**用户**，我可以按工具粒度开关某个 provider 的工具（默认全启用），停用某 provider 后立即不可用。
- 作为**用户**，我未启用任何 MCP 时，对话体验与现状一致（只有 7 个内置工具）。
- 作为**管理员**，我在二期可以配置系统内置 MCP 的 Token（加密存储）。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 内置数据源目录：provider（妙想/Tushare/Wind）+ endpoint（Wind 6 域）两级，含名称、URL、鉴权方案；一期只读，用户不可增删改 |
| FR-2 | 连接测试：用系统 Token 对 provider 发起真实握手，返回工具清单与耗时；失败给出可读错误 |
| FR-3 | 工具清单与开关：展示 provider 下 live 发现的工具列表（跨 domain 扁平），支持单工具启用/停用（默认全启用） |
| FR-4 | 用户配置：用户对每个 provider 保存启用开关 + 禁用工具清单（无 Token） |
| FR-5 | 对话按用户装配：内置 7 工具 + 本人启用的 provider 的 endpoint 工具，减去被禁用的工具 |
| FR-6 | 故障隔离：任一 endpoint 连接失败/超时，不影响对话主流程与内置工具；Agent 侧表现为该工具不可用 |
| FR-7 | 密钥安全：provider 系统 Token 一期数据 INSERT 预置（迁移 seed），二期 admin UI 配置时 AES-GCM 加密存储；任何 API 不回显明文 |
| FR-8 | 鉴权建模：支持 NONE / BEARER / HEADER 三类（妙想 HEADER `em_api_key`、Tushare BEARER、Wind BEARER，均经 P0 实测） |
| FR-9 | Harness 会话持久化：服务端按 (userId, sessionId) 持久化会话状态，前端只发最新一条消息，历史由服务端维护 |
| FR-10 | Harness 工作区与记忆：每用户独立工作区（AGENTS.md 人格注入）+ 双层持久记忆（对话事实跨会话沉淀） |
| FR-11 | Harness 对话压缩：历史超阈值时自动摘要，模型报 context overflow 时强制压缩重试 |
| FR-12 | Harness 文件系统与沙箱：文件工具经可插拔文件系统，配合 userId 做多租户隔离 |

## 非功能需求

- **性能**：MCP 初始化不阻塞对话首 token——client 池化复用 + 初始化超时（默认 10s）；配置变更即时生效。
- **可靠性**：单次工具调用超时（默认 30s），超时按 FR-6 降级。
- **可观测**：MCP 连接成功/失败、工具调用失败有日志（不含 Token）。
- **架构合规**：遵循 DDD 分包规范（`domain.mcp` / `application.mcp` / `web` / `infrastructure` / `agent`），ArchUnit 全绿。

## 验收标准

1. 用户启用 Wind 后对话可使用其工具；停用后立即不可用。
2. 未启用任何 MCP 的用户对话行为与现状一致（仅 7 内置工具）。
3. 两个数据源暴露同名工具时按「内置 > provider 顺序 > domain 顺序」去重。
4. 配置一个不可达的 endpoint，对话仍正常进行，日志有告警。
5. 服务端持久化后，同一 sessionId 的第二次对话能记得第一轮内容（harness 会话持久化）。
6. Token 不出现在任何 API 出参与日志（一期 seed 明文的已知风险见设计 §五）。
7. 覆盖率门槛不降级（后端 JaCoCo ≥80%），ArchUnit 全绿。

## 范围外（一期不做）与后续计划

**范围外（一期不做）**：

- stdio 传输、SSE（旧协议）传输
- 交易类 MCP 的接入与写工具识别
- 免费社区封装（mcp-eastmoney、akshare-one-mcp 等）
- MCP server 用量统计/计费配额
- 工具调用的用户级审计日志页面
- iFinD、Wind docs 域（端点未确认）

**后续计划（演进方向）**：

- **admin UI 配置系统内置 MCP**：二期管理员在界面配置 provider Token（AES-GCM 加密落库），替换一期迁移 seed
- **用户自建任意 MCP 服务器**：原「用户 CRUD URL/密钥 + 管理员审核」模型——届时补回 SSRF 校验、审核链
- **harness 增量能力**：技能市场、子 agent 编排、沙箱隔离执行按需逐步开启
