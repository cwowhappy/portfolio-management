# MCP 数据源接入 · 需求规格说明

> 状态：已确认需求（2026-09-06）。背景调研见 [docs/technology/research/03-金融机构MCP服务参考.md](../../../docs/technology/research/03-金融机构MCP服务参考.md)。
> 设计见 `02-design/设计规格说明.md`。

## 背景与目标

当前投研 Agent 只有 7 个内置 `@Tool`（行情/K线/财务/新闻/大盘/估值），数据能力由开发者硬编码。2026 年国内金融机构的官方 MCP 服务已成型（东财妙想、同花顺 iFinD、Wind AIFin、Tushare 官方等），可作为内置工具的补充数据源，扩展对话能回答的问题范围（宏观、公告、研报、港美股、债券等）。

**目标**：以**系统内置 MCP 目录**的方式接入这些官方数据源——目录由系统维护、用户不可自定义服务器或工具，用户只需「选择内置数据源 + 填自己的 Token + 按需开关」，对话时按用户动态装配 Agent 工具集。

## 关键决策（已与需求方确认，2026-09-06）

1. **MCP 服务器系统内置，用户不可自定义**：MCP 服务器及其工具由系统以「目录（catalog）」形式内置，一期收录 4 台官方远程；用户不能自行添加 URL/服务器/工具，只能配置与使用。
2. **纯用户自有 Token**：需要鉴权的数据源由用户填自己的 Token（加密存储），一期不做「系统共享 Token」；配额随各自账号天然隔离。
3. **一期只收官方远程 HTTP（Streamable HTTP）**：东财妙想、Tushare 官方、同花顺 iFinD、Wind AIFin；不支持 stdio（服务器 spawn 用户指定本地进程的风险不可接受）。
4. **本地内置工具优先**：7 个内置工具仍是行情类问题首选（有缓存/限流/降级链）；MCP 工具定位是扩展能力，提示词写明分工规约。
5. **不接交易类 MCP**：本系统是投研问答，无交易场景；一期不做「是否含写工具」识别，靠提示与用户自负其责。
6. **用户自建任意 MCP 作为后续计划**：原「用户自行增删 MCP 服务器 + 管理员审核」模型暂缓，作为后续演进方向（见「后续计划」）。

## 用户故事

- 作为**用户**，我在「MCP 设置」看到系统内置的 4 个数据源，选择 Tushare 填入自己的 Token，测试连接看到工具清单，按工具粒度启用/停用后，对话即可使用。
- 作为**用户**，我未配置任何 MCP 数据源时，对话体验与现在完全一致（只有 7 个内置工具）。
- 作为**用户**，我可以随时停用某个数据源或删除自己的配置（清除 Token）。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 内置数据源目录：系统维护 4 台官方远程 MCP（妙想/Tushare/iFinD/Wind），含名称、URL、鉴权方案；用户不可增删改 |
| FR-2 | 连接测试：用户填自己的 Token 后可发起真实握手，返回工具清单与耗时；失败给出可读错误 |
| FR-3 | 工具清单与开关：展示该数据源 live 发现的工具列表，支持单工具启用/停用（默认全启用） |
| FR-4 | 用户配置：用户对每个内置数据源保存自己的配置（启用开关、Token、禁用工具清单），Token 加密存储 |
| FR-5 | 对话按用户装配：内置 7 工具 + 本人启用且已配置 Token 的 MCP 工具，减去被禁用的工具 |
| FR-6 | 故障隔离：任一 MCP 服务器连接失败/超时，不影响对话主流程与内置工具；Agent 侧表现为该工具不可用 |
| FR-7 | 密钥安全：用户 Token 加密存储（AES-GCM，主密钥仅存于服务端环境变量），任何 API 不回显明文 |
| FR-8 | 鉴权建模：支持 NONE / BEARER / HEADER / URL_TOKEN 四类；URL_TOKEN 表达 Tushare 的 token-in-URL，存储与回显时脱敏 |

## 非功能需求

- **性能**：MCP 初始化不阻塞对话首 token——client 池化复用 + 异步预热 + 初始化超时（默认 10s）；配置变更即时生效（缓存失效重建）。
- **可靠性**：单次工具调用超时（默认 30s），超时按 FR-6 降级为「该工具不可用」。
- **可观测**：MCP 连接成功/失败、工具调用失败有日志（不含密钥）。
- **架构合规**：遵循 DDD 分包规范（`domain.mcp` / `application.mcp` / `web` / `infrastructure`），ArchUnit 全绿。

## 验收标准

1. 用户选择内置 Tushare 数据源、填自己的 Token 并启用后，对话可使用其工具；停用后立即不可用。
2. 未配置任何 MCP 的用户对话行为与现状一致（仅 7 个内置工具）。
3. Token 在 DB 中为密文；目录/配置列表/详情接口无 Token 明文。
4. 配置一个不可达或错误 Token 的服务器，测试连接返回可读错误；对话仍正常进行，日志有告警。
5. 两个数据源暴露同名工具时，按「内置 > 目录顺序」去重，冲突工具不可用并记日志。
6. 覆盖率门槛不降级（后端 JaCoCo ≥80%），ArchUnit 全绿。

## 范围外（一期不做）与后续计划

**范围外（一期不做）**：

- stdio 传输、SSE（旧协议）传输
- 交易类 MCP 的接入与写工具识别
- 免费社区封装（mcp-eastmoney、akshare-one-mcp 等）
- 系统共享 Token（公司统一账号）
- MCP server 用量统计/计费配额
- 工具调用的用户级审计日志页面
- 管理员 MCP 管理界面

**后续计划（演进方向）**：

- **用户自建任意 MCP 服务器**：原「用户 CRUD URL/密钥 + 管理员审核个人 MCP 权限」模型——届时补回 SSRF 校验、个人权限审核链、管理员管理界面
- 系统/管理员共享 Token（公司统一账号场景）
- 管理员全局停用某个内置数据源
