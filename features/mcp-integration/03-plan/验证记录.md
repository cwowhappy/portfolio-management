## 结论速览
| 问题 | 结论 |
|---|---|
| §1 覆盖点 | `AguiRuntimeContextResolver` 不是 starter 的 `@Bean`，无 `@ConditionalOnMissingBean`——它经 `ObjectProvider.getIfAvailable()` 可选注入，**项目只需声明任意名字的 `@Bean AguiRuntimeContextResolver` 即被拾取**。`DefaultAgentResolver` 同样**不是 bean**，被 `AguiMvcController` 构造器硬编码 `new`，**无 bean 级覆盖点**；要换 agent resolver 只能整体替换 `@ConditionalOnMissingBean` 的 `AguiMvcController` bean。 |
| §2 逐个注册/过滤 | `McpClientWrapper.listTools()` 返回 `Mono<List<McpSchema.Tool>>`；`McpTool extends ToolBase implements AgentTool`，可用 `toolkit.registerTool(Object)`（内部有 `instanceof AgentTool` 分支）或更直接的 `toolkit.registerAgentTool(AgentTool)` 逐个注册。但 **`disabled_tools` 过滤有官方 API**：`toolkit.registration().mcpClient(w).disableTools(List).enableTools(List).apply()`。 |
| §3 共享 Agent 并发 | `server-side-memory=false` 下 `DefaultAgentResolver` 每次返回**同一个**注册的单例 Agent。2.0.1 的 `ReActAgent` 实际实现已支持并发：会话状态按 `(userId, sessionId=threadId)` 存于 `ConcurrentHashMap`，每次调用的推理状态在 Reactor Context 上的 `CallExecution` 里，同 slot 的并发调用 FIFO 串行、不同 slot 并行。**单个共享 agent 安全；缓存键建议 `(userId, threadId)`**。⚠️ 类 Javadoc 仍写「not thread-safe / 并发抛 IllegalStateException」，与代码不一致（过时）；残留共享可变点见 §3。 |

## §1 DefaultAgentResolver / AguiRuntimeContextResolver 覆盖点

### 1.1 `AguiRuntimeContextResolver` — 可选注入，不是被覆盖的默认 bean

定义（`agentscope-agui-spring-boot-starter` 源码 `io/agentscope/spring/boot/agui/common/AguiRuntimeContextResolver.java`）：

```java
@FunctionalInterface
public interface AguiRuntimeContextResolver {
    RuntimeContext resolve(AguiRuntimeContextRequest request);  // 返回 null 表示不注入
}
```

starter **从不声明该类型的 `@Bean`**，因此也没有任何 `@ConditionalOnMissingBean(AguiRuntimeContextResolver.class)`。它在 `AgentscopeAguiMvcAutoConfiguration` 中以 `ObjectProvider` 形式被消费：

```java
// io.agentscope.spring.boot.agui.mvc.AgentscopeAguiMvcAutoConfiguration
@Bean
@ConditionalOnMissingBean
public AguiMvcController aguiMvcController(
        AguiAgentRegistry registry,
        ThreadSessionManager sessionManager,
        AguiProperties props,
        ObjectProvider<AgentEventConverter> eventConvertersProvider,
        ObjectProvider<AguiEventEnricher> eventEnrichersProvider,
        ObjectProvider<AguiRuntimeContextResolver> runtimeContextResolverProvider,  // ← 这里
        ObjectProvider<AguiAgentAdapterFactory> adapterFactoryProvider) {
    ...
    return AguiMvcController.builder()
            ...
            .runtimeContextResolver(runtimeContextResolverProvider.getIfAvailable())  // ← 拾取
            .adapterFactory(adapterFactoryProvider.getIfAvailable())
            .config(config)
            .build();
}
```

`AguiMvcController` 侧：`private final AguiRuntimeContextResolver runtimeContextResolver;`，请求处理时

```java
private RuntimeContext resolveRuntimeContext(RunAgentInput input, String headerAgentId, String pathAgentId, HttpServletRequest request) {
    return runtimeContextResolver != null
            ? runtimeContextResolver.resolve(runtimeContextRequest(input, headerAgentId, pathAgentId, request))
            : null;
}
```

**结论（覆盖写法）**：无需同名 bean、也无需「覆盖」任何默认实现——直接在项目里声明：

```java
@Bean
public AguiRuntimeContextResolver myRuntimeContextResolver() {
    return request -> RuntimeContext.builder().userId(/* 从 request 解析 */).build();
}
```

就会被 `ObjectProvider.getIfAvailable()` 注入。WebFlux 侧 `AgentscopeAguiWebFluxAutoConfiguration.aguiWebFluxHandler(...)` 完全相同（本应用走 MVC/Servlet，故以 MVC 为准）。

### 1.2 `DefaultAgentResolver` — 不是 bean，无 bean 级覆盖点

定义（`io/agentscope/spring/boot/agui/common/DefaultAgentResolver.java`）：

```java
public class DefaultAgentResolver implements AgentResolver {   // io.agentscope.core.agui.processor.AgentResolver
    public DefaultAgentResolver(AguiAgentRegistry registry);
    public DefaultAgentResolver(AguiAgentRegistry registry, ThreadSessionManager sessionManager, boolean serverSideMemory);
    public static Builder builder();
    public Agent resolveAgent(String agentId, String threadId);
    public boolean hasMemory(String threadId);
}
```

- **没有任何 `@Component`/`@Bean`/`@ConditionalOnMissingBean` 注解**。
- 它被 `AguiMvcController` 的**私有构造器硬编码**创建，再喂给 `AguiRequestProcessor`（源码 `io/agentscope/spring/boot/agui/mvc/AguiMvcController.java`）：

```java
private AguiMvcController(Builder builder) {
    this.processor = AguiRequestProcessor.builder()
            .agentResolver(DefaultAgentResolver.builder()
                    .registry(builder.registry)
                    .sessionManager(builder.sessionManager)
                    .serverSideMemory(builder.serverSideMemory)
                    .build())
            .config(...)
            .adapterFactory(builder.adapterFactory)
            .build();
    ...
}
```

`AguiRequestProcessor` 侧消费：`AgentResolver`（接口 `resolveAgent(String,String)` / `hasMemory(String)`），`process(...)` 里 `Agent agent = agentResolver.resolveAgent(agentId, threadId);`。

**结论（覆盖写法）**：无法通过 `@Bean DefaultAgentResolver` 覆盖——starter 根本不把它当 bean 管理，也没有注入点。若真要替换 agent 解析逻辑，唯一入口是整体替换 `@ConditionalOnMissingBean` 的 `AguiMvcController` bean（其 `Builder.agentRegistry/sessionManager/serverSideMemory/...` 都存在，但构造器内部仍然 `new DefaultAgentResolver`，因此需自建 controller 并用自定义 `AgentResolver` 构建 `AguiRequestProcessor`）。**对本 MCP 特性而言无需覆盖它**；运行时上下文注入走 §1.1 的 `AguiRuntimeContextResolver` 即可。

### 1.3 实际带 `@ConditionalOnMissingBean` 的 bean 清单（精确签名）

`io.agentscope.spring.boot.agui.common.AguiAgentRegistryAutoConfiguration`（`@AutoConfiguration @ConditionalOnClass(...)`）：

```java
@Bean @ConditionalOnMissingBean
public AguiAgentRegistry aguiAgentRegistry(ObjectProvider<AguiAgentRegistryCustomizer> customizerObjectProvider)

@Bean @ConditionalOnMissingBean
public AguiAgentAutoRegistration aguiAgentAutoRegistration(AguiAgentRegistry registry)
```

`io.agentscope.spring.boot.agui.mvc.AgentscopeAguiMvcAutoConfiguration`（`@AutoConfiguration @ConditionalOnClass({SseEmitter.class, Agent.class}) @ConditionalOnBean(AguiAgentRegistry.class) @ConditionalOnWebApplication(SERVLET) @EnableConfigurationProperties(AguiProperties.class)`）：

```java
@Bean @ConditionalOnMissingBean
public ThreadSessionManager threadSessionManager(AguiProperties props)

@Bean @ConditionalOnMissingBean
public AguiMvcController aguiMvcController(AguiAgentRegistry, ThreadSessionManager, AguiProperties,
        ObjectProvider<AgentEventConverter>, ObjectProvider<AguiEventEnricher>,
        ObjectProvider<AguiRuntimeContextResolver>, ObjectProvider<AguiAgentAdapterFactory>)

@Bean @ConditionalOnMissingBean
public AguiRestController aguiRestController(AguiMvcController aguiMvcController, AguiProperties props)
```

补充可定制点：`AguiAgentRegistryCustomizer` 是 `@FunctionalInterface` 且 `extends Consumer<AguiAgentRegistry>`（`void customize(AguiAgentRegistry)`），同样经 `ObjectProvider` 在 `aguiAgentRegistry(...)` 内被 stream 应用——项目可声明多个该类型 bean 来在 registry 上 `registerFactory/register`。

`AguiAgentAutoRegistration`（构造器 `public AguiAgentAutoRegistration(AguiAgentRegistry registry)`，`InitializingBean.afterPropertiesSet()` 触发扫描）：扫描所有 `Agent` bean；单例 scope → `registry.register(agentId, bean)`，prototype scope → `registry.registerFactory(agentId, () -> beanFactory.getBean(beanName, Agent.class))`；已有 `registry.hasAgent(agentId)` 时跳过（手动注册优先）。agentId 解析：`@AguiAgentId` 注解 → bean 名。

## §2 McpTool 逐个注册与过滤

### 2.1 工具清单获取（`McpClientWrapper`）

`io.agentscope.core.tool.mcp.McpClientWrapper`（抽象类，`implements AutoCloseable`；`McpSyncClientWrapper`/`McpAsyncClientWrapper` 是其子类）：

```java
public abstract Mono<Void> initialize();
public abstract Mono<List<McpSchema.Tool>> listTools();                 // ← 工具清单入口
public McpSchema.Tool getCachedTool(String toolName);                    // 按名取缓存定义
public abstract Mono<McpSchema.CallToolResult> callTool(String toolName, Map<String,Object> arguments);
public abstract Mono<McpSchema.CallToolResult> callTool(String toolName, Map<String,Object> arguments, Map<String,Object> meta);
public String getName();
```

`McpSchema.Tool` 是 MCP SDK 的 record，访问器：`name()`、`description()`、`inputSchema()`（返回 `McpSchema.JsonSchema`）、`outputSchema()`、`annotations()`（其中 `annotations().readOnlyHint()` 用于判定只读）。

### 2.2 `McpTool` 的字段/访问器与注册方式

`io.agentscope.core.tool.mcp.McpTool extends ToolBase`（`ToolBase implements AgentTool`）。首选构造器：

```java
public McpTool(String name, String description, Map<String,Object> parameters,
               Map<String,Object> outputSchema, McpClientWrapper clientWrapper,
               Map<String,Object> presetArguments, String mcpName, boolean readOnly)
```

（另有三个 `@Deprecated(since="2.0.0")` 兼容构造器。）`ToolBase` 提供的 final 访问器：`getName()`、`getDescription()`、`getParameters()`（即输入 schema）、`isReadOnly()`、`isConcurrencySafe()`、`isMcp()`、`getMcpName()`；`McpTool` 自身另有 `getClientName()`、`getPresetArguments()`，并 `@Override getOutputSchema()`。

静态转换工具：

```java
public static Map<String,Object> convertMcpSchemaToParameters(McpSchema.JsonSchema inputSchema, Set<String> excludeParams)
```

注册入口（`io.agentscope.core.tool.Toolkit`）：

```java
public void registerTool(Object toolObject)          // 内部有 `if (toolObject instanceof AgentTool)` 分支 → 委托 registerAgentTool
public void registerAgentTool(AgentTool tool)        // 直接注册单个 AgentTool
public Mono<Void> registerMcpClient(McpClientWrapper mcpClientWrapper)   // 注册整客户端（无过滤参数）
public Mono<Void> removeMcpClient(String mcpClientName)
public ToolRegistration registration()               // 流式 builder（含过滤）
```

`McpTool` **是** `AgentTool`，因此 `toolkit.registerTool(mcpTool)` 与 `toolkit.registerAgentTool(mcpTool)` 均可；注意 `registerTool(Object)` 对非 `AgentTool` 会扫描 `@Tool` 方法（`McpTool` 无该方法，走 `AgentTool` 分支，故两者等价）。

### 2.3 `disabled_tools` 过滤的两种写法

**写法 A（推荐，官方已内置过滤）**——`Toolkit.ToolRegistration` 流式 builder，`apply()` 同步阻塞完成注册：

```java
toolkit.registration()
       .mcpClient(clientWrapper)
       .disableTools(disabledTools)      // List<String>；enableTools 优先级高于 disableTools
       .enableTools(enableTools)         // 可选；null/空 = 不启用过滤
       .group("mcpGroup")                // 可选
       .apply();
```

底层 `McpClientManager.registerMcpClient(wrapper, enableTools, disableTools, groupName, presetParametersMapping)` 的过滤语义（`shouldRegisterTool`）：先按 `disableTools` 排除，若给了 `enableTools` 则只保留其中项。

**写法 B（逐条注册，完全手动控制）**：

```java
McpClientWrapper client = McpClientBuilder.create("server")
        .streamableHttpTransport(url).header(k, v).timeout(Duration.ofSeconds(30))
        .buildSync();                                  // 同步实现 McpSyncClientWrapper
client.initialize().block();
for (McpSchema.Tool t : client.listTools().block()) {
    if (disabledTools.contains(t.name())) continue;    // 读名称：t.name()
    Map<String,Object> params = McpTool.convertMcpSchemaToParameters(t.inputSchema(), Set.of());
    boolean readOnly = t.annotations() != null && Boolean.TRUE.equals(t.annotations().readOnlyHint());
    McpTool mt = new McpTool(
        t.name(),                                       // 名称
        t.description() != null ? t.description() : "", // 描述
        params,
        t.outputSchema() != null ? new java.util.concurrent.ConcurrentHashMap<>(t.outputSchema()) : null,
        client, null, client.getName(), readOnly);
    toolkit.registerAgentTool(mt);                     // 或 toolkit.registerTool(mt)
}
```

读名称/描述：注册前用 `McpSchema.Tool.name()/description()`；注册后（`McpTool`）用 `getName()/getDescription()`（final，继承自 `ToolBase`）。

## §3 共享 Agent 并发模型

### 3.1 `server-side-memory=false` 下的解析结果

`DefaultAgentResolver.resolveAgent`（§1.2）在 `serverSideMemory` 为假时：

```java
return registry.getAgent(agentId).orElseThrow(...);   // 每次请求返回同一个注册实例
```

`AguiAgentAutoRegistration` 对单例 scope 的 `Agent` bean 执行 `registry.register(agentId, agent)`（同一实例）。→ 所有并发 AG-UI 请求共享同一个 `ReActAgent` 实例。

会话 id 注入：`AguiAgentAdapter.buildRuntimeContext`（`io.agentscope.core.agui.adapter.AguiAgentAdapter`）：

```java
return RuntimeContext.builder(runtimeContext)
        .sessionId(input.getThreadId())          // sessionId ← AG-UI threadId
        ...put(RunAgentInput.class, input)...
        .build();
```

默认**不设 userId**（除非 `AguiRuntimeContextResolver` 注入）。

### 3.2 `ReActAgent` 2.0.1 的实际并发实现（与 Javadoc 不符）

类路径 `io.agentscope.core.ReActAgent extends AgentBase`（注意：不是 `io.agentscope.core.agent.ReActAgent`）。Javadoc 仍写：

> Thread Safety: ReActAgent is *not* thread-safe. A single instance processes exactly one call() at a time; a concurrent invocation on the same instance throws IllegalStateException.

但实际代码已重构为**支持并发**，证据：

1. 旧「checkRunning」门闩已移除：`AgentBase.acquireExecution()` 只调用 `GracefulShutdownManager.ensureAcceptingRequests()`；`isCheckRunning()` `@Deprecated` 且恒返回 `false`（注释「No longer enforced; per-session serialization handles concurrency」）。→ **并发调用不会抛 IllegalStateException**。
2. 每次调用的可变状态在**每调用一次的 `CallExecution`** 里（内部类，持有 `AgentState state`、`PermissionEngine`、`slotKey`、`systemMsg`、`eventSink`、`rc`、结构化输出 tool 等），由 `beforeAgentExecution → activateSlotForContext` 新建，经 Reactor Context 键 `AgentBase.CALL_SCOPE_KEY` 传递，`doCall` 用 `scopeFrom(cv)` 从 Context 读回——**不落在实例字段**。
3. 会话（对话）状态按 slot 缓存在并发容器：

```java
private final ConcurrentHashMap<String, AgentState> stateCache = new ConcurrentHashMap<>();
private final ConcurrentHashMap<String, PermissionEngine> permissionEngineCache = new ConcurrentHashMap<>();
// slotKey = (userId==null||blank ? "__anon__" : userId) + "/" + sessionId
```

4. 同 slot 串行、不同 slot 并行：`ReActAgent.callSerializationKey(rc)` 返回 `slotKey(uid, sid)`；`AgentBase.runLifecycle` 里 `serializeOnKey(gateKey, lifecycle)` 用 `callGates`（`ConcurrentHashMap<Object, Mono<Void>>`）做 FIFO 串行化（注释明确「same-session calls run one-at-a-time; distinct sessions run in parallel」）。
5. 默认有效缓存键：`sessionId = threadId`、`userId = null` ⇒ `"__anon__/threadId"`。若 `AguiRuntimeContextResolver` 注入 `userId`，则为 `"userId/threadId"`。

### 3.3 结论

**单个共享 `ReActAgent`（每用户一个或全局一个）在 `server-side-memory=false` 下安全**，因为会话状态按 `(userId, sessionId=threadId)` 存放于 `ConcurrentHashMap`，每次调用的推理/事件/待确认工具状态在 Reactor Context 上的 `CallExecution` 里，且同一 `threadId` 的并发调用被 FIFO 串行化、不同 `threadId` 并行。**应用侧缓存键建议 `(userId, threadId)`**（userId 可空 → 匿名），与框架 slot 键一致。

⚠️ 残留共享可变点（若共享单实例需规避）：

- `private volatile RuntimeContext activeRc`（实例字段）：`beforeAgentExecution` 置位、`afterAgentExecution` 置空，注释明确「仅作 out-of-call 访问器的旁路默认值」；推理循环读的是 `scope.rc`。但无参 `getRuntimeContext()`/`getAgentState()` 返回「最近一次激活的 slot」，并发下不可靠。
- `activateSlotForContext` 里 `toolkit.setActiveGroups(loaded.getToolContext().getActivatedGroups())` 会**修改共享 toolkit 的激活组**；但模型工具面由 `toolkit.getToolSchemas(state.getToolContext().getActivatedGroups())`（无状态变体，按本次调用 slot 解析）供给，故不影响发给模型的工具清单；`Toolkit.getActiveGroups()` 与 meta-tool 行为仍可能并发竞争。
- `bindRuntimeContextToHooks`/`unbindRuntimeContextFromHooks` 把 ctx 写进**共享**的 `RuntimeContextAware` hook 实例，若使用 `RuntimeContextAware` hook 则并发下会串。
- 弃用的无参 `interrupt()`/`interrupt(Msg)` 只作用于「最近激活 slot」；应使用 `interrupt(userId, sessionId)`。

结论一句话：**可安全共享；官方 Javadoc 的「not thread-safe」声明与 2.0.1 代码不一致（过时），但需规避 `RuntimeContextAware` hook 与弃用的无参 interrupt/getAgentState，并接受 `Toolkit.getActiveGroups()` 在并发下语义弱化。**
