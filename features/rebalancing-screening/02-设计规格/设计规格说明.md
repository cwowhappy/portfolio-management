# 再平衡与筛选增强（rebalancing-screening）设计规格说明

> 创建：2026-09-16 | 对应 [01-需求规格](../01-需求规格/需求规格说明.md) | 里程碑 MS-08

## 一、总体架构

三条主线，全部**在既有域内扩展**，`PackageConventionsTest` 白名单零改动：

1. **再平衡 = allocation 域读侧纯函数**（澄清 #9）：提醒状态与金额建议请求时计算，零调度零落库。数据链路复用偏离度既有聚合：`PortfolioApplicationService.allocation(userId)`（`application/portfolio/PortfolioApplicationService.java:334`）产出的 权益/现金 两片 → `AllocationApplicationService.mapHoldings`（`application/allocation/AllocationApplicationService.java:129`）映射到 5 类 → 新增 `RebalanceCalculator` 纯函数输出提醒与金额。
2. **自选 = screening 域新聚合 + 独立路径**（澄清 #10）：`WatchlistItem` 挂 `domain/screening`，控制器 `@RequestMapping("/api/watchlist")`——不在 `PublicEndpointPaths`（`infrastructure/security/PublicEndpointPaths.java:20`）公开清单 = Spring Security 默认需登录，**零安全配置改动**。
3. **成分股限定 = 纯消费**（澄清 #7）：`index_constituent` 表（V4）+ collector `index_constituent` 任务（180 天全量刷新，tushare index_weight）已在线且后端零消费，本设计只在 `ScreeningRepositoryImpl` SQL 加子查询。

不新建任何调度、提醒表、通知域；CSV 导出复用筛选查询与 5min 条件缓存（`application/screening/ScreeningApplicationService.java:50-57`）。

## 二、数据模型与迁移（Flyway V14）

```sql
-- 1) allocation_plan：再平衡频率 + 时间提醒锚点（一列两用：激活/ack 均重置）
ALTER TABLE allocation_plan
  ADD COLUMN rebalance_frequency VARCHAR(16) NOT NULL DEFAULT 'OFF',  -- OFF / QUARTERLY / SEMIANNUAL
  ADD COLUMN last_rebalanced_at  TIMESTAMP;
UPDATE allocation_plan SET last_rebalanced_at = now() WHERE active;   -- 存量生效方案以迁移日为基线

-- 2) 自选观察列表
CREATE TABLE watchlist_item (
  id         BIGSERIAL PRIMARY KEY,
  user_id    BIGINT NOT NULL REFERENCES app_user(id),
  stock_code VARCHAR(16) NOT NULL,
  added_at   TIMESTAMP NOT NULL DEFAULT now(),
  UNIQUE (user_id, stock_code)
);
CREATE INDEX idx_watchlist_user ON watchlist_item(user_id, added_at DESC);
```

**锚点语义**（澄清 #2 补充口径）：`last_rebalanced_at` 同时是「上次再平衡时间」与时间提醒起算点——**激活方案即视为一次配置确认，重置锚点**（新方案不会立即触发时间提醒，亦省去 activated_at 列）；编辑权重**不**重置（改目标 ≠ 再平衡）。

## 三、再平衡设计（M07-F04/F05）

### 3.1 领域层：RebalanceCalculator（纯函数，无 Spring 注解）

位置 `domain/allocation/RebalanceCalculator.java` + 值对象 `RebalanceResult`。入口形如：

```
RebalanceResult calculate(Map<AssetClass,BigDecimal> targetWeights,   // 生效方案
                          Map<AssetClass,BigDecimal> actualWeights,   // mapHoldings 产物（BOND/GOLD/REITS 恒 0）
                          BigDecimal totalAssets,                     // T = 权益市值 + 账户现金
                          RebalanceFrequency frequency, Instant anchor, Instant today)
```

计算规则（全部 BigDecimal，金额单位元、2 位小数 HALF_UP）：

- 逐类：`目标金额 = T × target%`、`当前金额 = T × actual%`、`建议金额 = 目标 − 当前`（正买负卖）；**Σ建议 ≡ 0**（容差 ±0.01 元，单测断言）；
- **阈值触发**：任一类别 `|actual% − target%| ≥ 5.00pp`（常量 `THRESHOLD_PP = 5`，硬编码同模板库口径）；
- **时间触发**：`frequency ≠ OFF` 且 `Duration(anchor → today) ≥ 90/180 自然日`；anchor 为 null 视为不触发（防御，正常链路 V14 已回填）；
- **空组合抑制**：`T = 0` 时两类触发与金额建议全部抑制，仅返回空态标记；
- 结果含 `anyAlert`（任一触发，供导航红点）。

`RebalanceFrequency` 枚举 `OFF/QUARTERLY/SEMIANNUAL`（域内新枚举，天数常量 90/180）。

### 3.2 聚合根扩展：AllocationPlan

`AllocationPlan`（`domain/allocation/AllocationPlan.java`，不可变聚合）加两字段 `rebalanceFrequency / lastRebalancedAt`：

- 工厂 `create(...)` 增 frequency 参数（默认 OFF 由 Command 层给值）；`reconstitute` 增两参数（仓储读回）；
- `activate()` 返回的实例同时 `lastRebalancedAt = now()`（锚点重置语义）；新增 `markRebalanced(Instant now)` 工厂方法供 ack；
- JPA 实体 `AllocationPlanJpaEntity` / `AllocationPlanRepositoryImpl` 同步两列映射（V9 乐观锁 version 机制不变）；
- `PlanView / CreatePlanCommand / UpdatePlanCommand` 扩 `rebalanceFrequency` 字段（`OFF/QUARTERLY/SEMIANNUAL` 字符串，非法值 400）。

### 3.3 应用层与端点（AllocationController 扩展）

- `GET /api/allocation/rebalance` → `RebalanceView{hasActivePlan, totalAssets, emptyPortfolio, items[assetClass,target%,actual%,deviation pp,targetAmount,currentAmount,suggestedAmount,thresholdBreached], timeTrigger{frequency,anchorDate,dueDate,daysOverdue,triggered}, anyAlert}`——页内卡与导航红点共用；无生效方案 → `hasActivePlan=false` 空态（对齐 `deviation()` 的空态语义，`AllocationApplicationService.java:77-91`）。
- `POST /api/allocation/rebalance/ack` → `requireActivePlan → markRebalanced(now) → save`；无生效方案 404（复用 `AllocationErrorCode.NOT_FOUND`）；幂等（重复 ack 刷新时间）。
- 均需登录（allocation 前缀本就在认证范围内）。

### 3.4 前端（/allocation 与导航）

- **RebalanceCard**（`components/allocation/` 新组件）：提醒横幅（阈值触发列类别与偏离、时间触发列到期天数）+ 建议表（类别/目标%/实际%/偏离 pp/建议金额，正数绿色「买入」负数红色「卖出」）+「已完成再平衡」按钮 + 口径折叠说明（BOND/GOLD/REITS 恒 0、5pp 固定、T=0 抑制）。
- **PlanEditor** 加「再平衡频率」下拉（关闭/季度/半年），进 create/update Command。
- **导航红点**：`app/layout.tsx`（导航清单在 L50-92）「配置」入口加红点。数据源 = 挂载时拉一次 `GET /api/allocation/rebalance`（登录态用 `useAuth().user`，`frontend/lib/auth.tsx:62-114` 的 AuthProvider 挂载时已 `GET /api/auth/me`；未登录/401/无方案静默不亮）；AllocationBoard 在 ack/激活后 `dispatchEvent(CustomEvent("rebalance-refresh"))`，导航监听重拉。不引入轮询。

## 四、筛选增强设计（M09-F03/F04/F05）

### 4.1 指数成分股限定（F05）

- `ScreeningCriteria`（`domain/screening/ScreeningCriteria.java`）加 `String indexCode` 字段；`hasAnyCondition()` 纳入（单独限指数 = 浏览成分股，合法）；缓存键 `cacheKey()`（`ScreeningApplicationService.java:61-72`）纳入。
- 白名单校验 `∈ {000300, 000905}`（与 `index_constituent.index_code` 存储格式一致——6 位无后缀，见 `collector/collector/sources/plugins.py:15,277-279`：stock_code 亦剥为 6 位）；非法 400。
- SQL（`ScreeningRepositoryImpl` 动态 AND 段）：`AND d.stock_code IN (SELECT stock_code FROM index_constituent WHERE index_code = ?)`。
- `ScreeningController` 加 `indexCode` @RequestParam；前端 `ScreeningForm` 加「指数范围」下拉、结果区标注当前范围。

### 4.2 自选观察列表（F03）

- 领域：`WatchlistItem(id, userId, stockCode, addedAt)` + `WatchlistRepository`（findByUserId 按添加时间倒序 / existsByUserIdAndStockCode / save / deleteByUserIdAndStockCode / countByUserId）+ 常量 `MAX_SIZE = 100`。
- 应用服务 `WatchlistApplicationService`（application/screening）：
  - `list(userId)`：自选代码集 → 一次 SQL join 最新快照（PE/PB/股息率/总市值）+ 申万行业 + **一次 `MarketDataService.quoteBatch(codes)` 批量现价**（复用 `PortfolioApplicationService` 同款取价端口，≤100 只单次调用；缺价显示空）；
  - `add(userId, stockCode)`：校验代码 ∈ 最新快照日 `stock_valuation_daily`（防脏数据）→ 已存在幂等返回 → 计数 ≥100 抛 `WATCHLIST_LIMIT_EXCEEDED`；
  - `remove(userId, stockCode)`：不存在亦 200（幂等删除）。
- 端点 `WatchlistController`（web，`/api/watchlist`）：`GET ""` / `POST ""` body `{stockCode}` / `DELETE /{stockCode}`；错误码并入 `ScreeningErrorCode`（新增 `WATCHLIST_LIMIT_EXCEEDED / INVALID_STOCK`）。
- 搜索：`GET /api/screening/stocks/search?q=`（**公开**，挂在既有公开前缀下）：最新快照日 `stock_valuation_daily` join `shenwan_industry_mapping`，`stock_code LIKE q% OR stock_name LIKE %q%`，limit 10，返回 `{stockCode, stockName, industryName, peTtm, pb, totalMv}`。
- Next 反代新增 `app/api/watchlist/[...path]/route.ts`（照抄 `app/api/allocation/[...path]/route.ts` 模式）。

### 4.3 前端（/screener）

- **⭐列**：`ScreeningResultsTable` 首列加星标；登录态用 `useAuth().user`（`frontend/lib/auth.tsx`，AuthProvider 全局挂载时拉 `/api/auth/me`；未登录点击 → 跳 `/login?redirect=/screener`；已登录 POST 后星实心，再点即移除）。
- **自选 tab**：`ScreenerBoard` 顶部「筛选 / 自选」切换；`WatchlistPanel`（新组件）= 搜索添加框（防抖调 search，候选下拉选中即加）+ 表格（代码/名称/行业/现价/PE/PB/股息率/总市值/添加时间/移除）+ 口径标注（现价实时、其余收盘快照）。
- **导出按钮**：结果表上方「导出 CSV」，`<a href={`/api/screening/stocks/export?${当前查询串}`}>` 直连 Next 反代触发浏览器原生下载（**不走** `lib/http.ts request<T>()` 的 zod JSON 链路）。

### 4.4 CSV 导出（F04）

- 端点 `GET /api/screening/stocks/export`（**公开**）：@RequestParam 与 `/api/screening/stocks` 完全一致（16 个 + indexCode）；直接调用 `ScreeningApplicationService.screen(criteria)`（同校验、同缓存）拿 `List<StockScreeningResult>`。
- 响应：`Content-Type: text/csv; charset=UTF-8`；首字节 **BOM**（`﻿`，Excel 兼容）；`Content-Disposition: attachment; filename="screening-YYYYMMDD-HHmmss.csv"`；`\r\n` 行尾；字段含逗号/引号/换行按 RFC 4180 双引号转义；表头中文，列 = **代码 + 结果表 13 列**（已核实 `ScreeningResultsTable.tsx:5-19`：名称/PE-TTM/PB/股息率/ROE/ROA/毛利率/资产负债率/流动比率/营收增速/净利增速/总市值(亿)/换手率；代码列 CSV 专属——唯一键供线下关联）；空结果仅表头行。
- **反代配套**：`frontend/lib/proxy.ts` relay 现只透传 Content-Type 与 Set-Cookie（L50-64），需补透传 `Content-Disposition`（一行；后端 JSON 端点不设此头，无回归面）。

## 五、错误处理与边界

| 场景 | 行为 |
|---|---|
| 无生效方案（rebalance GET） | `hasActivePlan=false` 空态，前端提示先设生效方案 |
| 无生效方案（ack） | 404 `NOT_FOUND`（用户隔离口径同方案操作） |
| T=0 空组合 | 触发与金额全抑制，`emptyPortfolio=true` |
| 自选未登录 | 401（Security 默认；前端已用会话态预判跳登录） |
| 自选超 100 | 400 `WATCHLIST_LIMIT_EXCEEDED` |
| 添加代码不在最新快照 | 400 `INVALID_STOCK` |
| 重复添加自选 / 重复删除 | 幂等成功 |
| 导出/筛选无任何条件（含 indexCode） | 400 `NO_CONDITION`（口径一致） |
| indexCode 非白名单 | 400 `INVALID_INPUT` |
| 停牌等现价缺失 | 现价列「—」；导出不含现价列（纯快照口径） |
| frequency 非法值 | 400 `INVALID_INPUT` |
| 成分股表空（环境未跑采集） | 限定结果为空集；前端下拉配「数据未就绪」空态提示（e2e 环境须先保证表有数） |

## 六、测试策略

- **纯函数单测（RebalanceCalculator）**：5.00pp 恰好触发/4.99 不触发；90/180 天边界（差一天不触发）；T=0 抑制；BOND/GOLD/REITS 目标 25/实际 0 → 建议买入 25%T；**Σ建议 ≡ 0 守恒**（容差 ±0.01）；anchor null 防御；无方案空态（应用层）。
- **领域/应用单测**：AllocationPlan.activate() 重置锚点、markRebalanced、frequency 校验；Watchlist add 幂等/上限/INVALID_STOCK/用户隔离（A 不可见 B）；indexCode 白名单校验。
- **集成测试**：indexCode=000300 时结果 ⊆ `index_constituent`（H2/测试库内造数）；CSV BOM 首字节、表头行、含逗号股票名转义、空结果仅表头、`NO_CONDITION`。
- **前端单测（V8）**：RebalanceCard 渲染（触发/空态/守恒展示）、WatchlistPanel（搜索候选/添加/移除）、⭐登录态分支。
- **e2e（Playwright）**：① 造偏离持仓 → 横幅出现 + 金额断言 → ack 后时间提醒消失（阈值仍在）② 登录 ⭐加自选 → 自选 tab 可见 → 移除；未登录点 ⭐跳登录 ③ 指数限定 → 抽样断言结果 ⊆ 成分股 ④ 导出 download 事件断言文件名/表头/行数 ≤ 筛选数。
- **门槛**：`make test`（JaCoCo/V8 ≥80%）全绿；`make smoke` 无新增段（无新外部数据源）。
