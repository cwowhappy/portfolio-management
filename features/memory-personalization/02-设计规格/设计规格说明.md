## 二、F01 记忆文件端口与管理链

### 2.1 文件模型与解析口径

管理对象（需求决策 #1/#2）：`<workspace>/<userId>/MEMORY.md`（策展层）+ `<workspace>/<userId>/memory/*.md`（当期日账本；`archive/` 与 `.consolidation_state` 排除——glob 时不匹配隐藏文件与子目录）。workspace 根取 `InvestProperties.Mcp.Harness.workspace`（`InvestProperties.java:364-393`，缺省 `.agentscope/workspace`；用户目录 = `userId` 十进制字符串，磁盘实况已验证）。

解析粒度（对齐决议「行级/节级」）：

- **策展层 → 行级**：非空行即条目（`lineIndex` 按文件内行序编号，含标题行；`# MEMORY.md` 库写标题行只读保护——删除/编辑请求命中首行标题时 400）。
- **日账本 → 节级**：`## ` 起始的节头切分；节类型 `kind = FLUSH | EXTERNAL_EVENT`（节头以 `## Memory Flush —` 前缀判定 FLUSH，其余含 `## 外部事件摘要` 前缀为 EXTERNAL_EVENT，再余归 FLUSH 兜底只读展示）。操作粒度 = 整节删（flush 节是原子语义单元，不拆行——与需求 §三 F01「删日账本节」一致）。

### 2.2 WorkspaceMemoryPort 接口（application/memory/）

```java
public interface WorkspaceMemoryPort {
    MemoryFilesView load(Long userId);                    // 策展层 + 当期日账本全视图（含各文件 sha256）
    CuratedMutationResult deleteCuratedLine(Long userId, int lineIndex, String expectLine, String baseHash);
    CuratedMutationResult editCuratedLine(Long userId, int lineIndex, String expectLine,
                                          String newLine, String baseHash);
    void deleteLedgerSection(Long userId, LocalDate date, String sectionHeader, String baseHash);
    void appendExternalEvent(Long userId, LocalDate date, String content);   // F03 复用
}
```

- 返回视图 record：`MemoryFilesView(curated: MemoryFileView, ledgers: List<LedgerFileView>)`；`MemoryFileView(hash, lines)`；`LedgerFileView(date, hash, sections)`；`Section(header, kind, lines)`。
- 实现要点（`infrastructure/workspace/WorkspaceMemoryFileAdapter`）：
  - **乐观并发三层校验**：`baseHash`（整文件 sha-256，409 冲突——沿 `conversations.ts:37-52` 409 先例）+ `lineIndex` + `expectLine`（行内容比对，410/400 mismatch）；写入前重读重算。
  - **原子写**：写同目录 temp 文件 + `Files.move(ATOMIC_MOVE)`，防与库 consolidation 的读交错产出半文件。
  - **策展层删除的两层同步**（决议 #2）：删策展层行后，对全部日账本执行**归一化相似行清除**——行文本 trim + 全角/半角 + 空白归一后，与被删行互为子串（≥12 字符阈值，短行跳过清除）的 bullet 行删除；结果计数回传（`purgedLedgerLines`）。LLM 改写导致匹配不全时残余源头由用户在日账本分栏节级手删兜底——UI 提示语与需求验收口径（「策展层不复活」硬保证、「日账本尽力清除」软保证）一致。
  - 文件/目录缺失 → 空视图（`MemoryFileView(hash=null, lines=[])`）；IO 异常 → 应用层 503 语义异常（GlobalExceptionHandler 翻译）。
- **不做**：`.consolidation_state` 触碰、archive 读写、sessions/ 工作区其他内容（需求 §三 F01 边界）。

### 2.3 应用服务与 REST 契约

`MemoryManagementApplicationService`（application/memory/，`@Transactional(readOnly=true)` 读写经端口无事务需求——文件操作无 JPA 事务，纯编排）+ `web/MemoryController`（`/api/memory/**`，本人隔离沿 `CurrentUserHolder` 模式；无 admin 端点——需求决策 #10）：

| 端点 | 语义 |
|---|---|
| `GET /api/memory` | 全视图（策展层+日账本） |
| `DELETE /api/memory/curated` | body `{lineIndex, expectLine, baseHash}` → `{purgedLedgerLines}` |
| `PUT /api/memory/curated` | body `{lineIndex, expectLine, newLine, baseHash}` |
| `DELETE /api/memory/ledger/{date}` | body `{sectionHeader, baseHash}`，204 |

错误映射：409 hash 冲突（提示刷新重试）、410 行漂移、400 命中只读标题行/参数非法——`GlobalExceptionHandler` 既有机制内新增异常类型。

## 三、F02 画像注入

### 3.1 数据模型（V7 表一：user_profile_config）

```sql
CREATE TABLE user_profile_config (
    id               BIGSERIAL PRIMARY KEY,
    user_id          BIGINT NOT NULL UNIQUE REFERENCES app_user(id),
    style_enabled    BOOLEAN NOT NULL DEFAULT FALSE,
    industry_enabled BOOLEAN NOT NULL DEFAULT FALSE,
    watchlist_enabled BOOLEAN NOT NULL DEFAULT FALSE,
    holdings_enabled BOOLEAN NOT NULL DEFAULT FALSE,
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

单行四列而非四行键值（需求决策 #3 表形态裁决）：四维度固定、读写永远全量（授权页/注入点都要四值齐读），键值行换来的是每次四行装配；新增维度 = 一次 Flyway 迁移（schema 本就 Flyway 管）。三层结构沿 `skill_user_config` 先例：domain `UserProfileConfig`（record + `update()` 返回新实例）→ domain 仓库端口 → JPA 实现（`infrastructure/persistence/`）。无行 = 全关（缺省 opt-in，决议 #3）。

`ProfileConfigApplicationService`：`config(userId)` 返回四开关 + 缺省全关；`save(userId, 四布尔)` upsert。**不建独立 domain/ 子包**——配置聚合极薄，落 `domain/memory/`（与 F01 视图 record 同包；M18 无业务不变量型聚合，`domain/memory/` 承载 record 与端口即可）。

### 3.2 ProfileContextBuilder（agent/）

`@Component`，依赖：`ProfileConfigApplicationService` + `AllocationApplicationService`（latestAssessment）+ `IndustryWatchApplicationService`（listWatched）+ `WatchlistApplicationService`（list）+ `PortfolioApplicationService`（overview）+ `InvestProperties.Profile`。

模板常量 `ProfileContextTemplate.TEXT`（版本资产，见 §3.4）与渲染逻辑：

```
<user_profile>
以下是经用户授权注入的个人投资画像，仅供个性化参考；其中的私有数据禁止作为参数传给任何 MCP 工具：
<risk_profile>平衡型</risk_profile>            ← style_enabled 且 latestAssessment 非空
<watched_industries>801017 银行, 801120 食品饮料</watched_industries>   ← industry_enabled 且非空
<watchlist>600519 贵州茅台, 000858 五粮液, …（共 N 只，前 30）</watchlist>  ← watchlist_enabled，截断 invest.profile.watchlist-limit（默认 30）
<holdings_summary>总资产 ¥1,234,567，总盈亏 +¥12,345（+1.0%），持仓 8 只，现金 ¥…</holdings_summary>  ← holdings_enabled 且 overview 成功

```

- **逐段独立 try/catch**：单段数据源失败/为空 → 该段省略 + WARN（需求 F02 边界），不拖垮其余段与整块。
- **限长**：渲染后整块超 `invest.profile.block-max-chars`（默认 800）截断 + 尾注「（已截断）」。
- 授权全关 / 全无数据 / 渲染整体失败 → 返回 `Optional.empty()` → sysPrompt 与现状逐字节一致（需求 F02 回归安全验收）。
- **数字来源纪律**：holdings_summary 各值直接取 `PortfolioOverviewView` 字段格式化，不二次计算。

## 四、F03 事件驱动记忆

### 4.1 调度与游标（V7 表二：memory_digest_cursor）

```sql
CREATE TABLE memory_digest_cursor (
    id             INT PRIMARY KEY DEFAULT 1 CHECK (id = 1),   -- 全局单行
    last_success_at TIMESTAMPTZ NOT NULL,
    updated_at      TIMESTAMPTZ NOT NULL DEFAULT now()
);
INSERT INTO memory_digest_cursor (id, last_success_at) VALUES (1, now());  -- 首跑窗口 = 24h
```

全局单行而非按用户行（决议 #8 失败粒度 = 整批顺延，无按用户断点需求；用户级增量留给后续）。domain 端口 + JPA 实体同 §3.1 模式（`domain/memory/`）。

`application/memory/MemoryDigestScheduler`（沿 `EvalScheduler.java:154-177` 三段式模板逐项对齐）：

1. `@Scheduled(cron = "0 7 21 * * *", zone = "Asia/Shanghai")` 字面量（cron 不入配置——`InvestProperties.java:504-509` 声明位先例）；类级 `@ConditionalOnExpression("!'true'.equals('${Eval_MODE:}')")`（:69 先例，eval 子进程不跑）。
2. 顶层 try/catch 护调度线程 → `invest.profile.digest-enabled` 开关 → `DEEPSEEK_API_KEY` 缺席静默跳过留痕。
3. 窗口 = `cursor.lastSuccessAt` → `now()`；**仅成功处理全部用户后推进游标**；失败/部分失败不推进（次日窗口自动扩大覆盖）。

### 4.2 摘要链（MemoryDigestService）

```
UserRepository.findAll(enabled 用户)
  → 逐用户 JournalApplicationService.timeline(userId, window.from, window.to)   # 现成八类事件（:82-115）
  → 非空 → IntelligenceChatPort.complete(system, user)                          # 复用（application→application 合法）
  → Optional 非空 → WorkspaceMemoryPort.appendExternalEvent(userId, today, digest)
```

- **LLM 端口复用 `IntelligenceChatPort`**（application/intelligence，零新端口）：其契约（失败返回 empty 静默跳批、无 key 返回 empty、120s block、temperature 0——`AgentScopeIntelligenceChatPort.java:29-88`）与本场景完全对位；**系统 key**（决策 #3：系统调度器发起）自动成立。
- 逐用户 try/catch：单用户失败 WARN 跳过，不挡批、不回滚游标（游标推进条件 = 全批执行完毕而非全成功；失败用户次日由扩大的窗口自动重试——口径：游标推进记「批完成」，与决议 #8「失败顺延」的落点是窗口扩大重试，不是卡死整批）。
- **摘要 prompt**（新资产 `digest.memory`，SKILL.md 之外的第一类「任务 prompt」资产——`ToolkitPromptAssetCollector` 追加登记，键沿 `system.invest.profile` 先例命名）：
  - system：`你是投资助理。将用户投资事件流摘要为不超过 5 条要点 bullet（中文，保留标的代码/金额/方向等关键事实，不添加推断）。`
  - user：窗口起止 + `timeline` 事件 JSON（单事件超长截断保护）。
- **写入格式**（决议 #9「外部事件」节，与库 flush 节头可区分）：

  ```
  ## 外部事件摘要 — 2026-10-10（2026-10-09T21:07 ~ 2026-10-10T21:07）
  - <bullet>
  - <bullet>
  ```

  写当日账本 `memory/<today>.md`（append；文件不存在则创建）。consolidation 自然吸收（下周期合并进策展层）；管理界面日账本分栏按节头前缀展示 `事件` 徽标（§2.1 kind 判定）——「自动落盘可在管理界面回溯」验收闭环。
- token 量级：活跃用户个位数 × 每摘要 ~1K token，远低于情报域 dailyTokenGuardrail 量级，不设专项护栏（复盘观察项留痕）。
