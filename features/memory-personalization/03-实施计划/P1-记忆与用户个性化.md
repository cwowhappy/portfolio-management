# 记忆与用户个性化（MS-31 / M18）实施计划 P1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 M18 三功能点——记忆管理界面（文件唯一真相源）、画像授权注入（四类开关+预览+护栏）、事件驱动记忆（每日摘要落盘可回溯），顺带清偿 P3 前端交互域认领 4 项。

**Architecture:** 记忆不迁库——`WorkspaceMemoryPort`（application 接口）+ 文件适配器（infrastructure/workspace 新子包）直管 harness 工作区 Markdown；画像段渲染提为 domain 纯函数供 agent（注入）与 application（预览）双路消费；F03 每日 21:07 定时批（timeline 源 + 复用 IntelligenceChatPort + 全局单行游标）。

**Tech Stack:** Spring Boot 4 / Flyway V7 / ArchUnit 守护 / Next.js 15 + zod / Playwright e2e（node fs 直种记忆文件）。

**Spec:** [需求规格 v1.0](../01-需求规格/需求规格说明.md)（17 项决议）+ [设计规格 v1.0](../02-设计规格/设计规格说明.md)（锚点均已对照 main=9beedf1f 验证）。

## Global Constraints

- 覆盖率 ≥80%（后端 JaCoCo 聚合三层 / 前端 V8），`make test` 三端全绿；链接门禁零断链。
- 后端分层由 ArchUnit 强制：agent 禁依赖 infrastructure/web；application 禁依赖 agent/infrastructure；web 只碰 `*ApplicationService`/Controller 层。新代码零白名单登记（设计规格 §一）。
- Jackson 2（不引 Jackson 3）；domain 零 Spring/JPA 注解。
- 前端组件禁直接 fetch（走 `lib/http.ts`）；测试过滤用 `pnpm vitest run <file>`（`pnpm test --` 过滤失效）。
- 提交规范：`feat(backend): MS-31 …` / `feat(frontend): MS-31 …` / `test: …`，中文描述。
- 授权全关/无数据时 sysPrompt 与现状**逐字节一致**（回归红线，B5 有断言）。
- 管理操作不触碰 `.consolidation_state` 与 `memory/archive/`；不对 sessions/ 工作区其他内容做任何读写。

## Review Focus

实现评审五类最易咬人的输入/条件（每条已锚定到 owning 任务的测试）：

1. **读后写前文件被库 flush 改动**（管理页删除 vs Agent flush 并发）→ baseHash 三层校验必须 409 而非覆盖丢更新 → B2 步骤「并发窗口测试」。
2. **策展层删除的日账本残留**（LLM 改写后归一化匹配不中）→ 不复活硬保证仅对策展层成立，响应计数必须如实、前端文案不得承诺「彻底遗忘」→ B2 匹配计数测试 + F2 文案断言。
3. **F03 单用户失败卡死整批**→ 游标推进条件 = 批完成（非全成功），失败用户靠次日扩大窗口重试 → B6「部分失败仍推进」测试。
4. **预览与注入渲染漂移**→ 两路必须同走 `ProfileSectionRenderer`，任何一边私自拼字符串即破「所见即所注入」→ B4/B5 各自断言渲染输出与 renderer 直出一致。
5. **P3⑦ 修复破坏既有 409 冲突语义**（conversations.ts 现有 status 分类处理）→ 改造后 409 路径行为不变、仅失败可见性增加 → F4 vitest 守 409 既有断言 + 新增失败可见断言。
