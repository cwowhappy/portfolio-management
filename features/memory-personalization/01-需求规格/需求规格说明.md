## 一、背景与目标

长期记忆已由 `HarnessAgentFactory` 装配落盘（agentscope-harness 2.0.3 `MemoryConfig`），但呈现三个黑盒问题（[侦察报告](../09-调研报告/2026-10-10-立项侦察报告.md) §一/§二/§三）：

- **不可见**：记忆是工作区 Markdown 文件（`workspace/<userId>/MEMORY.md` 策展层 + `memory/YYYY-MM-DD.md` 日账本），不落数据库，后端零自有读写代码——用户无从知道自己被记住了什么。本地盘 271 个用户目录仅 29 个有 `MEMORY.md`、134 个有日账本（长尾空态常态）；且现有内容以开发测试产生的项目知识为主，**未沉淀出投资画像**。
- **不可管**：无任何查看/编辑/删除通道；库契约单一写入者（日账本只由 FlushManager 写、`MEMORY.md` 只由 Consolidator 写）使「管理」必须想清楚与 consolidation 的共生关系，不能裸写文件。
- **不个性化**：`InvestSystemPrompt.TEXT` 是静态常量，唯一按用户差异进提示词的内容是 skill 启用集（`<available_skills>`）；用户的投资风格（`risk_assessment` 五档）、关注行业、自选股、当前持仓四类现成结构化数据从未进入 Agent 上下文；调仓/分红/交易日志事件流与记忆完全断开。

本特性（MS-31 / M18）交付：**F01 记忆管理界面**（文件为唯一真相源的透明可控通道）、**F02 画像注入**（四类结构化数据经授权按需注入系统提示 + 透明预览 + 私有数据外传护栏）、**F03 事件驱动记忆**（投资事件定时摘要自动落盘可回溯）。一句话：长期记忆从「不可解释的黑盒」变为「透明可控 + 授权注入」——金融场景的信任前提。

## 二、澄清决策汇总

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|
| 1 | F01 存储通道 | **文件为唯一真相源**：管理界面直接管 `MEMORY.md`+日账本文件，零新记忆表 | F01 验收对象即「已落盘记忆」；DB 投影造成两套真相源；自建 DB 记忆替换需放弃库抽取能力、超里程碑体量 |
| 2 | F01 v1 范围 | 查看（策展+日账本分栏）+ 删除（**两层同步删**）+ 编辑（**仅策展层行级**，日账本不可编辑） | 删除清干净两层则 consolidation 无源不复活（其只从日账本吸收且仅在用户活跃对话时触发）；编辑与 LLM 合并语义的摩擦以「只编辑策展层」收敛，日账本保持 append-only 保真 |
| 3 | F02 授权模型 | 四类数据（风格/关注行业/自选股/持仓汇总）**独立开关，默认关**（opt-in），沿 `mcp_user_config` 模式，Flyway **V7 一表** | 「经用户授权」语义 = 显式开启；独立开关满足按需注入的 token 控制 |

| 8 | F03 触发 | **每日 21:07 定时批量摘要**（与现有 11 cron 错峰：当日事件基本齐、早于 22:40 深夜批次、晚间对话高峰前完成）；失败游标顺延次日重试（窗口自动扩大） | 同步 hook 仓内零 `@Async`/`@TransactionalEventListener` 先例且 LLM 时延挂用户操作；批量摘要先例全套现成 |
| 9 | F03 数据链 | 源=`JournalApplicationService.timeline` 现成八类事件流 → LLM 摘要（`IntelligenceChatPort` 模式端口）→ **经 F01 文件端口以「外部事件」节写当日账本** | 读路径零新建；系统 key（阶段三规划 §三编排决策 #3：系统调度器发起 → 系统 key，判据天然满足）；写入与用户管理同构、consolidation 自然吸收 |
| 10 | 隐私边界 | 记忆与画像配置**仅本人可见可管**；管理员不可查用户记忆（系统级运行遥测如观测表除外——那是遥测不是用户内容） | 记忆内容含用户私有投资观点/持仓态度，贴「私人笔记」性质 |

| 13 | 通道覆盖 | 飞书（`HarnessAgentInvoker`）与 AG-UI **同权注入**（同一 userId 同一画像） | 两通道同走 `build(userId)`，无理由差异化 |
| 14 | P3 台账（§8.2 分摊） | **认领 4 项**：③K 线切换失败静默+标签不符、⑤Dialog 无 Escape/focus trap+删除确认标准不一、⑦keepalive PUT 64KB 静默丢失（加失败提示）、⑨`BacktestView` 未知 window 原样回显；**留痕降级 5 项**：①消息列表虚拟化、②aria-live 刷屏、④移动端顶栏折叠、⑥反代请求体大小限制、⑧HSTS（视部署层） | 认领项轻量且与 F01/F02 前端动工面重叠；降级项各自需要独立设计投入或属部署层决策（清单见 [侦察报告](../09-调研报告/2026-10-10-立项侦察报告.md) §七） |
| 15 | 记忆质量与 eval 关系 | **不加新 eval 题、不动夜间回归**；记忆质量以人工抽检 + 复盘观察项留痕（沿 MS-30 首跑观察清单先例） | 规划风险表「纳入 eval 基线关注项」以观察兑现；若抽检发现注入劣化对话质量再立项补题 |
| 16 | 页面/端点 | 记忆管理落 **`settings/memory`** 设置页（AuthNav 登记）；REST 走 **`/api/memory/**`** + 画像配置端点；README 端点表登记 | 设置页三先例同构（MCP/Skill/情报订阅），记忆属个人数据管理语义 |
| 17 | 非目标确认 | 记忆手动新增、忽略清单、向量检索、DB 记忆替换、管理员代管、归档文件管理（v1 管理对象=`MEMORY.md`+当期 `memory/*.md`，`memory/archive/` 不在范围）、画像内容编辑（画像只能经源数据变更：做测评/改自选/调持仓） | roadmap F01 三动词外的新增能力与派生数据的编辑语义均 YAGNI（§六逐条） |

**版本链口径（决策 #5 附注）**：`prompt_asset_version` 的 `system.invest` 资产登记**静态模板骨架**（含画像块占位形态的拼接模板）；实际注入内容系 DB 派生、每用户不同，不入版本链。机制细节设计规格定。

## 三、功能需求（M18-F01~F03，编号承阶段三规划，不增删改）

### M18-F01 长期记忆管理界面

**描述**：新建 `settings/memory` 设置页与 `/api/memory/**` 端点，用户首次可见可管自己已落盘的长期记忆（文件为唯一真相源，决策 #1）。

**业务规则**：

- **查看**：分栏呈现——① 策展层 `MEMORY.md`（条目化解析展示）；② 日账本 `memory/*.md` 当期文件（按日分组，节粒度 = `## Memory Flush — <时间戳>`）。空记忆用户呈现空态与「记忆如何产生」说明（长尾常态，见 §一）。
- **删除**：行级/节级删除**两层同步**——删策展层条目时同步从日账本源头删净（决策 #2：consolidation 只从日账本吸收，源头清净则不复活）；删日账本节同理不触策展层（等下轮 consolidation 自然收敛）。条目无 ID（纯 Markdown），行级寻址与并发保护机制（内容指纹/乐观校验）设计规格定。
- **编辑**：仅策展层行级编辑；日账本不可编辑（append-only 保真）。编辑后与日账本原条目并存，由下轮 consolidation 去重合并（语义可接受，已拍板）。
- **隐私**：全部端点本人隔离（`CurrentUserHolder`），管理员无代查代管端点（决策 #10）。
- **管理对象边界**：`MEMORY.md` + 当期 `memory/*.md`；`memory/archive/` 与 `.consolidation_state` 不在管理范围（后者为库内部状态文件，任何管理操作不触碰）。

**边界与异常**：文件缺失/损坏降级为空态或错误提示，不抛 500；文件读写与库 consolidation 的竞态以原子写（temp+rename）收敛，机制设计规格定；`sessions/`、`chart/` 等工作区其他内容**不是**记忆，不进管理界面。

### M18-F02 画像注入

**描述**：四类结构化画像数据经用户授权（独立开关、默认关）按需注入系统提示，授权页透明预览，私有数据外传有护栏有抽检。

**业务规则**：

- **授权配置**：V7 迁移新建画像授权开关表（四类独立布尔，沿 `mcp_user_config` 模式；表形态设计规格定）；`PUT` 全量保存语义（沿 skill 配置先例）。
- **画像源与口径**（决策 #4/#6）：风格=最新风险测评五档枚举（如「平衡型」）；关注行业=`industry_watch` 行业码列表；自选股=`watchlist` 代码列表（截断至上限 N，可配）；持仓=`overview` 聚合（总资产/总成本/总盈亏/持仓数——不含个股明细）。数据缺失的段独立省略，不注入占位空值。
- **注入通道**（决策 #5/#13）：`build(userId)` 时拼接 `TEXT + 画像块`；AG-UI 与飞书同权。授权全关或全无数据时 sysPrompt 与现状逐字节一致（零注入回归安全）。
- **透明预览**（决策 #11）：授权页每开关下折叠展示对应画像摘要（同源同刻查询，与管理界面所见一致）。
- **护栏**（决策 #7）：`InvestSystemPrompt` 禁传条款扩展为覆盖「系统提示注入的用户画像（风格/关注行业/自选股/持仓汇总）」；验收抽检以 `tool_invocation_obs`（`mcp=true`，args 全量）核对无私有数据外传。

**边界与异常**：画像查询失败（如行情源不可用影响 overview 实时价）降级为该段省略 + WARN，不阻断对话构建；注入块限长超限截断留痕。

### M18-F03 事件驱动记忆

**描述**：用户投资事件（调仓/分红/交易日志）每日定时摘要自动写入记忆，管理界面可回溯（规划验收原文）。

**业务规则**：

- **定时**（决策 #8）：每日 21:07（Asia/Shanghai，`@Scheduled` 字面量沿 11 任务先例）；窗口 = 游标时刻 → 当日，断点游标落 DB，成功后推进；失败整批顺延次日（窗口自动扩大），沿 eval 调度三段式模板（调度保护 + 开关 + key 缺席静默跳过）。
- **数据链**（决策 #9）：逐用户读 `timeline`（八类事件流）→ 窗口内非空才摘要 → LLM 摘要（`IntelligenceChatPort` 同模式端口：失败返回 empty 静默跳批，**系统 key**）→ 经 F01 文件端口以**「外部事件」节**（区别于库的 `## Memory Flush` 节）追加写当日账本 → 下轮 consolidation 自然吸收进策展层。
- **回溯**：事件记忆在管理界面日账本分栏以节类型标记区分（`Memory Flush` vs `外部事件`），满足「自动落盘可在管理界面回溯」验收。

**边界与异常**：写文件复用 F01 端口同一原子写与并发保护；LLM 失败不推进游标（次日重试）；无事件用户零成本跳过。

### 工程随附项：P3 顺带清理（决策 #14）

- **认领 4 项清零**：③K 线周期切换失败静默且标签与数据不符 → 失败可见 + 标签与数据一致；⑤Dialog 无 Escape/focus trap + 删除会话无确认 → 统一确认与焦点管理标准；⑦keepalive PUT 受浏览器 64KB 限制超长对话静默丢失 → 失败可见提示；⑨`BacktestView` 未知 window 原样回显 → 未知值处理。
- **留痕降级 5 项**：①消息列表虚拟化、②aria-live 刷屏、④移动端顶栏折叠、⑥反代请求体大小限制、⑧HSTS——降级理由与去向更新 §8.2 台账（①②④属独立性能/可达性专项，⑥⑧属部署层安全基线）。

## 四、非功能需求

1. **主链零劣化**：画像注入为 build 时四次轻查询（低频写高频读，缓存策略设计规格定）+ 字符串拼接；不新增对话链路中间件。
2. **token 护栏**：画像块限长可配（`InvestProperties` 新增 `invest.profile.*` 分组）；F03 每日单批小摘要，token 成本纳入护栏观察。
3. **隐私硬边界**：记忆/画像端点本人隔离；画像数据禁传 MCP 条款 + 抽检；观测表抽检通道（admin）与用户内容管理（本人）职责分离。
4. **覆盖率与测试**：后端 JaCoCo / 前端 V8 ≥80%，`make test` 三端全绿；记忆管理页与授权页走 Playwright e2e 真浏览器（沿「mock 盲区」教训——文件端口行为、画像预览同源性必须有真浏览器断言）；画像注入真值（sysPrompt 内容）走后端切片测试（e2e 只能验 UI 面）。
5. **架构与登记**：新表走 Flyway V7（`FlywayMigrationCountGuardTest` 常量 6→7）；记忆文件端口按 ArchUnit 约束落位（端口接口不得定义在 agent 包——infrastructure 禁依赖 agent；具体落位设计规格定）；V7 表为用户归属表，`scripts/e2e-cleanup.sh` 登记 DELETE 行；README 端点表、`docs/function/00-功能模块概览.md` M18 登记（五登记位沿 M17 先例）、`AuthNav` 导航、模块文档同步。
6. **契约同步**：前端 zod schema、e2e 断言、`ToolkitPromptAssetCollector` 版本资产（模板骨架登记，决策 #5 附注）同步。

## 五、验收标准（与规划文档 MS-31 节对齐）

- **记忆增删改查端到端可用**：本人可见策展层与日账本分栏；删除后条目从两层消失且后续对话不再注入已删内容（consolidation 不复活）；编辑仅策展层生效；e2e 真浏览器通过（含空态）。
- **注入后个性化回答可感知，MCP 工具调用 payload 抽检无私有数据外传**：开启授权后对话体现画像上下文（人工抽检可感知）；关闭授权后 sysPrompt 与现状逐字节一致；`tool_invocation_obs` 中 `mcp=true` 记录的 args 抽检无画像私有数据。
- **事件记忆自动落盘可在管理界面回溯**：制造投资事件（交易/日志）→ 定时窗口跑后日账本出现「外部事件」节 → 管理界面按节类型标记可见。
- **P3 台账**：认领 4 项清零（③⑤⑦⑨），降级 5 项留痕更新（§8.2 台账勾销记录）。
- **门槛**：`make test` 三端全绿（含 ArchUnit / 链接门禁 / Flyway 守护测试同步）。

## 六、YAGNI 排除清单（逐条给排除理由）

- **记忆手动新增**——roadmap F01 三动词（查看/编辑/删除）外；LLM `memory_save` 工具与 flush 已覆盖记忆产生通道。
- **忽略清单（删了不再记）**——决策 #12：删除不阻止未来记忆形成，库能力边界。
- **向量检索/记忆嵌入**——库 `memory_search` 关键词扫描对个人记忆量级（策展层 ≤4000 token）够用；引入向量设施超里程碑体量。
- **DB 记忆存储替换库文件记忆**——决策 #1：文件即真相源；替换需放弃库抽取（flush/consolidation）能力。
- **管理员代管用户记忆**——决策 #10：隐私边界，仅本人。
- **归档文件（`memory/archive/`）管理**——v1 管理对象限当期文件；归档 90 天后才出现且 `memory_search` 仍可达，管理需求未证实。
- **画像内容编辑**——画像系派生数据（决策 #17），编辑入口即源数据（做测评/改自选/调持仓），双入口制造不一致。
- **对话内动态开关注入（按轮触发）**——授权是用户级配置语义（决策 #3），每轮注入与授权开关一致；轮级触发语义复杂化无需求支撑。
- **画像注入 eval 题**——决策 #15：人工抽检 + 复盘观察项先行。
- **多记忆模板/分类体系**——库记忆无结构化字段，管理界面按文件层（策展/日账本）与节类型组织已满足透明可控；自建分类体系违背文件真相源。
- **F03 同步实时摘要**——决策 #8：定时批量；同步 hook 无先例且有事务边界与延迟代价。
