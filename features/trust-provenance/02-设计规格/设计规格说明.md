## 一、设计总览

### 1.1 机制选型（用户已拍板）

| 分叉 | 选型 | 依据 |
|---|---|---|
| 真值捕获 | **X1 Toolkit 装饰器**：`UserToolkitFactory` 装配时以 `AgentTool` 装饰器同名覆盖注册 | 参数与结果同点捕获，16 个 @Tool 方法零改动；`AgentTool` 公开接口天然可包装 |
| 校验/改写 | **Y1 PostSummary/PostCall hook**：完整文本齐备后校验，`setSummaryMessage` 改写 + Custom 事件修正指令 | 唯一有真实落点（SSE 编码层为包私有库内件，无业务挂点）；stateStore 与线上文本同源一致 |
| 送达/持久化 | **Z1 Custom 事件（当轮）+ Wire payload（持久化）** | 渲染与持久化同源；前端携带天然免疫 PUT 全删重插 |
| 挂载位 | **W1 `HarnessAgentFactory.build()`** | AG-UI + 飞书两路共同漏斗，Builder `.hook()`/`.middleware()` 当前零占用（`HarnessAgentFactory.java:38-60`）；飞书路径免费获得校验改写（无 Custom 消费者，锚定静默不发） |

### 1.2 组件与数据流

```
┌─ backend agent 域 ──────────────────────────────────────────────┐
│ HarnessAgentFactory.build(userId)                                │
│   ├─ toolkitFactory.build(userId)                                │
│   │    └─ RecordingAgentToolDecorator 包装每个注册工具            │
│   │         callAsync → 记录 (tool, args, result) → RuntimeContext │
│   └─ .hook(new TrustAgentHook(...))          ← W1 挂载           │
│        PostSummary: 完整文本 + 真值池 → NumberExtractor            │
│          → ConsistencyValidator（三态判定）→ 大偏差 setSummaryMessage│
│          → AgentEventEmitter.emit(CustomEvent("trust.anchors"))   │
│          → CustomEvent("trust.correction")（有大偏差时）            │
│          → AdviceDetector（自声明标记 + 词表）→ ConfidenceScorer    │
└──────────────────────────────────────────────────────────────────┘
SSE: AguiEvent$Custom(name="trust.anchors"/"trust.correction", value=Map)
 → 反代（不过滤）→ 前端 agent.subscribe({onCustomEvent})
 → TrustMeta state（Map<messageId, TrustMeta>）
   ├─ 渲染：remark 插件插 sup 角标 + CSS hover 浮层 + 横幅/disclaimer
   ├─ 修正：AgentStateMutation{messages} 原位替换 + 更新 TrustMeta
   └─ 持久化：agentMessagesToHistory 携带 payload → PUT → chat_message.payload(jsonb)
回灌：GET /messages（Wire 带 payload）→ historyToAgentMessages 重建 → TrustMeta
```

关键时序事实（侦察证实）：前端 PUT 为全删重插且流式中即周期发生（`ThreadArea.tsx:575-601` 防抖 150/400ms、`:604-619` 回合末、`:623-631` 切换 keepalive），Wire 现不含 payload（`ChatMessageWire.java:14-18`）——**后端直写必被冲掉**，故 payload 由前端携带（Z1）。

## 二、数据模型（零 Flyway 迁移）

### 2.1 `chat_message.payload`（已有列，`V1__baseline.sql:44-53`；JPA 已映射 `ChatMessageJpaEntity.java:34-36` String→jsonb）

```jsonc
// payload 结构 v1（无 null——NonNullCodec 属性级+内容级双剥除，缺省即缺键）
{
  "v": 1,
  "anchors": [                      // 每个锚定数字一条
    {
      "snippet": "1520.00",          // 文本中的原文片段（定位用）
      "occ": 1,                      // 该片段在本消息中的第几次出现（1-based）
      "state": "verified",           // verified | sourced | unverified
      "tool": "get_quote",           // 来源工具（sourced/verified 必有）
      "args": {"code": "600519"},   // 调用参数（MCP 工具同样记录）
      "asOf": "2026-10-05 14:59:32",// 数据时间戳
      "asOfKind": "data",           // data | generated | call（决策 #17 语义）
      "raw": "1520.33"              // 工具返回原值（verified 必有，供人工核对）
    }
  ],
  "correction": {"notes": ["原文误述 15.20"]},   // 有修正时才有本键
  "advice": {"flag": true, "by": "self"},        // by: self | lexicon | both
  "confidence": {"signals": ["stale_quotes:3", "unverified_ratio:0.4"]},  // 低置信才有
  "stats": {"verified": 2, "sourced": 1, "unverified": 3}
}
```

- 仅 assistant 消息携带；user 消息 payload 恒缺省。
- `snippet+occ` 定位而非字符偏移——原位替换后偏移漂移，片段+序次稳定；同一 `snippet` 多态冲突时以后端 anchor 顺序为准。

### 2.2 跨轮数值池摘要（决策 #15 回溯数据源）

本回合「数字值→(tool, asOf)」映射摘要写入 assistant `Msg` 的 metadata map（Msg 级 metadata 已有先例 `_chat_usage`，随 `agent_state.json` 落盘）；下轮回溯配对优先读本回合池 → 次选历史 Msg metadata。**降级**：历史被 `CompactionConfig`（`HarnessAgentFactory.java:51-55`）或 harness 内置 `ToolResultEvictionMiddleware` 清理时，该数字按「未溯源」处理（宁可少标）。

## 三、领域模型（agent 域内部模型，纯 POJO 不进 domain 分层）

`agent/trust/` 子包（沿 `agent/chart/` 先例）：

| 类 | 职责 |
|---|---|
| `ToolInvocation` | 一次工具调用记录：toolName、args(Map)、resultText、emittedSpecs(List\<String\>)、asOf/asOfKind、failed |
| `AnchorRecord` | 单数字锚定（payload v1 单条 anchor 的内存形态） |
| `AnchorBatch` | 一条 assistant 消息的锚定集 + stats + correction notes |

数字提取与比对为纯函数：`NumberExtractor.extract(text) → List<NumberToken>`、`ConsistencyValidator.verify(tokens, invocationPool) → AnchorBatch`——单测密度优先（NFR-4）。

## 四、后端组件与接口契约

### 4.1 `RecordingAgentToolDecorator`（X1）

- `implements AgentTool`（`io.agentscope.core.tool.AgentTool`：getName/getDescription/getParameters/getStrict/getOutputSchema/isReadOnly 委托被包装者；`callAsync(ToolCallParam)` 拦截）。
- 装配：`UserToolkitFactory.build()` 在 `registerTool(investTools)`（`UserToolkitFactory.java:54`）、`registerTool(new UserInvestTools(...))`（`:56-57`）与 MCP `registerAgentTool(mcpTool(...))`（`:78`）后，遍历 `toolkit.getToolNames()` 同名覆盖注册装饰器（`ToolRegistry.register` 为 Map.put 后写覆盖，`:59` 注释自证）。内置工具的 asOf 取返回 DTO 时点（见 §6.1）；MCP 工具 asOfKind=call、state 恒 sourced（决策 #5）。
- 记录落点：`ToolCallParam.getRuntimeContext()` typed put（RuntimeContext 同 call 内对 hook 可见，侦察证实）；ThreadLocal（`CurrentUserHolder` 先例）作回退通道。
- 全量真值增强：`toolkit.setChunkCallback`（用户级，2.0.3 无人占用）捕获 emit 的 ChartSpec 全量 JSON（`InvestTools.java:116/140/276/300/362/393/416/435` 等 emit 点）；**共存语义不确定时的回退**：仅记录返回文本 + 容差覆盖摘要舍入（2% 相对容差天然覆盖 `%.2f` 舍入）。

### 4.2 `TrustAgentHook`（Y1/W1，核心）

`implements io.agentscope.core.hook.Hook`，`HarnessAgentFactory.build()` 经 `.hook()` 挂载（Builder 原生支持，当前零占用）。

**PostSummaryEvent**（最终回复消息生成后、SSE 流完成前，侦察证实时序）：

1. `NumberExtractor.extract(summaryText)`——数据性数字判定式（参数组②）；
2. 用户数字豁免：NumberToken 值出现在近期 user 消息文本 → 跳过（决策 #16）；
3. `ConsistencyValidator` 比对（基线 = RuntimeContext 真值池 + §2.2 历史池回溯）：三态判定（容差参数组①，`InvestProperties` 可配）；
4. 大偏差 → 确定性替换该 snippet 为工具原值 + 追加注记行「> ⚠ 校验修正：原文误述 X」；替换后**重校验**，重试上限 2 次（参数组⑥），触达转标注 + 记 `correction_failed` 信号（决策 #12）；
5. `setSummaryMessage(修正后 Msg)`——stateStore 与 SSE 最终文本同源；
6. `AgentEventEmitter.fromContext(...)`（hook Mono 内 `deferContextual`）发 `CustomEvent("trust.correction", {messageId, snippet, occ, replacement, note})`（有大偏差时）与 `CustomEvent("trust.anchors", {messageId, payload})`（锚定批次，payload 即 §2.1 结构）；emitter 不可得时回退：Middleware `Flux.just(customEvent)` merge（侦察证实两路等价）；
7. `AdviceDetector`：① 自声明——提示词约束模型含投资建议时在文末输出标记行 `<!--advice-->`（HTML 注释 markdown 不渲染，天然隐蔽），hook 检测并剥离、置 flag；② 词表兜底扫描（参数组④，可配）；井集记 `advice.by`；
8. `ConfidenceScorer`：四类信号（参数组⑤），任一命中 → payload.confidence；
9. 摘要池写入 Msg metadata（§2.2）；修正/拦截/未懂数计数留痕（NFR-5，后续 MS-30 看板供数——本里程碑打结构化日志）。

**PostCallEvent**：兜底校验（飞书 `HarnessAgentInvoker` 同享改写，`HarnessAgentInvoker.java:36-41` 的 `reply.getTextContent()` 即改写后文本）。

**异常护栏**：整个 hook 体 try-catch，异常时跳过校验直通原文 + WARN 日志（决策：宁可少标不可断流）。

### 4.3 Custom 事件契约

| name | value（Map，无 null） | 时机 |
|---|---|---|
| `trust.anchors` | `{messageId, payload}`（payload=§2.1） | PostSummary 末尾，每 assistant 消息一次 |
| `trust.correction` | `{messageId, snippet, occ, replacement, note}` | 有大偏差修正时，先于 anchors |

桥接链路（侦察证实）：`CustomEvent(name, Map)` → `CustomAgentEventConverter` → `AguiEvent$Custom(threadId, runId, name, value)` → SSE；前端 `agent.subscribe({onCustomEvent})` 收 `CustomEvent{name, value}`。

### 4.4 Wire 扩展（Z1 持久化）

- `ChatMessageWire`（`ChatMessageWire.java:14-18`）增可选字段 `payload`（String，JSON；user 恒 null）；`toDomain()` 透传（现为恒 null，`ChatMessageWire.java:26`）。
- `ChatMessage` domain 已有 payload 位（`domain/conversation/ChatMessage.java`）；`ChatMessageJpaEntity` 已映射（`:34-36`）——**零迁移**。
- PUT 校验：payload 长度上限（防滥用，默认 64KB/条，`InvestProperties`）；非法 JSON 拒该条 payload（置 null 存文本，不整批拒绝）。
- GET 回灌：`ConversationMessagesView` 携带 payload 原样返回。

### 4.5 提示词约束（`InvestSystemPrompt.java`，静态 text block 61 行）

- `## 回答规范`（:29-33）追加两条：数字引用规范（数据性结论只用工具返回数字，避免二次计算值混入正文——计算过程单独成段）、advice 自声明标记（含买卖/仓位/目标价类建议时文末加 `<!--advice-->`）；

## 五、前端设计

### 5.1 事件接入与状态

- `ThreadArea` 已有 subscribe 先例（`ThreadArea.tsx:485-494` onRunErrorEvent）；新增订阅 `onCustomEvent`：按 name 分派——`trust.anchors` → `setTrustMeta(prev => ({...prev, [messageId]: payload}))`；`trust.correction` → 返回 `AgentStateMutation {messages: 替换后}`（@ag-ui/client sanctioned 路径，库实现已验证支持 stopPropagation/消息替换）+ 更新对应 TrustMeta 的 anchors/correction。
- TrustMeta 持有于 `ThreadArea` 父组件 state；`AssistantMessage`（memo，`ThreadArea.tsx:216-251`）增可选 prop `trust`（比较器补引用比较）。

### 5.2 角标渲染（remark AST 插件）

- 自定义 remark 插件：遍历 text 节点，按 payload anchors 的 `snippet+occ` 匹配切分，新节点盖 `data.hName: "sup"` + `data.hProperties: {data-anchor-idx}`；react-markdown 10 components 映射 `sup` → 自定义 `AnchorBadge` 组件（渲染角标序号，样式按 state 三态：verified 中性绿、sourced 中性灰、unverified 弱灰——决策 #9 弱样式）。
- `MarkdownView` 被四处共用（wiki/intelligence）——**不改签名**：新组件 `TrustMarkdownView`（包 `MarkdownView` + remark 插件 + anchors prop）仅对话侧使用，共用方零影响。
- 浮层：`AnchorBadge` CSS hover 展开绝对定位卡片（工具名 + 参数 + asOf + asOfKind 标注 + raw 原值）；仓库无 Popover 组件，自建（`group-hover` 先例 `Sidebar.tsx`）。
- 浮层措辞（决策 #13）：verified 显示「数值与工具返回一致」，不出现「已核实陈述」。

### 5.3 横幅与 disclaimer

- 消息级横幅：`AssistantMessage` 内容列（`ThreadArea.tsx:232` div 补 `relative`）在 MarkdownView 与 FeedbackBar 之间插 `ConfidenceBanner`（payload.confidence.signals 命中时）+ `DisclaimerNote`（payload.advice.flag 时，文案 §4.6）。

### 5.4 持久化与回灌（Z1）

- `agentMessagesToHistory`（`RuntimeProvider.tsx:90-115`）携带 payload：从 TrustMeta 按 `m.id` 取（assistant 消息 id 即 AG-UI messageId，链路同源已证）；`ChatMessage` 类型（`lib/types.ts:3-8`）与 zod schema（`lib/conversations.ts:16-17`）增可选 `payload`。
- 多标签 union（`ThreadArea.tsx:531-572` GET+union+PUT）：**非空 payload 优先**——同 id 合并时保留 payload 非空侧。
- 回灌：`historyToAgentMessages`（`RuntimeProvider.tsx:70-77`）重建时把 payload 写入独立 TrustMeta store（不塞 AG-UI Message.metadata，避免污染消息通道），GET 响应已带 payload（§4.4）。
- 旧消息（无 payload）：TrustMeta 无记录 → 不渲染角标（决策 #7 自然降级）。

## 七、测试策略（四层继承，覆盖率 ≥80%）

1. **单元（test）**：NumberExtractor（判定式全覆盖：万/亿/百分比/千分位/年份排除/序号排除）、ConsistencyValidator（testFixtures 纯确定性 ~30 例——容差边界/大偏差/未溯源/中文归一/方向陷阱各覆盖，验收 90%/5% 门槛锚定于此）、AdviceDetector（词表+标记+井集+否定语境豁免）、ConfidenceScorer 阈值、RecordingAgentToolDecorator 记录正确性、Hook 修正替换重试与降级出口。
2. **切片**：Wire payload 序列化往返、PUT 非法 JSON 降级、`InvestProperties` 绑定。
3. **集成（Testcontainers）**：payload 落库/回灌往返、多标签 union 非空优先（服务端 If-Match 并发既有用例扩展）。
4. **e2e（Playwright，清 `.next` 后真浏览器）**：三态角标渲染与浮层内容、刷新后角标仍在（payload 回灌）、修正原位替换、disclaimer 出现/不误附、低置信横幅。fixture 用 stub 模型出固定错值场景（确定性）。
5. **契约验证**：Custom 事件 payload 全字段无 null 的序列化断言（NonNullCodec 行为锁定，防回归）。
