## 二、经验（值得沉淀）

1. **立项侦察前置的价值**：七路代码侦察（AG-UI 通道/持久化链路/工具拦截/前端挂点等）在写设计前推翻了一个核心前提（TextMessage 无 metadata 字段）、坐实了两个口径（DTO 真值基线、剥 null 双层）、抓到了 PUT 全删重插会冲掉后端直写——设计规格因此没有一行凭记忆写的代码引用。**机制假设必须字节码/实机级证实**：B5 的锚点改判（POST_CALL setFinalMessage 不达 stateStore）是「设计裁定时证据不足 → 实现探针推翻 → 改判留痕」的标准样本。
2. **前后端同语义必须单一真相源**：F1 定位器逐语义移植后端 `validBoundary`（审查拦下嵌套数字错位）+ 多修正台账对原文计数——前后端各写一套近似逻辑是角标/替换错位的根源。
3. **审查网的真实拦截率**：7 个修复轮 + 终审 2 Important 全部由审查代理拦下（非实现者自报）：复合单位回写退化、emit 订阅时异常逃逸护栏、occ 口径缺口（Critical）、research_draft 回显污染、浮层触屏不可达。**逐任务 fresh 审查 + 终审跨任务视角的分层不可省**。
4. **探针附录回填制**（B0 三探针结论写进计划附录、失败走既定回退）把 spike 的不确定性变成了设计参数，值得复用。
5. **AgentStateMutation/setMessages、chunkCallback 双回调、Hook/Middleware 分工**等 agentscope 2.0.3 机制结论已沉淀至 [01-Agent实现 §7](../../../docs/technology/modules/01-Agent实现.md)，供 MS-31/32 复用。

## 三、不足与已知残留

1. **延后 4 项**（终审 triage 随后小 PR；**已于 chore/ms29-followups 交付**）：前端剥离 advice 标记（实时文本残留 HTML 注释，不可见但裸复制存在）/ poolSummary LinkedHashMap 覆盖序与 40-cap 驱逐意图矛盾 / 真实二回合 stateStore 往返集成断言（原仅合成测试）/ 瞬时高亮（拍板 #10 另一半，替换可见性已由注记块+横幅信号补偿）。
2. **Hook 系 forRemoval 钉版风险**：升级 agentscope 须迁移（文档已记义务）；升级窗口应加迁移探针。
3. **配对规则的残余误配面**（前 2 位有效数字同源+跨度≤4）：33 例锚定下 100%/0%，真实语料分布未知——MS-30 幻觉诱导基线是真正的试金石。
4. **排除工具锚定无 tool 来源展示**（research_draft 双池全排的取舍代价）：其数字恒 unverified 无归因信息。
5. 部署机人工项：无新增（零迁移、零新端点、配置有默认值）；但 `invest.trust.*` 阈值生产校准依赖 MS-30 观测数据。
