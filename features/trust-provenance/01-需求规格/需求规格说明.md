## 一、背景与目标

阶段一/二交付了「数据与记录 + 信息消化与决策流程」闭环（全系统 149/149），Agent 工具返回数据经聊天图表双通道（`ToolResultBlocks`）完整呈现，但 **LLM 文本结论与工具数据之间无强制绑定**：数字性结论无来源标注、陈述数字与工具返回值可能不一致（幻觉）、低置信回答无显式提示、投资建议无统一免责。金融场景下这是合规与信任的准入门槛（阶段三规划 D1·P0）。

本特性（M17，MS-29）交付**可信底座**：每条数据性结论可溯源（数字级角标 → 来源工具+调用参数+数据时间戳）、文本陈述数字与工具实际返回值强制比对（不一致分级处置）、低置信回答机制化显式提示、投资建议 disclaimer 统一双层触发。全部复用既有资产：图表双通道已有全量数据面（溯源只是把「已有数据」与「文本结论」绑定）、`AguiEventNonNullCodec`/`AguiWireJsonConfig` 序列化先例、`UserToolkitFactory` 工具装配链（内置 + MCP）、HITL 审批卡片交互先例（角标浮层同类交互）。校验器为**规则/数值比对层，不在对话主链引入额外 LLM 调用**（方向规划定位「事实校验 Agent 的单机轻量版」）。

按阶段三规划，MS-29 是关键路径 MS-28 → MS-29 → MS-32 的中间节点：M17-F02 校验器是 MS-32 深度研究「草稿过校验器」的硬依赖。

## 三、功能需求（M17-F01~F03，编号/名称承规划文档，不增删改）

### M17-F01 结论引用锚定

**描述**：Agent 输出文本通道中每个被直接引用的数字，在 AG-UI 事件流 metadata 中携带锚定记录（数字在文本中的定位、来源工具名、调用参数、数据时间戳、校验态）；前端在对应数字处渲染上标角标（决策 #2），点击浮层展示来源详情；同句多数字共享同次工具调用时共用角标编号。

**业务规则**：

- 锚定对象 = 文本通道中的**数据性数字**（价格/涨跌幅/财务指标/市值/宏观指标等度量值；日期年份、序号编号等非度量数字不锚定，判定式设计规格定）；中文习惯格式「万/亿/百分比」归一化后定位。锚定面宽于比对面：锚定覆盖全部数据性数字（含无工具支撑者——其态为「未溯源」、Agent 二次计算值——有工具上下文但非直接引用，态为「已溯源未校验」）；F02 比对范围仅为「直接引用值 ∩ 内置工具」子集。
- 角标三态（决策 #5）：**已校验**（内置工具返回值比对通过，绿/中性样式）/ **已溯源未校验**（MCP 工具来源，中性样式）/ **未溯源**（无任何工具数据支撑，警示样式）。
- 浮层内容：工具名 + 调用参数 + 数据时间戳（工具返回含数据时点以返回为准，否则取调用时刻）；同一浮层内可含「工具返回原值」字段辅助人工核对。
- metadata 扩展字段设计须过 `AguiEventNonNullCodec` 剥 null 序列化验证（规划 §8 风险表立项验证项：关键字段不因剥 null 丢失、前端必达）——具体 schema 与验证用例在设计规格对照真实代码定。
- MCP 工具锚定走同一锚定记录结构（来源工具 + 参数 + 调用时刻），校验态固定「已溯源未校验」（决策 #5）。

**边界与异常**：

- 历史消息无 metadata：自然降级不渲染（决策 #7），前端不报错。
- 工具调用失败仍被文本引用的数字：按「未溯源」处理（无返回值可比对、无有效时间戳可展示，浮层仅示来源工具与调用参数）。
- 同一数字命中多次工具调用的歧义归因规则在设计规格定（MVP 允许取最近一次命中并留痕）。

### M17-F02 数字一致性校验器

**描述**：轻量规则校验层比对「文本陈述数字 vs 内置只读数据工具实际返回值」，按分级混合策略（决策 #1）输出三态处置：容差内放行 / 大偏差拦截改写 / 无法比对标注「未溯源」。校验结论写入 F01 锚定记录的校验态字段，是角标渲染与 F03 置信度信号的共同数据源。

**业务规则**：

- 比对范围（MVP，方向决策 #1 + 决策 #5/#6）：仅**直接引用值**（工具返回值被文本原文引用的数字；Agent 二次计算值后置）；仅**文本通道**；仅**内置只读数据工具**（现况 16 个 `@Tool`：`InvestTools` 13 + `UserInvestTools` 3；其中写工具 `research_draft` 与无返回值比对意义的工具排除，清单设计规格定稿）。
- 三级处置（决策 #1）：
  - **容差内** → 静默放行，角标「已校验」；容差语义覆盖舍入（约 15.2 vs 15.23）、万亿/百分比换算（1.9 万亿 vs 19,000 亿）、有效位（1520 vs 1520.00）；绝对+相对组合容差，具体数值入 `InvestProperties` 可配（沿 M15 重要度阈值先例）。
  - **大偏差** → 拦截改写该句：错误数字替换为工具返回值，并附「校验修正：原文误述 X」注记；修正执行机制（harness 内改写 vs 事件流后处理）为设计规格首要拍板项。
  - **无法比对** → 原文保留 + 「未溯源」标注（含 MCP 来源数字与非工具来源数字）。
- 中文数字格式归一化（万/亿/百分比/千分位）后进入比对。
- 校验结果计数（拦截数/修正数/未懂数）留痕供 F03 信号与 MS-30 观测看板消费。

**边界与异常**：

- 校验器自身异常**不得阻断对话主链**：降级为「已溯源未校验」态并告警留痕（可信机制自身失效时宁可少标不可错杀）。
- 二次计算值（如据工具价推导涨幅）不在比对范围，其数字按来源工具锚定为「已溯源未校验」（有工具上下文但非直接引用）——设计规格明确判定式。
- 空/无数字回答：校验层直通，零开销。

### M17-F03 置信度与免责标准化

**描述**：机制信号推导的低置信消息级横幅（含核实路径建议）+ 双层触发的投资建议 disclaimer 统一模板。

**业务规则**：

- **低置信横幅**（决策 #3）：信号四类——①未溯源数字比例 ②数据时间戳陈旧度（阈值可配）③工具调用失败/降级 ④校验修正次数；组合超阈值 → 消息尾部横幅列明命中信号与核实路径建议。核实路径 v1 为按数据类型的静态映射模板（行情类 → 建议对话内重问最新价或东方财富行情页；公告类 → 巨潮资讯网；宏观类 → 统计局/央行官网）。
- **disclaimer**（决策 #4）：触发 = Agent 自声明 advice 标记（`InvestSystemPrompt` 增约束）∪ 后端词表兜底（词表可配、有测试锚定）；统一模板含「AI 生成、不构成投资建议、市场有风险、独立判断或咨询持牌机构」要素，文案设计规格定稿。
- 横幅与 disclaimer 可同消息并存，互不抑制。
- 提示词新增约束（自声明 + 数字引用规范）纳入提示词资产维护，衔接 MS-30 版本化与 eval 回归。

**边界与异常**：

- 词表兜底扫描仅消息文本，不扫工具返回与图表 spec（工具数据非建议表述）。
- 自声明与词表均未命中的隐晦建议属已知残余风险，留 MS-30 幻觉诱导基线度量（本里程碑不建 eval 基线）。

### 工程随附项：agent/web 域 P3 顺带清理（决策 #8，规划 §8.2 台账）

六项打磨（①反注入总则句 ②draftJson 大小上限 ③`hasSize(16)` 断言易破 ④`TtlCache` 原子性 ⑤Flyway 迁移数守护测试 ⑥FeishuBinding 时区解释）随本里程碑交付清零或留痕降级，交付时逐项勾销；其中 ①反注入总则句与 F03 提示词改动同文件顺带、②draftJson 上限与 F02「内置工具返回值治理」同域，优先随做。

## 四、非功能需求

1. **流式体验**：锚定/校验/横幅机制不明显劣化首字时延与整体流畅度——校验为纯规则数值比对，主链零额外 LLM 调用；大偏差拦截改写的重写轮次须有上限护栏（防循环修正），上限可配。
2. **协议兼容**：AG-UI metadata 扩展过 `AguiEventNonNullCodec`/`AguiWireJsonConfig` 剥 null 序列化验证（设计规格含验证用例）；旧消息降级（决策 #7）；前端对缺失字段防御性渲染。
3. **安全**：不引入新攻击面——锚定浮层内容（工具名/参数/时间戳）均为系统内数据，无用户可控注入路径；P3-①反注入总则句顺带补入 `InvestSystemPrompt`；词表与容差配置入库可管，无 CORS/CSRF 现状变化。
4. **覆盖率与测试**：后端 JaCoCo / 前端 V8 ≥80%，`make test` 三端全绿；校验器容差/归一化/三态处置为纯函数优先（单测密度高）；角标浮层三态与 disclaimer 走 Playwright e2e（真浏览器，沿「e2e 旧构建产物与 mock 盲区」教训——关键前端改动须清 `.next` 后真浏览器验收）。
5. **可观测**：校验拦截/修正/未懂数、低置信横幅触发、disclaimer 触发（自声明/词表分别计）留痕计数，为 MS-30 观测看板与幻觉诱导基线供数。
6. **架构**：校验器与锚定落 `agent` 能力域（规划 §六先例：消费 application/domain，`PackageConventionsTest` 白名单按需登记）；如需持久化（校验留痕表）走 Flyway + DDD 分层；`InvestProperties` 承容差/词表/阈值配置。

## 五、验收标准（与规划文档 MS-29 节对齐）

- **溯源可见**：数字性结论点击可见来源与时间戳——e2e 覆盖角标三态渲染与浮层内容（内置/MCP/未溯源三场景）。
- **校验有效**：固定 fixture 集上，直接引用错值检出率（拦截改写+显式标注合计）≥ 90%，正确值误改写率 ≤ 5%；fixture 集入库随仓库维护（幻觉诱导 eval 基线与真实模型指标由 MS-30 产出，规划已定归属）。
- **流畅度**：抽检对话（含多工具调用场景）首字时延与往返体验不明显劣化；修正重写不常触发、有上限。
- **disclaimer 覆盖**：投资建议类输出全量覆盖（自声明 ∪ 词表井集，词表命中有测试锚定）；非建议类输出不误附。
- **P3 台账**：六项清零或留痕降级（逐项勾销）。
- **门槛**：`make test` 三端全绿（含 ArchUnit / 链接门禁）。

## 六、YAGNI 排除清单（逐条给排除理由）

- **二次计算值校验**——方向决策 #1（2026-10-04 已确认后置）：推导链归因复杂，MVP 先锁直接引用值。
- **模型自评置信度**——决策 #3：LLM 过度自信通病，机制信号已覆盖数据维不确定性。
- **MCP 工具数字比对**——决策 #5：异构返回语义未知，值巧合匹配产假「已校验」（漏杀）比不校验更有害。
- **LLM 判定式事实核查（事实校验 Agent 重模式）**——方向规划定位即「单机轻量版」；主链加 LLM 调用伤时延与成本。
- **幻觉诱导 eval 基线与幻觉率指标**——规划归属 MS-30（D4.1），本里程碑只交付校验器本体与供数。
- **D2 研报草稿强制过校验**——MS-32 消费端（M19-F03），本里程碑只保证校验器可被复用。
- **修正版本 diff 视图**——「校验修正：原文误述 X」内联注记已满足透明性；diff 视图无既定消费场景。
- **英文/多语言数字格式**——产品语言为中文，仅归一化中文习惯格式（万/亿/百分比/千分位）。
- **M17 概览登记与模块文档**——立项后续动作（头部注明），随交付回填收口。

## 七、开放问题（2026-10-05 立项澄清全部关闭）

| # | 原问题 | 定论 |
|---|--------|------|
| 1 | 校验器拦截策略（拦截修正 vs 显式标注，规划 §8 点名立项拍板） | 决策 #1：分级混合三态处置 |
