# MS-29 立项三路侦察报告（AG-UI 通道 / 会话持久化 / 工具返回时点）

> 日期：2026-10-05 | 背景：MS-29（trust-provenance）需求规格 v1.0 grilling 评审期间，三路并行代码侦察（Explore 子代理）核实规格前提；结论已并入[需求规格 v1.1](../01-需求规格/需求规格说明.md) 决策 #9~#17。
> 仓库状态：main=c30de26f；agentscope 2.0.3（jar 于仓库 `.gradle-home`）；前端 @ag-ui/core 0.0.59。

## 一、AG-UI 事件通道与 codec（侦察 A）

**结论：AgentScope 2.0.3 的 TextMessage 事件无 metadata 字段——原生 metadata 通道后端不可设；可用替代通道为 Custom 事件与 Interrupt.metadata。**

- `TextMessageStart/Content/End/Chunk`（`io.agentscope.core.agui.event.AguiEvent$*`）为固定组件 record（threadId/runId/messageId/role/delta/timestamp/rawEvent），javap 证实无自定义 metadata 组件；`AguiMessage` 模型同样无。
- 线协议与前端**支持** metadata：@ag-ui/core 0.0.59 各 role 消息 schema 均有可选 `metadata`（`frontend/node_modules/@ag-ui/core/dist/index.d.ts:4474/1006/1086`）——缺的仅是 AgentScope 后端事件模型这一段。
- 可用通道先例：`AguiEvent$Custom`（任意 `value` Object）；`Interrupt.metadata()`（Map）——HITL 已在用（`frontend/components/chat/ThreadArea.tsx:414-415` 读 `toolName`/`toolInput`，`InterruptApprovalCard.tsx:7` 同源）。
- `AguiEventNonNullCodec`（`backend/.../agent/AguiEventNonNullCodec.java:26-28`）仅对 `AguiEvent` 实例生效（LLM 请求体/stateStore/工具参数走默认 delegate）；经 `AguiWireJsonConfig`（`AguiWireJsonConfig.java:16-23`）全局 `setSerializationInclusion(NON_NULL)`——**剥两层**：属性级 null（字段消失）+ 内容级 null（Map null 值 entry、集合 null 元素，递归对象图；javap 字节码证实 valueInclusion/contentInclusion 同设）。**含义：锚定 payload 结构不得依赖 null 值表达缺省，须用缺键。**

## 二、会话持久化语义（侦察 B）

**结论：自定义事件 metadata 只活在当轮 SSE 流内，刷新/重开后经三处丢弃点必然丢失；`chat_message.payload` 预留 JSONB 列是持久化落点。**

- 服务端会话状态为 ADR-0011（非 AGENTS.md 所写 ADR-0009）：`JsonFileAgentStateStore`（`HarnessAgentFactory.java:50`，`.agentscope/state/<userId>/<threadId>/agent_state.json`）存**消息级 Msg**（id/role/content 块/Msg 级 metadata map/timestamp），非 AG-UI 事件流；单机文件前提。
- UI 展示双轨独立：`GET /api/conversations/{id}/messages` 返回 `ChatMessageWire = {id, role, content, createdAt}`（`ChatMessageWire.java:14-18`）——纯文本，无 metadata/toolCalls/reasoning；旧轮 SSE 流从不重放（`AguiRequestProcessor` 命中 server-side-memory 只取 follow-up）。
- 三处丢弃点：① 前端 `agentMessagesToHistory`（`RuntimeProvider.tsx:90-113`）只保 id/role/content/createdAt；② 线上格式 `ChatMessageWire` 无 metadata 字段；③ 回灌 `historyToAgentMessages`（`RuntimeProvider.tsx:70-77`）只重建三字段，zod schema 同（`frontend/lib/conversations.ts:16-17`）。
- **`chat_message.payload JSONB` 列已存在且恒写 null**（`V1__baseline.sql:35-53`；`ChatMessageWire.java:13` 注释「payload 预留」）——锚定记录持久化的现成落点：写入 payload + Wire 扩展带回 + 前端回灌重建角标，无需新表。

## 三、内置工具返回形态与数据时点（侦察 C）

**结论：比对基线必须是服务侧 DTO 真值（约半数工具给 LLM 的是格式化中文摘要）；数据时点 DTO 层覆盖良好，唯二缺口 screen_stocks 与 analyze_industry 板面。**

- 返回形态三类（LLM 视角无强类型对象）：(a) record 直序列化 JSON——search_stock/get_quote/get_news；(b) LinkedHashMap 信封 JSON——search_news/macro_brief/search_announcements；(c) `ToolResultBlock` 双通道——get_kline/get_financials/get_market_overview/get_valuation/screen_stocks/analyze_financials/analyze_industry/analyze_portfolio/suggest_allocation，**LLM 只见 `ChartSpecs.*Summary` 中文摘要文本**（数字 `%.2f` 内嵌句中；emit 块只进前端不进 LLM，`InvestTools.java:115-121`）。
- 时点清单（DTO 字段 → 锚定浮层可用）：`Quote.time`、`KlineBar.date`（DTO 有但 klineSummary 摘要无——不影响服务侧锚定）、`FinancialIndicator.reportDate`、`ValuationSnapshot.tradingDay`、macro `period/periodType`+`generatedAt`+`publishedAt`、news `date/publishedAt`、`FinancialRecord.reportDate`+杜邦双期别——**锚定层在服务端直读 DTO，与 LLM 摘要可见性无关**。
- **DTO 层缺口**：`StockScreeningResult` 14 字段无任何日期（底层快照 tradeDate 存在未透出，`StockScreeningResult.java:5-12`）；`IndustryBoardView` 无日期（`IndustryValuationPoint.tradingDay` 存在未进视图）。
- 语义注意：`get_market_overview` 的 `time` 三条解析路径均取 `LocalDateTime.now(MARKET_ZONE)`（`MarketDataParser.java:152/310/333`）——是抓取/生成时刻非源站行情时刻，浮层展示须如实按生成时刻标注。

## 四、对需求规格的影响汇总

| 规格前提 | 侦察结论 | 规格落点 |
|---|---|---|
| 「扩展 AG-UI 事件 metadata」 | TextMessage 事件无 metadata 字段（2.0.3） | 决策 #11/背景改写：Custom 事件（当轮实时）+ payload 回灌（持久化）组合，通道细节设计规格拍板 |
| codec 兼容验证 | 双层剥 null（属性级+内容级） | NFR-2：payload 用缺键不用 null |
| 刷新后角标可见性 | 三处丢弃点，事件级 metadata 必丢 | 决策 #11：`chat_message.payload` 预留列全持久化 |
| F02 比对基线 | LLM 可见约半数为摘要文本（含舍入） | 决策/业务规则：基线 = 服务侧拦截的 DTO 结构化真值 |
| F01 浮层时间戳 | DTO 时点覆盖良好，两处未透出 | 决策 #17：screen_stocks/analyze_industry 板面顺带透出；overview 按生成时刻如实标注 |
