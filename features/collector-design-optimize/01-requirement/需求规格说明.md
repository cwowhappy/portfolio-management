# 数据采集服务重构 需求规格说明

- 日期：2026-08-29
- 状态：待实施
- 范围：数据采集服务（`collector/`）的架构重构与扩展
- 依据文档：[数据采集服务架构](../../../docs/technology/architecture/04-数据采集服务架构.md) · [ADR-0003 行情数据源](../../../docs/technology/decisions/0003-market-data-source.md) · [数据需求附录](../../../docs/function/99-附录-数据需求与技术扩展.md) · [市场估值需求规格说明](../../market-valuation/01-requirement/需求规格说明.md) · [P3 估值数据采集服务实施计划](../../market-valuation/02-plan/P3-估值数据采集服务.md)

## 一、背景与目标

「市场估值」特性交付后，采集服务 `collector/` 是**单用途脚本**：`sources/`（akshare + tushare）→ `calc/`（pandas 计算）→ `store/`（psycopg 幂等 upsert）→ `scheduler/jobs.py`（单一 cron）。它在可扩展性上存在明确局限：

1. **数据源单一且硬编码**：每个数据类型只有一个来源（全A估值/国债仅 akshare，指数/申万仅 tushare），无同类型多供应商兜底。
2. **无法低成本扩展**：新增一个数据类型 = 新写 source 函数 + calc + store + 手工接进 `collect_once` 编排，没有统一抽象。
3. **调度单一**：只有一个「工作日 15:30」cron，无法表达不同数据类型的差异化频率（如申万映射应周级缓存、指数成分股应每半年更新）。
4. **缺少工程能力**：无客户端限速、固定 30s 重试无退避、未接交易日历、回填逐行 commit、无执行历史/源健康度可观测。

**目标**：把 `collector/` 重构为**可扩展的数据采集框架**——数据源与格式转换器可插拔、任务按数据类型用 DB 元数据驱动调度、支持差异化的采集频率与手动执行、支持回填，并补齐上述工程能力。

**非目标**：不改变「采集(写)与查询(读)分离」「业务表 schema 由 Java 后端 Flyway 单一拥有」的既定原则；不提供对外 HTTP API（读侧仍由 Java 后端负责）。

## 二、需求澄清汇总

## 四、功能需求

### FR-1 可扩展数据源适配器（Source）

- 每个数据源（akshare/tushare/东财/中债/中证…）封装为 `Source` 适配器，返回**原始数据**。
- 简单数据源（单接口调用 + 参数）经 YAML 声明即可接入，**零代码**。
- 复杂数据源（循环取数、跨接口组合）实现 `Source` 接口，逻辑独立可单测。
- 同一数据类型可声明**有序多源列表**，供可靠性选源与降级。

### FR-2 可扩展格式转换器（Converter）

- 原始数据经 `Converter` 归一化为**规范记录**（字段映射 + 类型转换 + 清洗 + 单位归一），输出与目标表列对齐。
- 简单映射经 YAML 声明（列映射/类型）；复杂转换实现 `Converter` 接口。
- 计算型任务（如全A估值中位数、行业市值加权）在转换之后有独立的**计算（Calc）**环节，作为可选步骤。

### FR-3 采集任务（Collector/Task）

- 一个数据类型对应一个采集任务，绑定「数据源列表 + 转换器 + 校验 + 目标表 + 调度」。
- 任务定义存 PostgreSQL `collector_task` 表，支持经 CLI/DB 增删改查与启停；启停/改调度经 DB 变更后**重启生效**（一期不做热重载）。
- 任务执行最小单元，由执行器统一驱动。

### FR-4 调度与多频率

- 每个任务独立定义调度周期（cron / interval），支持差异化频率（日频快照、周级申万映射、每半年成分股等）。
- 调度执行前经**交易日历**门控：非交易日跳过。
- **同任务互斥**：同一任务同一时刻仅一个实例运行（并发触发或与手动触发重叠时，后到者跳过）。

### FR-5 手动执行

- CLI 子命令：`run <task>`（触发一次）、`list`（列任务）、`backfill <task> --start --end`（回填）。
- `run` 支持 `--force` 跳过交易日历门控（用于补数）。

### FR-6 可靠性动态选源

- 维护每个数据源的**健康度与评分**（成功率、连续失败次数、延迟、最近成功时间）。
- 执行时按评分从高优先源开始，跳过近期连续失败的源；选中源失败则降级到下一健康源。

### FR-7 可配置数据校验

- 转换/计算之后、落库之前执行 `Validator`，规则经 YAML 声明。
- 内建规则：`required` / `not_null` / `type` / `range` / `unique` / `min_rows` / `allowed_values`。
- 分级：`hard`（失败 → 任务失败或降级下一源）/ `soft`（失败 → 记告警、剔除异常行继续）。

### FR-8 回填

- 任意声明 `supports_range` 的数据源支持按时间区间回填历史数据并落库。
- 回填复用同一条执行管道（选源 → 拉取 → 转换 → 校验 → 落库），参数为区间而非当日。
- 幂等 upsert 保证重复回填无脏数据；批量写入（`executemany` 单事务）。

### FR-9 幂等落库

- 业务数据写入 Java 后端 Flyway 定义的表，仅 INSERT/UPDATE，**零 DDL**（业务表）。
- 表名/列名逐字对齐跨服务契约；重复执行不产生重复数据。

### FR-10 执行历史与源健康可观测

- 每次执行记录 `collector_task_run`（起止时间、状态 success/partial/failed/skipped、所用源、写入行数、错误）。
- 源健康度落 `collector_source_health`，供选源评分与运维排查。

### FR-11 速率控制与重试

- 客户端限速（对循环调用加调用间隔或简单令牌桶），降低上游限流风险。
- 整任务重试带**指数退避**（替换固定 30s）。

## 五、非功能需求（NFR）

| 类别 | 要求 |
|---|---|
| 数据新鲜度 | 快照类任务交易日收盘后完成；页面/读侧可标注数据截止交易日 |
| 可靠性 | 重试带退避；幂等 upsert；多源降级；失败隔离不滚已落库数据；同任务不并行 |
| 可扩展性 | 新增数据源/数据类型零代码（配置）或低代码（插件）；不破坏既有任务 |
| 可观测性 | 执行历史表 + 源健康表 + 结构化日志，失败可追溯 |
| 性能 | 回填与映射批量写入（executemany 单事务）；客户端限速保护上游 |
| 一致性 | 业务表 schema 与 Java 后端 Flyway 对齐；跨服务契约不变 |
| 可测试性 | Source/Converter/Validator 用 mock + 离线 fixture 单测，不碰真实网络；覆盖率 ≥80% |

## 六、验收标准

### A. 可扩展性（FR-1/2/3）

- 新增一个「单接口 + 列映射」数据源，**仅通过 YAML 配置、零代码**即可接入并跑通采集。
- 新增一个复杂数据源，实现 `Source` 接口后按插件名注册即可接入。
- 新增数据类型无需改动 Executor / Scheduler / Store 核心代码。

### B. 现有数据迁移（FR-9）

- 连续 5 个交易日，全A快照 / 国债曲线 / 指数估值 / 申万映射 / 行业加权各表数据正确落库。
- 快照中位数与破净数与抽验口径一致（剔 PE≤0 与 PE>100）。
- 国债 10Y 写入曲线表 `term='10Y'`，旧 `treasury_yield` 表在 ERP 读侧切换后废弃。

### C. 一期新增数据

- 国债收益率曲线 1/3/5/10/30Y 按交易日落库。
- 指数股息率写入 `index_valuation_history.dividend_yield`（不再恒为 None）。
- 指数成分股写入 `index_constituent`，唯一键 `(index_code, stock_code)` 幂等。

### D. 调度与并发（FR-4）

- 差异化频率生效：快照日频、申万映射周频、成分股低频，各自独立 cron。
- 非交易日（节假日）调度被跳过。
- 同任务并发触发（调度重叠或手动 vs 调度）→ 仅一个实例执行，另一个 `skipped`。

### E. 多源降级（FR-6）

- 主源故障 → 自动降级备源，任务成功且 `source_used=备源`。
- 源连续失败达阈值 → 熔断跳过；冷却期后 half-open 试探；试探成功恢复。
- 全部源失败 → 任务 `failed` 且记录到 `task_run`。

### F. 校验（FR-7）

- hard 规则失败 → 任务失败或降级下一源。
- soft 规则失败 → 剔除异常行，其余落库并记录告警。

### G. 回填（FR-8）

- `backfill` 按区间回填指数 / 曲线历史，幂等可重复执行。
- 回填执行记录 `task_run.mode=backfill`。

### H. 手动执行（FR-5）

- CLI `run / list / backfill / seed / history` 五命令可用。

### I. 质量门槛

- 覆盖率 ≥80%（`make collect-test`）；测试不碰真实网络（mock + fixture）。

## 七、明确不做（YAGNI）

- 数据**导出**机制（CSV/Parquet/JSON 落盘）——数据读取由 Java 后端 API 负责。
- 对外 HTTP API / 管理界面——本期仅 CLI 手动执行。
- 分布式任务队列（Celery 等）、workflow/DAG 编排引擎。
- 可转债/基金/宏观/信用债/个股历史估值等二期数据类型的实际接入（本期仅盘点）。
- 复杂的跨字段/跨表校验规则引擎（仅内建规则 + 自定义 Validator 兜底）。
- 数据源健康评分的机器学习/自适应调权（仅用确定性公式：成功率×新鲜度−延迟惩罚）。

## 八、依赖与风险

**依赖**

- 新业务表（`treasury_yield_curve`、`index_constituent`）需 Java 后端新增 Flyway 迁移（V4）。
- 国债 10Y 切表：ERP 读侧从 `treasury_yield.yield_10y` 切换到 `treasury_yield_curve`（term='10Y'），并废弃旧表。
- 交易日历数据源（akshare 交易日历接口或内置静态日历）。
- 指数股息率数据源（中证指数公司 / 乐咕乐股）的可用性与格式。
- 中国债券信息网多期限收益率曲线的解析。

**风险**

| 风险 | 影响 | 应对 |
|---|---|---|
| 新数据源格式不确定/变动 | 转换器解析失败 | 接口名/列名在 adapter 阶段用 mock 收敛；源健康度标记失败并降级 |
| 中证指数/中债为官方下载式接口 | 自动化取数门槛高 | 优先可程序化访问的源；官方源作备选，主源用 akshare/tushare |
| 可靠性评分数据冷启动 | 初期无历史评分 | 评分含默认值，冷启动先按声明优先级尝试 |
| 引入运维表打破「collector 零 DDL」 | 运维元数据与业务数据混用原则 | 运维表 collector 自有迁移，业务表仍零 DDL，边界清晰 |
| 新业务表需 Java 侧迁移 | 跨服务联调 | 一期先定义 V4 契约，collector 与 Java 迁移并行，读侧后续接入 |

## 附：术语

| 术语 | 含义 |
|---|---|
| Source（数据源适配器） | 对接具体数据源、返回原始数据的组件 |
| Converter（格式转换器） | 将原始数据归一化为规范记录的组件 |
| Calc（计算） | 从规范记录聚合出衍生指标的可选步骤（中位数/市值加权等） |
| Validator（校验器） | 落库前按可配置规则校验数据的组件 |
| Collector/Task（采集任务） | 一个数据类型对应的采集单元，绑定源/转换/校验/目标表/调度 |
| SourceSelector（选源器） | 按可靠性评分从多源中动态选源的组件 |
| Executor（执行器） | 驱动一次任务执行（选源→拉取→转换→计算→校验→落库）的组件 |
| 回填（Backfill） | 按时间区间一次性拉取历史数据并落库的运行模式 |
| 规范记录 | 转换器输出、与目标表列对齐且类型确定的记录 |
| 可靠性评分 | 由成功率/新鲜度/延迟等综合出的源可用性分数 |
