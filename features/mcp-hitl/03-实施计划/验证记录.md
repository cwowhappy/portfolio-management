## 结论速览（2.0.1 实测勘误）

| # | 勘误要点 | 实测结论 |
|---|---|---|
| 1 | interrupt 以 RAW 事件透传 | 权限确认中断**不走** `RUN_FINISHED.outcome.interrupts[]`：`RequireUserConfirmEvent` 与 `RequestStopEvent` 以两条 `RAW` 事件透传，`RUN_FINISHED` 无 `outcome`；计划声称的 `agentscope.interruptKind` 等扁平 metadata 键在真实输出中一律不存在 |
| 2 | `resume[]` 对权限确认流一律契约错误 | approved:true / approved:false 两种 payload 均返回 `RUN_ERROR / AGUI_INTERRUPT_CONTRACT_ERROR`；工具未执行（无 `TOOL_CALL_END`、无 `TEXT_MESSAGE`），Agent 未续跑 |
| 3 | 真实续跑形状 | 后续消息 metadata 键 `agentscope_confirm_results`（`Msg.METADATA_CONFIRM_RESULTS`）挂 `List<ConfirmResult>`；`confirmed=true` 执行工具，`false` 写 DENIED 结果后 Agent 继续 |
| 4 | AG-UI 无法承载 | `AguiMessage` 无 metadata 字段、`AguiMessageConverter` 丢弃 metadata、`resume[]` 只转成 `ToolResultBlock` 而非 `ConfirmResult`——前端经 `/agui/run` 当时无任何字段可送 `ConfirmResult` |

## §1 真实 interrupt 形状：RAW 事件透传，无 interrupt outcome

计划预期 `RUN_FINISHED.outcome.interrupt.interrupts[].metadata`，实际不是。真实中断以两条 `RAW` 事件透传（P0 实测抓包，2026-09-07）：

`RequireUserConfirmEvent`（RAW）：

```json
{"type":"RAW","threadId":"p0-hitl","runId":"p0-hitl-1",
 "event":{"id":"2add98587ced48dbb4fb57279737c6cc",
          "createdAt":"2026-09-07T16:23:55.191250Z",
          "replyId":"75014daaa5c74ad1b81f6320597dfbd2",
          "toolCalls":[{"type":"tool_use",
                        "id":"call_00_AQ2LWtj5kfHIyQGyr8RJ6336",
                        "name":"trade_cal",
                        "input":{"end_date":"20260930","exchange":"SSE","start_date":"20260825"},
                        "content":"{\"start_date\": \"20260825\", \"end_date\": \"20260930\", \"exchange\": \"SSE\"}",
                        "metadata":{},
                        "state":"pending"}],
          "type":"REQUIRE_USER_CONFIRM"}}
```

`RequestStopEvent`（RAW）：

```json
{"type":"RAW","threadId":"p0-hitl","runId":"p0-hitl-1",
 "event":{"id":"ad64d8cbfb334f228dbdc27f9b927331",
          "createdAt":"2026-09-07T16:23:55.191310Z",
          "reason":"permission asking",
          "generateReason":"PERMISSION_ASKING",
          "type":"REQUEST_STOP"}}
```

`RUN_FINISHED`（无 `outcome`）：

```json
{"type":"RUN_FINISHED","threadId":"p0-hitl","runId":"p0-hitl-1"}
```

**metadata 键确认结果**：计划声称的扁平键 `"agentscope.interruptKind":"permission_confirm"`、`"toolName"`、`"toolInput"`、`"replyId"` 及 `interrupts[].id` 在真实输出中一律不存在。全量 grep agentscope 2.0.1 源码：`interruptKind`、`permission_confirm` 两个字符串 **0 命中**。中断所需信息实际散落为：`replyId=75014daaa5c74ad1b81f6320597dfbd2`、`toolCallId=call_00_AQ2LWtj5kfHIyQGyr8RJ6336`、`toolName=trade_cal`、`toolInput={start_date:20260825,end_date:20260930,exchange:SSE}`。

## §2 `resume[]`（approved:true）→ 契约错误，工具未执行

按计划 shape 提交 resume（两种 interruptId 拼法——`replyId:toolCallId` 与裸 `toolCallId`——结果完全一致）：

```bash
curl -s --max-time 60 -b "$COOKIE" -X POST http://localhost:8080/agui/run \
  -H "Content-Type: application/json" \
  -d '{"threadId":"p0-hitl","runId":"p0-hitl-2","messages":[],"resume":[{"interruptId":"75014daaa5c74ad1b81f6320597dfbd2:call_00_AQ2LWtj5kfHIyQGyr8RJ6336","status":"resolved","payload":{"approved":true}}],"state":{},"tools":[]}'
```

响应：`RUN_STARTED`（`input.resume` 回显，证明 `resume` 确为 `RunAgentInput` 顶层字段——此点与计划一致）→ `RUN_ERROR`：

```json
{"type":"RUN_ERROR","threadId":"p0-hitl","runId":"p0-hitl-2",
 "message":"RunAgentInput.resume does not match any open interrupt",
 "code":"AGUI_INTERRUPT_CONTRACT_ERROR"}
```

**工具未执行**（无 `TOOL_CALL_END`、无 `TEXT_MESSAGE`）。

## §3 `resume[]`（approved:false）→ 同契约错误，Agent 未续跑

`payload.approved:false`：响应同为 `RUN_ERROR / AGUI_INTERRUPT_CONTRACT_ERROR`。Agent 未继续，无「工具被拒绝」文本。

## §4 真实续跑形状（`agentscope_confirm_results`）+ AG-UI 承载 blocker

向挂起线程发普通后续消息（不带 resume）：

```bash
curl -s --max-time 60 -b "$COOKIE" -X POST http://localhost:8080/agui/run \
  -H "Content-Type: application/json" \
  -d '{"threadId":"p0-hitl","runId":"p0-hitl-4","messages":[{"id":"m2","role":"user","content":"继续"}],"state":{},"tools":[]}'
```

响应 `RUN_ERROR`（`INVALID_INPUT_ERROR`）暴露真实续跑要求：

```json
{"message":"Agent is paused for human-in-the-loop confirmation: the following tool call(s) are in ASKING state and need your approval before the agent can continue: [trade_cal (id=call_00_AQ2LWtj5kfHIyQGyr8RJ6336)]. This call supplied no confirmation, so it cannot proceed.\nTo resume, send a follow-up message that carries a List<ConfirmResult> under the metadata key \"agentscope_confirm_results\" ..."}
```

即正确 resume 形状是：**后续消息 metadata 键 `agentscope_confirm_results`（`Msg.METADATA_CONFIRM_RESULTS`）挂 `List<ConfirmResult>`**，`ConfirmResult(boolean confirmed, ToolUseBlock toolCall, List<PermissionRule> rules)`；`confirmed=true` 执行工具，`false` 写 DENIED 结果后 Agent 继续。

但该形状 AG-UI 协议承载不了（P0 时期的四点 shape 意外，摘 P0-report §三）：

1. `resume` 字段位置：确在 `RunAgentInput` 顶层（与计划一致）；`AguiResume{interruptId,status,payload}` 结构也一致。
2. `resume[]` 语义不适用权限确认流：`AguiResumeCoordinator` 仅在 `RUN_FINISHED.outcome` 为 `RunFinishedInterruptOutcome`（`TOOL_SUSPENDED` 流）时跟踪 pending interrupt；权限确认流产出 `PERMISSION_ASKING`，无 interrupt outcome → `resume[]` 一律被 `AGUI_INTERRUPT_CONTRACT_ERROR` 拒绝。
3. 无 `agentscope.interruptKind` metadata：连 `TOOL_SUSPENDED` 流的 `buildToolCallInterrupt` 也只写 `toolName`/`toolInput`/`replyId`，从不写 `agentscope.interruptKind`。
4. 真实确认续跑形状 AG-UI 承载不了：`AguiMessage` 无 metadata 字段、`AguiMessageConverter` 丢弃 metadata、`resume[]` 只转成 `ToolResultBlock` 而非 `ConfirmResult`。前端经 `/agui/run` 当时无任何字段可送 `ConfirmResult`。

## §5 根因（agentscope 2.0.1 源码）

`io.agentscope:agentscope-*:2.0.1`（当时 `backend/build.gradle`），源码在 Gradle 缓存聚合包 `agentscope-2.0.1-sources.jar`：

- `AgentEventConverterRegistry`：内置 converter 不覆盖 `RequireUserConfirmEvent`/`RequestStopEvent` → 兜底 `RawAgentEventConverter` → `RAW` 事件。
- `AgentLifecycleEventConverter`：仅 `TOOL_SUSPENDED` 产出 interrupt outcome；`PERMISSION_ASKING` 不产。
- `AguiResumeCoordinator`：无 pending interrupt 时拒绝 `resume[]`。
- `ReActAgent`（core）：确认续跑要求 `agentscope_confirm_results` metadata。

即上游文档 [docs/technology/research/agentscope/agui.md](../../../docs/technology/research/agentscope/agui.md) §HITL Interrupts 当时描述的「`RequireUserConfirmEvent → tool_call interrupt`（含 `agentscope.interruptKind`）+ `resume[] → ConfirmResult`」在 2.0.1 版本未实现（该文档已补版本注意块）。

## §6 对 P1/P2 的影响与候选方案（P0 结论）

- 勿按当前计划推进 P1（`useInterrupt` + `resume[]` 依赖不存在的 interrupt outcome）——需回到计划/设计环节先定方案，再重排 P0/P1。
- 三条候选方案：① 改后端自定义 `AgentEventConverter`/`AguiEventEnricher` + 自定义 resume 承载（starter 已提供 `ObjectProvider<AgentEventConverter>` 注入点，`AgentscopeAguiMvcAutoConfiguration`，但 `AguiMessage` 缺 metadata 字段的缺口仍需单独解决）；② 升级 agentscope 版本；③ 自定义端点旁路。

## §7 闭环：2.0.3 升级（PR #22）→ 特性交付（PR #23）→ 修复（PR #28 / #30）

### 7.1 勘误消解：升级 AgentScope 2.0.3（PR #22，2026-09-08，merge `408f73d`）

采纳 §6 候选方案②。commit `316e835`「升级 AgentScope 2.0.3 并落地权限确认 HITL 端到端验证」：2.0.3 起权限确认契约内建实现（上游 PR #2495），本项目以 `AguiInterruptIntegrationTest` 四场景（ASK→interrupt、approved 续跑、denied 续跑、契约错误）集成测试验证全绿。§1-§4 四条勘误的消解方式（对照[设计规格 §一](../02-设计规格/设计规格说明.md)总体链路）：

| 勘误 | 2.0.3 消解 |
|---|---|
| RAW 透传、无 outcome/metadata | `RequireUserConfirmEvent` 映射为 `RUN_FINISHED.outcome.interrupts[]`：`reason:"tool_call"`、`metadata.agentscope.interruptKind:"permission_confirm"`、`toolName/toolInput/toolContent/replyId`、`id=replyId:toolCallId` |
| `resume[]` 一律契约错误 | `AguiResumeCoordinator` 跟踪权限确认 pending interrupt 并校验 `resume[]`（无 open interrupt 时仍返回 `AGUI_INTERRUPT_CONTRACT_ERROR`，契约行为保持） |
| 真实续跑需 `agentscope_confirm_results` | `resume[]` 的 payload 由 `AguiMessageConverter#toConfirmResultMsg` 转 `ConfirmResult`，前端无需手工挂 metadata |
| `AguiMessage` 无 metadata 承载不了 | 上一行同一机制绕开该缺口（`AguiMessage` 本身未加字段） |

### 7.3 修复闭环一：审批卡不渲染（issue #25 → PR #28，2026-09-11，merge `72ef619`）

首轮真机验收发现：agentscope 2.0.3 interrupt 携带 `expiresAt:null`，后端 AG-UI SSE 事件序列化原样保留 null 字段，`@ag-ui/core 0.0.59` 的 schema 拒收 null → 审批卡不渲染（FR-3 阻断，开 [issue #25](https://github.com/cwowhappy/portfolio-management/issues/25)）。修复：AG-UI 事件序列化剥离 null 字段（SSE 线上无 `expiresAt`，先以集成测试钉红再修绿），并建真实浏览器 e2e（零依赖 MCP server + env 门控 provider 种子）钉住「卡片/批准/拒绝/落盘」全链路。2026-09-09 修复分支上复跑真机验收：四项人工清单全部实测通过——含 FR-8 场景B（服务端重启后点残留卡片 → 流内契约错误 → 中文横幅）；FR-8 场景A 前提经实测结构性不成立（CopilotKit v2 每次页面加载自铸新 AG-UI threadId，旧服务端 interrupt 成孤儿，LLM 依回灌历史重发工具调用弹新卡，自愈而非缺陷）。证据与注记见[设计规格 §七](../02-设计规格/设计规格说明.md)与[交接事项.md](交接事项.md) §2。

### 7.4 修复闭环二：多卡逐张反馈（FR-5 补全，PR #30，2026-09-12，merge `999abff`）

多审批卡逐张已处理反馈：单卡点击后按钮区即时替换为「已批准/已拒绝，等待其余确认…」，其余卡仍可独立操作，全部应答后整组提交续跑（accumulate-then-submit 协议行为不变）。v2 修复 `useInterrupt` 返回元素 memo 不随宿主重渲染的问题（改卡片内部态），含 e2e 钉子。记录见[交接事项.md](交接事项.md) §3 末注。
