# MCP 工具权限审批（HITL）· 需求规格说明

> 状态：已确认需求（2026-09-08）；同日 grilling 评审定稿，补充决策 3–5 与 FR-7/FR-8。
> 前置验证：AgentScope 已升级 2.0.3，权限确认 HITL 中断契约经本项目集成测试验证（[调研报告](../../../docs/technology/research/copilotkit/agui-hitl.md) §4.4，`AguiInterruptIntegrationTest` 四场景）。
> 设计见 `../02-design/设计规格说明.md`。

## 背景与目标

MCP 接入一期（`features/mcp-integration`）落地时，AgentScope 2.0.1 尚未实现「权限确认 → AG-UI interrupt」映射（P0 验证记录），因此 `UserToolkitFactory` 将 MCP 工具强制 `readOnly=true` 绕过权限确认——所有 MCP 工具静默放行，**写操作被谎标只读，安全语义缺失**。

AgentScope 2.0.3（PR #2495）已补齐该映射，且本项目已完成升级与端到端验证（PR #22）：写工具触发权限 ASK → `RUN_FINISHED.outcome.interrupts[]` → 前端 `resume[]`（approved）→ `ConfirmResult` → 工具执行/拒绝后 Agent 续跑。

**目标**：移除 `readOnly=true` 强制放行，恢复 MCP 工具真实读写语义；用户在对话内对写工具调用逐次审批（批准/拒绝）。

## 关键决策（已确认，2026-09-08）

1. **readOnly 判定按 MCP 规范：缺省视为写**。`readOnlyHint=true` → 只读放行；缺省或 `false` → 视为写，触发权限审批。符合 MCP 规范（`readOnlyHint` 缺省按 false 处理），与上游 `McpClientManager` 判定逐字一致。安全边界取「宁多问不漏问」——当前 MCP 数据源工具大多未标 `readOnlyHint`，上线后 MCP 工具调用将全部弹审批，此为知情选择；后续靠规则沉淀/provider 信任配置治理（见非目标）。
2. **审批卡片取最小集**：展示工具名 + 入参 JSON + 说明文案，仅「批准 / 拒绝」两个动作。多 interrupt 时全部铺开、逐张批准/拒绝，由 `useInterrupt` 自动汇齐后提交。不做参数编辑（`editedArgs`）、不做「不再询问」规则沉淀。
3. **无回退开关**：readOnly 判定上线即全量生效，不留 `FORCE_READONLY` 类绕过配置（避免「静默绕过审批」后门与测试矩阵膨胀）；回滚路径 = git revert，写入 ADR。
4. **拒绝后防重试走提示词**：Agent 收到 denied 结果后可能再次发起同一工具调用（反复弹卡拉锯），不做机械防护，仅在系统提示（`HarnessAgentFactory`）加一句「工具调用被用户拒绝后不要原样重试，改走替代方案或说明无法完成」（注意：`AguiInterruptIntegrationTest` denied 场景无重试断言，该行为未被测试钉住，靠提示词收敛）。
5. **契约错误人话化**：上游 `AguiResumeCoordinator` 的两条英文契约错误（刷新后同线程发消息 / 中断丢失后 resume）在 `ThreadArea` 错误处理处翻译为中文并引导开新对话（FR-8；两条文案为 2.0.3 字节码核对的稳定字面量）。

## 用户故事

- 作为**用户**，Agent 要调用一个写性质（未标 `readOnlyHint`）的 MCP 工具时，我在对话内看到审批卡片（工具名 + 将要传入的参数），可以选择批准或拒绝；批准后工具执行、Agent 继续，拒绝后 Agent 收到拒绝结果并继续给出替代结论。
- 作为**用户**，只读工具（`readOnlyHint=true`）与内置 7 个投研工具不弹审批，体验不变。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | MCP 工具 readOnly 按规范判定：`readOnlyHint=true` → 只读放行；缺省/`false` → 写，触发权限审批 |
| FR-2 | 写工具调用触发中断：`RUN_FINISHED.outcome.interrupts[]`（`reason:"tool_call"`、`agentscope.interruptKind:"permission_confirm"`），工具在审批前不执行 |
| FR-3 | 审批卡片：消息流尾部展示工具名、入参 JSON、说明文案，提供「批准 / 拒绝」 |
| FR-4 | 审批后续跑：批准 → 工具执行 + Agent 续跑；拒绝 → 工具收到 denied 结果 + Agent 续跑 |
| FR-5 | 多工具中断**全部铺开**、逐张批准/拒绝，全部处理后续跑（`resume[]` 覆盖全部 open interrupts，`resolve` 显式传 `interruptId`） |
| FR-6 | 内置 InvestTools（`readOnly=true`）与只读 MCP 工具不受影响，不弹审批 |
| FR-7 | 系统提示约束：工具调用被用户拒绝后不原样重试，改走替代方案或说明无法完成 |
| FR-8 | 契约错误可读化：`AGUI_INTERRUPT_CONTRACT_ERROR` 的两条上游英文文案翻译为中文提示，并引导用户开启新对话 |

## 非目标（后续治理另行立项）

- `editedArgs` 参数编辑（responseSchema 已支持，暂无场景）
- `ConfirmResult.rules` 规则沉淀（「本次会话不再询问」）
- provider/endpoint 级「只读数据源」信任配置（批量放行）
- 审批卡片展示 MCP server 来源：上游 interrupt metadata 仅含 `toolName/toolInput/toolContent/replyId`（2.0.3 字节码核对），无 `mcpName` 且无注入点；随 provider 信任配置治理时一并解决
- 页面刷新后的中断恢复（当前为已知限制：刷新丢卡片后，同线程再发消息将收到契约错误——文案已按 FR-8 翻译为中文并引导新线程，恢复机制仍需后续立项）
