## 一、设计总览

### 1.1 架构落位

```
collector（Python，纯采集）                     backend（Spring Boot，分析与消费）          frontend
┌──────────────────────────┐   同库 PG    ┌────────────────────────────────────┐   ┌──────────────────┐
│ 新增 Source 插件 + YAML 任务 │ ──upsert──▶ │ domain/intelligence + application/  │   │ /intelligence    │
│  新闻（东财主/新浪备）        │  原始表     │  intelligence + web + infrastructure│◀──│  四 tab 工作台     │
│  公告（巨潮主/东财备）        │            │  ├ 定时：抽取×2/简报生成/推送/触达/清理│   │ /settings/        │
│  政策（四部委官网）          │            │  ├ Agent 工具 ×3（InvestTools/       │   │  intelligence    │
│  宏观（统计局/央行页）       │            │  │   UserInvestTools）               │   │ 订阅+飞书绑定     │
└──────────────────────────┘            │  ├ IntelligenceSubscriptionHook 实现        │   └──────────────────┘
        复用：限速/重试/熔断换源/告警        │  └ 飞书绑定表 + open_id 单发          │
                                         └──── DeepSeek（Model bean）──┘
```

- **schema 边界照既有惯例**：业务表（含 collector 写入的原始表）全部落 backend Flyway `V3__intelligence.sql`；collector Alembic（`collector/migrations/versions/0001_baseline.py`，仅 5 张运维表）不动。先例：`V1__baseline.sql` 内 `treasury_yield_curve`/`stock_valuation_daily` 即「backend 建表、collector 写入」的跨服务契约。
- **collector 保持纯采集**（需求决策 #2/#15）：新闻/公告/政策/宏观的 LLM 结构化全部在 backend 定时任务。

### 1.2 新增设计决策（本规格裁定，编号 D1~D22）

| # | 决策点 | 裁定 | 理由 / 依据 |
|---|---|---|---|
| D1 | 新闻采集调度 | **双任务同表**：`news_fast`（cron `*/10 7-23 * * *`）+ `news_night`（`0 */2 0-6 * * *`），同一对源、同一目标表，业务键幂等去重；增量按「分页拉取至首个已存 external_id 截断」（watermark 思路照 `TreasuryCurveSource`，collector/collector/sources/plugins.py:823） | 单 cron 无法变频（需求 F01「盘中盘后高频、非交易日低频」）；频次只影响延迟不影响完整性（90 天保留兜底，盘前批 07:40 前有夜间任务覆盖「昨夜」） |
| D2 | 源降级机制 | 全部双源任务用 **executor 既有 selector**（健康分 + 熔断 3 连败/600s 冷却，collector/collector/scheduler/executor/selector.py）主源优先互备，**非双采** | selector 即 failover 语义 → 跨源同一公告/新闻天然不重复，需求 F06「两源归并以法定源为准」由「主源可用时备源不采」直接满足，免归并键 |

| D7 | F02 规则预过滤 | **v1 不做内容预过滤**，仅「长度 < 8 字符跳过 + 全量过批」 | 日 300~800 条 × ~200 token ≈ 16 万 token/日（数元量级，规划 §8.2），预过滤规则维护成本高于 token 节省；信噪比交给重要度分层 |

## 三、领域模型（`domain/intelligence`，纯 POJO）

- **实体/值对象**：`NewsRecord`/`NewsExtractResult`、`AnnouncementRecord`/`AnnouncementExtractResult`、`PolicyEvent`、`MacroPoint`、`MacroCalendarEntry`、`DailyBrief`、`IntelligenceSubscription`（聚合根：pushEnabled/industries + SubscriptionStock 集，含 toggle/addStock/removeStock 行为）、`FeishuBinding`、`PushLog`。
