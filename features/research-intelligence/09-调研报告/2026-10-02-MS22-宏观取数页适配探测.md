## 1. 统计局数据发布页（CPI / PPI / PMI 同源）

### 1.1 列表页（发现层）

```bash
curl -sL 'https://www.stats.gov.cn/sj/zxfb/'
# 实测：HTTP 200，73KB，~0.7s（偶发 4.7s 慢响应，重试沿 collector 默认）。服务端渲染，列表直出。
# 条目为相对链接：./202609/t20260930_1965449.html → https://www.stats.gov.cn/sj/zxfb/202609/t20260930_1965449.html
```

- **指标识别（标题关键词 → 指标）**：`居民消费价格`→CPI、`工业生产者出厂价格`→PPI、`采购经理指数`→PMI。同一列表页混排全部统计发布（工业企业利润/70 城房价/流通领域价格旬报等），关键词过滤即得目标三篇。
- **URL 规律**：`./{YYYYMM}/t{YYYYMMDD}_{id}.html`，`t` 后日期 = 发布日（CPI 2026-08 期 = `t20260909_`；PMI 2026-09 期 = `t20260930_`，**PMI 当月末日发布、CPI/PPI 次月 9 日左右发布**——与日历种子 D22 一致）。
- **翻页**：首页 `index.html`，后续 `index_1.html`、`index_2.html`…（`createPageHTML` 静态分页，实测 `index_1.html` 200）。每页 ~20 条 ≈ 覆盖约 3~4 周发布量；cron 窗口（10-13 日）内目标文章**必在第 1 页**，翻页仅 backfill 需要。
- **期别提取**：从标题正则 `(\d{4})年(\d{1,2})月份?`（「2026年8月份居民消费价格…」→`2026-08`）；PMI 标题为「2026年9月中国采购经理指数…」（无「份」字），统一 `(\d{4})年(\d{1,2})月` 提取后补零。
- **重复坑**：同一条目在列表 HTML 中出现 3 次（不同终端适配 class：pc/移动/隐藏副本），按 href 去重。

### 1.3 详情页——PPI

实测样本：`t20260909_1965262.html`（265KB）。与 CPI 同构：2 个重复表格（52 行），表头同款 4 列。headline 行指标名带序号前缀：`一、工业生产者出厂价格`（列序 `0.4 | 3.8 | 2.0`）。**取数规则**：指标列去序号前缀（strip `一、`）或直接取**首个数据行**；列 3 = 同比 → value=3.8，yoy=null，期别 `2026-08`。表内其余为生产资料/采掘/原材料/加工/生活资料与购进价格细分（不采）。

### 1.4 详情页——PMI

实测样本：`t20260930_1965449.html`（421KB，0.75s）。**页面含 8 个 `<table>` = 4 个不同表 × 2 份打印副本**：

| 表序（取前 4 个的奇数序） | 内容 | 结构 |
|---|---|---|

- **期别注意**：PMI 表内时间序列**含最新 13 个月**（2025-09~2026-09），末行即当期——不要按「首行最新」假设。

CPI/PPI value（同比%）合理区间 `-5 ~ 105`；PMI `30 ~ 60`；区间外 warn 不拦（soft 校验，沿计划 §Task 3「按指标配 range」）。

### 4.2 「连续 2 发布期失败」的月度聚组口径（写死进 T7 常量注释）

`collector_task_run` 实测字段（Alembic 0001 baseline + executor 代码核对）：

- **成功路径**：`status='success'`（或 `'partial'`，validator 有 issues 时）**必带 `source_used=src.source_id`**（executor.py:197/208 回填）。
- **全败路径**：终行 `status='failed'`、`source_used=NULL`（AllSourcesFailed 时 record_kwargs 不含 source_used）、`error='AllSourcesFailed'`。
- 另有 `'running'`（TaskRunner 前置行，未终态）与 `'skipped'`。

**月度聚组规则建议（T7 直接采用）**：

1. 查询：task_code=`macro_afmi` 近 **65 天** runs（覆盖 ≥2 个完整发布期；JOIN `collector_task` 取 task_id，按 `started_at` 过滤、`finished_at IS NOT NULL` 只看终态）。
2. 按 `started_at` 的 Asia/Shanghai **自然月**分组，每「有 run 的月」判定：
   - **socfin 月度成功** ⇔ ∃ run `source_used='socfin' AND status IN ('success','partial')`；
   - **socfin 月度失败** ⇔ 该月有终态 run 但无上述成功（含：全部落 m2 的月 / 全 failed 的月 / 混合月）；
   - **无 run 的月不参与判定**（任务未上线/停用窗口不触发降级——发布窗口 12-16 日之外的 cron 空窗天然不产生 run，但 65 天窗口内通常每月 5 个 run，空月即异常静默，另记 log.warn 不触发切换）。
3. **触发降级留痕 + 告警一次**：最近 **2 个连续「socfin 月度失败」**的月 → `insertSourceSwitch("AFMI","socfin","m2","连续2发布期失败")` + 飞书告警——**仅当 `lastSourceSwitchAt` 为空或上次留痕后状态翻转**（告警恰一次语义，D19）。「连续」按**日历月相邻**判定：两个失败月之间隔着无 run 的空月（或成功月）即打断连续性，不视为连续 2 期。
4. **恢复回切**：最近一个「socfin 月度成功」月出现 → `insertSourceSwitch("AFMI","m2","socfin","主源恢复")`，**不告警**。
5. 边界语义：`partial`（如 xlsx 解析出数据但 validator 有警告）按成功计；`running` 未终态行跳过（巡检 08:05 早于任务 11:00 无并发风险）。
6. **与采集侧的职责边界**：selector 的自动 failover 是**期内的**（当日 socfin 失败即落 m2）；T7 判定的是**发布期级的持续劣化**（连续 2 期都要靠 m2 兜底 = 主源结构性失效）——两者不冲突，T7 留痕晚于 selector 动作属预期。
