## 一、背景与目标

阶段一（MS-00~19）交付了「数据与记录」闭环（行情/估值/筛选/持仓/配置/收益/journal/wiki/Agent 平台能力），但不回答「昨夜今晨发生了什么、跟我有什么关系」。本特性（主线一「智能情报」，M15，MS-20~23）把**财经新闻、公告与财报要点、宏观政策**三路信源变成「可查询、可推送、可复盘」的结构化情报资产：collector 扩采集，backend 定时任务做 LLM 批量结构化抽取与盘前摘要，Agent 工具与工作台页面消费。阶段一资产全部复用——collector 插件机制（限速/重试/告警/幂等落库体系）、Agent 内核（InvestTools/UserToolkitFactory/提示词/工具卡）、DeepSeek 通道、feishu-messaging 飞书推送、PG + Flyway、SchedulingConfig 定时任务（原则预警日终巡检同模式）、agent-testing eval 设施、行情台/行业中心的标的与行业映射（标签挂靠与互跳）、M13 wiki（知识类内容的归属）。按架构决策 #4，**本期弃用 RAG**：情报消费 = 结构化字段检索（pg_trgm 辅助）+ 盘前摘要推送，不做 embedding/向量检索/文档问答。

## 三、功能需求（M15-F01~F18，编号/名称/归属里程碑承规划文档，不增删改）

### A. MS-20 · 财经新闻采集与 AI 结构化（F01~F05）

**M15-F01 新闻采集任务**（东财 7×24 为主源 + 新浪/腾讯降级，collector YAML 任务、幂等落库）

- 描述：collector 新增新闻采集插件（`plugins.py` Source 子类 + YAML 任务），主源东财 7×24 快讯，降级源新浪 zhibo feed（腾讯留降级位）；原始条目（标题/摘要/时间/来源/原文链接/标的标签）增量拉取落库。
- 业务规则：全市场 7×24 采集，不因用户自选范围裁剪采集面（决策 #7）；以东财快讯唯一 id 为业务键幂等去重；复用 collector 既有任务模式的限速/重试/失败告警；任务按交易日盘中+盘后高频、非交易日低频的调度运行。
- 边界与异常：主源不可达/字段漂移自动切新浪降级并告警；双源均失败按批次告警留痕；单批次解析失败条数超阈值触发字段漂移告警；非交易日快讯稀疏照常采集。

**M15-F02 AI 结构化抽取流水线**（JSON Schema：标的/行业标签、摘要、方向、关键数字、重要度评分；抽取质量 eval 回归）

- 描述：backend 定时任务（SchedulingConfig，日终巡检同模式）对当日入库新闻走 DeepSeek 批量抽取，按 JSON Schema 输出事件类型、涉及标的与行业、摘要、方向（利好/利空/中性）、关键数字、重要度评分，结果与原始条目关联落库。
- 业务规则：当日新闻全量过批（可先用规则预过滤明显无关项省 token，设计期定）；重要度分层结果供 F04 盘前摘要与 F15 工作台过滤消费；抽取质量 eval 回归集随本流水线建立（复用 agent-testing 设施），提示词/模型变更须过回归（NFR-2）。
- 边界与异常：抽取失败条目（超时/JSON 不合法/Schema 不符）入重试队列，重试仍败标记失败并告警，不阻塞批次其余条目；日 input 超百万 token 成本护栏阈值时告警（规划 §8.2 日成本数元量级）。

**M15-F03 新闻检索 Agent 工具（`search_news`）**（纳入提示词与工具卡）

- 描述：新增内置只读工具 `search_news`，按关键词/标的/行业/时间范围/重要度检索结构化新闻，纳入 InvestSystemPrompt 与前端工具卡。
- 业务规则：`readOnlyHint=true` 不触发 HITL；检索以结构化字段过滤为主、pg_trgm 辅助全文匹配；结果按重要度/时间倒序，返回摘要+方向+关键数字+原文链接。
- 边界与异常：无结果返回空列表与友好话术，不报错；标的/行业标签挂靠既有证券主数据映射，未映射标签原样返回并留痕；90 天外新闻因清理策略检索不到（决策 #9）。

**M15-F04 每日盘前情报摘要**（LLM 汇总昨夜今晨 → 飞书推送，DeepSeek 通道）

- 描述：backend 定时任务交易日 8:30 前对昨夜今晨重要情报（重要度分层后 top 条目）生成飞书单条长文推送，分主题小节，并归档落库供 F18 查询。
- 业务规则：仅交易日推送（决策 #8），非交易日不生成不发送，交易日判定复用 A 股交易日历设施（设计期确认）；推送通道复用 feishu-messaging 飞书客户端；推送范围尊重 F16 订阅设置（开关 + 关注标的/行业定向）。
- 边界与异常：当日无达阈值情报时发简版说明（决策 #22：一句话 + 数据截止期别，不跳过）；LLM 生成失败重试一次，仍败告警且不补发陈旧摘要；飞书发送失败沿既有重试/告警。

**M15-F05 情报存储模型**（Flyway 新表：原始条目 + 结构化结果，DDD 新域 `domain/intelligence`）

- 描述：Flyway 新增情报域迁移（原始条目表、结构化结果表，预留公告/政策/简报/订阅表随 MS-21~23 落地），backend 新建 DDD 域承载（域名定稿 `intelligence`，决策 #28），ArchUnit `PackageConventionsTest` domain 层级通配自动覆盖（同步 DDD 分包规范子包清单）；`pg_trgm` 随迁移启用。
- 业务规则：领域模型纯 POJO 零 Spring/JPA 注解，JPA 实体落 infrastructure/persistence；schema 全部走 Flyway（ddl-auto: none）；订阅等用户级数据按用户隔离存储。
- 边界与异常：迁移幂等可重放（Flyway 既有机制）；90 天滚动清理以定时清理任务实现，清理不破坏简报等长期表（简报自含摘要快照，无跨表引用悬空）。

### B. MS-21 · 公告与财报要点采集（F06~F10）

**M15-F06 公告采集**（巨潮 hisAnnouncement 为主源 + 东财公告流降级；公告列表 + 定期报告元数据落库）

- 描述：collector 新增公告采集插件，双源互备：巨潮（法定披露主源，POST，返回元数据/PDF URL/文件大小/分类）+ 东财公告流（art_code/股票映射/栏目分类/披露时间）；公告列表与定期报告元数据落库。
- 业务规则：覆盖 = 自选/持仓池标的公告全量 + 全市场仅重大类型（决策 #10，类型判定依赖 F08 标签）；以公告唯一编码（巨潮 announcementId / 东财 art_code）为业务键幂等去重；PDF 原文不留存，仅存元数据 + 抽取后文本 + PDF URL（决策 #16）；双源字段映射对齐（标的/标题/披露时间/类型/URL）。
- 边界与异常：巨潮不可达切东财公告流并告警，双源失败按批次告警；PDF 下载失败（URL 过期/网络）标记文本缺失，不阻塞批次；两源同一公告去重归并（以法定源为准，设计期定归并键）。

**M15-F07 业绩类公告要点抽取**（营收/归母净利/同比/分红方案等关键数字结构化）

- 描述：backend 定时任务对业绩类公告（业绩预告/快报/正式财报）拉取 PDF、提取文本、走 DeepSeek 要点抽取（collector 保持纯采集，PDF 处理全在 backend 分析管道，PDF 字节不落盘）；抽取字段六项起步：营业收入、归母净利润、同比增速、扣非净利润、毛利率、分红方案（决策 #11）。
- 业务规则：关键数字带口径标注（亿元/%/每股），同比口径 = 相对上年同期；字段纳入 eval 回归集，与原文抽验一致率过门槛（承 MS-21 验收）；非业绩类公告不进本流水线。
- 边界与异常：公告未披露某字段 → 置空并标注「未披露」，严禁模型编造；PDF 解析失败/加密 → 标记失败、告警、可重试；PDF 临时文件即取即删（决策 #16）。

**M15-F08 公告分类标签**（增减持/回购/定增/关联交易/业绩预告等重大事件类型）

- 描述：LLM 对公告打受控枚举的重大事件类型标签，v1 十类 + 其他（决策 #24：增持/减持/回购/定增配股/关联交易/业绩预告/业绩快报/定期报告/股权激励/退市风险警示）。
- 业务规则：全市场重大类型过滤依赖本标签（决策 #10）；不入枚举的类型归「其他」；一条公告可多标签（决策 #24）；类型分类准确率纳入 eval 回归（MS-21 验收：抽检达标）；东财/巨潮自带栏目分类与 LLM 标签的取舍以设计定稿为准（自带分类优先、LLM 补充修正为默认建议）。
- 边界与异常：一条公告允许多标签（如预案 + 关联交易）；LLM 分类置信度低的条目降级使用源站栏目并标注。

**M15-F09 公告检索 Agent 工具 + 定向订阅**（按标的/持仓过滤）

- 描述：新增只读工具 `search_announcements`，按标的/类型/时间/关键词检索公告及其要点字段；定向订阅 = 用户按标的/持仓圈定关注范围，与 F16 订阅设置同一数据面。
- 业务规则：`readOnlyHint=true`；检索返回元数据 + 要点字段 + PDF/原文链接；订阅数据按用户隔离；持仓池联动取 portfolio 域数据（跨域依赖随新域白名单登记）。
- 边界与异常：无结果空列表；标的无公告时返回空态说明（区别于检索失败）；未设置订阅则工具检索不受限、主动触达（F10）不生效。

**M15-F10 新公告主动触达**（订阅范围内重大公告飞书提醒）

- 描述：订阅范围内重大类型公告（F08 标签）在采集 + 要点抽取完成后触发飞书提醒。
- 业务规则：推送条件 = 标的 ∈ 用户订阅范围 ∧ 类型 ∈ 重大类型 ∧ 推送开关开（F16）；同一公告多标的命中合并为一条推送；推送内容 = 标题/类型/要点摘要/链接；触发时点（抽取完成后发 or 先发元数据提醒）设计期定。
- 边界与异常：推送失败沿 feishu-messaging 重试/告警；抽取失败公告不发要点版，可选发元数据简版（设计期定）；尊重用户推送开关，关闭即静默。

### C. MS-22 · 宏观政策库（F11~F14）

**M15-F11 宏观指标序列采集**（CPI/PPI/PMI/社融/M2/LPR 等；国债收益率复用 `treasury_yield_curve`）

- 描述：collector 新增宏观指标任务，首批五指标：CPI/PPI/PMI/LPR/社融（社融源不稳则降 M2，决策 #12）；国债收益率已有 `treasury_yield_curve` 任务直接复用，不重复建。
- 业务规则：按「指标 + 期别（月/日）」为业务键幂等落库；每条带来源页与口径标注；央行/统计局具体数据页在 MS-22 启动前完成按源适配探测（质量门槛⑤），页面结构变化走告警 + 人工适配。
- 边界与异常：发布延迟/未更新不视为失败（按日历预期管理，F14）；页面结构漂移致解析失败 → 告警；社融「不稳」判定与降级留痕按决策 #25（连续 2 发布期无有效数据或单期重试 3 次全败 → 切 M2 + `source_switch` 留痕 + 告警一次，人工判定后手动切回）。

**M15-F12 政策事件库**（央行/财政部/证监会政策发布结构化：方向/力度/影响领域/原文链接）

- 描述：采集四部委官网政策发布（collector 侧源插件 + backend 侧 LLM 结构化），结构化字段：政策方向/力度/影响领域/原文链接/发布时间，落政策事件库。
- 业务规则：来源仅中央部委官网（央行/证监会/财政部/统计局），排除行业/地方政策与媒体转述（决策 #13）；政策事件长期保留（决策 #9）；每条可回溯原文链接。
- 边界与异常：官网结构漂移 → 采集告警 + 人工适配；非政策类官网动态（领导活动/转载）由规则 + LLM 过滤，误收录须标注为低置信。

**M15-F13 宏观简报 Agent 工具（`macro_brief`）**（指标现状 + 近期政策 + 市场含义）

- 描述：新增只读工具 `macro_brief`：汇总首批五指标现状（最新值 + 近 N 期走势）+ 近期政策事件（F12）+ 市场含义解读。
- 业务规则：指标与政策事实必须来自本库结构化数据（MS-22 验收：问答有真实数据支撑），仅「市场含义」层可调 LLM；口径与来源随结果返回（NFR 口径诚实）。
- 边界与异常：指标缺失（未发布/采集失败）显式说明缺失项，不编造；政策事件为空时仅答指标现状；工具结果标注数据截止期别。

**M15-F14 宏观日历**（指标发布日程 + 发布日提醒）

- 描述：内置静态发布日程表（指标 → 频率/预计发布日/来源官网）+ 发布日飞书/页面提醒。
- 业务规则：静态表 + 人工定期维护（决策 #14/#29：种子数据 + SQL 维护，无管理 UI，同 M10 策展先例；`/intelligence` 政策库区块显示日程最近维护时间）；提醒消费 F16 推送开关；日历为预期非承诺，实际发布以 F11 采集落库为准。
- 边界与异常：日程过期未维护 → 提醒缺失可接受，页面标注最近维护时间；提醒发送失败沿飞书既有告警。

### D. MS-23 · 情报工作台（F15~F18）

**M15-F15 情报工作台页面**（`/intelligence`：新闻流 / 公告流 / 政策库 / 简报归档）

- 描述：前端新增 `/intelligence` 页面（路由随域名定稿，决策 #28），四区块（新闻流/公告流/政策库/简报归档）同页统一检索过滤：关键词、标的、行业、时间范围、重要度、公告类型。
- 业务规则：登录态访问（沿用现状会话隔离）；过滤以结构化字段为主、pg_trgm 辅助；列表服务端分页 + 服务端过滤（年 15~25 万行不做全量拉取）；重要度过滤与标的方向抽检合理（MS-23 验收）。
- 边界与异常：空态（区块无数据/检索无结果）显式空态文案；四区块可独立过滤也可统一关键词（交互细节设计期定）。

**M15-F16 情报订阅设置**（推送开关、关注标的/行业定向、飞书绑定）

- 描述：订阅管理界面（设置页或 `/intelligence` 内入口）：推送总开关、关注标的/行业定向（联动持仓与行情台标的）、飞书绑定入口（决策 #18：设置页生成一次性绑定码，用户在飞书对机器人发码完成绑定）。
- 业务规则：订阅数据按用户隔离；总开关默认开（决策 #27），关闭 → F04 盘前摘要与 F10 公告提醒均不发；未设置订阅 → 默认推送全市场盘前摘要（重要度过滤后），不推定向公告提醒；摘要时段固定交易日 8:30，不做配置（决策 #8/#27）；未绑定飞书的用户 F04 走配置群统一版，定向公告提醒需绑定才实际生效（决策 #18/#27）。
- 边界与异常：设置保存失败正常报错回滚（沿用现状表单设施）；标的从持仓移除后订阅联动策略设计期定（默认保留、页面提示）；绑定码一次性失效（过期/已用即拒绝，防冒领）。

**M15-F17 标的情报聚合**（个股/行业维度聚合三路情报，与行情台/行业中心互跳）

- 描述：个股/行业维度聚合三路情报（新闻/公告/政策），入口在工作台、行情台、行业中心，三处互跳。
- 业务规则：标的维度 = 结构化结果标的标签命中；行业维度 = 标的标签映射申万行业（复用 M10 既有映射）；互跳：情报页跳行情台 `/stock` 与行业中心 `/industry/[industryCode]`，反向在行情台/行业中心挂情报入口。
- 边界与异常：无情报标的显示空态 + 引导跳转既有页面；政策类情报无标的标签，行业聚合可只含新闻/公告（页面说明口径）。

**M15-F18 简报归档查询**（历史盘前摘要检索）

- 描述：历史盘前摘要归档按日期浏览 + 检索。
- 业务规则：简报长期保留，不受新闻 90 天清理影响（决策 #9，简报表独立）；归档含生成时间/主题小节/涉及标的清单（top 标的落库快照，决策 #23）；检索维度 = 日期浏览 + 涉及标的过滤 + pg_trgm 全文关键词（决策 #23）；生成失败的交易日留档标注（无内容 + 失败原因）。
- 边界与异常：归档缺失日期显式标注原因；检索无结果空态。

## 四、非功能需求

1. **幂等落库与数据一致性**：所有采集条目以业务键幂等（新闻 id / 公告编码 / 指标期别），重复采集、失败重试、任务重跑不产生重复行；抽取结果与原始条目外键关联；90 天滚动清理不破坏长期表引用完整性（简报/公告/政策自含快照，无悬空引用）；多源归并以法定源为准。
2. **LLM 抽取质量 eval 回归**：复用 agent-testing 设施建立抽取质量回归集（新闻标的/行业标签、业绩关键数字、公告类型分类），纳入既有 eval 运行方式；提示词/模型/参数变更须过回归方可合并；指标口径与 MS-20/21 验收抽检一致（标签准确率 ≥90% 量级、业绩数字与原文一致、分类准确率达标）。
3. **性能与量级**：交易日 300~800 新闻、年 15~25 万行 PG 单机入库可接受；盘前摘要批处理须在 8:30 前完成；工作台列表服务端分页，单页响应沿用现状前端列表性能基线；LLM 日 input 百万 token 量级内设成本护栏告警。
4. **安全**：全部情报 API 登录态访问，会话与用户数据隔离沿用现状（非本人订阅/设置不可见）；飞书推送按用户订阅隔离；采集与 LLM 调用不引入终端用户凭证；无 CORS/CSRF 现状不变（同源 Cookie 前提不破）。
5. **可观测**：采集失败/字段漂移走 collector 既有飞书告警；抽取失败重试 + 失败计数告警；盘前摘要生成/推送结果留痕（成功/失败/跳过原因）；LLM token 成本监控。
6. **覆盖率与测试**：后端 JaCoCo / 前端 V8 / collector pytest ≥80%，`make test` 通过；新域 Testcontainers 集成测试（照 PostgresTestSupport 先例）；Playwright e2e 新增 `/intelligence` 用例（空态/有数据双态断言照 industry.spec 先例）。
7. **DDD 与 schema**：新域遵循 DDD 分包规范并在 `PackageConventionsTest` 登记依赖白名单；schema 变更走 Flyway；`pg_trgm` 随迁移启用（zhparser 不装）。

## 五、验收标准（与规划文档各里程碑验收对齐）

- **MS-20**：连续 5 个交易日采集落库正常；抽取结果抽验（标的/行业标签准确率人工抽检 ≥90% 量级）；`make test` 三端全绿 + smoke/e2e 过；部署机 smoke 含网络探测段（决策 #17）。
- **MS-21**：业绩公告关键数字与原文抽验一致；公告类型分类准确率抽检达标；PDF 全文问答明确不在本里程碑（RAG 增强期）。
- **MS-22**：指标序列与官方发布值抽验一致；政策事件带来源链接；宏观简报工具问答有真实数据支撑。
- **MS-23**：三路情报同页检索过滤可用；订阅推送端到端（设置 → 定时产出 → 飞书/页面触达）；重要度过滤与标的方向抽检合理；M16-F11 回接收口（决策 #26：union 查询 + journal 留痕 + 项目级开关）。

## 六、YAGNI 排除清单（逐条给排除理由）

- **RAG / embedding / 向量检索**——决策 #3（#4 行）：embedding 选型部署、chunking、中文检索调优成本高，与工程纪律摩擦大；归「RAG 增强批次」另行立项。
- **文档全文问答 / PDF 年报全文分析**——决策 #3 + MS-23 预留明确不做：全文问答依赖 RAG；本期 PDF 仅元数据 + 文本要点。
- **行业/地方政策**——决策 #13：来源质量不可控、范围易蔓延；本期仅中央部委官网。
- **舆情情感指数**——规划 MS-23 预留项明确不做：情感标注噪声大、无既定决策消费场景；本期仅有方向（利好/利空/中性）。
- **新闻评论/互动**——无稳定公开接口、信噪比低、无决策消费场景。
- **全市场公告全量采集**——决策 #10：量级差约 10 倍，自选/持仓全量 + 全市场重大类型已覆盖决策相关面。
- **腾讯新闻源参数修复**——决策 #4 行：参数待修、降级位非必须，东财 + 新浪已够用（资源清单 #5）。
- **财联社官方 API 接入**——决策 #6 行：无官方 API（Web 端 sign 机制），增强源非必须，列 MS-20 探测专项评估。
