# 智能情报实施计划 P2 · MS-21：公告与财报要点采集

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 交付 M15-F06~F10——公告双源采集（巨潮主源 + 东财降级，全量=自选/持仓池标的 + 全市场重大类型栏目过滤）、业绩类公告 PDF 要点抽取（六字段 + 未披露标注，pdfbox 内存解析）、LLM 公告类型标签（十类受控枚举）、`search_announcements` 工具（含订阅/持仓 scope）、公告定向推送服务与订阅数据面最小版。

**Architecture:** collector 公告双源经 selector failover 落 `intelligence_announcement`（栏目映射预判 major）；backend `AnnouncementExtractionService`（22:40/06:40 双批，晚间披露高峰后即时触达）下载 PDF → `AnnouncementPdfTextPort`（pdfbox）→ `IntelligenceChatPort` 一次调用同时产出 metrics + ann_types；`AnnouncementPushService` 订阅 union = F16 订阅表 ∪ `IntelligenceSubscriptionHook`（POSITION 项目持仓）。**范围裁定：F16 的数据面（订阅表 + SubscriptionService REST，无 UI）与 hook JPA 实现随本册交付**——F10 推送逻辑的依赖项；F16 设置界面、飞书绑定、open_id 单发端到端仍在 P4（MS-23 验收「订阅推送端到端」）；本册推送在有绑定者出现前空转安全（空集短路）。

**Tech Stack:** 同 P1 + `org.apache.pdfbox:pdfbox`（3.x，**新增生产依赖**——D18）。

**Spec:** [需求规格说明 v1.0](../01-需求规格/需求规格说明.md) F06~F10 + 决策 #24（十类枚举）；[设计规格说明 v1.0](../02-设计规格/设计规格说明.md) D2/D3/D11/D12/D18/§4.4 metrics 契约。

## Global Constraints

（承 P1 全部——命名 intelligence 全名 / Flyway-only / ArchUnit / 覆盖率 ≥80% / 四层测试 / 定向测试命令 / collector 八处改动面 / DeepSeek 经 IntelligenceChatPort / commit 规范。追加：）

- **PDF 不落盘**（决策 #16）：`byte[]` 全内存解析；下载/解析失败标 FAILED 可重试，**PDF 字节禁止写任何临时文件**。
- **业绩字段契约**（设计 §4.4）：`{"revenueYi","netProfitYi","netProfitYoyPct","deductedProfitYi","grossMarginPct","dividendDesc","undisclosed":[…]}`——未披露字段进 `undisclosed` 数组，**严禁编造数值**（提示词硬约束 + 解析侧 null 容忍）。
- **AnnouncementType 十类固定**（决策 #24）：INCREASE_HOLD/DECREASE_HOLD/BUYBACK/PLACEMENT/RELATED_TRANSACTION/EARNINGS_FORECAST/EARNINGS_FLASH/PERIODIC_REPORT/EQUITY_INCENTIVE/DELISTING_RISK/OTHER；源站栏目映射优先、LLM 补充修正（需求 F08 默认建议）。

## Review Focus

- 巨潮不可达 → 自动切东财公告流并告警（selector）；双源均败按批次告警留痕。
- 业绩公告未披露某字段（如无分红方案）→ metrics 该键缺省 + `undisclosed` 含字段名，**绝不出现编造数字**。
- PDF URL 过期/加密/扫描件无文本层 → 该公告标 FAILED（fail_reason 记录原因）可重试，不阻塞批次。
- 同一公告多标的命中（如增减持双方）→ 推送合并为一条（按 external_id 聚合）。
- 用户无订阅且无 POSITION 项目 → 推送空转零调用，抽取批不受影响。
