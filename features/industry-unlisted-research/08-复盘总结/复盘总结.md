## 二、经验（做对了什么）

1. **裁决先行，三批计划与真实代码互证**：数据源替代裁决（方案 A）→ grilling 8 决策 → 设计规格 file:line 锚定 → P1/P2/P3 任务级计划。执行中「计划假设对不上代码以代码为准 + 计划追加偏差注记」双向跑通（本批 7 处偏差注记全部当日回写）。
2. **成员派生关联是本批最优设计决策**：链-行业不建关联表，一条 EXISTS join 派生——种子链在 801730/801050/801880/801150 多个下钻页自动出现，编辑链即刻生效，零一致性维护。种子设计也反向验证了该口径（上市成员行业归属决定链出现在哪些页）。
3. **全文档替换收窄 CRUD 面**：链仅 2~3 条量级，stages+members 嵌套整体替换（删旧再插）而非逐实体 CRUD——单事务 + ON DELETE CASCADE 保证原子性，服务层/前端编辑器两侧状态模型都简化成「一份文档」。
4. **P2 评审五项收口全部落进 P3 批次**：口径定案回写设计规格（coverageNote 两处透出）、镜像锁定测试（fundingRounds 全量 toEqual + 顺序）、e2e 断言解耦（策展头部数改为接口对拍）、cleanup 脚本残留行（E2E策展%/E2E链%，护栏测试 --rerun 复核）、BDD 卫生行（601997 占位映射清理）——评审发现即入列即闭环。
5. **JdbcTemplate/JPA 混合落位有据**：链读侧（派生 join + 两步批查组装）照 `IndustryRepositoryImpl` 用 JdbcTemplate，层级插入用 stage/member 两 JPA 仓储（IDENTITY 即时 INSERT 使 CHECK 违例事务内抛出）——各取所长的同时拒绝了「为计划而建死代码」（未建无仓储的 chain JpaEntity）。

## 三、不足

1. **种子上市成员依赖 dev 库既有映射**：V20 种子的链-行业派生依赖 `shenwan_industry_mapping`（collector 数据面）——CI/空库环境种子链不派生（e2e 靠 boardHasData 门控跳过）；集成测试须自种映射行。两库数据面分叉与 MS-13/14 不足同象。
2. **链编辑器未上市成员下拉只列当前行业策展企业**：跨行业挂成员（如锂电池链挂电子行业策展企业）无 UI 路径（后端支持任意 unlistedCompanyId）——窄入口防误挂，真有跨链需求再扩。
3. **e2e 建链用例第二成员只能用 LISTED**（801730 无 V19 策展企业，下拉空）——未上市成员的端到端建链链路由 vitest 组件测试覆盖，真浏览器路径留白。
4. **`make smoke` 首跑 §1 红是操作时序**（e2e 收尾后端已关、smoke 需前后端在跑）——非产品问题但说明 smoke 前置假设未写进脚本自检（失败信息已足够定位）。
5. **P2 期注释失实（fundingRounds 镜像「由组件测试锁定」不实）**——评审抓出后补锁定测试；暴露「注释声称的保障」若无对应测试文件引用即不可信，应机械可查。

## 四、优化建议

1. **e2e-cleanup 脚本行与护栏测试联动**：护栏只校验 app_user FK 覆盖，前缀清理行（E2E策展%/E2E链%）无机械护栏——新增类似前缀时须人工记得加行，可把「e2e 新建数据的命名前缀清单」收进 features 测试规约文档。
2. **链编辑器成员下拉支持跨行业搜索**（后端已支持）：按 unlistedCompanyId 全局查（fetchUnlistedCompanies 逐行业或加 q 参数），现窄入口在真实跨行业链（如锂电+有色）会别扭。
3. **空库 CI 的链图谱覆盖缺口**：可在 CI e2e 前插入最小 shenwan 映射种子（仅 300750→801730 一行）使 V20 种子链在 CI 也可断言——投入一行种子换数据态用例去门控。
4. **smoke.sh §1 前自检提示**：健康检查失败时输出「需先 make dev」提示语，减少误判为产品回归。
