# 投资 SOP 实施计划 P4 · MS-27：复盘闭环

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付 M16-F13~F16——复盘 CRUD（三档模板，字段集 JSONB 待 MS-24 收敛）、自动数据带入（analytics + 行情快照定格 + 口径标注 + 用户覆盖）、归因圈选（批次时间窗自动 + 手动修正）、证伪评审（结论枚举 + hit 回填 + journal 留痕）、wiki 回流（用户确认 + SOP_REVIEW 标记）与模板改进建议收集；e2e 主链路全通（D14：不含 F11）。

**Architecture:** 快照**写入时定格**（不复算历史）：`ReviewSnapshotComposer` 在创建复盘时经 application 层消费 analytics（nav/tradeStats）与 market 行情，产出带口径标注的 JSONB；归因圈选按 entry batch 时间窗自动圈 trade 软引用 + 手动修正；回流经 `application/wiki` 创建 `RESEARCH_NOTE`（category=SOP_REVIEW）。

**Tech Stack:** Java 21 / Jackson 2（JSONB 序列化）/ Next.js 15 表单 + zod / Cucumber BDD + Playwright。

**Spec:** [需求规格说明 v1.0](../01-需求规格/需求规格说明.md) F13~F16 + D7/D11/D14/D15；[设计规格说明](../02-设计规格/设计规格说明.md) §4.3（ReviewSnapshotComposer）、§4.1（reviews/reflux/feedback 端点）。

## Global Constraints

- ArchUnit 测试规范同 P2/P3；覆盖率 ≥80%；跨域消费仅 application 层。
- 回流**用户确认后入库**（F16）：不自动回流；回流失败（wiki 写异常）不阻断复盘保存（try-catch 降级 + reflux_state 回 PENDING）。
- 自动值为草稿、用户可覆盖（F14）：overrides 与 auto_snapshot 分开存，展示层并列。
- 无数据标注「无数据」不留白；区间起止与价格口径必须写入快照字段（验收口径：自动计算与手算一致）。
- 复盘三档字段集为 MS-24 内容依赖（§八-1）：answers JSONB 弹性承载，前端表单 schema 由常量表驱动，字段集变更不改后端。
- 定向测试：`./gradlew test --tests '*Review*'`；BDD `./gradlew bdd --tests '*Research*'`。
- commit scope：`feat(research): …` / `feat(ui): …` / `test(e2e): …`。

## Review Focus

- 期间无交易/无持仓 → 快照对应字段为 `"无数据"` 字符串标注，不是 null/0（手算一致性验收的易错点）。
- 同标的多项目 → 自动圈选只圈本项目 entry batch 时间窗内的 trade，窗外交易不并入（D11 边界）。
- REVISE 处置后策略仍为 FINALIZED → 评审提交时若 conclusion=REVISE，须同步提示前端调 revise（不自动改策略——落库与策略修订分离，避免隐式派生）。
- reflux 二次点击 → 幂等（REFLOWN 态直接返回既有 wiki_entry_id，不重复建条目）。
- 归因手动修正后 trade_ids 重复/乱序 → 去重排序后落库。
