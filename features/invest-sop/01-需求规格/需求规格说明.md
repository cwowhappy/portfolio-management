## 一、背景与目标

阶段一交付了「数据与记录」闭环（行情/估值/筛选/持仓/配置/收益分析 + journal/知识库 + Agent 平台能力），阶段二本特性把「新分析 → 制定投资策略 → 建仓与持仓 → 复盘」四阶段流程化：**新分析**（发现标的、立项研究）→ **制定投资策略**（结构化策略文档：投资逻辑/估值区间/仓位计划/买入条件/风险与证伪条件）→ **建仓与持仓**（建仓计划 + 买入纪律检查 + 持仓监控）→ **复盘**（模板化复盘 + 证伪评审 + 知识回流）。实现方式 = 架构决策 #2 的双层结构：数据层新建 `domain/research` 结构化研究项目域承载四阶段状态机与产物，引导层四个内置 SOP SKILL.md 由 Agent 按阶段引导收集要素并做纪律检查，知识层 SOP v1 最佳实践沉淀为 M13 wiki 模板；阶段一资产全面复用——MS-17 Skill 系统承载四 Skill 按用户启停、M13 wiki 承接模板 seeding 与复盘结论回流、M13 PrincipleRule 供建仓/买卖纪律检查消费、journal 承接备忘与时间线联动、analytics 复盘数据自动带入（买卖点 vs 后续走势）、M15 智能情报（阶段二主线一交付）提供持仓标的公告/新闻监控。一句话：**让投资决策从「随手记」变成「有流程、有纪律、可复盘」的系统内建作业方式**。

## 二、澄清决策汇总

| 编号 | 决策点 | 结论 | 理由 |
|:---:|--------|------|------|
| 1 | **架构决策 #2：SOP 形态** | 结构化研究项目 + 内置 SOP Skill 双层：数据层新建 `domain/research`（ResearchProject 四阶段状态机 + 策略文档 + 复盘记录，Flyway 迁移，ArchUnit 白名单登记）；引导层 = 四个内置 SKILL.md（新分析/制定策略/建仓持仓/复盘，复用 MS-17 Skill 系统按用户启停，Agent 引导收集要素 + 纪律检查）；知识层 = SOP v1 沉淀为 M13 wiki 模板（幂等 seeding） | 备选 A「只做 wiki 静态文档」被动、无流程沉淀；备选 D「全 Agent 黑盒自主流程」不可控、不可测试。双层各取所长：结构可测、引导灵活 |
| 2 | **架构决策 #4（2026-09-28 用户裁决）：SOP 知识组织** | 弃用 RAG。SOP 知识以 M13 wiki 方式组织与查询，不做 embedding/向量检索 | embedding 选型部署、chunking、中文检索调优成本高，与「覆盖率 ≥80% + DDD 可测」工程纪律摩擦大；wiki 模板化组织已满足 SOP v1 查询需求 |
| 3 | **澄清 #9：投资风格** | SOP v1 纯价值投资主线；趋势/技术面检查项归 v2 | 与阶段一估值/筛选/持仓数据面同源一致，聚焦可落地；趋势信号与现有结构化数据面不匹配，需另建指标体系 |
| 4 | **澄清 #10：四阶段流转** | 灵活推进 + 各阶段完成度记录，不硬锁线性状态机 | 真实研究在阶段间往返迭代（复盘常触发重新分析），硬锁线性状态机会大幅降低使用率；完成度记录已够支撑进度可见 |
| 5 | **澄清 #11：纪律检查严格度** | 软提醒：与 PrincipleRule 冲突时显式提示 + 留痕，不阻断录入 | 规则阈值主观且 v1 未经实盘校验，硬拦截可能误伤正常操作；软提醒 + 留痕先积累口径，严格度可后调 |
| 6 | **澄清 #12：策略文档形态** | 结构化五字段（投资逻辑/估值区间/仓位计划/买入条件/风险与证伪条件）；估值区间手动填写；简化估值自动计算模型归 v2 | 结构化字段才可被纪律检查与复盘消费；估值模型变量多、口径主观，先沉淀手动数据再议自动化 |
| 7 | **澄清 #13：复盘默认周期** | 月主模板 + 季深度模板（附周简版） | 月粒度匹配 A 股持仓复盘节奏（业绩/公告月度密度），季粒度适合深度归因，周粒度过密以简版兜底 |
| 8 | **附：四阶段定义** | 新分析 → 制定投资策略 → 建仓与持仓 → 复盘 | 阶段二规划主线二既定流程，本特性全部功能点归属以此为纲 |

## 三、最佳实践来源（SOP v1 收集范围）

- **经典框架**：格雷厄姆/巴菲特/芒格（能力圈、安全边际、护城河）；多尔西《股市真规则》分析 checklist；霍华德·马克斯（周期、第二层思维）；费雪《怎样选择成长股》；彼得·林奇六种公司分类。
- **国内实践**：段永平（商业模式优先、Stop Doing List）；唐朝估值三段式；张磊《价值》；李录。
- **交易纪律**：仓位管理（凯利简化、单票/行业上限）；买入前检查单；证伪/退出条件。
- **复盘方法论**：回顾目标 → 评估结果 → 分析原因 → 总结经验（邱昭良《复盘+》及企业实践）。

收集与定稿方式（承规划文档 MS-24 风险条款）：内容为强主观性工作，**v1 必须用户参与评审**——每阶段「必须有 / 可选项」清单逐条确认后方可定稿，作为 F02/F03 的唯一内容源。

## 四、功能需求（M16-F01~F16，按里程碑四组组织）

### A. MS-24 · SOP 最佳实践沉淀与 Skill 化

#### M16-F01 SOP 四阶段最佳实践 v1 定稿

- **描述**：内容研究工作——按 §三 范围收集整理四阶段最佳实践，产出每阶段「必须有 / 可选项」checklist、模板要点与纪律检查项初稿；v1 以价值投资为主线（决策 #3）。
- **业务规则**：每阶段「必须有 / 可选项」清单逐条经用户评审确认后定稿（MS-24 验收门槛）；定稿产物是 F02（Skill 内容）与 F03（wiki 模板内容）的唯一内容源；趋势/技术面检查项明确不归入 v1。
- **边界与异常**：纯内容产出，无代码交付；内容定稿阻塞 F02/F03 开工，是 MS-24 关键路径。

#### M16-F02 四个内置 SOP SKILL.md

- **描述**：新分析 / 制定策略 / 建仓持仓 / 复盘 四个 SKILL.md 落 `backend/src/main/resources/skills/`，复用 MS-17 Skill 系统按用户启停；Agent 按阶段引导用户收集要素（对话式逐要素收集）+ 纪律检查（消费 PrincipleRule，软提醒）。
- **业务规则**：目录随应用发布（DB 不存目录，只存用户启用集），front-matter `default_enabled` 建议 `false`（用户显式启用）；未启用不进入 Agent 上下文（`HarnessAgentFactory` 装配先例）；Skill 产出结构化草稿，引导不强制线性流程（决策 #4）。
- **边界与异常**：Skill 只引导与生成草稿，**不直接写库**——落库走 `/research` 应用服务 API（可控、可测）；Skill 停用不删除既有项目数据。

#### M16-F03 SOP wiki 模板 seeding

- **描述**：SOP v1 定稿内容（四阶段模板/检查单）入 M13 知识库，幂等 seeding（照 F03 概念速查 `wiki_seed_state` 先例）。
- **业务规则**：幂等——每用户只 seed 一次，删光不复活；用户可增删改（同既有 wiki 权限）；具体落 `wiki_entry` 类型扩展或复用既有类型由设计规格定。
- **边界与异常**：seeding 失败不阻断主流程（下回访问重试）；发布升级不覆盖用户已修改的条目（用户版本优先）。

### B. MS-25 · 研究项目域

#### M16-F04 研究项目域（domain/research）

- **描述**：新建 `domain/research` 域——ResearchProject 四阶段状态机（新分析/制定投资策略/建仓与持仓/复盘 枚举）+ 策略文档 + 复盘记录 + 阶段产物；Flyway 新表；ArchUnit `PackageConventionsTest` 白名单登记。
- **业务规则**：灵活推进——阶段可任意顺序进入/回退，系统记录各阶段完成度而非锁流转（决策 #4）；项目归属 userId，非本人访问 404（照会话/journal 隔离先例）；领域纯 POJO，依赖方向遵守 DDD 规范（§五 NFR-4）。
- **边界与异常**：完成度判定口径待开放问题 #1 定稿，v1 采轻量口径（阶段状态 + 产物有无）；项目删除策略（归档软删 vs 硬删）由设计规格定。

#### M16-F05 新分析立项

- **描述**：从筛选器/行业中心一键发起研究项目，研究模板带入（公司基本面清单/行业框架/估值方法适配）；对话内经「新分析」Skill 引导发起为并列入口。
- **业务规则**：一键发起预填标的代码/名称/行业字段，创建后项目进入「新分析」阶段；带入模板内容取自 F01 定稿的「必须有」清单；允许同一标的多个项目并行（见 YAGNI-5）。
- **边界与异常**：非自选/非关注标的亦可手动立项（研究不以前置关注为门槛）；从外部入口（筛选器/行业中心）传入的非法标的代码按参数校验拒绝。

#### M16-F06 策略文档结构

- **描述**：策略文档五个结构化字段——投资逻辑 / 估值区间 / 仓位计划 / 买入条件 / 风险与证伪条件。
- **业务规则**：估值区间**手动填写**（决策 #6），不内置自动计算；证伪条件 = 可勾选判定项 + 文本说明，供 F15 命中检测；允许暂存草稿（字段不完整可保存），「定稿」为显式动作（定稿留痕、进入下一阶段语义）。
- **边界与异常**：估值区间校验下限 < 上限；证伪条件检测方式（规则引擎 vs LLM 评估）为开放问题 #3，v1 倾向规则式 + 人工确认；定稿后修改走修订（保留历史版本），历史版本策略 v1 仅存不定稿前的草稿态与定稿态两级。

#### M16-F07 研究项目前端页（/research）

- **描述**：项目列表 + 阶段进度 + 产物查看。列表按阶段/更新时间过滤排序；阶段进度以四阶段 + 完成度可视化；产物（策略文档/建仓计划/复盘记录/检查单留痕）页内查看。
- **业务规则**：登录可用（未登录入口隐藏，照既有页面先例）；项目数据仅限本人（后端隔离，前端不做他人数据假面）；空态引导从筛选器/对话发起立项。
- **边界与异常**：移动端适配沿用既有规范；项目/产物数量级小（每用户数十），无虚拟滚动需求。

#### M16-F08 项目与 journal/wiki 联动

- **描述**：研究笔记、备忘可关联项目（journal 备忘挂 projectId）；journal 时间线可见项目事件（立项/阶段流转/策略定稿/买卖检查/复盘/证伪评审）；项目页可反查关联备忘与 wiki 条目。
- **业务规则**：联动为单向引用——journal/wiki 记项目 id，项目域不反向持有；项目事件由 application 服务在对应用例点写入 journal 时间线（留痕）。
- **边界与异常**：删除项目不级联删除 journal/wiki 内容（解除关联、内容保留）；联动入口未登录隐藏。

### C. MS-26 · 策略与建仓持仓联动

#### M16-F09 建仓计划

- **描述**：建仓计划结构化（批次方案：分批价格区间/数量/金额/预计仓位占比），仓位计算参考凯利简化口径；消费 M13 PrincipleRule 校验单票/行业上限。
- **业务规则**：与 PrincipleRule 冲突时**软提醒 + 留痕**（决策 #5：显式提示冲突项与规则阈值，不阻断录入）；PrincipleRule 未配置对应指标时提示「未设定规则」而非静默放行；各批次仓位占比合计 > 100% 时校验拒绝。
- **边界与异常**：计划 ≠ 成交——实际持仓以 portfolio 流水为准，计划是事前结构化记录；标的行情数据缺失时仓位计算标注「按最近可得价」。

#### M16-F10 买入纪律检查单

- **描述**：买入前 checklist（检查项源自 F01 定稿「必须有」清单 + 用户 PrincipleRule：能力圈/安全边际/估值区间核对/仓位上限/买入条件满足情况）+ HITL 确认；不达规则项显式提示。
- **业务规则**：检查结果留痕（时间、命中项、用户确认/越过及理由）——越过提示继续时**必填理由**（留痕最低要求，承决策 #5）；软提醒不阻断（决策 #5）；检查单机制复用 ADR-0010 HITL 前端审批卡片先例。
- **边界与异常**：检查项全部通过亦只是流程确认，页面明示不构成投资建议；PrincipleRule 未配置时检查单给出「未设定」中性结论，不视为通过也不视为失败。

#### M16-F11 持仓情报监控

- **描述**：研究项目持仓标的自动挂接 M15 智能情报订阅（阶段二主线一交付），相关公告/新闻主动提醒（飞书 + 页面触达）。
- **业务规则**：复用 M15 订阅设施与飞书通道（ADR-0013），本特性不新建触达设施；订阅范围 = 项目进入「建仓与持仓」阶段后的持仓标的；提醒与项目关联留痕（journal 时间线可见）。
- **边界与异常**：**依赖 M15（MS-20~23）交付，未交付前本点阻塞**（规划依赖关系）；情报源不可用降级复用 collector 告警通道；用户可在设置中关闭提醒（沿用 M15 订阅设置）。

#### M16-F12 加减仓/卖出纪律检查

- **描述**：与建仓同口径——加减仓/卖出前 checklist + 软提醒 + 留痕；卖出检查项额外含证伪条件核对（联动 F15）。
- **业务规则**：检查单机制与留痕格式与 F10 完全复用（同一领域服务，不同检查项集）；卖出检查触发证伪条件命中提示时，同步提示「可发起证伪评审」入口。
- **边界与异常**：同 F10；加减仓计划变更仓位占比同样消费 PrincipleRule 校验；实际成交以 portfolio 流水为准。

### D. MS-27 · 复盘闭环

#### M16-F13 复盘模板

- **描述**：复盘模板三档——**月主模板**（默认）、**季深度模板**（深度归因）、**周简版**（轻量 checklist）（决策 #7）；维度：决策质量 vs 结果质量、纪律遵守度、归因。
- **业务规则**：模板结构与内容源自 F01 定稿复盘方法论（回顾目标→评估结果→分析原因→总结经验）；复盘为可选动作，不阻断阶段流转；复盘记录归属项目。
- **边界与异常**：三套模板的最小字段集为开放问题 #2，随 MS-24 内容评审逐条确认；无持仓变动的月份仍允许复盘（决策质量复盘）。

#### M16-F14 复盘数据自动带入

- **描述**：复盘报告自动带入买卖点 vs 后续走势、区间收益，接 analytics 净值序列/持仓流水（M12 已交付）。
- **业务规则**：数据以 analytics 域为唯一真源（跨域消费经 application 层编排，见 NFR-4）；自动计算值标注口径（区间起止、价格口径）；自动带入值为草稿、用户可手动覆盖编辑。
- **边界与异常**：区间无数据（未建仓/数据缺口）标注「无数据」而非留白；自动计算与手算一致性为 MS-27 验收口径。

#### M16-F15 策略证伪评审

- **描述**：策略证伪条件命中时提醒（页面 + 可选飞书）+ 评审记录 + 处置留痕。
- **业务规则**：命中检测 v1 采**规则式确定性检查 + 人工确认**（开放问题 #3 定稿前按此实现）；评审记录结构化（结论枚举：维持/减仓/退出/修订策略 + 理由）；处置动作与理由留痕入 journal 时间线并可在项目页查看。
- **边界与异常**：提醒为软提醒不强制；每次命中提示须可解释（命中哪条条件、依据什么数据），避免黑盒判定。

#### M16-F16 复盘归档与知识回流

- **描述**：复盘结论一键回流 M13 wiki（可检索、可复用）；模板改进建议结构化沉淀（建议内容/对应阶段/来源复盘），反哺 SOP v2。
- **业务规则**：回流 wiki 走既有 `wiki_entry`（类型/标签方案由设计规格定），**用户确认后入库**（不自动回流）；改进建议单独结构化留存，供 SOP v2 内容迭代消费。
- **边界与异常**：v1 不做模板自动改写（改进只收集不生效）；回流失败（wiki 写入异常）不阻断复盘保存。

## 五、非功能需求

1. **领域模型一致性**：四阶段枚举（新分析/制定投资策略/建仓与持仓/复盘）与完成度口径为全端单一真源——后端 domain 枚举 = 前端展示 = SKILL.md 引导语引用同一份契约；完成度口径定稿后（开放问题 #1）以领域服务为唯一计算点，前端不重复实现；阶段枚举变更须 Flyway 迁移 + 契约测试。
2. **数据安全**：项目归属隔离沿用会话体系（userId 归属、非本人访问 404，照 journal/会话隔离先例）；策略文档/建仓计划/复盘记录含个人投资意图与持仓信息，**不设公开端点**（区别于行业中心读侧公开先例）；检查单与证伪留痕不可篡改（只增不改）。
3. **可测试性**：纪律检查规则纯函数化——输入（检查单上下文 + PrincipleRule 集）→ 输出（命中项列表），无副作用，可单测全覆盖；四阶段完成度计算、证伪条件命中判定同为纯领域逻辑；状态机流转边界（灵活推进的回退/重入）domain 单测覆盖；JaCoCo ≥80% 门槛继承。
4. **与既有域的依赖方向（DDD 规范）**：`domain/research` 为纯 POJO（零 Spring/JPA 注解）；依赖方向向下（web→application→domain；infrastructure→domain/application/config），禁止反向与成环；跨域消费（journal 时间线、analytics 数据、wiki 回流、PrincipleRule 读取、M15 情报订阅）一律经 application 层编排，domain 之间不横向依赖；`PackageConventionsTest` 登记 `research` 域依赖白名单（新增能力域登记先例）。
5. **Schema 与 seeding**：新表走 Flyway 迁移（版本号接当前最新 V 后续）；wiki 模板 seeding 与 Skill 目录均幂等（用户删光不复活、升级不覆盖用户修改）。
6. **覆盖率与质量门槛**：后端 JaCoCo / 前端 V8 ≥80%，`make test` 三端全绿；`make smoke` + Playwright e2e 通过（e2e 覆盖立项→策略→检查单→复盘主链路）。
7. **性能**：研究项目量级小（每用户数十项目、产物数百），无缓存与异步需求（YAGNI）；复盘数据带入为按需查询 analytics 既有接口。

## 七、YAGNI 排除清单（逐条理由）

| # | 排除项 | 排除理由 |
|:---:|--------|------|
| 1 | 纪律硬拦截（冲突禁录） | 决策 #5 裁决软提醒：规则阈值主观、v1 未经实盘校验，硬拦截可能误伤；先留痕积累口径，严格度后调 |
| 2 | 估值自动计算模型（合理区间自动算） | 决策 #6 裁决手动填写：估值模型变量多、口径主观，自动化收益不确定；先沉淀结构化手动数据再议（v2） |
| 3 | 技术面/趋势分析检查项 | 决策 #3 裁决 v1 纯价值投资主线：趋势信号与现有估值/筛选结构化数据面不匹配，需另建指标体系（v2） |
| 4 | 强制线性四阶段流转 | 决策 #4 裁决灵活推进：真实研究在阶段间往返迭代（复盘常触发重新分析），硬锁状态机会降低使用率 |
| 5 | 多策略并行组合管理 | v1 单项目单策略主线；组合层配置与再平衡 M07 已覆盖，重复建设且引入组合-策略两级心智负担 |
| 6 | 策略自动下单执行 | 系统定位为投研辅助与记录，不触达交易通道（账户安全与合规边界）；检查单止于事前留痕 |
| 7 | 社交分享/团队协同 | 个人投研工具定位；分享涉及持仓/策略隐私与整套权限模型扩展，当前无需求来源 |
| 8 | RAG/向量检索（SOP 知识） | 决策 #2（架构决策 #4）：wiki 模板化组织与查询已够用，embedding 选型/调优成本高且与 DDD 可测纪律摩擦 |

## 八、开放问题（留待 grilling）

1. **四阶段完成度的判定口径**：产物齐套数 / checklist 勾选比例 / 用户手动标记，还是多信号加权？——直接影响 F04 状态机字段设计与 F07 进度展示语义。
2. **复盘模板字段集**：月主/季深度/周三套模板的最小字段清单——随 MS-24 内容评审逐条确认（本规格仅定维度：决策质量 vs 结果质量、纪律遵守度、归因）。
3. **证伪条件的检测方式**：规则引擎式确定性检查 vs LLM 评估——影响 F15 可测试性、成本与解释性；初稿倾向 v1 规则式 + 人工确认，待裁决。
4. **研究项目与现有 watchlist（自选/行业关注集）的关系**：立项是否自动挂关注、项目完结/退出是否解除关注、筛选器入口与 watchlist 入口的优先级——影响 F05 交互设计。
