## 一、背景与目标

阶段一交付了「数据与记录」闭环（行情/估值/筛选/持仓/配置/收益分析 + journal/知识库 + Agent 平台能力），阶段二本特性把「新分析 → 制定投资策略 → 建仓与持仓 → 复盘」四阶段流程化：**新分析**（发现标的、立项研究）→ **制定投资策略**（结构化策略文档：投资逻辑/估值区间/仓位计划/买入条件/风险与证伪条件）→ **建仓与持仓**（建仓计划 + 买入纪律检查 + 持仓监控）→ **复盘**（模板化复盘 + 证伪评审 + 知识回流）。实现方式 = 架构决策 #2 的双层结构：数据层新建 `domain/research` 结构化研究项目域承载四阶段状态机与产物，引导层四个内置 SOP SKILL.md 由 Agent 按阶段引导收集要素并做纪律检查，知识层 SOP v1 最佳实践沉淀为 M13 wiki 模板；阶段一资产全面复用——MS-17 Skill 系统承载四 Skill 按用户启停、M13 wiki 承接模板 seeding 与复盘结论回流、M13 PrincipleRule 供建仓/买卖纪律检查消费、journal 承接备忘与时间线联动、analytics 复盘数据自动带入（买卖点 vs 后续走势）、M15 智能情报（阶段二主线一交付）提供持仓标的公告/新闻监控。一句话：**让投资决策从「随手记」变成「有流程、有纪律、可复盘」的系统内建作业方式**。

## 二、决策汇总

> D1~D8 承上游规划（架构决策 #2/#4、澄清 #9~13、四阶段定义）；D9~D23 为 2026-09-28 grilling 两轮 18 问裁决（用户全部确认）。

| 编号 | 决策点 | 结论 | 理由 |
|:---:|--------|------|------|
| D1 | **架构决策 #2：SOP 形态** | 结构化研究项目 + 内置 SOP Skill 双层：数据层新建 `domain/research`（ResearchProject 四阶段状态机 + 策略文档 + 复盘记录，Flyway 迁移；domain 子包由 ArchUnit 层级通配自动覆盖、无需登记，同步 DDD 分包规范子包清单）；引导层 = 四个内置 SKILL.md（新分析/制定策略/建仓持仓/复盘，复用 MS-17 Skill 系统按用户启停，Agent 引导收集要素 + 纪律检查）；知识层 = SOP v1 沉淀为 M13 wiki 模板（幂等 seeding） | 备选 A「只做 wiki 静态文档」被动、无流程沉淀；备选 D「全 Agent 黑盒自主流程」不可控、不可测试。双层各取所长：结构可测、引导灵活 |
| D2 | **架构决策 #4（2026-09-28 用户裁决）：SOP 知识组织** | 弃用 RAG。SOP 知识以 M13 wiki 方式组织与查询，不做 embedding/向量检索 | embedding 选型部署、chunking、中文检索调优成本高，与「覆盖率 ≥80% + DDD 可测」工程纪律摩擦大；wiki 模板化组织已满足 SOP v1 查询需求 |
| D3 | **澄清 #9：投资风格** | SOP v1 纯价值投资主线；趋势/技术面检查项归 v2 | 与阶段一估值/筛选/持仓数据面同源一致，聚焦可落地；趋势信号与现有结构化数据面不匹配，需另建指标体系 |
| D4 | **澄清 #10：四阶段流转** | 灵活推进 + 各阶段完成度记录，不硬锁线性状态机 | 真实研究在阶段间往返迭代（复盘常触发重新分析），硬锁线性状态机会大幅降低使用率；完成度记录已够支撑进度可见 |
| D5 | **澄清 #11：纪律检查严格度** | 软提醒：与 PrincipleRule 冲突时显式提示 + 留痕，不阻断录入 | 规则阈值主观且 v1 未经实盘校验，硬拦截可能误伤正常操作；软提醒 + 留痕先积累口径，严格度可后调 |
| D6 | **澄清 #12：策略文档形态** | 结构化五字段（投资逻辑/估值区间/仓位计划/买入条件/风险与证伪条件）；估值区间手动填写；简化估值自动计算模型归 v2 | 结构化字段才可被纪律检查与复盘消费；估值模型变量多、口径主观，先沉淀手动数据再议自动化 |
| D7 | **澄清 #13：复盘默认周期** | 月主模板 + 季深度模板（附周简版） | 月粒度匹配 A 股持仓复盘节奏（业绩/公告月度密度），季粒度适合深度归因，周粒度过密以简版兜底 |
| D8 | **附：四阶段定义** | 新分析 → 制定投资策略 → 建仓与持仓 → 复盘 | 阶段二规划主线二既定流程，本特性全部功能点归属以此为纲 |
| D9 | **草稿落库通路** | 前端确认落库：Skill 草稿经 AG-UI 事件流到前端，用户确认保存后由前端调 `/research` 应用服务 API（仿 chart spec 双通道先例），不引入 Agent 写库工具 | 落库 = 用户确认动作，留痕语义清晰；与 D1「Skill 只引导不写库」自洽 |
| D10 | **证伪检测方式与条件结构** | 规则式确定性检查 + 人工确认；条件 = 价格/估值两类结构化谓词（跌破价格/升破价格/PE 超阈/PB 超阈 + 阈值）+ 事件类人工勾选 | 可从既有行情/估值数据面确定性判定、可解释、可纯函数单测；事件类结构化成本高且 M15 未交付 |
| D11 | **同标的多项目 × 复盘归因** | 交易归因按建仓计划批次时间窗自动圈选 + 手动修正 | 免手动负担、兜底口径误差；不推翻多项目并行（YAGNI-5） |
| D12 | **F08 schema 显式化** | `journal_entry`/`wiki_entry` 加 project 引用列 + `TimelineEventType` 扩展 + `timeline()` 合并改造，列明进 F04 迁移范围 | v1 唯一动既有表处，进迁移清单才能进评审视野与 Flyway 评审惯例 |
| D13 | **策略修订历史** | v1 覆盖式两级：仅存最新定稿 + 当前草稿，修订即覆盖，版本链归 v2 | v1 无消费方需要版本链（复盘只看最新策略），与 D16 轻量完成度同水位 |
| D14 | **MS-26 验收对冲 M15** | F11 情报触达拆为顺延项，不阻塞 MS-26 其余验收；e2e 主链路不含 F11（触达端到端由 smoke 手测覆盖） | M15 现状零代码（仅 v0.1 规格初稿），绑定整里程碑验收会放大排期风险 |
| D15 | **飞书证伪提醒隐私** | 推送文案仅项目名 + 命中条件名，不含策略详情/持仓/数字 | 策略意图与持仓是敏感个人信息，飞书为外部通道，最小化推送 + 站内看详情 |
| D16 | **四阶段完成度口径** | 必备产物齐套 → 自动标记完成（必备产物由 F01「必须有」清单映射），用户可手动标记/取消兜底 | 与 F01 内容定稿天然同源（必须有清单即完成度定义），避免比例/加权伪精确 |
| D17 | **项目与 watchlist 关系** | 零自动联动：立项不自动挂关注、完结/退出不自动解除；项目页「加自选」手动桥接 | 关注是轻量观察行为、项目是重流程行为，自动联动使清理成本互相传染；手动桥接方向单一可控 |
| D18 | **检查单宿主与触发** | 项目页自建确认流（复用 ADR-0010 `InterruptApprovalCard` 卡片 UI 形态），从建仓计划批次/卖出意图主动发起，与 portfolio 交易录入解耦 | D9 已排除 Agent 写库通路，检查单同理由页面承载；主动发起避免「录交易被卡 / 检查了没录」耦合歧义，留痕独立完整 |
| D19 | **估值区间 × 证伪条件** | 不自动派生默认证伪条件；Skill 引导时建议勾选「跌破估值区间下限」模板项 | 数据层不隐式派生（策略五字段各自显式），引导层建议模板项——与 D1 双层分工一致 |
| D20 | **未保存草稿兜底** | 不自动暂存：显式保存才落库，未保存草稿留存于会话历史（文本可随时找回） | 与「用户确认后入库」同哲学（F16 回流同例）；自动暂存产生半成品污染项目列表 |
| D21 | **证伪命中触发时机** | 页面实时判定（纯函数、即时可解释）+ 飞书日终汇总一次（复用 18:33 日终巡检调度先例），盘中不推 | 实时判定零成本；盘中逐条推送打扰且行情波动造成命中抖动，日终汇总稳定可解释 |
| D22 | **F07 进度展示语义** | 每阶段三态（未开始/进行中/完成）+ 完成方式角标（自动齐套/手动标记），不做百分比 | 与 D16 拒绝比例伪精确同口径；三态 + 角标既表达进度又表达完成依据 |
| D23 | **凯利简化输入** | v1 用户手动输入胜率/赔率，系统只做算术与仓位占比校验；自动估计归 v2 | 参数主观性强，先沉淀显式输入（与 D6 估值手动同理）；自动估计需 analytics 口径定义 |

## 三、最佳实践来源（SOP v1 收集范围）

- **经典框架**：格雷厄姆/巴菲特/芒格（能力圈、安全边际、护城河）；多尔西《股市真规则》分析 checklist；霍华德·马克斯（周期、第二层思维）；费雪《怎样选择成长股》；彼得·林奇六种公司分类。
- **国内实践**：段永平（商业模式优先、Stop Doing List）；唐朝估值三段式；张磊《价值》；李录。
- **交易纪律**：仓位管理（凯利简化、单票/行业上限）；买入前检查单；证伪/退出条件。
- **复盘方法论**：回顾目标 → 评估结果 → 分析原因 → 总结经验（邱昭良《复盘+》及企业实践）。

收集与定稿方式（承规划文档 MS-24 风险条款）：内容为强主观性工作，**v1 必须用户参与评审**——每阶段「必须有 / 可选项」清单逐条确认后方可定稿，作为 F02/F03 的唯一内容源。

## 四、功能需求（M16-F01~F16，按里程碑四组组织）

### A. MS-24 · SOP 最佳实践沉淀与 Skill 化

#### M16-F01 SOP 四阶段最佳实践 v1 定稿

- **描述**：内容研究工作——按 §三 范围收集整理四阶段最佳实践，产出每阶段「必须有 / 可选项」checklist、模板要点与纪律检查项初稿；v1 以价值投资为主线（D3）。
- **业务规则**：每阶段「必须有 / 可选项」清单逐条经用户评审确认后定稿（MS-24 验收门槛）；定稿产物是 F02（Skill 内容）与 F03（wiki 模板内容）的唯一内容源；趋势/技术面检查项明确不归入 v1。
- **边界与异常**：纯内容产出，无代码交付；内容定稿阻塞 F02/F03 开工，是 MS-24 关键路径。

#### M16-F02 四个内置 SOP SKILL.md

- **描述**：新分析 / 制定策略 / 建仓持仓 / 复盘 四个 SKILL.md 落 `backend/src/main/resources/skills/`，复用 MS-17 Skill 系统按用户启停；Agent 按阶段引导用户收集要素（对话式逐要素收集）+ 纪律检查（消费 PrincipleRule，软提醒）。
- **业务规则**：目录随应用发布（DB 不存目录，只存用户启用集），front-matter `default_enabled` 建议 `false`（用户显式启用）；未启用不进入 Agent 上下文（`HarnessAgentFactory` 装配先例）；Skill 产出结构化草稿，引导不强制线性流程（D4）。
- **边界与异常**：Skill 只引导与生成草稿，**不直接写库**——草稿经 AG-UI 事件流到前端，用户确认保存后由前端调 `/research` 应用服务 API（仿 chart spec 双通道先例，D9）；未保存草稿不自动暂存，留存于会话历史（D20）；Skill 停用不删除既有项目数据。

#### M16-F03 SOP wiki 模板 seeding

- **描述**：SOP v1 定稿内容（四阶段模板/检查单）入 M13 知识库，幂等 seeding（照 M13-F03 概念速查 `wiki_seed_state` 先例）。
- **业务规则**：幂等——每用户只 seed 一次，删光不复活；用户可增删改（同既有 wiki 权限）；具体落 `wiki_entry` 类型扩展或复用既有类型由设计规格定。
- **边界与异常**：seeding 失败不阻断主流程（下回访问重试）；发布升级不覆盖用户已修改的条目（用户版本优先）。

### B. MS-25 · 研究项目域

#### M16-F04 研究项目域（domain/research）

- **描述**：新建 `domain/research` 域——ResearchProject 四阶段状态机（新分析/制定投资策略/建仓与持仓/复盘 枚举）+ 策略文档 + 复盘记录 + 阶段产物；Flyway 新表。`domain/research` 子包由 `PackageConventionsTest` 的 `domain..` 层级通配自动覆盖（无需白名单登记），需同步 `docs/technology/conventions/01-后端DDD分包规范.md` 的 domain 子包清单。迁移范围含既有表加列：`journal_entry`/`wiki_entry` 加 project 引用列、`TimelineEventType` 扩展与 `timeline()` 合并改造（D12，v1 唯一动既有表处）。
- **业务规则**：灵活推进——阶段可任意顺序进入/回退，系统记录各阶段完成度而非锁流转（D4）；完成度口径（D16）：每阶段**必备产物齐套 → 自动标记完成**（必备产物由 F01「必须有」清单映射），用户可手动标记/取消兜底；项目归属 userId，非本人访问 404（照会话/journal 隔离先例）；领域纯 POJO，依赖方向遵守 DDD 规范（§五 NFR-4）。
- **边界与异常**：项目删除策略（归档软删 vs 硬删）由设计规格定。

#### M16-F05 新分析立项

- **描述**：从筛选器/行业中心一键发起研究项目，研究模板带入（公司基本面清单/行业框架/估值方法适配）；对话内经「新分析」Skill 引导发起为并列入口。
- **业务规则**：一键发起预填标的代码/名称/行业字段，创建后项目进入「新分析」阶段；带入模板内容取自 F01 定稿的「必须有」清单；允许同一标的多个项目并行（见 YAGNI-5）；与 watchlist（自选/行业关注集）**零自动联动**——立项不自动挂关注、完结/退出不自动解除，项目页「加自选」手动桥接（D17）。
- **边界与异常**：非自选/非关注标的亦可手动立项（研究不以前置关注为门槛）；从外部入口（筛选器/行业中心）传入的非法标的代码按参数校验拒绝。

#### M16-F06 策略文档结构

- **描述**：策略文档五个结构化字段——投资逻辑 / 估值区间 / 仓位计划 / 买入条件 / 风险与证伪条件。
- **业务规则**：估值区间**手动填写**（D6），不内置自动计算；证伪条件（D10）= 价格/估值两类**结构化谓词**（跌破价格/升破价格/PE 超阈/PB 超阈 + 阈值）+ 事件类人工勾选项（布尔 + 文本说明），供 F15 规则式命中检测；允许暂存草稿（字段不完整可保存），「定稿」为显式动作（定稿留痕、进入下一阶段语义）。
- **边界与异常**：估值区间校验下限 < 上限；估值区间**不自动派生**默认证伪条件，Skill 引导时建议勾选「跌破估值区间下限」模板项（D19）；定稿后修改走修订，v1 为**覆盖式两级**——仅存最新定稿 + 当前草稿，修订即覆盖，版本链归 v2（D13）。

#### M16-F07 研究项目前端页（/research）

- **描述**：项目列表 + 阶段进度 + 产物查看。列表按阶段/更新时间过滤排序；阶段进度以四阶段**三态**（未开始/进行中/完成）+ 完成方式角标（自动齐套/手动标记）可视化，不做百分比（D22）；产物（策略文档/建仓计划/复盘记录/检查单留痕）页内查看。
- **业务规则**：登录可用（未登录入口隐藏，照既有页面先例）；项目数据仅限本人（后端隔离，前端不做他人数据假面）；空态引导从筛选器/对话发起立项。
- **边界与异常**：移动端适配沿用既有规范；项目/产物数量级小（每用户数十），无虚拟滚动需求。

#### M16-F08 项目与 journal/wiki 联动

- **描述**：研究笔记、备忘可关联项目（journal 备忘挂 projectId）；journal 时间线可见项目事件（立项/阶段流转/策略定稿/买卖检查/复盘/证伪评审）；项目页可反查关联备忘与 wiki 条目。
- **业务规则**：联动为单向引用——journal/wiki 记项目 id，项目域不反向持有；项目事件由 application 服务在对应用例点写入 journal 时间线（留痕）。
- **边界与异常**：删除项目不级联删除 journal/wiki 内容（解除关联、内容保留）；联动入口未登录隐藏。

### C. MS-26 · 策略与建仓持仓联动

#### M16-F09 建仓计划

- **描述**：建仓计划结构化（批次方案：分批价格区间/数量/金额/预计仓位占比），仓位计算参考凯利简化口径（胜率/赔率参数 v1 用户手动输入，D23）；消费 M13 PrincipleRule 校验单票/行业上限。
- **业务规则**：与 PrincipleRule 冲突时**软提醒 + 留痕**（D5：显式提示冲突项与规则阈值，不阻断录入）；PrincipleRule 未配置对应指标时提示「未设定规则」而非静默放行；各批次仓位占比合计 > 100% 时校验拒绝。
- **边界与异常**：计划 ≠ 成交——实际持仓以 portfolio 流水为准，计划是事前结构化记录；标的行情数据缺失时仓位计算标注「按最近可得价」。

#### M16-F10 买入纪律检查单

- **描述**：买入前 checklist（检查项源自 F01 定稿「必须有」清单 + 用户 PrincipleRule：能力圈/安全边际/估值区间核对/仓位上限/买入条件满足情况）+ 用户逐项确认；不达规则项显式提示。
- **业务规则**：检查结果留痕（时间、命中项、用户确认/越过及理由）——越过提示继续时**必填理由**（留痕最低要求，承 D5）；软提醒不阻断（D5）；检查单确认为**项目页自建确认流**，复用 ADR-0010 `InterruptApprovalCard` 的卡片 UI 形态（D18）——ADR-0010 的 interrupt 机制绑定对话内写工具调用（readOnly=false 触发、卡片仅挂对话页 ThreadArea），不能直接用于检查单确认；从建仓计划批次/卖出意图主动发起，与 portfolio 交易录入解耦。
- **边界与异常**：检查项全部通过亦只是流程确认，页面明示不构成投资建议；PrincipleRule 未配置时检查单给出「未设定」中性结论，不视为通过也不视为失败。

#### M16-F11 持仓情报监控

- **描述**：研究项目持仓标的自动挂接 M15 智能情报订阅（阶段二主线一交付），相关公告/新闻主动提醒（飞书 + 页面触达）。
- **业务规则**：复用 M15 订阅设施与飞书通道（ADR-0013），本特性不新建触达设施；订阅范围 = 项目进入「建仓与持仓」阶段后的持仓标的；提醒与项目关联留痕（journal 时间线可见）。
- **边界与异常**：**依赖 M15（MS-20~23）交付，未交付前本点顺延、不阻塞 MS-26 其余验收**（D14）；情报源不可用降级复用 collector 告警通道；用户可在设置中关闭提醒（沿用 M15 订阅设置）。

#### M16-F12 加减仓/卖出纪律检查

- **描述**：与建仓同口径——加减仓/卖出前 checklist + 软提醒 + 留痕；卖出检查项额外含证伪条件核对（联动 F15）。
- **业务规则**：检查单机制与留痕格式与 F10 完全复用（同一领域服务，不同检查项集）；卖出检查触发证伪条件命中提示时，同步提示「可发起证伪评审」入口。
- **边界与异常**：同 F10；加减仓计划变更仓位占比同样消费 PrincipleRule 校验；实际成交以 portfolio 流水为准。

### D. MS-27 · 复盘闭环

#### M16-F13 复盘模板

- **描述**：复盘模板三档——**月主模板**（默认）、**季深度模板**（深度归因）、**周简版**（轻量 checklist）（D7）；维度：决策质量 vs 结果质量、纪律遵守度、归因。
- **业务规则**：模板结构与内容源自 F01 定稿复盘方法论（回顾目标→评估结果→分析原因→总结经验）；复盘为可选动作，不阻断阶段流转；复盘记录归属项目。
- **边界与异常**：三套模板的最小字段集为开放问题（见 §八），随 MS-24 内容评审逐条确认；无持仓变动的月份仍允许复盘（决策质量复盘）。

#### M16-F14 复盘数据自动带入

- **描述**：复盘报告自动带入买卖点 vs 后续走势、区间收益，接 analytics 净值序列/持仓流水（M12 已交付）。同标的多项目并行时，交易归因按建仓计划批次时间窗自动圈选 + 手动修正（D11）。
- **业务规则**：数据以 analytics 域为唯一真源（跨域消费经 application 层编排，见 NFR-4）；自动计算值标注口径（区间起止、价格口径）；自动带入值为草稿、用户可手动覆盖编辑。
- **边界与异常**：区间无数据（未建仓/数据缺口）标注「无数据」而非留白；自动计算与手算一致性为 MS-27 验收口径。

#### M16-F15 策略证伪评审

- **描述**：策略证伪条件命中时提醒（页面 + 可选飞书）+ 评审记录 + 处置留痕。
- **业务规则**：命中检测采**规则式确定性检查 + 人工确认**（D10）：**页面实时判定**（纯函数、即时可解释）+ **飞书日终汇总一次**（复用 18:33 日终巡检调度先例），盘中不推（D21）；飞书文案仅项目名 + 命中条件名，不含策略详情/持仓/数字（D15）；评审记录结构化（结论枚举：维持/减仓/退出/修订策略 + 理由）；处置动作与理由留痕入 journal 时间线并可在项目页查看。
- **边界与异常**：提醒为软提醒不强制；每次命中提示须可解释（命中哪条条件、依据什么数据），避免黑盒判定。

#### M16-F16 复盘归档与知识回流

- **描述**：复盘结论一键回流 M13 wiki（可检索、可复用）；模板改进建议结构化沉淀（建议内容/对应阶段/来源复盘），反哺 SOP v2。
- **业务规则**：回流 wiki 走既有 `wiki_entry`（类型/标签方案由设计规格定），**用户确认后入库**（不自动回流）；改进建议单独结构化留存，供 SOP v2 内容迭代消费。
- **边界与异常**：v1 不做模板自动改写（改进只收集不生效）；回流失败（wiki 写入异常）不阻断复盘保存。

## 五、非功能需求

1. **领域模型一致性**：四阶段枚举（新分析/制定投资策略/建仓与持仓/复盘）与完成度口径（D16）为全端单一真源——后端 domain 枚举 = 前端展示 = SKILL.md 引导语引用同一份契约；完成度以领域服务为唯一计算点，前端不重复实现；阶段枚举的存储形态与变更约束由设计规格定，契约测试锁定。
2. **数据安全**：项目归属隔离沿用会话体系（userId 归属、非本人访问 404，照 journal/会话隔离先例）；策略文档/建仓计划/复盘记录含个人投资意图与持仓信息，**不设公开端点**（区别于行业中心读侧公开先例）；检查单与证伪留痕不可篡改（只增不改）。
3. **可测试性**：纪律检查规则纯函数化——输入（检查单上下文 + PrincipleRule 集）→ 输出（命中项列表），无副作用，可单测全覆盖；四阶段完成度计算、证伪条件命中判定同为纯领域逻辑；状态机流转边界（灵活推进的回退/重入）domain 单测覆盖；JaCoCo ≥80% 门槛继承。
4. **与既有域的依赖方向（DDD 规范）**：`domain/research` 为纯 POJO（零 Spring/JPA 注解）；依赖方向向下（web→application→domain；infrastructure→domain/application/config），禁止反向与成环；跨域消费（journal 时间线、analytics 数据、wiki 回流、PrincipleRule 读取、M15 情报订阅）一律经 application 层编排，domain 之间不横向依赖；新增 `domain/research` 子包由 `PackageConventionsTest` 层级通配自动覆盖、无需改测试——白名单登记仅适用于新增顶层能力包（agent 层先例），本特性不涉及，需同步的是 `01-后端DDD分包规范` 的 domain 子包清单。
5. **Schema 与 seeding**：新表走 Flyway 迁移（版本号接当前最新 V 后续）；wiki 模板 seeding 与 Skill 目录均幂等（用户删光不复活、升级不覆盖用户修改）。
6. **覆盖率与质量门槛**：后端 JaCoCo / 前端 V8 ≥80%，`make test` 三端全绿；`make smoke` + Playwright e2e 通过（e2e 覆盖立项→策略→检查单→复盘主链路；主链路不含 F11 情报触达——依赖外部飞书通道，由 smoke 手测覆盖，D14）。
7. **性能**：研究项目量级小（每用户数十项目、产物数百），无缓存与异步需求（YAGNI）；复盘数据带入为按需查询 analytics 既有接口。

|--------|------|

## 七、YAGNI 排除清单（逐条理由）

| # | 排除项 | 排除理由 |
|:---:|--------|------|
| 1 | 纪律硬拦截（冲突禁录） | D5 裁决软提醒：规则阈值主观、v1 未经实盘校验，硬拦截可能误伤；先留痕积累口径，严格度后调 |
| 2 | 估值自动计算模型（合理区间自动算） | D6 裁决手动填写：估值模型变量多、口径主观，自动化收益不确定；先沉淀结构化手动数据再议（v2） |
| 3 | 技术面/趋势分析检查项 | D3 裁决 v1 纯价值投资主线：趋势信号与现有估值/筛选结构化数据面不匹配，需另建指标体系（v2） |
| 4 | 强制线性四阶段流转 | D4 裁决灵活推进：真实研究在阶段间往返迭代（复盘常触发重新分析），硬锁状态机会降低使用率 |
| 5 | 多策略并行组合管理 | v1 单项目单策略主线；组合层配置与再平衡 M07 已覆盖，重复建设且引入组合-策略两级心智负担 |
| 6 | 策略自动下单执行 | 系统定位为投研辅助与记录，不触达交易通道（账户安全与合规边界）；检查单止于事前留痕 |
| 7 | 社交分享/团队协同 | 个人投研工具定位；分享涉及持仓/策略隐私与整套权限模型扩展，当前无需求来源 |
| 8 | RAG/向量检索（SOP 知识） | D2（架构决策 #4）裁决：wiki 模板化组织与查询已够用，embedding 选型/调优成本高且与 DDD 可测纪律摩擦 |
