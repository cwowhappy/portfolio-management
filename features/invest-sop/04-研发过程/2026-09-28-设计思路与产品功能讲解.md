> 决策台账终确认与规格 v1.0 定稿落盘为后续动作，本文按「已接受裁决」口径讲解。
> 上游：[需求规格说明](../01-需求规格/需求规格说明.md)（含 A 类事实性错误修订，commit 9e02296）。

## 一、总述：这是什么、为什么做

**一句话定位**：把「新分析 → 制定投资策略 → 建仓与持仓 → 复盘」四阶段投资流程内建为系统作业方式，让投资决策**从随手记变成有流程、有纪律、可复盘**。

**它解决的问题**：阶段一（MS-00~19）交付的是「数据与记录」——行情、估值、筛选、持仓、配置、收益分析、journal、知识库都在，但**决策过程本身是散的**：研究笔记随手记、买入凭感觉、复盘想不起来做、亏了不知道错在认知还是运气。invest-sop 不新增数据能力，而是把既有数据**串成有纪律的作业流程**。

**核心循环**（不是线性管道，是环）：

```
  ① 新分析 ────→ ② 制定投资策略 ────→ ③ 建仓与持仓 ────→ ④ 复盘
 (发现标的、    (五字段策略文档、       (建仓计划、纪律      (模板化复盘、
  立项研究)      手动估值区间)          检查单、情报监控)     证伪评审、知识回流)
      ↑                                                        │
      └────────────── 复盘常触发重新分析（灵活回退，不硬锁）──────────┘
                                   │
                                   ↓
                        复盘结论回流 wiki → 反哺 SOP v2
```

## 二、设计思路（三层架构 + 四条哲学）

### 2.1 三层架构（架构决策 #2）

SOP 形态是整个特性最核心的设计判断：

| 层 | 载体 | 职责 | 为什么 |
|---|---|---|---|
| **数据层** | 新建 `domain/research`（ResearchProject 四阶段状态机 + 策略文档 + 复盘记录） | 结构化承载：状态、产物、留痕，**可测试、可查询** | 备选 A「只做 wiki 静态文档」太被动——没有流程状态，无法做纪律检查与复盘联动 |
| **引导层** | 四个内置 SKILL.md（新分析/制定策略/建仓持仓/复盘），复用 MS-17 Skill 系统按用户启停 | Agent 对话式逐要素引导收集 + 纪律检查提醒，**产出结构化草稿但不写库** | 备选 D「全 Agent 黑盒自主流程」不可控不可测——引导归 Agent，落库归显式 API，各取所长 |
| **知识层** | SOP v1 最佳实践沉淀为 M13 wiki 模板（幂等 seeding） | 可检索、可复用的方法论内容 | 与决策 #4（弃用 RAG）一致：模板化 wiki 组织够用，避免 embedding 选型调优成本 |

三层分工一句话：**结构可测、引导灵活、知识可生长**。

### 2.2 四条贯穿性设计哲学（grilling 后定型）

1. **数据不隐式派生，引导只建议**：估值区间不会自动生成默认证伪条件，Skill 引导时建议勾选模板项，但落库的每个字段都是用户显式动作。
2. **落库 = 用户确认**：Agent 产出的草稿经 AG-UI 流到前端，用户点「保存到项目」才落库（仿 chart spec 双通道先例）；不自动暂存、不 Agent 写库。确认即留痕。
3. **软提醒不阻断**：纪律检查与 PrincipleRule 冲突时显式提示 + 留痕，但**不拦截录入**（澄清 #11）——规则阈值主观且未经实盘校验，先积累口径；唯一例外是硬校验（仓位占比合计 >100% 拒绝）。
4. **灵活流转不硬锁**：四阶段可任意顺序进入/回退，系统记录各阶段完成度而非锁状态机（澄清 #10）——真实研究就是往返迭代的。

## 三、产品功能：按四块里程碑逐块讲（M16-F01~F16）

### 块 A · MS-24：SOP 最佳实践沉淀与 Skill 化（内容先行）

**块职责**：先把「什么是好的投资纪律」变成内容，再 Skill 化。是后续一切功能点的**唯一内容源**，也是 MS-24 的关键路径。

- **F01 最佳实践 v1 定稿**：内容研究——格雷厄姆/巴菲特/芒格/多尔西/段永平/唐朝等经典框架 + 交易纪律 + 复盘方法论，按四阶段产出「必须有 / 可选项」checklist。**纯价值投资主线**（技术面归 v2，决策 #3）。硬门槛：逐条经用户评审确认才能定稿。
- **F02 四个内置 SKILL.md**：落 `backend/src/main/resources/skills/`，`default_enabled: false`（用户显式启用）。Agent 按阶段引导收集要素 + 纪律检查（消费 PrincipleRule 软提醒）。
- **F03 wiki 模板 seeding**：定稿内容入 M13 知识库，照 M13-F03 概念速查的 `wiki_seed_state` 幂等先例——每用户只 seed 一次、删光不复活、升级不覆盖用户修改。

### 块 B · MS-25：研究项目域（结构载体）

**块职责**：SOP 有了结构化载体——数据层落地 + 前端可管理。

- **F04 `domain/research` 域**：ResearchProject（单标的单策略）+ 四阶段状态 + 完成度。完成度口径：**必备产物齐套 → 自动标记完成**（必备产物由 F01「必须有」清单映射）+ 用户手动标记/取消兜底。Flyway 新表；v1 唯一动既有表的地方列明在此：`journal_entry`/`wiki_entry` 加 project 引用列、`TimelineEventType` 扩展、`timeline()` 合并改造。
- **F05 新分析立项**：筛选器/行业中心一键发起（预填代码/名称/行业），对话内经「新分析」Skill 引导是并列入口；非自选标的也可手动立项；允许同标的多项目并行。与 watchlist **零自动联动**，项目页手动「加自选」桥接。
- **F06 策略文档五字段**：投资逻辑 / 估值区间 / 仓位计划 / 买入条件 / 风险与证伪条件。估值区间**手动填写**（决策 #6，自动化归 v2）。草稿可暂存，「定稿」是显式动作。修订为**覆盖式两级**（仅存最新定稿 + 当前草稿，版本链归 v2）。证伪条件 = **价格/估值两类结构化谓词 + 事件类人工勾选**。
- **F07 前端页 `/research`**：项目列表 + 阶段进度 + 产物查看。进度展示：每阶段**三态 + 完成方式角标**（自动齐套/手动标记），不做百分比。
- **F08 journal/wiki 联动**：单向引用（journal/wiki 记 projectId，项目域不反向持有）；项目事件（立项/流转/定稿/检查/复盘/证伪评审）写入 journal 时间线留痕；删项目不级联删内容。

### 块 C · MS-26：策略与建仓持仓联动（纪律落地）

**块职责**：把策略接到操作环节——事前计划、事前检查、事中监控。

- **F09 建仓计划**：分批方案（价格区间/数量/金额/仓位占比），凯利简化口径 **v1 手动输入参数**，消费 PrincipleRule 校验单票/行业上限——冲突**软提醒 + 留痕**，未配置规则提示「未设定」而非静默放行。计划 ≠ 成交，实际以 portfolio 流水为准。
- **F10 买入纪律检查单**：检查项来自 F01「必须有」清单 + 用户 PrincipleRule。机制：**项目页自建确认流**（仿 ADR-0010 审批卡片 UI 形态），从建仓计划批次主动发起，与交易录入解耦；**越过提示必填理由**；结果只增不改留痕。
- **F11 持仓情报监控**：项目进入「建仓与持仓」阶段后，标的自动挂 M15 智能情报订阅，公告/新闻经飞书 + 页面触达。**依赖 M15（MS-20~23），已拆为顺延项不阻塞 MS-26 其余验收**。
- **F12 加减仓/卖出检查**：与 F10 同一领域服务、不同检查项集；卖出额外含证伪条件核对，命中时提示「可发起证伪评审」入口。

### 块 D · MS-27：复盘闭环（学习落地）

**块职责**：让每一次操作变成可积累的认知，闭环回知识层。

- **F13 复盘模板三档**：月主模板（默认）/ 季深度（归因）/ 周简版（轻量 checklist），维度 = 决策质量 vs 结果质量、纪律遵守度、归因。字段集延迟至 MS-24 内容评审逐条定。
- **F14 复盘数据自动带入**：买卖点 vs 后续走势、区间收益，接 analytics 净值序列/持仓流水（M12 已交付），自动值为草稿可覆盖，口径标注。同标的多项目归因：**建仓批次时间窗自动圈选 + 手动修正**。
- **F15 策略证伪评审**：命中检测 = **规则式确定性检查 + 人工确认**，**页面实时判定 + 飞书日终汇总一次**；飞书文案仅项目名 + 命中条件名（隐私口径）；评审结论结构化（维持/减仓/退出/修订策略 + 理由），处置留痕入 journal 时间线。
- **F16 复盘归档与知识回流**：复盘结论一键回流 M13 wiki（**用户确认后入库**，不自动回流）；模板改进建议结构化沉淀（只收集不生效），反哺 SOP v2。

## 四、四个签名机制深剖（跨块串联）

### 4.1 纪律检查链路（F09/F10/F12 共用）

```
检查上下文（策略文档 + 建仓计划 + 检查单输入）
        + PrincipleRule 集（M13：单票/行业仓位上限、PE/PB 上限）
        ↓ 【纯函数领域服务，NFR-3 可单测全覆盖】
   命中项列表（哪条规则、阈值、当前值）→ 可解释
        ↓
   软提醒卡片（项目页确认流）→ 用户确认 / 越过（必填理由）
        ↓
   留痕（时间、命中项、结论、理由）——只增不改
```

关键点：检查是**纯函数**（输入上下文 + 规则集 → 输出命中项），规则阈值来自 M13 PrincipleRule（4 指标枚举），未配置给「未设定」中性结论——既不纵容也不误伤。

### 4.2 证伪机制（F06 定义 → F15 执行）

投资 SOP 的灵魂是「知道自己错了」。链路：策略定稿时写证伪条件（价格/估值谓词 + 事件勾选）→ 持仓期间页面实时纯函数判定（跌破下限、PE 超阈）→ 命中即日终飞书汇总 + 页面提醒 → 用户发起评审 → 结构化处置（维持/减仓/退出/修订）+ 理由留痕。**每次命中可解释**（哪条条件、依据什么数据），避免黑盒判定。

### 4.3 复盘数据链（F14）

analytics 是唯一真源：跨域经 application 层编排取净值序列/流水 → 自动算买卖点 vs 后续走势、区间收益（标注口径）→ 作为草稿带入复盘模板 → 用户覆盖编辑。「无数据」标注而非留白；自动计算与手算一致性是 MS-27 验收口径。

### 4.4 知识回流闭环（F13/F16 → F01 v2）

复盘结论（确认后）→ wiki 可检索；改进建议（对应阶段/来源复盘）结构化留存 → SOP v2 内容迭代输入。**只收集不自动生效**——方法论演进必须人审，与 F01「用户评审定稿」同一门槛。这一环让 SOP 不是死模板，而是随使用进化的活系统。

## 五、边界与依赖

**复用 vs 新建**：复用 Skill 系统、M13 wiki/PrincipleRule/seeding、journal 时间线、analytics、chart spec 双通道先例、审批卡片 UI 形态、（顺延）M15 情报与飞书通道；新建仅 `domain/research` 域、`/research` 前端页、检查单确认流、证伪检测纯函数。**明确不做**（YAGNI 八条）：硬拦截、估值自动计算、技术面分析、强制线性流转、多策略组合、自动下单、社交分享、RAG。

**依赖风险**：M15 是唯一外部依赖（零代码现状），已做验收拆分对冲；F01 内容定稿是 MS-24 关键路径，阻塞 F02/F03 开工。
