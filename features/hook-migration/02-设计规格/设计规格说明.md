# Hook forRemoval 专项（hook-migration）设计规格说明

> 创建：2026-10-12 | 上游：[需求规格说明](../01-需求规格/需求规格说明.md)（v1.0，含能力矩阵与决策汇总）
> 状态：v1.0 待评审
> 代码锚定：以下 file:line 以 main=f5a41217（PR #110 合并后）为基线。

## 一、设计总览

三个生产 Hook 按 2.0.4 Middleware 能力矩阵分流：**两个纯观测职责（Observability/ReportUsage）全迁移**到单点拦截中间件；**一个 Msg 改写职责（Trust）留守** Hook API 并文档化重开触发条件。迁移后 main 代码的 Hook 引用面收敛到 TrustAgentHook 一处，2.1.x 升级的改造面随之收敛。

```
迁移前（现状）                                迁移后
─────────────────────────────                ─────────────────────────────
.hook(trustHook)            ← 保留           .hook(trustHook)                  ← 留守（rc 仍走桥接）
.hook(observabilityHook)    ← 迁移           .middleware(rcBridge(trust))
.hook(usageHook)(report 路) ← 迁移           .middleware(observabilityMiddleware)   ← 新
.middleware(rcBridge(2~3))  ← 瘦身           .middleware(usageMiddleware)(report 路) ← 新
.middleware(wireId)                          .middleware(wireId)
```

核心时序事实（设计成立依据，2.0.4 源码实证）：

1. **onAgent 链包在 runLifecycle 外侧**（`ReActAgent.buildAgentStream`）：PRE_CALL/POST_CALL 等 Hook 事件在链内侧核心内触发——外层中间件的 `doFinally`/`doOnComplete` 天然晚于 Trust 的 POST_CALL 兜底收尾，`trustHook.lastReport()` 读取时 Trust 已处理完本回合（**替代 ObservabilityAgentHook 的 priority=200 装配序**，无需 Hook/Middleware 混排协调）。
2. **事件全量可见**：模型级事件（ModelCallStart/End、TextBlock 系）经 EVENT_SINK 发布上行，onAgent 层可见全部——单点过滤即可覆盖 reasoning+summary 双路的 usage。
3. **ctx 同源**：onAgent 的 `ctx` 参数即 `ensureSessionDefaults` 派生的 effective rc（与工具装饰器、TrustContext 池同源，PR #110 已实证）——两新中间件不再依赖桥接。

## 二、组件设计

### 2.1 `ObservabilityAgentMiddleware`（新建，`agent/observability/`）

```java
public final class ObservabilityAgentMiddleware implements MiddlewareBase {
    // 依赖注入同 ObservabilityAgentHook：ObservabilityRecorder + TrustAgentHook（lastReport 并集源）+ ObjectMapper
    // 回合态字段同构迁移：turnRecorded / promptTokens / completionTokens / usageSeen /
    //                     turnStartReport（identity 护栏基线）/ startNanos（见 §三简化）
    @Override
    public Flux<AgentEvent> onAgent(Agent agent, RuntimeContext ctx, AgentInput input,
            Function<AgentInput, Flux<AgentEvent>> next) {
        onTurnStart();                                    // 重置 + nanoTime 起点 + trust 报告快照
        return next.apply(input)
                .doOnNext(this::onEvent)                 // ModelCallEndEvent→accumulate；AgentResultEvent→record(result,false,null)
                .doOnError(error -> record(null, true, error));
    }
}
```

- **职责映射**（Hook → Middleware 事件源，逐条等价）：

| 现职责（Hook 事件） | 新事件源（onAgent 层） | 口径 |
|---|---|---|
| PRE_CALL 重置/起点 | `onTurnStart()`（onAgent 入口，先于核心内 PRE_CALL） | 同 |
| POST_REASONING/POST_SUMMARY usage 累计 | `doOnNext` 过滤 `ModelCallEndEvent.getUsage()` | input/output 原值；缺席→三分量 null；reasoning+summary 双路都发此事件 |
| POST_CALL 正常轮落库 | `doOnNext` 过滤 `AgentResultEvent.getResult()` | 最终 Msg 落库；messageId 回退 Msg id |
| ErrorEvent failed 轮落库 | `doOnError(Throwable)` | 错误摘要类名+消息截断 200 码点不变 |
| 防双写 | `turnRecorded` 标记（AgentResultEvent 与 doOnError 理论互斥，防御双发） | 同 |

- **落库组装零改动**：`record()` 内 userId/sessionId/messageId 解析（`rc.getUserId()/getSessionId()`、RC_KEY 优先回退 Msg id）、`trustStats()` 六键标量并集（identity 护栏：本轮 trust 无新报告→null）、`mapTools()`（`TrustContext.current(ctx).invocations()` 当轮实录，历史池不进观测）、`calledAt` 回解、`argsJson` 降级——逻辑与方法体原样迁移。
- **次序取消**：删除 `priority()=200` 覆写（中间件层无 Hook 比较器参与）；装配序不敏感（§一事实 1）。

### 2.2 `ReportUsageMiddleware`（新建，`agent/report/`）

```java
public final class ReportUsageMiddleware implements MiddlewareBase {
    // LongAdder totalTokens + ConcurrentLinkedQueue<ToolInvocation> truthInvocations（并发语义同 ReportUsageHook）
    @Override
    public Flux<AgentEvent> onAgent(Agent agent, RuntimeContext ctx, AgentInput input,
            Function<AgentInput, Flux<AgentEvent>> next) {
        return next.apply(input)
                .doOnNext(this::accumulate)      // ModelCallEndEvent → totalTokens.add(input+output)
                .doOnComplete(this::collectTruth); // TrustContext.current(ctx).invocations() 快照入队
    }
    public long totalTokens() { ... }              // 签名/语义不变（编排器读数口）
    public List<ToolInvocation> drainTruthInvocations() { ... }  // 排空语义不变（防跨轮重复累计）
}
```

- 真值快照时点：`doOnComplete` 晚于核心内 state 落盘与 Trust 的 POST_CALL（清 ThreadLocal 兜底通道不动 rc 池）——与现状 POST_CALL 时序等价、读取安全同款论证（MS-32 类注释②结论原样成立）。
- usage 缺席安全跳过、采集异常 WARN 降级（任务将在校验门如实红）——同现状。

### 2.3 删除与涟漪

- 删 `ObservabilityAgentHook.java` / `ReportUsageHook.java`。
- `ReportAgentRunner.create(Long, ReportUsageHook)` → `(Long, ReportUsageMiddleware)`；`ReportAgentRunnerFactory` / `HarnessReportAgentRunner` 同步；`ReportWorkflowOrchestrator` 每任务 `new ReportUsageHook()` → `new ReportUsageMiddleware()`。
- `RuntimeContextBridgeMiddleware`：两装配点消费者瘦身为 `trustHook::setRuntimeContext` 单消费者；javadoc「三个生产 Hook」表述更新为「TrustAgentHook（留守，02-设计规格 §五）」。

### 2.4 `HarnessAgentFactory` 装配（双路径同构）

```java
// build(Long)
TrustAgentHook trustHook = new TrustAgentHook(trust);
ObservabilityAgentMiddleware observability =
        new ObservabilityAgentMiddleware(observabilityRecorder, trustHook, mapper);
...
.hook(trustHook)
.middleware(new RuntimeContextBridgeMiddleware(trustHook::setRuntimeContext))
.middleware(observability)
.middleware(new TrustWireMessageIdMiddleware())
// buildReportAgent 追加：.middleware(usageMiddleware)（参数类型 ReportUsageMiddleware）
```

中间件注册序（bridge → observability/usage → wireId）即执行序；时序正确性由 §一事实 1/3 与注册序保证（终审勘误：2.0.4 `MiddlewareChain` 不做 order 排序——javap 全扫 core+harness 无 order() 调用，链序=纯注册序，自尾向头包裹、先注册=最外层；bridge 先注册故最外层，语义同现状）。

## 三、数据流与时序（含两处有意简化）

1. **时延起点简化**：`RC_TURN_START_NANOS` 的 rc typed 属性**取消**，降级为实例字段 `startNanos`（原 fallbackStartNanos 路径转正）。理由：全仓无跨组件读者（grep 实证），rc 通道是 Hook 时代为「PRE_CALL 写、POST_CALL 读」服务的；中间件闭包内同回合读写，实例字段即足。`durationMs` 口径不变（nanoStart 折毫秒、下限 0 防时钟回退、无起点 null）。
2. **record 时点**：`AgentResultEvent` 在 `AgentEndEvent` 前发出（buildAgentStream 实证），doOnNext 拦截即落库——与 POST_CALL（runLifecycle 尾部）时序几乎同点，观测行 `recorded_at` 取 `Instant.now(clock)` 口径不变。
3. **messageId 读取时点**：record 发生在回合末，`TrustWireMessageIdMiddleware`（onModelCall，核心内侧）已完成 RC_KEY 写入——与现状 POST_CALL 读取同点，复合 id（PR #110）解析逻辑零改动。

## 四、错误处理（NFR-3 红线）

- onAgent 内 `onTurnStart`/`onEvent`/`record`/`collectTruth` 全部 try/catch 包裹：观测侧 ERROR 留痕 + 流原样放行；真值侧 WARN 留痕（任务在校验门如实红）——与现状双层防御第一层等价迁移，SSE 不因观测旁路中断。
- `doOnError` 落库自身的异常同样吞并（吞并中的吞并，现状 onEvent try-catch 同款）。

## 五、TrustAgentHook 留守与重开触发条件

**留守理由**（能力矩阵 ❌ 两项 + ⚠️ 一项）：2.0.4 Middleware 无 Msg-metadata 写入口（跨轮真值池 §2.2 持久化断链）、无 summary 路径 state 改写口（maxIters 耗尽锚点降级）、末轮改写 wire/state 单一源头（流式 UX 牺牲）——全迁必然损失 MS-29 已交付能力。

**重开触发条件**（满足其一即另立任务迁移 Trust）：

1. **2.1.0 正式版删除 Hook 系**（届时即使能力缺口仍在，也被迫迁移——需先按缺口做功能降级设计评审）；
2. **上游补齐口**：Msg metadata 写入口（或等价的 state 侧回合末改写口）+ summary 路径 `replaceAccumulatedText` 同款机制——届时做无损迁移。

评估入口：2.1.0 发布时对照 [版本演进调研](../../../docs/research/2026-10-11-AgentScope-Java版本演进调研.md) §3.2 的 #3441（harness context 重设计）与官方迁移指南；调研结论有效期约一个月，届时需更新勘测。

落点：本节 + `TrustAgentHook` javadoc 钉版注记 + `docs/technology/modules/01-Agent实现.md` 注记。

## 七、风险与待定项

| 风险 | 缓解 |
|---|---|
| onAgent 层事件可见性与 2.0.4 内部发布路径的耦合（EVENT_SINK 机制变更会静默断流） | 集成测试钉住「事件到达」语义（观测行落库即证）；2.1.x 升级时本节重勘 |
| doOnNext 内落库阻塞 Reactor 线程（现状 Hook 事件线程同款） | recordTurn 端口实现侧已有异步/自吞防御（MS-30 Task 8）；不新增阻塞面 |
| 中间件实例随 agent 按请求构建的前提被打破（未来复用 agent） | 与现状 Hook 同前提；NFR-5 记录，届时回合态字段需改 rc 携带 |
| BDD 剧本模拟失真（模拟的 onAgent 与真实装配路径行为分叉） | 剧本注释保留「模拟派生 rc」字节码行为论证；集成测试用真实 HarnessAgent 兜底 |
