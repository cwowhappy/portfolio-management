# Hook forRemoval 专项（hook-migration）需求规格说明

> 创建：2026-10-12 | 性质：工程专项（非产品功能）| 分支：`chore/hook-migration`（全周期同分支同 PR）
> 状态：**v1.0 定稿（2026-10-12 brainstorming 收口，成功标准与拦截点拓扑均经用户裁决）**
> 上游：[AgentScope Java 版本演进调研](../../../docs/research/2026-10-11-AgentScope-Java版本演进调研.md) · [agentscope 2.0.4 升级计划](../../plans/2026-10-11-agentscope-2.0.4升级.md)（PR #110 已合并，main=f5a41217，遗留「2.1.x 前置专项」即本特性）

## 一、背景与目标

AgentScope 的 Hook 系自 2.0.0 起标记 `@Deprecated(forRemoval=true)`，2.0.4 仍未兑现删除但官方口径明确「Middleware 取代整个 Hook 系统」。本项目有三个生产 Hook 挂在 HarnessAgent 上（TrustAgentHook / ObservabilityAgentHook / ReportUsageHook），另有十余个测试与 BDD 装配直接构造 Hook 事件对象——一旦上游兑现删除（最早 2.1.0），升级即被阻断。

本专项目标：**按 2.0.4 Middleware 能力矩阵把可无损迁移的部分迁净，把不可无损的部分（TrustAgentHook）文档化留守并定义重开触发条件**，使未来 2.1.x 升级的改造面收敛到零或仅剩 Trust 一处。

### 2.0.4 Middleware 能力矩阵（源码实证，设计依据）

| 能力需求 | 2.0.4 口 | 结论 |
|---|---|---|
| usage 逐次累计 | `ModelCallEndEvent.getUsage()`（reasoning+summary 双路均过 onModelCall 链，事件上行至 onAgent 层） | ✅ 等价 |
| 回合边界/起点/终态 | `onAgent` 入口 + `doOnNext`/`doOnError`/`doFinally` | ✅ 等价 |
| 最终 Msg 读取 | `AgentResultEvent.getResult()`（onAgent 流内） | ✅ 等价 |
| 真值池轮末快照 | `onAgent` 完成时点（晚于核心内 state 落盘，与 POST_CALL 时序等价） | ✅ 等价 |
| 末轮文本改写→stateStore+返回值（Trust） | onModelCall delta 变换→`replaceAccumulatedText` | ⚠️ wire/state 单一源头，流式 UX 牺牲 |
| POST_SUMMARY 路径 state 改写（Trust） | `summaryStream` 无 replaceAccumulatedText 机制 | ❌ |
| Msg metadata 写入（Trust 跨轮池 §2.2） | 无口（AgentResultEvent 改写仅达返回值半边） | ❌ |

## 二、澄清决策汇总

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| 1 | 成功标准（用户 2026-10-12 裁决） | **扫清障碍即可**：两观测 Hook 无损全迁；TrustAgentHook 留守 Hook API 并文档化触发条件。不以「main 零 Hook API」为目标 | 全迁必然损失 MS-29 两项已交付能力（跨轮池持久化、summary 路径 state 改写）+ 流式 UX 变更；零功能损失、风险最小；2.1.x 若与 2.0.4 一样不兑现删除，Trust 甚至无需再动 |
| 2 | 拦截点拓扑（用户确认） | **单点拦截**：每枚新中间件只覆写 `onAgent`，usage/边界/终态/错误在 doOnNext/doOnError/doFinally 事件过滤中闭环 | 链上节点最少；外层完成信号天然晚于核心内 Hook 的 POST_CALL——`lastReport()` 读取时 Trust 已收尾，**替代 priority=200 装配序机制**；FinalAnswerFilterMiddleware 同款单层过滤先例 |
| 3 | 旧类处置 | ObservabilityAgentHook / ReportUsageHook **删除**（不留弃用壳） | 成功标准=扫清障碍；留壳违背「迁净」且仍占 Hook 引用面 |
| 4 | 公开 API 兼容 | `totalTokens()` / `drainTruthInvocations()` 方法名与排空语义不变（落在 ReportUsageMiddleware） | 编排器（B9）消费面零改动语义；BDD 剧本契约（真值通道）不变 |
| 5 | Trust 留守重开触发条件 | 满足其一：① 2.1.0 正式版删除 Hook 系；② 上游补 Msg-metadata 写入口或 summary 路径 state 改写口 | 见 02-设计规格 §五 |
| 6 | 落位 | `features/hook-migration/` 全周期（规格/计划/复盘同目录）+ 分支 `chore/hook-migration` | 用户指定遵循特性开发流程 |

## 三、功能需求

- **FR-1** 新增 `ObservabilityAgentMiddleware`（`agent/observability/`）：单点拦截 onAgent，承担 ObservabilityAgentHook 全部职责——回合重置与 nanoTime 起点、usage 逐次累计（input/output 原值、缺席三分量 null）、正常轮落库（AgentResultEvent）、failed 轮落库（doOnError，错误摘要截断 200 码点）、trust 六键标量并集（identity 护栏）、工具观测行映射（TrustContext 当轮实录）、messageId/userId/sessionId 解析（RC_KEY 优先回退 Msg id）。
- **FR-2** 新增 `ReportUsageMiddleware`（`agent/report/`）：单点拦截 onAgent，usage 累计 + 完成时真值快照入并发队列；`totalTokens()` / `drainTruthInvocations()` 签名与语义不变。
- **FR-3** 删除 `ObservabilityAgentHook` / `ReportUsageHook`；`ReportAgentRunner` / `ReportAgentRunnerFactory` / `HarnessReportAgentRunner` 参数类型替换。
- **FR-4** `HarnessAgentFactory` 双装配点：Trust 留 `.hook()`，两新中间件入 `.middleware()` 链；`RuntimeContextBridgeMiddleware` 消费者瘦身为仅 trustHook。
- **FR-5** `TrustAgentHook` 行为零改动；javadoc 钉版注记更新（留守裁决 + 触发条件指向本特性 02-设计规格 §五）。
- **FR-6** 测试迁移（15 文件引用面）：重写 2（Hook 测试→中间件测试，GWT 命名）、适配 11（装配断言/类型替换/探针 3 事件源/BDD 剧本模拟改 onAgent 合成事件流）、注释引用 2。

## 四、NFR（非功能需求）

- **NFR-1 零功能损失**：观测两表（turn_observation / tool_invocation_obs）落库口径、字段、时延语义零变更；真值通道（drain）契约零变更。
- **NFR-2 红线**：TrustAgentHook 行为零变更；AG-UI wire 契约零变更；对话链路 `build(Long)` 除中间件装配外零变更；`systemPrompt` 字节级不变。
- **NFR-3 观测旁路失效不断对话**：onAgent 内全部拦截逻辑异常吞并留痕（ERROR/WARN 分级同现状）。
- **NFR-4 覆盖率 ≥80%**（JaCoCo 指令+分支）；ArchUnit 21 条规则全过（含 GWT 测试命名）。
- **NFR-5 并发安全**：中间件实例随 agent 按请求构建（现状同构）；回合态字段并发语义不低于现状。

## 五、验收标准

1. `make test-backend` 全绿（单元+切片 / Testcontainers 集成 / BDD / ArchUnit / JaCoCo 双门槛）。
2. `make smoke`：观测链路证据链不降——turn_observation 落行 user_id 非空、trust Custom 事件复合 messageId 同源（Trust 零改动的旁证）。
3. `cd frontend && pnpm test:e2e` 全绿（fresh build；HITL 审批卡用例）。
4. `grep -r "io.agentscope.core.hook" backend/src/main` 仅剩 TrustAgentHook 一处 import 面（Trust 留守的机器可验证口径）。
5. 终审（最强档位全分支评审）通过。

## 六、YAGNI（明确不做）

- 不做 TrustAgentHook 迁移（决策 #1；触发条件见 02-设计规格 §五）。
- 不为 2.1.0 未公布的 API 预留抽象层/接口（harness context 重设计 #3441 可能再变，预设接口是投机）。
- 不动 TrustWireMessageIdMiddleware / RuntimeContextBridgeMiddleware 的机制本身（仅瘦身消费者与 javadoc）。
- 不做前端任何改动。
