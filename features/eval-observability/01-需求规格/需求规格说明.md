## 一、背景与目标

agent-testing 特性（跨 MS-16~19）建立了 eval 起步资产：对话轨 34 题（九维结构断言 + LLM-judge 双层计分）与抽取轨 22 题，`src/eval` 独立源集 JavaExec 手动跑、`compileEvalJava` 挂 check 编译防漂。但它是**手动工具而非生产体系**（[侦察报告](../09-调研报告/2026-10-06-立项侦察与隔离方案评估.md) 证实）：

- **无回归机制**：退出码恒 0、无阈值判定、无定时、无告警；报告覆盖写 `backend/build/reports/` 不落库，历史仅靠手动归档；
- **无版本锚点**：提示词资产五类（系统提示词 1 + `@Tool` 描述 16 + SKILL.md 6 + 情报抽取 prompt 4 + eval judge 模板/rubric）全部硬编码、零版本概念——评测结果无从锚定「当时用的提示词」，回归比对无基准（阶段三规划决策 #5 点名 D4.3 为 eval 关联前置）；
- **无线上观测**：对话链路 token usage 未消费（`emit-token-usage: true` 已配但全链零消费）、LLM 与工具调用零耗时记录、日志纯文本无 requestId——规划「复用现有日志」的前提不成立，唯一结构化留痕是 MS-29 的 `trust.turn` 回合日志与 `RecordingAgentToolDecorator` 内存调用池（有 callTime 无 duration、不落库）；
- **规划口径过期**：「现 11 条人工维护」实为 14 条工具规范编号规则 + 16 个 `@Tool`，提示词资产全集 31 条目（侦察修正）。

本特性（MS-30）交付**生产化评测体系 + 线上观测底座**：三类金融 QA 基准（行情事实/指标计算/幻觉诱导——承接 D1.4 幻觉率指标与 MS-29 后置的方向词关注项）、backend 调度的每晚定时回归与相对回归阈值告警（飞书留痕）、提示词登记制版本化（eval 关联版本）、工具调用与对话轮双层观测落库 + admin 看板。全部复用既有资产：eval 双层计分框架、`--compare` 对比、`RecordingAgentToolDecorator` 旁路、`AlertNotifier` 飞书+邮件降级链、`IntelligenceCleanupService` 滚动清理先例、AnalyticsBoard/EChart/TanStack 前端形态。

## 二、澄清决策汇总

| # | 决策点 | 结论 | 理由 |
|---|--------|------|------|
| 1 | eval 定时任务宿主（规划 §七点名立项拍板） | **backend `@Scheduled` 触发子进程执行**（阶段三规划 §三编排决策 #3：走系统 key） | 与现有 10 个定时任务同宿主、告警链路同进程复用、部署零新增；子进程形态规避进程内第二 Spring 上下文的静态互扰（agentscope ModelRegistry 双上下文仓库内无法验证）与双调度器问题 |
| 2 | eval 数据隔离（部署机无 Docker，Testcontainers 不可用） | **同 PG 实例独立 schema**：datasource URL `currentSchema` 单旋钮（Flyway/JPA/JdbcTemplate 全覆盖），生产上下文零改动 | 侦察证实 eval datasource 单点注入、全仓 65 表 DDL/实体非 schema 限定、无命名序列——改动面最小；对比独立 database 免验 pg_trgm trusted extension、免多库对象 |
| 3 | 独立 schema 三伴生条件 | ① **eval 上下文禁一切生产副作用任务**（`@Scheduled` 调度与 seeder 在 eval 上下文不得存活——否则新闻抽取批在 eval 环境真调 LLM 外呼）；② **每轮跑前重置 schema**（DROP CASCADE + CREATE + Flyway 全量迁移，复原容器级「每轮全新库」语义）；③ datasource 守卫断言同步改（防连错库初衷保留） | eval 起完整生产装配（`InvestAgentApplication`），容器时代被掩盖的副作用任务在持久环境显形；每轮重置免清理策略维护 |
| 4 | 提示词版本化形态 | **登记制**：真相源留代码/git；版本登记表按资产独立版本链（内容快照 hash + 变更说明），启动/eval 运行时对账自动登记 | 决策 #5 定位「eval 关联的前置」——目的是锚定版本不是改分发链路；入库制（DB 存储+加载链路全改+热载）违背 YAGNI，git 失去真相源 |
| 5 | 三类基线规模 | **每类 8~10 题合计 ~25**；每晚全量 81 题（34 对话 + 22 抽取 + ~25 新增） | 覆盖三类核心场景且统计效力可用；DeepSeek flash 价格下每晚成本个位数人民币量级；5 题最小集阈值告警易抖动、15+ 集 upfront 出题维护成本大 |
| 6 | 观测采集落点 | **双层落库**：工具调用级（`RecordingAgentToolDecorator` 加 duration 落表）+ 对话轮级（token 消费 + 轮时延落表）；`trust.turn` 同源信号并入 | 侦察证实「复用现有日志」字面不可行（无 trace/token/时延数据）；decorator 是现成旁路（记录全部工具调用，缺 duration 与落库）；个人系统量级可全量记录 |
| 7 | 特性目录归属 | **新建 `features/eval-observability/`** 承载 MS-30 全范围；agent-testing 交付回填时补收口注记 | 里程碑↔特性一一对应（trust-provenance 先例）；版本化+看板超出 agent-testing「测试加固」语义 |
| 8 | 阈值判定形态 | **相对回归**：以最近一次人工确认良好的运行为 baseline 参照，通过率降幅 / PASS→FAIL 翻转数超阈值（`InvestProperties` 可配）即告警 | 对话轨基线 pass 率 62%，绝对分数线难定且模型侧抖动易误报；相对回归直指「劣化」本意 |
| 9 | 幻觉诱导类判定口径 | **结构断言主导**（期望行为 = 拒答/声明无数据/不出现编造具体值）+ judge 辅评拒答自然度（复用 `rubric-refusal` 先例）；MS-29 校验器指标（诱导题未溯源标注率/拦截率）作附加度量 | 与现有双层计分架构一致；judge 主导在幻觉题上自身稳定性存疑；纯规则检测僵化（换说法即漏） |
| 10 | 不完整运行语义（grilling R1-Q2） | 单题 ERROR **视同 FAIL** 计入告警判定；整跑总时长护栏可配，超时中止剩余题、标记 PARTIAL；**PARTIAL 运行不任 baseline** | 防「异常多→分母小→通过率虚高」漏报漏洞；PARTIAL 参与告警判定（保守方向）但不得担任参照 |
| 11 | 版本可比性条件（grilling R1-Q3） | eval 运行记录**全资产版本快照 + 题库内容 hash + rubric 版本快照**；跨题库/rubric 变更的对比标注「不可比——基准已变更」 | rubric/题库变更本身影响评测结果，只有「同基准 × 变提示词/模型」才是回归判定的合法对象 |
| 12 | 版本变更说明来源（grilling R1-Q3） | 自动登记允许空说明（标「未注记」），看板补注；不假装从生产 jar 拿 commit message | 自动对账只能发现 hash 变化；未注记变更看板可见，欠账显性化 |
| 13 | 观测数据边界（grilling R1-Q4） | 工具级 `resultText` **截断落库**（~2KB 可配；args 全量 + specs 计数）；token **三值全记原始数**（prompt/completion/total，不做入库单价换算——看板可选配单价展示估算成本）；失败/异常轮**照记**（failed 标记 + 异常摘要） | 完整原文已有 `chat_message.payload`/图表通道留痕，观测表职责是 trace/成本/时延非存档；单价易变属展示层；失败是重试成本与时延视图的重要信号 |
| 14 | 新题轨属与告警粒度（grilling R1-Q5） | **同轨 category 扩展**（`EvalQuestion.category` 现有四类先例，报告按类分组出分）；**总轨 + 三新类分类双判定**：总通过率降幅 OR 任一新类分类降幅/翻转超阈值即告警；抽取/对话老题仅参与总轨 | 独立轨 = 重复 runner/报告/schema 无增益；幻觉率劣化单独可见是 D1.4 本意 |
| 15 | 计算类断言容差（grilling R1-Q5） | 指标计算类期望值断言带**相对容差**，具体数值入 `InvestProperties` 可配（对齐 MS-29 校验器 2% 量级）——需求定「有容差、可配」，数值设计规格定 | LLM 数字表述有舍入习惯，零容差误杀；数值锁死在需求层无弹性 |
| 16 | 告警行为（grilling R2-Q2） | 持续劣化**每晚告警**（不去重）+ **恢复通知**（劣化消失后下一跑发「已恢复」，该跑升级 baseline 候选——仍需人工确认标记）；飞书 `AlertNotifier` 卡片 + 邮件降级沿三处先例 | 日级告警不去重（「还没修」是有效信号）；恢复自动担任参照会误采纳抖动样本，人工确认保留 |
| 17 | admin 管理面形态（grilling R2-Q3） | **`/admin` 单页四区块**：trace/成本/时延三视图 + **提示词版本视图**（版本链列表、未注记标记、补注编辑、与 eval 运行关联展示）；eval 运行历史内嵌 baseline 标记与手动触发；CLI `make eval-*` 保留 | admin 区先例 + AnalyticsBoard 单页多区块形态；不另开路由不拆页面；观测数据含全用户成本数据故 admin-only |
| 18 | smoke.sh 挂 CI 形态（grilling R2-Q4） | GitHub Actions **`schedule` 每日 + `workflow_dispatch` 手动**；**不挂 PR**（真行情 + 真 LLM 成本，方向决策 #2 同理由）；密钥走 repo secrets | 腾讯 fixture 漂移探测价值随 schedule 兑现；PR 挂真 LLM 与 eval 不挂 PR 先例同理 |

**P3 归属留痕（决策外附记）**：code-review-2026-10 P3「评测/提示词域」分摊清单存在事实缺口（无文档逐项枚举，[侦察报告](../09-调研报告/2026-10-06-立项侦察与隔离方案评估.md) §5）。本次裁决：**「smoke.sh 未挂 CI」随 MS-30 清零（决策 #18）**；**「domain 藏系统时钟」归属 MS-32 深度研究**（research 域为 `Instant.now()` 直调重灾区——`Review`/`ResearchProject`/`StrategyDoc`/`Falsifier` 等 30+ 处，MS-32 本就要大动 research 域，顺手统一成本最低；本特性不认领）。

## 三、功能需求（D4-1~D4-4，编号承方向规划，不增删改）

### D4-1 eval 三类基准扩充

**描述**：在现有对话轨题库上扩充三类金融 QA 基准（合计 ~25 题），复用 `EvalStubMarketService` 逐题桩注入 + 九维结构断言 + LLM-judge 双层计分框架；`EvalQuestion.category` 扩展三类，报告按类分组出分。

**业务规则**：

- **行情事实类**（8~10 题）：价格/涨跌幅/市值/成交额直查——模型应调工具取数并准确复述；断言含 entityAlignment/dataFidelity，judge 按 `rubric-answer-quality` 评 0-5。
- **指标计算类**（8~10 题）：PE/PB/涨幅/估值分位类推导问题——考验工具链组合调用与数字表述；期望值断言带相对容差（决策 #15，数值可配设计规格定）。
- **幻觉诱导类**（8~10 题）：诱导编造不存在的股票/政策/数据（桩数据自然为空或查无）——**断言主导**（决策 #9）：期望行为 = 拒答 / 声明无数据 / 不出现编造的具体数值；judge 辅评拒答自然度（复用 `rubric-refusal-naturalness` 三场景先例）；**MS-29 交接项并入**：诱导题上校验器的未溯源标注率/拦截率作附加度量列（承接 D1.4 幻觉率指标进基线与 MS-29 后置的方向词关注项——方向词校验本里程碑不实现，作为基线可观测项跟踪）。
- 题库落 `src/eval/resources/questions/` 既有目录结构与装载 fail-fast 校验；分类通过率进报告汇总与告警判定（决策 #14）。

**边界与异常**：诱导题的桩行情「查无」路径必须真实走空结果分支（不得因桩配置错误变成事实题）；计算类容差判定失败时报告须呈现期望值与实际表述原文供人工复核。

### D4-2 eval 回归触发（定时 + 手动 + 阈值告警留痕）

**描述**：eval 从手动 JavaExec 升级为 backend `@Scheduled` 调度的每晚定时回归 + admin 手动触发，配套相对回归阈值判定与飞书告警留痕；eval 运行结果落库形成可查历史。

**业务规则**：

- **执行形态**（决策 #1/#2/#3）：`@Scheduled` 触发**独立子进程**执行 eval（单上下文规避双上下文互扰）；子进程 datasource 指向**同实例独立 schema**（`currentSchema` 连接级隔离，生产上下文零改动）；每轮跑前重置 schema（DROP CASCADE + CREATE + Flyway 全量迁移）；eval 上下文**禁一切生产副作用任务**（`@Scheduled` 调度与 seeder 不得存活）；datasource 守卫断言指向 eval schema（防连错库）。抽取轨无 DB 依赖零改造。子进程打包形态（eval 类进 bootJar 或独立发行物）归设计规格。
- **定时**：每晚一跑全量（对话 34 + 抽取 22 + 三类新增 ~25 = 81 题），时段按现有任务错峰原则选（设计规格定）；真 LLM 走系统 key（阶段三规划 §三编排决策 #3：系统调度任务用系统 key，eval 回归属此列）。
- **手动**：admin 触发端点（异步执行 + 运行状态查询，新先例）+ `make eval-agent`/`eval-extraction` CLI 保留。
- **阈值判定**（决策 #8/#10/#14）：以人工标记 baseline 的运行为参照——总通过率降幅超阈值 OR PASS→FAIL 翻转数超阈值 OR 三新类任一分类劣化超阈值 → 告警；单题 ERROR 视同 FAIL 计入；整跑总时长护栏可配，超时中止剩余题标 PARTIAL；**仅完整（非 PARTIAL）运行可任 baseline**。
- **告警留痕**（决策 #16）：飞书 `AlertNotifier` 卡片 + 邮件降级（沿 PrincipleAlert/FalsifierScan/MacroHealth 三处先例）；持续劣化每晚告警；恢复通知后该跑升级 baseline 候选（人工确认生效）；**eval 运行落表**——每次运行记录触发方式（定时/手动）、各轨各分类得分、阈值判定结论、告警状态、提示词版本快照、题库 hash、rubric 版本（决策 #11）、耗时与完整性标记。
- **基线对比**：`--compare` 既有差异机制保留；跨题库/rubric 版本的对比在报告标注「不可比——基准已变更」（决策 #11）。

**边界与异常**：定时任务顶层 try/catch 护调度线程（沿现有 10 任务先例）；eval 子进程崩溃/超时由调度侧收割（进程退出码 + 时限双保险），崩溃运行按 PARTIAL 语义处理（不任 baseline、参与告警判定）；DEEPSEEK_API_KEY 缺失时静默跳过并留痕（沿 `AgentScopeIntelligenceChatPort` 空 key 整批跳过先例）。

### D4-3 工具提示词版本化（登记制）

**描述**：提示词资产建立版本登记——真相源留代码/git，登记表记录每资产的版本链与变更历史，eval 运行关联当时的全资产版本快照，使「提示词变更前后的评测对比」有锚点。

**业务规则**：

- **登记资产五类**（决策 #4，自动对账成本低故全量）：系统提示词（`InvestSystemPrompt.TEXT`）1 条、`@Tool` 描述 16 个（`InvestTools` 13 + `UserInvestTools` 3）、SKILL.md 6 份、情报抽取 system prompt 4 条（News/Announcement/Policy/BriefLead）、eval judge 模板与 rubric。顺带修正规划「11 条」过期口径（实况见 [侦察报告](../09-调研报告/2026-10-06-立项侦察与隔离方案评估.md) §2）。
- **登记机制**：应用启动与 eval 运行时对账——资产内容 hash 变化即自动登记新版本（版本号按资产独立递增）；变更说明允许空（标「未注记」），看板补注（决策 #12）。
- **eval 关联**：eval 运行记录携带全资产版本快照（决策 #11），与题库 hash、rubric 版本共同构成运行的可比性指纹。

**边界与异常**：登记失败不阻断启动（告警留痕，沿可信机制自身失效宁可降级不阻断先例）；登记制不改提示词加载链路（运行时仍读代码常量/classpath——版本表是登记簿不是数据源）。

### D4-4 线上观测看板（双层落库 + admin 四区块）

**描述**：工具调用级与对话轮级观测数据双层落库，`/admin` 单页看板呈现 trace 明细 / token 成本 / 时延三视图 + 提示词版本视图。

**业务规则**：

- **工具调用级**（决策 #6/#13）：`RecordingAgentToolDecorator` 旁路增强——补 duration，随回合落表；字段含 toolName / args（全量）/ resultText（截断 ~2KB 可配）/ specs 计数 / asOf 与 asOfKind / failed / mcp / callTime / 会话与用户归属。
- **对话轮级**：消费 LLM 响应 token usage（`emit-token-usage` 已开启未消费）三值（prompt/completion/total）+ 轮时延 + 工具调用计数；失败/异常轮照记（failed 标记 + 异常摘要）；`trust.turn` 回合信号（锚定/校验/修正计数，字段名已稳定）并入轮级记录。
- **看板**（决策 #17）：`/admin` 单页四区块——① trace 明细（TanStack 表，时间/会话/工具/时延/成功筛选与分页）；② 成本聚合（EChart，token 按日/按工具分布，可选配单价显示估算成本——不入库）；③ 时延聚合（EChart，轮级/工具级时延分布与趋势）；④ 提示词版本视图（版本链、未注记标记、补注编辑、eval 运行关联展示）+ eval 运行历史（得分、阈值判定、baseline 标记、手动触发按钮）。
- **保留策略**：滚动清理挂 `IntelligenceCleanupService` 先例（每日 04:07 类错峰），保留天数 `InvestProperties` 可配。

**边界与异常**：观测采集**不得阻断对话主链**——落库异步/批量，采集异常降级为日志告警（沿 MS-29 hook 异常直通先例）；旧消息/历史轮无观测数据自然降级（看板仅呈现上线后数据）；观测表含全部用户会话参数，admin-only 访问。

### 工程随附项：P3 顺带清理（决策 #18 + 归属留痕）

- **smoke.sh 挂 CI**：GitHub Actions `schedule` 每日 + `workflow_dispatch` 手动，不挂 PR；腾讯 fixture 漂移探测随 schedule 兑现；密钥走 repo secrets。
- **P3 归属留痕**：「domain 藏系统时钟」归属 MS-32（理由见 §二附记），本里程碑不清零、台账留痕更新。

## 四、非功能需求

1. **成本护栏**：每晚全量 81 题真 LLM 成本控制在个位数人民币量级（DeepSeek flash 单价下）；eval 侧沿用 token 护栏思路（超当日预算中止并告警，参照 `IntelligenceTokenBudget` 先例）——具体限额设计规格定。手动触发不设频控（admin 自担），定时每晚一跑固定。
2. **隔离硬边界**：eval 运行**绝不读写生产业务数据**（独立 schema 连接级隔离 + 守卫断言）；eval 上下文不执行任何生产副作用任务（调度/seeder/外呼）；观测采集只读旁路 + 自有新表，不触碰既有业务表结构。
3. **主链零劣化**：观测采集（decorator 计时 + 轮级 usage 消费 + 异步落库）不明显劣化对话首字时延——计时为纯 `Clock`/nanoTime 开销，落库出主链；采集层异常降级不阻断（沿 MS-29「hook 异常直通」先例）。
4. **覆盖率与测试**：后端 JaCoCo / 前端 V8 ≥80%，`make test` 三端全绿；三类基准题库走 `--list` 装载校验进 CI 编译防漂（`compileEvalJava` 既有机制）；阈值判定/版本对账/告警状态机为纯函数优先（单测密度高）；看板四区块走 Playwright e2e 真浏览器（沿「mock 盲区」教训）。
5. **架构**：新表走 Flyway 迁移（eval 运行表、版本登记表、观测两表——均在生产 schema）；eval runner 核心从 `src/eval` 源集抽为 main 可复用组件时**保持 `compileEvalJava` 防漂断有效**、eval 源集独立性设计不破（切分方案设计规格定）；新增代码按 DDD 分层归位（调度/触发落 application，观测装配落 agent 基建旁路，ArchUnit 白名单按需登记）。
6. **契约同步**：admin 触发端点进 README 端点表；看板与版本视图进模块文档；前端 zod schema 同步；e2e 断言同步。
7. **告警留痕可查**：eval 运行表本身即告警留痕（触发/得分/判定/告警状态），飞书卡片与邮件为通知通道非唯一记录——「留痕」以库表为准（对比 `intelligence_push_log` 先例）。

## 五、验收标准（与规划文档 MS-30 节对齐）

- **三类基线跑通且告警可见**：行情事实/指标计算/幻觉诱导三类在真实模型上全量跑通；诱导类断言主导判定生效（拒答/无数据/不编造）；人为劣化场景（如调高阈值或注入坏基准）下飞书告警触发且运行表留痕可见、恢复通知生效。
- **提示词变更可关联前后评测对比**：改动一处提示词资产 → 对账登记新版本 → 手动触发 eval → 运行记录关联新版本快照，与旧版本运行可对比（同题库/rubric 下可比性成立；跨基准变更标注不可比）。
- **看板呈现真实调用数据**：trace/成本/时延三视图呈现真实对话产生的数据（非 fixture）；工具级时延与轮级 token 有数；版本视图展示版本链与未注记标记。
- **生产形态闭环**：定时回归在无 Docker 部署形态下可执行（独立 schema 重置 + 子进程 + 副作用任务禁用验证——eval 上下文中新闻抽取等任务不跑）；抽取轨定时化零 DB 改造验证。
- **P3 台账**：smoke.sh 挂 CI 清零（schedule 跑通一次）；「domain 藏系统时钟」归属留痕更新。
- **门槛**：`make test` 三端全绿（含 ArchUnit / 链接门禁）；e2e 看板真浏览器通过。

## 六、YAGNI 排除清单（逐条给排除理由）

- **eval 挂 PR 门禁**——方向决策 #2（2026-10-04 已确认）：真 LLM 成本与模型侧抖动，不阻塞 PR。
- **提示词入库制（DB 存储 + 界面编辑 + 热载）**——登记制已满足「变更历史 + 评测关联」本意；加载链路改造与 git 失去真相源代价不成比例（决策 #4）。
- **绝对分数线告警**——对话轨基线 pass 率 62%，绝对线难定且抖动误报（决策 #8）。
- **LLM-judge 主导诱导类判定**——judge 自身在幻觉题上稳定性存疑，且每题多一次调用成本（决策 #9）。
- **token 单价入库换算**——单价易变属展示层，看板可选配置展示即可（决策 #13）。
- **APM 新设施（OpenTelemetry/追踪系统）**——规划明言轻量；双层落库 + 自建看板已覆盖 trace/成本/时延三视图。
- **resultText 全文落库**——`chat_message.payload` 与图表通道已有完整留痕，观测表职责非存档（决策 #13）。
- **baseline 自动升级（无人工确认）**——恢复跑自动担任参照会误采纳抖动样本（决策 #16）。
- **多模型/BYOK 模型对比评测**——D7 BYOK 落地后再议；当前单 DeepSeek 无对比对象。
- **eval 类打包形态预设（bootJar 内置 vs 独立发行物）**——设计规格对照构建配置定，需求层不锁死。
- **跨服务分布式追踪（trace 传播协议）**——单体应用内调用链，无需 W3C traceparent 类设施。
- **agent-testing 历史基线（2026-09-15）重跑归档**——既有归档保留原样；新体系从 MS-30 交付后建立运行历史，不回补。
