# 评测与可观测性加固（MS-30）实施计划 P1

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把 eval 从手动工具升级为「三类金融 QA 基准 + 每晚定时回归 + 相对回归告警 + 提示词版本锚定 + 双层观测看板」的生产化体系。

**Architecture:** backend `@Scheduled` 触发独立子进程（`evalBootJar`）跑 eval，数据隔离走同库独立 schema（每轮重置）；报告 JSON 由生产上下文收割落库（eval_run + 版本登记）并做相对回归判定告警；观测走 agent hook 旁路（decorator 计时 + PreCall/PostCall 时延 + 各轮 usage 累计）经 domain 端口 JdbcTemplate 落两表；`/admin` 单页四区块看板。

**Tech Stack:** Spring Boot 4 / Gradle BootJar 自定义任务 / PostgreSQL 16 Flyway V5 / agentscope Hook（`PreCallEvent/PostCallEvent/PostReasoningEvent`）/ JdbcTemplate（风格 A）/ Next.js 15 + TanStack Table + EChart 6 / GitHub Actions。

**Spec:** [需求规格](../01-需求规格/需求规格说明.md) v1.0 + [设计规格](../02-设计规格/设计规格说明.md) v1.0——计划从规格推导，执行者须两份同读；本计划所有 file:line 锚点以设计规格 §十侦察依据为准。

## Global Constraints

- 后端 DDD 分层（ArchUnit 强制）：agent 禁依赖 `infrastructure/web`（观测落库走 `domain/observability` 端口）。
- Schema 变更走 Flyway：新增 `V5__ms30_eval_observability.sql` 后 `FlywayMigrationCountGuardTest.EXPECTED_MIGRATION_COUNT` 4→5（`FlywayMigrationCountGuardTest.java:22`）。
- 覆盖率 ≥80%（JaCoCo 聚合/V8/pytest），`make test` 三端全绿；链接门禁 `make check-links` 零断链。
- eval 不挂 PR 门禁、不进 CI（方向决策 #2）；`compileEvalJava` 防漂断（build.gradle:238-242）不可破坏。
- 观测表**不建 user_id FK**（弱引用 + 保留期清理，规避 `E2eCleanupScriptCoverageTest` 登记义务）。
- 新端点全部 `/api/admin/**`（路径级 hasRole 自动覆盖，`SecurityConfig.java:71`）。
- 提交信息中文、类型前缀（feat/fix/test/docs/build），逐任务一提交。
- 提示词资产真相源留代码——版本表是登记簿，任何任务不得改提示词加载链路。

## Review Focus

1. **判定边界抖动**：降幅 9.9pp 不告警、10.1pp 告警；翻转 2 题不告警、3 题告警 → Task 5 边界三分测试。
2. **eval 连错库**：datasource URL 不含 `currentSchema=eval_schema` 必须 fail-fast → Task 2 守卫测试。
3. **观测落库异常阻断对话**：端口抛异常时 PostCallEvent 仍正常传播、对话不断 → Task 9 降级测试。
4. **子进程环境泄漏**：ProcessBuilder env 只含白名单变量（ADMIN_*/FEISHU_*/MAIL_*/E2E_* 必须缺席）→ Task 6 env 断言测试。
5. **PARTIAL/劣化跑被标 baseline**：PUT baseline 对非 COMPLETED 或告警跑返回 422 → Task 7 校验测试。
