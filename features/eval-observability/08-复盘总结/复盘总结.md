## 二、经验（值得沉淀）

1. **子进程隔离的三层实证法**：eval 上下文起完整生产装配的雷（seeder 真调 LLM、双调度器）靠三层机制各自实证后落地——env 白名单（seeder「变量缺席即跳过」的运行时语义零改动复用）、类级 `@ConditionalOnExpression`（Eval_MODE 命令行参数，沿全仓唯一先例不引新机制）、schema 双段 `currentSchema=eval_schema,public`（单段下 V3 pg_trgm 算子类解析必炸——三层实证推翻设计稿单段写法并回写规格）。**跨上下文装配方案必须「jar 字节码 + 集成测试」双证实，设计稿的连接 URL 形态不能凭 JDBC 文档直觉写**。
2. **迁移不可变原则的实战回退**（Task 10）：V5 已在分支多提交且 dev 库 public 已应用后，发现注释口径漂移想顺手改——**改内容即 Flyway validate 炸已应用库**，裁定零改动回退、口径修正落在 `TurnObservation` javadoc。教训：迁移合入后注释也是契约，措辞债记 javadoc/文档还，不动迁移。
3. **审查网对「链路型任务」的价值集中在冒烟盲区**：Task 6 的三个 Critical（子进程上下文装配失败 / 陈旧报告跨跑污染 / `jar:nested:` 未识别）全部在「调度→子进程→收割」链上——冒烟只跑 `--list` 没有端到端，恰好盲。链路型任务的审查必须包含至少一次真实子进程起跑证据（e2e 实证后来补上）。
4. **收割口径与执行口径分离**：单题 ERROR「视同 FAIL 计分母」不改 runner 跳过行为、改收割统计口径（改动面最小）；triggered_by 子进程恒 MANUAL、真值归调度侧落库——子进程不可知的字段不要假装知道。
5. **双通道版本登记绕 classpath 边界**：生产 bootJar 无 rubric 资源（eval-only），版本回流走「子进程报告 runMeta 携 hash → 收割器在生产库 upsert」——跨源集资产登记的通用解法。
6. **浮点阈值判定用长整型交叉相乘**：`100·(bp·ct−cp·bt) ≥ 阈·bt·ct` 替代 double 直减（`1.0−0.9=0.0999…98` 会漏报「恰降 10pp」），边界测试钉死。
7. **fixture 取服务层真实产出**（沿 MS-28 教训执行到位）：Task 14 zod fixture 从 Task 7 集成测试真实响应抄录，前端契约零漂移。

## 四、优化建议

1. 首跑后按误报数据迭代题库锚表述（allowedValues 扩充），判定式与阈值不动——数据驱动校准而非拍脑袋改断言。
2. eval 报告（`data-root` 下 JSON）目前无归档策略，建议保留近 N 份滚动清理（磁盘护栏，个人系统量级低优先）。
3. CI smoke 首跑若 runner 到东财/腾讯不可达，考虑加 retry 或换 runner 镜像（job 已有失败诊断步骤，定位成本低）。
4. 题库 category 词表（`MARKET_FACT`/`METRIC_CALC`/`HALLUCINATION_INDUCTION`）与 judge 常量是隐式契约（错则静默旁路）——后续加一道装载期词表校验断言。
5. ClassOrderer 显式排序建议在下一轮后端构建策略调整时一并拍板（评测域 `EvalPostgresProvisionerIntegrationTest` 的 `@AfterAll` 清扫是权宜）。

## 五、计划偏差清单

| 偏差 | 原计划 | 实际 | 裁决与理由 |
|---|---|---|---|
| schema URL 形态 | `currentSchema=eval_schema` 单段 | 双段 `eval_schema,public` | 三层实证：单段 pgjdbc 整体替换 search_path，V3 gin_trgm_ops 在 public 解析不到必炸；双段隔离语义不变（设计规格同步修订） |
| 命令行参数 | 调度器传全套覆盖参数（datasource/hikari/state-root…） | 只传 `--invest.eval.data-root` + env 白名单 | runner 已内部构造全部覆盖项，`Options.parse` 拒未知参数——传全套反而炸 |
| `LEAD_SYSTEM_PROMPT` 可见性 | private → 包级 | public static final | 消费者跨包（registrar 在 application/eval、hasher 在 eval 源集），包级够不着；沿三处情报 prompt public 常量先例 |
| rubric 版本快照 | 单数 `rubricVersion` | `rubricVersions` Map | 上位指令裁定：判定用「与 baseline 版本集全等」对齐 §4.2 可比性指纹 |
| `RunResult` 形状 | 计划冻结签名 (current, Optional\<baseline\>) | 增 `outcomes[{id,pass}]` 明细 + `prevRunDegraded` | 翻转判定需题目级输入；恢复判定的「上一跑劣化」在冻结签名内推不出（baseline 恒非劣化跑），收割侧带内传入是唯一通道 |
| 降幅边界算法 | double 百分点直减 | 长整型交叉相乘 | `1.0−0.9` 浮点误差漏报「恰降 10pp」，边界测试钉死 |
| 不可比分支 | 「跳翻转只判降幅」宽松读法 | 整体降级只判绝对完成率 | 规格内两处冲突仲裁，取专条：异分母降幅无对照意义 |
| ERROR 分母口径 | 收割侧预合并计数 | judge 统一计入分母，收割传原始计数 | 预合并 = 双计 → 通过率虚低 → 假告警 |
| 版本资产规模 | 「31 条目」（侦察修正后） | 33 资产 | eval 侧补录 `intel.brief_lead` 第 33 项（两侧快照一致语义，一行成本） |
| 指标计算类题型 | 含 PB 推导 | PB 换 6 形态（净利率/市值/超额收益/振幅/均值/倍数） | bps 只在 financialsTable（双通道剥离 LLM 不可见），硬出 PB 题只产无意义 FAIL |
| 单价显示通道 | 后端 `invest.eval.observability.unit-price-cny-per-mtok` | 前端 `NEXT_PUBLIC_UNIT_PRICE_CNY_PER_MTOK`（后端键成死配置） | 无后端 GET 通道（Task 7 传导裁定）；展示层易变值走构建期注入，死键三处文档标注 |
| V5 注释口径 | 顺手修 trust_stats 六键注释 | 零改动回退 | 迁移不可变：V5 已应用库改内容即 validate 炸（§二.2） |
