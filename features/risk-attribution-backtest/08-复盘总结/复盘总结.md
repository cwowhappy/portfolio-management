## 二、经验（做对了什么）

1. **主源被权限挡住时「先实证降级路径、再拿选项拍板」**：Task 0 探测发现 tushare `sw_daily` 积分门槛不可得（复测确认非限频），没有立即改计划——先对需求规格 §七各预案逐一实证（B：akshare `index_hist_sw` 801010 全历史 6,462 行可得；C：申万码走 `index_daily` 返回空，直接排除），连同 31 码四方对齐零差异一起落成探测报告，交用户裁决选项 B 后才动 Task 1（裁决单独落盘 commit，换源理由可追溯）。
2. **已知答案测试两次拦下计划手算笔误**（计划不是事实源的又一实证）：
   - **夏普 rf 单位**：计划测试注释手算 `e_t=0.009/0.019/0.029`、期望 30.163——rf 按 0.001/日（漏了 ÷365）；红灯后按实现口径重算 `e_t=0.0099/0.0199/0.0299` → **31.590**，注释与期望一并修正；
   - **cashWeight 期初快照**：计划 Task 8 `buildDailyRows` 描述写 `cashWeight=cashBalance_t/totalValue_t`（当日期末口径），与设计规格 §2.4 的 `w_{t−1}`（前一日收盘快照）不一致；两行业两日手算对拍红灯暴露后统一为期初快照口径，完整手算链固化在测试注释里。
3. **CI 双态断言模式可复制**（MS-09/analytics 先例第二次复用）：CI 种子库与本地真库数据面分叉是常态——analytics 侧「本地多日序列数据态 / CI 种子单点 → 204 空态」、allocation 侧「本地三代码收盘充足成功态 / CI 种子无收盘 → 400 错误文案分支」两处形态不同但同一解法：**种子收窄不动、每条断言 `.or()` 双态、注释写明两态口径与成因**。断言双态化后 e2e 在两个环境都稳定绿。
4. **`.next` 陈旧坑两次命中、处置固定化**：Task 11/16 e2e 首跑均命中「复用陈旧 .next 产物用旧代码跑新断言」——前端图表/渲染器类改动后的 e2e 一律 `E2E_FRESH_BUILD=1` 净构建（`scripts/e2e-frontend.sh` 已固化该开关），本特性收尾全量 e2e 即按此跑通 51+2。

## 三、不足

1. **归因取数全量 31 行业**：`attribution` 每次请求对映射表全部 31 个行业码逐一取收盘序列（含未持仓、非基准成分的行业）——本地短窗口无感，长窗口高频访问会放大 IO（见优化建议 #1）。
2. **CI 上测不到数据态**：or() 双态断言让 CI 稳定绿，但也意味着 CI 环境永远走的是空态/错误分支——数据态（曲线渲染、指标卡数值）只靠本地真库 e2e + 服务层已知答案单测兜底，两库数据面持续分叉本身没有被收敛。
3. **计划期数值口径笔误复发**：MS-12 复盘不足 #2（计划自审不核数值）本特性再现——rf 单位与快照时点两处（另有一处循环边界计划预标 ⚠️ 由执行者以测试为准消化）：「数值刻度」上期入过核实清单，但「时点口径」（期初/期末、t/t−1）没入。

## 四、优化建议

1. **归因行业取数收窄**：按「持仓行业 ∪ 基准成分行业」收窄 `industryCloses` 取数清单（当前全量 31 个 `IndexClosePort.closes` 调用）。
2. **`BenchmarkIndustryWeightAdapter` NULL 防护**：`SUM(c.weight)` 未过滤 NULL，成分表出现 NULL weight 行会 NPE——SQL 加 `COALESCE`/`filter (where ...)` 或读侧判空。
3. **`HttpStatus.UNPROCESSABLE_ENTITY` 换新**：Spring 7 已弃用该常量，`GlobalExceptionHandler` 改 `HttpStatusCode.valueOf(422)`（评审挂账 deferred minor）。
4. **Makefile `python` 别名**：collector 目标用 `python -m collector.cli`，macOS 默认无 `python`（仅 python3）——改 `python3` 或复用 `.venv/bin/python`（评审挂账 deferred minor）。
5. **计划核实清单扩到「时点口径」**：在「签名/类型/数值刻度」之外补「快照时点（期初/期末、t/t−1）」——Brinson/回撤类时序计算最易错处（本期两处笔误同源）。
