## 一、F01 编排落点：单 Agent 多步工作流的硬约束与三选项

### 1.1 第一硬约束：maxIters=10 与 run-timeout 5m

- `HarnessAgent.Builder` 构造器默认 `maxIters=10`（jar 字节码 `bipush 10` 核实）；`HarnessAgentFactory.build()`（`backend/src/main/java/com/portfolio/invest/agent/HarnessAgentFactory.java:58-88`）**未覆写**，即生产运行每轮对话至多 10 次 ReAct 迭代。
- `parallelToolCalls=false`（`agent/AgentConfig.java:34`）⇒ 一次迭代 ≈ 一次工具调用 ⇒ **单轮对话约 8-10 次工具调用即触顶**（耗尽走 POST_SUMMARY 收尾，`agent/trust/TrustAgentHook.java:40-44`）。
- AG-UI `run-timeout: 5m`（`backend/src/main/resources/application.yml:46-58`）。深研任务（预计 20+ 工具调用、分钟级）单轮对话**撑不住**：须显式 `.maxIters(≥25-30)` 并自管超时。
- Builder 现成 `.maxIters()` 口（jar 公开 API）；压缩配置原生支持 token 维度（`CompactionConfig` 含 triggerTokens/keepTokens，仓库未用，现仅消息数 30/10，`application.yml:137-140`）。

### 1.2 AgentScope 2.0.3 无 workflow 引擎

core 与 harness jar 内 "workflow" 命名类 = 0：无 DAG/pipeline 编排。可用原语：ReAct 循环（maxIters）、Plan 模式（`PlanModeMiddleware` + `enterPlanMode`——交互式规划，非任务流）、Subagents/Teams 中间件（未启用，且 MS-32 明确单 Agent 先行）、skill（提示词级过程知识）。**不应在其上假设存在编排类能力**。

### 1.3 三编排选项支持度对比（R4 侦察）

| 维度 | a 对话内多步（skill 驱动） | b 专用端点 + 独立 Agent 实例（异步任务） | c 后台调度任务 |

关键事实补充：

- **stateStore 是断点续跑现成底座**：`JsonFileAgentStateStore(.agentscope/state)` 按 (userId, sessionId) 落 `agent_state.json`，每次 call 自动 load/save（磁盘实证 `backend/.agentscope/state/<userId>/<sessionId>/`），天然支持跨轮/跨天/跨进程续跑——恢复粒度 = 整段会话消息历史 + summary，无阶段级中间产物粒度。
- **服务端同步调用先例**：飞书 `HarnessAgentInvoker.ask()`（`agent/feishu/HarnessAgentInvoker.java:30-42`，`agent.call(...).block(240s)`；单用户实例缓存 :44-52——多任务并发需自管实例生命周期）。`CurrentUserHolder` 是请求级 ThreadLocal，异步执行需显式传 userId 给 `build()`。
- **无用户级/动态调度基建**：`config/SchedulingConfig.java:15-18` 仅全局 cron 字面量（12 处 @Scheduled 全为系统批任务），无动态注册。

## 二、草稿人工确认：HITL 字面复用的实证挑战

### 2.1 HITL 现状（链路全绿）

- 触发：MCP 工具 `readOnlyHint` 缺省/false → 写 → agentscope 内建 ASK 门（`McpTool#checkPermissions`，jar javap 核实）→ `RequireUserConfirmEvent` → RUN_FINISHED 携 `outcome.interrupts[]`。契约钉于 `McpHitlIntegrationTest.java:196-213`。
- **内置工具现状不触发 HITL**：`@Tool` 注解工具 `ToolBase#checkPermissions` 默认 passthrough（javap 核实）；但 ToolBase 子类可覆写 checkPermissions→ask 主动加入（`AguiInterruptIntegrationTest.java:279-298` WriteGateTool 先例）。
- 审批态存储：**纯 JVM 内存**（`AguiResumeCoordinator.pendingInterruptsByThread`，javap 核实）+ 客户端浏览器内存——**无 TTL、不落 stateStore/DB，重启/刷新双丢**；未决 interrupt 卡死整线程（ADR-0012 threadId 绑会话后，该会话普通消息即契约错误）。
- 前端卡：`components/chat/InterruptApprovalCard.tsx`（参数查看器形态：JSON 折叠 + 批准/拒绝）；e2e 真链路覆盖（`e2e/hitl.spec.ts`）。
- resume payload 仅 boolean approved / editedArgs，**无自定义确认表单通道**；仅 AG-UI 通道（飞书 `HarnessAgentInvoker` 无 resume 路径）。

### 2.2 字面复用（草稿作 interrupt payload）的六项反对证据

1. **interrupt payload = 工具入参而非工具产出**：草稿确认走 HITL 意味着研报全文（几千字 markdown）须是写工具的**函数调用参数**——LLM 以 function-call 参数形式重复生成整稿，token 翻倍（MS-32 验收项本身是 token 配额）。
2. **双零持久化**：interrupt 与草稿内容均不持久（前后端内存态），刷新/重启后草稿与审批态全灭——与「多步工作流中断恢复」立项风险点直接冲突。
3. **仓内明文决策先例反对**：`components/research/ChecklistConfirmCard.tsx:7-10` 头注释（invest-sop D18 决策）：「ADR-0010 interrupt 绑对话内写工具，不能复用于检查确认」——确认对象不是一次工具调用入参的场景不挂 interrupt，研报草稿同构。
4. **未决 interrupt 卡死线程**：分钟级工作流长时间挂起 = 高危（会话内残留未决 interrupt 即永久卡死，重启不自愈，需人工清 state）。
5. **单字段 zod 不兼容拒收整条 RUN_FINISHED** 的脆弱性先例（issue #25：一个 `expiresAt:null` 卡全链路）。
6. **飞书通道无 resume 能力**。

### 2.3 替代路径资产（PENDING 落库 + 页面级确认）

- 状态机先例：`domain/research/StrategyState.java`（DRAFT/FINALIZED 两级）+ `ProjectStatus`；`research_review.auto_snapshot` JSONB 定格快照。
- 三段式确认先例：`web/ResearchController.java:142-149` checks preview→POST（preview-确认-留痕，CONFIRMED/OVERRIDDEN+理由必填）；`ChecklistConfirmCard` 即页面级确认卡实体。
- 对话侧草稿链路半现成：`agent/research/ResearchDraftSpec.java`（sealed 四变体，specVersion=1）+ 前端 zod 镜像 `lib/research-draft.ts` + `DraftCard.tsx`（```research-draft 围栏提取 → 只读卡 → 「保存到项目」onSave——**当前恒抛错占位**，`toolRenderers.tsx:25-30`，因无会话↔项目绑定）。
- 代价：需新建研报实体（含状态列）+ 落库/确认端点 + 确认卡；确认是**异步落库门**（不阻塞 Agent 当轮）——若 F01 语义要求「确认后才继续下一步」，需补跨轮信号（HITL 路径天然阻塞，这是其唯一结构优势）。

## 三、F03 草稿过校验器：被动 fail-open → 主动 fail-closed 门

- **比对核心可直接调用，无需抽取**：`agent/trust/ConsistencyValidator.java:46` 纯函数 final 类（零 Spring），核心入口 `correct(String text, List<ToolInvocation> pool)`（:98）→ 修正后文本 + AnchorBatch + corrections + correctionFailures；`verify()`（:69）只锚定不改写。`TrustTurnProcessor.process()`（`trust/TrustTurnProcessor.java:62`）为全流水（豁免/advice/confidence）。
- **现状全链 fail-open**：hook 异常原文直通（`TrustAgentHook.java:121-125`）、修正重试耗尽降级出稿（`ConsistencyValidator.java:124-133`）——「宁可少标不可断流」。**无 fail-closed 门语义**，F03 需新写：基于 corrections/correctionFailures/Stats 判定通过/阻断/回炉重生成。`deviation` 参数（0.10）现为注释明示的「后续分级钩子」（javadoc :35-36），可作研报严格档参数位。
- **research_draft 排除不应解除**：`POOL_EXCLUDED_TOOLS = Set.of("research_draft")`（`TrustTurnProcessor.java:35`）。排除理由（MS-29 设计规格 :78）：它是**回显类工具**，返回是模型自产数据的回显而非独立真值——入池产生「echo-sourced」自证循环，压制 unverified 信号（终审 Important 拦下的「回显污染」）。F03 正确方向：**保持排除，在草稿产出/提交前用池内其它数据工具的独立真值主动校验草稿**。
- **真值捕获在独立工作流下成立**：装饰器挂在 Toolkit 装配层（`UserToolkitFactory.java:97-104` decorateWithRecording，内置+MCP 全覆盖），与对话 ReAct 无耦合——工作流复用同一 Toolkit，每次调用照常落 `TrustContext`。**不成立的是触发侧**：回合边界管理在 TrustAgentHook（HarnessAgent 回合生命周期）——独立工作流需在草稿校验点**主动取** `TrustContext.current(rc).invocations()` 并直接调 `correct()`；跨步真值可直接累积 `List<ToolInvocation>` 传参（比对话的 `_trust_pool` metadata 40 条摘要更强，无损）。
- **结构化草稿需适配层**：草稿是 stage 变体 JSON（估值区间/胜率/盈亏比等数字字段，`InvestTools.java:481-507`），入口吃 String——需数字字段→文本→校验的适配。
- **配置可场景差异化**：参数构造器注入、类无单例约束——对话实例沿用现配置，研报实例可 `new` 更严容差（复盘明示「校准走 InvestProperties 配置而非改码」）。

## 四、F02 关键假设数据跟踪：锚点资产与缺口

- **最小数据单元现成**：`ToolInvocation`（`trust/ToolInvocation.java:19-28`：toolName/args/resultText/asOf/asOfKind(DATA|GENERATED|CALL)/mcp）与 anchor `{tool, args, asOf, asOfKind, raw}`（`TrustTurnReport.java:46-95` payload v1）即「数字声明绑定数据源+时间戳」的最小结构。
- **陈旧度判定已有半边**：`ConfidenceScorer` stale 族信号 + 阈值——行情 1 天 / 财报 110 天 / 宏观 35 天（`InvestProperties.java:433-507`，`invest.trust.confidence.stale-*`）。「数据刷新后提示过期」只差**重查比对**。
- **缺口：锚点是消息级沉没资产**——messageId 键控、随 `chat_message.payload` 落库、回合结束即不可跨时间重查；无「假设/研报」领域实体承载「声明↔锚点↔刷新状态」。F02 需研报域新表（Flyway）+ 打开时/定时重查机制（触发方式留设计规格拍板）。
- 现有最近似物 `Falsifier`(predicate/threshold) + `FalsifierHit.basis`（可解释依据字符串）无数据源绑定/新鲜度语义；证伪扫描 18:43 工作日全局批（`ResearchFalsifierScanService.java:61`）是「定时重查+命中留痕」的域内先例。

## 五、token 配额与缓存：可用资产与缺口

- **无 per-user 配额**：全仓仅两处域内预算先例——`IntelligenceTokenBudget`（`application/intelligence/IntelligenceTokenBudget.java:19-71`，进程内自然日累计、重启丢、不分用户）与 eval `TokenBudgetGuard`（单 run 粒度）。仿制 per-user 版需新设计（落库 or 进程内）。
- **无 BYOK**：模型是全局单例 Model bean（`AgentConfig.java:23-38`，`@ConditionalOnExpression` DEEPSEEK_API_KEY），所有用户共用系统 key。**阶段三决策 #3「用户会话内路径走用户 key」在 D7（P2）落地前技术上不可执行**——研报 token 事实全记系统 key 账，**配额护栏是唯一实际控制手段**（这直接影响 F01 配额验收项的口径）。
- **观测自动采集的条件**：凡经 `HarnessAgentFactory.build(userId)` 构建的 Agent，token 三值（prompt/completion/total）经 `ObservabilityAgentHook` 自动落 `turn_observation`/`tool_invocation_obs`（V5 表，admin 看板 `/api/admin/observability/*`）。**直调 Model 不进观测**（`AgentScopeIntelligenceChatPort.java:62-64` 先例即漏采）——工作流必须走 build() 漏斗才有成本账。
- **缓存**：行情/财报侧 `CachedMarketDataService`（@Primary 装饰器）已缓存（quote 15s/kline 5m/financials 1h 等，`application.yml:220-225`），研报重复收集零成本命中；`TtlCache.getOrLoad` 单飞防惊群。**LLM 产物无缓存先例**。
- 限流：三行情客户端共享令牌桶（`MarketConfig.java:26-28`）经 `HttpExecutor` 可重试退避。
- 防超大输入先例：`invest.trust.draft-json-max-bytes=32768`（`InvestProperties.java:450`）。
- 死键备忘：`invest.mcp.pool-max-size`（`application.yml:131`）main 代码零消费方（历史死配置）。
