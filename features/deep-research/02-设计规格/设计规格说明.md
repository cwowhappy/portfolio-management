> 创建：2026-10-11 | 版本：v1.0 | 上游：[需求规格 v1.0](../01-需求规格/需求规格说明.md)（D1~D8 决议）+ [立项侦察报告](../09-调研报告/2026-10-11-立项侦察报告.md)
> 核实口径：本文全部代码引用经 Read/javadoc 实读；agentscope 2.0.3 内建行为（`maxIters(int)`/`hook(Hook)`/`interrupt()` 公开 API、`call(List<Msg>, RuntimeContext)` 签名）经 jar javap 核实；机制假设标注【实测】/【推断】（推断项在实施计划 B0 探针回填）。

## 一、架构总览

```
web/ReportTaskController ──→ application/research/ReportApplicationService ──→ domain/research（新实体×4 + 仓库接口）
   │                └──→ agent/report/ReportWorkflowOrchestrator（异步执行）
   │                          ├── HarnessAgentFactory.buildReportAgent(userId, usageHook)   【新变体】
   │                          │      独立 sessionId=report-<taskId>、maxIters 覆写、MCP 排除、ReportUsageHook
   │                          ├── 三轮 call()（收集→分析→草稿）+ 回炉轮（校验/格式反馈）
   │                          ├── agent/report/ReportValidationGate（fail-closed，主动调 ConsistencyValidator）
   │                          └── ReportAgentRunner 接口（真实现包 HarnessAgent；测试脚本化 fake）
   ├──web/ResearchController（既有，不动）
   └──infrastructure/persistence（JPA 实体/仓库实现 + Flyway V8 四表）
```

分层落位（阶段三规划 §六.1 预判口径）：**编排落 `agent/report/`**（消费 application/domain，沿 agent/trust 先例）；**任务/研报/锚点/假设/配额实体落 `domain/research/`**（层级通配自动覆盖 ArchUnit）；web 编排 application + agent 两方（web→agent 边既有）。**application 不依赖 agent**——启动任务的组合根在 Controller：先 `ReportApplicationService.createTask()`（事务+配额+单任务约束），再 `ReportWorkflowOrchestrator.submit()`（异步）。

## 二、数据模型（Flyway V8，沿 V7 风格：BIGSERIAL PK / TIMESTAMPTZ / 注释引规格节）

```sql
-- V8__ms32_deep_research.sql（FlywayMigrationCountGuardTest 常量 7→8 前置改守卫）

CREATE TABLE research_report_task (
    id            BIGSERIAL PRIMARY KEY,
    project_id    BIGINT NOT NULL REFERENCES research_project(id),
    user_id       BIGINT NOT NULL REFERENCES app_user(id),
    status        TEXT NOT NULL CHECK (status IN ('PENDING','RUNNING','SUCCEEDED','FAILED')),
    stage         TEXT NOT NULL DEFAULT 'COLLECTING'
                  CHECK (stage IN ('COLLECTING','ANALYZING','DRAFTING','VALIDATING')),
    token_usage   BIGINT NOT NULL DEFAULT 0,          -- ReportUsageHook 累计（结算入 quota）
    error_code    TEXT,                                -- QUOTA_TASK_CAP/TIMEOUT/VALIDATION_FAILED/PARSE_FAILED/AGENT_ERROR
    error_message TEXT,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    started_at    TIMESTAMPTZ,
    finished_at   TIMESTAMPTZ
);
-- 同项目至多一个活跃任务（需求 §三 F01；「至多一个 active」部分唯一索引先例）
CREATE UNIQUE INDEX uq_report_task_active ON research_report_task (project_id)
    WHERE status IN ('PENDING','RUNNING');

CREATE TABLE research_report (
    id             BIGSERIAL PRIMARY KEY,
    project_id     BIGINT NOT NULL REFERENCES research_project(id),
    task_id        BIGINT NOT NULL REFERENCES research_report_task(id),
    user_id        BIGINT NOT NULL REFERENCES app_user(id),
    status         TEXT NOT NULL DEFAULT 'PENDING_CONFIRM'
                   CHECK (status IN ('PENDING_CONFIRM','CONFIRMED','REJECTED')),
    title          TEXT NOT NULL,
    content_md     TEXT NOT NULL,                      -- 校验门修正后的定稿文本（含 ⚠ 校验修正注记行）
    limitations    TEXT,                               -- 数据局限注记（工具失败等）
    confirmed_at   TIMESTAMPTZ,
    rejected_reason TEXT,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE research_report_anchor (
    id          BIGSERIAL PRIMARY KEY,
    report_id   BIGINT NOT NULL REFERENCES research_report(id),
    snippet     TEXT NOT NULL,                         -- 数字片段（MS-29 anchor 语义）
    occ         INT NOT NULL,                          -- 同 snippet 第几次出现
    state       TEXT NOT NULL CHECK (state IN ('VERIFIED','SOURCED','UNVERIFIED')),
    tool_name   TEXT,
    args        JSONB,
    as_of       TIMESTAMPTZ,
    as_of_kind  TEXT,                                  -- DATA/GENERATED/CALL（沿 ToolInvocation）
    raw         TEXT                                   -- 工具原值文本
);

CREATE TABLE research_report_assumption (
    id          BIGSERIAL PRIMARY KEY,
    report_id   BIGSERIAL NOT NULL REFERENCES research_report(id),
    seq         INT NOT NULL,
    statement   TEXT NOT NULL,
    anchor_id   BIGINT REFERENCES research_report_anchor(id),  -- NULL = 未绑定（门语义见 §3.5）
    UNIQUE (report_id, seq)
);

CREATE TABLE report_token_quota (
    user_id     BIGINT NOT NULL REFERENCES app_user(id),
    quota_date  DATE NOT NULL,
    tokens_used BIGINT NOT NULL DEFAULT 0,
    PRIMARY KEY (user_id, quota_date)
);
```

- 锚点行**创建后不可变**（审计真相）；过期状态为打开时重查的瞬态计算（ApplicationCache 缓存，§3.8），不落库。
- `scripts/e2e-cleanup.sh` 登记四表 DELETE 行（FK 顺序：assumption → anchor → report → task → quota）。

### 3.1 Agent 构建（HarnessAgentFactory 新变体）

- **sessionId 约定**：`report-<taskId>`（RuntimeContext 传入，非 build 期）；stateStore 按 (userId, sessionId) 寻址，与对话会话天然隔离；失败重来 = 新任务新 sessionId（D3，不续跑旧会话）。
- **多轮驱动替代超大 maxIters**：工作流 = 3~4 次 `call()`（每轮一次用户消息，同 sessionId 续会话），单轮 maxIters=15 已够每轮 10+ 次工具调用；单轮超时 240s（沿 `HarnessAgentInvoker.CALL_TIMEOUT` :19 先例）+ 任务总超时（默认 15m，配置）。
- **画像注入**：`systemPrompt(userId)` 复用（MS-31 `ProfileContextBuilder` 自动生效，D1 增益零接线）。

**§3.1.1 MCP 排除（安全设计，非可选）**：`UserToolkitFactory` 新增 `buildWithoutMcp(Long userId)`——复用 `build()` :53-88 的内置+用户态装配路径、跳过 provider 循环与 `decorateWithRecording` 的 MCP 名单（装饰器仍包内置工具，真值捕获成立）。理由：写 MCP 工具在独立 call 下触发 ASK 门无 UI 应对方（R2 侦察：interrupt 无超时无持久化），挂死风险；提示词约束（e2e 经验 #24）仅作软引导，结构排除才是硬保障。研报五源均为内置工具，无能力损失。

### 3.2 工作流编排（agent/report/ReportWorkflowOrchestrator）

```
submit(taskId, userId, projectId)  → ExecutorService 提交（有界线程池，容量=invest.report.execution.pool-size 默认 2；
                                     拒绝/中断 → 任务 FAILED(AGENT_ERROR)）
run(task):
  stage=COLLECTING  → call(收集提示：按项目 stockCode/行业，五源工具面点名，产出=工具清单式中间小结)
  stage=ANALYZING   → call(分析提示：估值/财务质量/情报信号/风险，引用已收集数据)
  stage=DRAFTING    → call(草稿提示：最终消息必须是 ```research-report 围栏 JSON，契约 §3.4)
  stage=VALIDATING  → 真值池快照（§3.5）→ 门判定：
                       PASS   → 修正后 contentMd + anchors + assumptions 落库 → 任务 SUCCEEDED（研报 PENDING_CONFIRM）
                       FAIL-1 → 回炉轮（≤ max-regen-rounds=1）：反馈 {correctionFailures + 未锚定数字 + 未绑定假设}
                                → 重新提草稿 → 再过门 → 仍 FAIL → FAILED(VALIDATION_FAILED)
                       PARSE 失败 → 格式反馈重试 1 轮 → 仍败 → FAILED(PARSE_FAILED)
  全程：ReportUsageHook 累计 token；每轮返回后查总超时/单任务上限 → 超限 FAILED(QUOTA_TASK_CAP/TIMEOUT)
  结算：token_usage 写回任务行 + report_token_quota 当日行 upsert 累加（§3.9）
```

- **调用范式**（沿 `HarnessAgentInvoker.ask` :36-39 实测先例）：`agent.call(Msg.builder().role(MsgRole.USER).textContent(prompt).build(), RuntimeContext.builder().userId(userId.toString()).sessionId("report-"+taskId).build()).block(roundTimeout)`；返回 `Msg.getTextContent()`。
- **真值池累积**（R3 侦察结论落地）：TrustAgentHook 的 `PRE_CALL fresh()` 每轮清池——编排器在**每轮 call 返回后**快照 `TrustContext.current(rc).invocations()` 累积进任务级 `List<ToolInvocation>`（无损，优于对话的 `_trust_pool` 40 条摘要）；门只吃累积池。【推断：invocations() 读取 API 形态——B0 探针 1 回填】
- **进程重启恢复**：`ApplicationRunner`（`infrastructure/seed` 先例位）启动时将 status IN (PENDING,RUNNING) 的任务批量标 `FAILED(AGENT_ERROR, "进程重启中断，可重试")`（D3 失败重来语义）。
- **取消**：v1 不做（YAGNI，需求 §六）；任务最长存活 = 总超时。

### 3.3 深研指引（agent/report/ReportWorkflowPrompt）

常量 `BLOCK`（追加在 systemPrompt 尾部），内容四节：①工作流三阶段说明（本轮任务语境）；②工具面点名（行情/财务/情报/公告/wiki 五源 + 各自适用问题）；③**输出契约**：最终消息 = 单个 ```research-report 围栏 JSON（schema §3.4），数字必须直接引用工具返回值、不得凭记忆填写；④关键假设章节要求：每条假设注明来源工具与数字。版本资产登记 `system.invest.report`（沿 MS-31 `system.invest.profile` 先例，`ToolkitPromptAssetCollector` 五类→六类扩一资产）。

### 3.5 校验门（agent/report/ReportValidationGate，fail-closed）

```java
public final class ReportValidationGate {           // 纯 POJO（沿 ConsistencyValidator 风格，可直 new）
    public GateResult evaluate(String contentMd, String assumptionText, List<ToolInvocation> pool) { … }
    public record GateResult(boolean passed, String correctedMd, AnchorBatch anchors,
                             List<String> correctionFailures, double unverifiedRatio,
                             List<AssumptionBinding> bindings) {}

```

- **主判定**：`new ConsistencyValidator(strictTrust).correct(contentMd, pool)`（签名 `ConsistencyValidator.java:98` 实测）——自动修正（原位替换+⚠注记行）进 `correctedMd`；`correctionFailures` 非空 → FAIL。
- **未锚定线**：unverifiedRatio > `invest.report.validation.unverified-ratio-max`（默认 0.10，严于对话 0.30）→ FAIL。
- **假设绑定线**（§3.7）：存在「关键假设」条目零锚点绑定 → FAIL（回炉反馈列出未绑定条目）。「关键假设」章节为空 → FAIL（验收「假设带数据源」硬要求）。
- **严格档配置**：`invest.report.validation` 组（`InvestProperties.Report.Validation`：relative 0.01/absolute 0.03/price 0.005/unverified-ratio-max 0.10/max-regen-rounds 1）——**独立实例注入，对话档 `invest.trust.*` 零改动**（R3 证实构造器注入、天然可多实例）。
- **`research_draft` 排除维持**（`TrustTurnProcessor.java:35` 不动）；门的真值 = 编排器累积池（不含回显——回显工具本就不在报告工具面）。
- **异常语义**：门内部异常 → 任务 FAILED（fail-closed，与对话档 fail-open 刻意相反）；池空（收集轮全失败）→ FAILED(VALIDATION_FAILED,"无真值")。

### 3.7 假设↔锚点自动绑定（门后处理）

- 输入：「关键假设」章节文本（contentMd 中按标题切出）逐条（`^\d+\.` 编号行）；每条 `NumberExtractor.extract(statement)`（`trust/NumberExtractor.java:70` 实测）取数字。
- 绑定：数字与 anchors 匹配（数值相等或容差内，复用 judge 语义）→ 该假设绑定首个匹配 anchor（`anchor_id` 写入 assumption 行）；条目无任何数字或全部不匹配 → `anchor_id=NULL` → 门 FAIL 反馈。
- 展示语义：假设条目状态 = 其锚点重查状态（§3.8）；`anchor_id=NULL` 不可能出现在已出稿研报（门拦）。

### 3.8 过期重查（application/research/ReportStalenessService，打开时触发）

- **入口**：`GET /api/research/reports/{id}`（detail）时对 anchors 计算状态；结果整体缓存 `ApplicationCache`（键 `report-staleness:{reportId}`，TTL `invest.report.staleness.recheck-ttl` 默认 5m——`CacheConfig` :12-16 三参通用形态直接可用）。
- **重查派发**（`ReportAnchorRechecker`，白名单制）：按 `anchor.tool_name` 直调 `InvestTools`/`UserInvestTools` 实例方法（**直调方法绕过装饰器**——不污染任何真值池；args 反构造按各工具入参 record）。白名单 v1：`get_quote/get_kline/get_financials/get_market_overview/get_valuation/analyze_financials/analyze_industry/macro_brief/search_news/search_announcements/search_wiki`；其余 → UNVERIFIABLE。
- **判定**：现值结果文本 `NumberExtractor.extract` 取数值集；锚定数值在容差内再现 → `FRESH`，否则 `CHANGED`（容差 `invest.report.staleness.changed-relative` 默认 0.02，复用 trust relative 语义）；`as_of` 距今超 stale 线（复用 `invest.trust.confidence.stale-*` 1/110/35 天，不另设）→ `STALE`（与 CHANGED 并存时 CHANGED 优先）。工具失败 → UNVERIFIABLE。
- **不回写**：锚点行不可变；状态仅入缓存随 detail 响应透出（`{anchorId, state, currentValue?}`）。

### 3.9 token 配额（application/research/ReportTokenQuotaService）

- 语义沿 `IntelligenceTokenBudget.java:19-71`（超=严格大于；Clock 注入可测）但**落库持久化**（D7：重启不丢）：
  - `tryStartNewTask(userId)`：当日行 `tokens_used < daily-budget`（默认 500,000，`invest.report.quota.daily-token-budget`）才放行；**软检查**（并发双任务可同时过检——由单任务上限兜底最坏值，文档化此语义）。
  - `settle(userId, tokens)`：任务终态时 `INSERT … ON CONFLICT (user_id, quota_date) DO UPDATE SET tokens_used = report_token_quota.tokens_used + EXCLUDED.tokens_used`。
  - `remainingToday(userId)`：设置/详情透出余量（前端发起前提示）。
- **单任务上限**（`per-task-token-cap` 默认 150,000）：`ReportUsageHook`（agent/report，per-task 实例）累计 usage——沿 `ObservabilityAgentHook.accumulate()` :174-181 的 usage 事件源同构【推断：POST_REASONING/POST_SUMMARY 事件携带 usage 字段形态——B0 探针 3 回填】；编排器每轮返回后检查，超限 → FAILED(QUOTA_TASK_CAP)。

### 3.10 确认状态机（application/research，沿 StrategyDoc 两级状态机 + checks 三段式先例）

- `PENDING_CONFIRM --confirm--> CONFIRMED`（写 confirmed_at + journal RESEARCH_EVENT 事件「研报定稿」，沿 `ResearchApplicationService.writeEvent` :650-654 模式）；
- `PENDING_CONFIRM --reject(reason 必填)--> REJECTED`（留痕可重生成=发新任务）；
- 幂等：非 PENDING_CONFIRM 态的 confirm/reject → 409；并发双击以状态行 UPDATE ... WHERE status='PENDING_CONFIRM' 争用判定（恰一成功）。
- 研报属项目产物：详情页⑦「关联记录」区新增研报列表引用（只读链接）。

### 3.13 Clock 注入 P3（domain 全域 37 处，D5）
