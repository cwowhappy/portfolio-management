## 一、背景与目标

阶段三已交付可信底座（MS-29 校验器/锚定）与个性化（MS-31 画像注入），但 Agent 仍是**单轮 ReAct**：无多步任务编排、无产出物生命周期。现状四个硬缺口（[侦察报告](../09-调研报告/2026-10-11-立项侦察报告.md)）：

- **单轮撑不住深研**：`maxIters=10`（Builder 默认，工厂未覆写）+ `run-timeout 5m`——单轮约 8-10 次工具调用即触顶，深研任务需 20+ 次；AgentScope 2.0.3 无 workflow 引擎（jar 核实 0 个 workflow 类）。
- **研报无落地形态**：`research_draft` 是纯回显工具（不落库），前端「保存到项目」恒抛错（无会话↔项目绑定）；无研报产物表、无草稿状态机。
- **锚点是消息级沉没资产**：MS-29 锚点随消息 payload 落库、回合结束不可跨时间重查——「假设绑定数据源+刷新提示过期」（F02）无承载实体。
- **token 无配额**：无 per-user 配额机制；无 BYOK（决策 #3 的用户 key 边界 D7 前不可执行），配额护栏是唯一实际成本控制手段。

本特性（MS-32 / M19）交付：**F01 研报生成任务流**（研究页发起 → 单 Agent 异步多步 → 草稿过校验门落库 → 人工确认挂研究项目）、**F02 关键假设数据跟踪**（假设↔锚点持久化 + 打开时重查过期提示）、**F03 草稿过校验器**（fail-closed 门：数字一致性不通过不出稿）。一句话：从单轮 ReAct 到**多步研报任务流**——选题到草稿全程可溯源、假设可跟踪、产出挂 SOP 研究项目。

## 三、功能需求（M19-F01~F03，编号承阶段三规划，不增删改）

### M19-F01 研报生成任务流

**描述**：研究页项目详情页新增「生成研报」入口，后端异步执行单 Agent 多步工作流（选题方向 → 多源数据收集 → 分析 → 草稿），草稿过 F03 校验门后落库 PENDING 态，人工确认后挂研究项目定稿（决策 D1/D2）。

**业务规则**：

- **发起**：研究页项目详情页操作区「生成研报」按钮 → 校验配额（决策 D7：日预算余量不足即拒绝，提示次日恢复）→ 创建研报任务（PENDING 态）。同一项目同时至多一个进行中任务（重复发起提示等待完成；具体并发约束设计规格定）。
- **执行**：异步任务内 `HarnessAgentFactory.build(userId)` 构建独立 Agent 实例——独立 sessionId（与对话会话隔离，命名如 `report-<taskId>`）、`maxIters` 显式调大（≥30）、自管超时（分钟级，具体值设计规格定）；系统提示注入深研工作流指引（多源收集→分析→草稿的步骤指引与工具使用规范，落 skill 或提示词扩展设计规格定）。**画像注入经 build 自动生效**（MS-31 增益零接线）。
- **多源数据收集**：行情/财务（`get_quote`/`get_kline`/`get_financials`/`analyze_financials` 等）、情报三路（`search_news`/`search_announcements`/`macro_brief`）、**wiki（新建检索 @Tool**，readOnly=true 不触发审批，读 WikiEntryRepository）——五源齐备；复用既有 TTL 缓存（重复收集近零成本）。
- **进度**：任务状态机（PENDING → RUNNING（阶段：收集/分析/草稿）→ SUCCEEDED（草稿 PENDING 确认）/ FAILED / 超限中止）落任务表；前端轮询展示（EvalRunsPanel 5s 先例；阶段粒度即可，非工具调用级）。
- **失败与重试**（决策 D3）：失败任务可整体重试（新建任务复用缓存与已捕获真值池语义）；无阶段级断点续跑。
- **确认**（决策 D2）：草稿落库为 PENDING 态（研报实体，含全文 markdown + 结构化假设章节引用）；前端确认卡（确认/拒绝+理由，仿 ChecklistConfirmCard 与 CONFIRMED/OVERRIDDEN 留痕形态；卡片落研究页详情区，对话流内是否同步透出设计规格定）→ 确认后研报定稿挂项目；拒绝则研报留 REJECTED 痕迹可重生成。
- **token 观测**：经 build() 漏斗自动落 `turn_observation`/`tool_invocation_obs`（MS-30 现成）；任务表记录本次任务 token 消耗汇总（对账配额）。
- **SOP v2 轻量并入**（决策 D4）：对话内 `research_draft` 草稿卡「保存到项目」解除恒抛错——保存时定位目标项目（选定 projectId 的最小形态，具体交互设计规格定），调用既有研究域落库 REST。

**边界与异常**：任务执行中进程重启 → 任务标 FAILED（可重试）；Agent 工具调用异常不致任务悬挂（超时看护中止）；配额检查在发起与执行两处（执行中超单任务上限即中止标失败留痕）；wiki/行情源不可用按工具失败语义进草稿「数据局限」注记，不阻断整个任务。

### M19-F02 关键假设数据跟踪

**描述**：研报内关键假设与数字声明绑定数据源锚点持久化；用户打开研报时重查数据源，偏差超阈值提示过期（决策 D6/D8）。

**业务规则**：

- **锚点持久化**：F03 校验门产出的锚定记录（`{tool, args, asOf, asOfKind, raw, 锚定值}`，复用 MS-29 anchor 结构）随研报落库（新表，研报↔锚点一对多）；「关键假设」章节条目（LLM 生成的假设声明）与锚点关联（假设引用锚点 id 或声明级绑定，形态设计规格定）。
- **过期判定**：打开研报/项目详情（含研报区）时触发重查——对锚点数据源重调工具取现值，与锚定值比对：偏差超阈值（复用/新设阈值口径设计规格定，参考 trust 容差与 stale 阈值 1/110/35 天）标「数据已变」；数据时间戳距今超 stale 阈值标「数据陈旧」。重查结果不回写研报正文（原文不可变），仅作状态徽标与浮层提示。
- **展示**：研报查看态假设条目带状态徽标（新鲜/陈旧/已变）+ 点击可见来源工具/参数/锚定值与现值对照（复用溯源浮层形态）。
- **频率控制**：重查按需触发，带 TTL 防抖（短时间内重复打开不重复重查，TTL 可配）；无定时巡检。

**边界与异常**：重查工具失败 → 该锚点标「无法核实」而非报错；锚点对应工具已下线/参数失效 → 同「无法核实」；重查不阻塞研报正文渲染（异步加载状态区）。

### M19-F03 草稿过校验器

**描述**：草稿产出前强制走 M17-F02 校验层——数字一致性不通过不出稿（fail-closed 门，决策 D2 关联）。

**业务规则**：

- **主动门**：工作流草稿产出点主动取本任务累积真值池（`TrustContext` 装饰器捕获的 `ToolInvocation` 全量，无损传递——不依赖对话回合的 hook 触发）+ 调 `ConsistencyValidator.correct(草稿文本, 真值池)`（纯函数直接调用，侦察 §三）；结构化草稿（章节 JSON）经适配层转文本校验。
- **fail-closed 语义**：correct() 自动修正可修正项（原位替换+注记）→ 剩余 `correctionFailures`（无法修正的大偏差）触发**回炉重生成一轮**（带失败清单反馈给 Agent 自纠）→ 仍失败则任务标 FAILED（不出稿，失败原因留痕可查）。**禁止**未过门草稿进入 PENDING 确认态。
- **`research_draft` 排除保持不动**：不将回显工具入真值池（echo 自证循环，MS-29 裁定维持）；校验真值一律来自池内独立数据工具。
- **严格档参数**：研报校验实例独立配置（`InvestProperties` 新增研报档容差组，可严于对话档 2%；具体值设计规格定）——对话档行为零变更。
- **锚点产出**：门的锚定结果（AnchorBatch）即 F02 持久化输入；未匹配数字按 MS-29 语义标 unverified——研报场景下 unverified 数字超过阈值（可配）同样触发回炉/失败（「数字全部过校验」验收的严格化，阈值设计规格定）。

**边界与异常**：真值池为空（工具全失败）→ 任务失败（无真值即无校验，不出稿）；校验器内部异常 → 任务失败（fail-closed，不降级出稿——与对话档 fail-open 刻意相反）。

## 五、验收标准（与规划文档 MS-32 节对齐）

- **端到端产出一份研报草稿**：研究页发起 → 任务运行（多源收集含 wiki）→ 草稿落库 PENDING → 确认卡确认 → 定稿挂研究项目；e2e 真浏览器全链路通过。
- **数字全部过校验**：出稿（进入 PENDING）的研报无未解决 correctionFailures；门语义 fail-closed（构造错值草稿用例被拦，不出稿）；对话档校验行为回归零变更。
- **假设带数据源与时间戳**：关键假设条目关联锚点（tool/args/asOf 可见）；打开时重查对「数据已变/陈旧」正确标示（构造锚定后数据变化用例）；重查失败标「无法核实」不报错。
- **经人工确认挂研究项目**：确认/拒绝留痕；拒绝后可重生成；对话内 research_draft 草稿可保存到指定项目（SOP v2 轻量并入，恒抛错桩解除）。
- **token 消耗有配额与缓存策略**：日预算+单任务上限生效（超限行为符合 D7）；任务 token 汇总可查对账；多源收集命中 TTL 缓存（重复收集成本近零可证）；画像注入在研报任务内生效（授权开启用户抽检）。
- **P3 台账**：domain 37 处时钟统一清零（`Instant.now()` 直调 grep 零命中为证）。
- **门槛**：`make test` 三端全绿（含 ArchUnit / 链接门禁 / Flyway 守卫 7→8 同步）。

## 六、YAGNI 排除清单（逐条给排除理由）

- **多 Agent 分工编排**——方向决策 #3：单 Agent 多步先行，验证价值后再演进；AgentScope 亦无编排引擎可用。
- **阶段级断点续跑**——决策 D3：失败重来+缓存/真值复用；断点续跑列复盘观察项，价值未证实不预建。
- **定时巡检假设过期**——决策 D6：打开时重查；巡检成本随研报量增长，v1 无需求。
- **BYOK / 用户自有 key**——D7（P2）范围；本特性以配额护栏控制成本，key 边界留 D7 落地。
- **LLM 产物缓存**——仓库无先例、失效语义复杂；数据侧 TTL 缓存已护住大头（行情/财报），LLM 侧重复生成成本由重试受控+配额兜住。
- **研报版本树/原地修订**——v1 每次生成为新研报记录（拒绝可重生成），不做 diff/版本对比；项目维度研报列表足够。
- **研报导出（PDF/分享）/模板自定义**——roadmap 未列；产出物在系统内可查可溯源即满足验收。
- **对话内发起研报任务**——决策 D1 裁研究页发起（projectId 无歧义）；对话内发起需绑定/创建项目交互，价值未证实，留后续（对话侧仅并入 SOP v2 草稿直存 D4）。
- **对话内推进 SOP 阶段/研究流程深化**——SOP v2 完整形态（D4 明确轻量并入边界）。
- **飞书通道发起/确认研报**——研报确认走 Web 确认卡；飞书通知触达属 D5 主动式 Agent 范围。
- **假设清单全部数字平铺**——决策 D8：语义筛选的关键假设+锚点绑定，避免过期提示噪声。
- **研报内图表嵌入**——研报以 markdown 文本+锚点为主；图表通道（chart spec）已有能力按需后续接。
