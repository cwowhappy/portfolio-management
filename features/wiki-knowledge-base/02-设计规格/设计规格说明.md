# 投资知识库（wiki-knowledge-base）设计规格说明

> 创建：2026-09-22 | 状态：待评审 | 依据：[需求规格说明](../01-需求规格/需求规格说明.md)
> 模板先例：journal 域（domain 纯 POJO + application 用例 + infrastructure JPA + web 控制器）

## 一、总体架构

```
前端                              后端
/wiki (WikiBoard 四 tab)           web/WikiController ── /api/wiki/entries|rules
/industry/[code] +保存结论入口  →  application/wiki ── WikiApplicationService（含概念 seeding）
  ↳ app/api/wiki/[...path] relay      PrincipleRuleApplicationService
    lib/wikiApi.ts                domain/wiki ── WikiEntry / PrincipleRule 聚合 + 仓库端口
                                  infrastructure/persistence ── JPA 实现三表（V16）
```

- 单域 `domain/wiki` 两聚合（同域两聚合先例：allocation 的 AllocationPlan + RiskAssessment）；
- 内容三类共用 `wiki_entry`（type 列），规则独立 `principle_rule`；
- 预置概念为 classpath 资源（`resources/wiki/preset-concepts.json`），Skill 域 ClasspathSkillRepository 同款「资源随 jar 分发」先例。

## 二、数据模型与迁移（Flyway V16）

新迁移 `backend/src/main/resources/db/migration/V16__wiki.sql`（当前最新 V15）：

```sql
CREATE TABLE wiki_entry (
    id            BIGSERIAL PRIMARY KEY,
    user_id       BIGINT NOT NULL REFERENCES app_user(id),
    type          VARCHAR(16)  NOT NULL,   -- BOOK_NOTE / CONCEPT / RESEARCH_NOTE
    title         VARCHAR(200) NOT NULL,   -- 概念词条即术语名本身，不另设 term 列
    content       TEXT NOT NULL,           -- Markdown
    category      VARCHAR(50),             -- CONCEPT 专用：分类（估值/质量/行为…）
    industry_code VARCHAR(16),             -- RESEARCH_NOTE 专用：申万一级行业代码
    version       BIGINT NOT NULL DEFAULT 0,
    created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_wiki_entry_user_type ON wiki_entry(user_id, type, updated_at DESC);

CREATE TABLE principle_rule (
    id          BIGSERIAL PRIMARY KEY,
    user_id     BIGINT NOT NULL REFERENCES app_user(id),
    metric      VARCHAR(32) NOT NULL,      -- 指标枚举（§2.1）
    threshold   NUMERIC(12,4) NOT NULL,    -- 单位由枚举语义约定
    enabled     BOOLEAN NOT NULL DEFAULT TRUE,
    description VARCHAR(500),              -- 可选：给三期预警展示用的规则说明
    version     BIGINT NOT NULL DEFAULT 0,
    created_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
    CONSTRAINT uk_principle_rule_user_metric UNIQUE (user_id, metric)
);

CREATE TABLE wiki_seed_state (
    user_id    BIGINT PRIMARY KEY REFERENCES app_user(id),
    seeded_at  TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

### 2.1 指标枚举（PrincipleMetric，首批 4 种）

| metric | 含义 | 单位与校验边界 | 示例阈值 |
|---|---|---|---|
| `SINGLE_POSITION_RATIO` | 单票市值占组合比例上限 | 比例，`0 < t ≤ 1` | 0.20 |
| `INDUSTRY_POSITION_RATIO` | 单一行业仓位上限 | 比例，`0 < t ≤ 1` | 0.35 |
| `STOCK_PE_MAX` | 个股 PE(TTM) 上限 | 倍数，`t > 0` | 40 |
| `STOCK_PB_MAX` | 个股 PB 上限 | 倍数，`t > 0` | 6 |

枚举自带 `isRatio()` 单位语义；三期 MS-15 预警消费同一枚举（稳定契约）。

### 2.2 有意识的取舍

1. **`UNIQUE(user_id, metric)`**：每指标至多一条规则，三期消费每指标取唯一阈值最简；
2. **CONCEPT 无 term 列**：title 即术语名；
3. **单表 + type 列**：journal 单表 4 类型先例同构，类型特有列在其它类型上 NULL；
4. **乐观锁**：两内容表均带 `version`（V9 模式，JPA `@Version`）。

## 三、后端 domain/wiki 设计

### 3.1 域结构（照 journal 域模式）

**`domain/wiki`（纯 POJO，零 Spring/JPA）**：

- `WikiEntry` — 不可变聚合根：静态工厂 `create(userId, type, title, content, category, industryCode, now)` / `reconstitute(...)`，实例方法 `update(...)` 返回新实例；私有 `validate`：title 非空 ≤200、content 非空。类型特有列不做强校验（`industry_code` 由行业入口带入，手工创建可不填——校验从轻，避免堵死用户路径）；
- `WikiEntryType` 枚举：`BOOK_NOTE` / `CONCEPT` / `RESEARCH_NOTE`；
- `PrincipleRule` — 不可变聚合根，同款工厂模式；`validate` 按 `PrincipleMetric` 单位语义校验阈值、description ≤500；
- `PrincipleMetric` 枚举 — 4 值 + `isRatio()`；
- `WikiEntryRepository` / `PrincipleRuleRepository` 端口：`findByUserId(userId, type)`、`findByIdAndUserId(id, userId)`、`save`、`deleteById`（journal 仓库签名风格）；
- `WikiErrorCode`（INVALID_INPUT / NOT_FOUND / DUPLICATE_METRIC）+ `WikiException`。

**`application/wiki`**：

- `WikiApplicationService`：`entries(userId, type)` / `getEntry` / `createEntry` / `updateEntry` / `deleteEntry`；`requireEntry(userId, entryId)` 归属校验（缺失抛 NOT_FOUND）；事务边界在此层；
- `PrincipleRuleApplicationService`：`rules(userId)` / `createRule` / `updateRule` / `deleteRule`；UNIQUE 冲突（`DataIntegrityViolationException`）翻译为 `WikiException(DUPLICATE_METRIC)`；
- `PresetConceptCatalog` — 读 classpath `resources/wiki/preset-concepts.json`（约 10 条：title/category/content Markdown 正文，内容执笔：护城河、安全边际、能力圈、市场先生、内在价值、复利、均值回归、ROE、PE、PB）；
- DTO（record + jakarta 校验）：`CreateWikiEntryCommand` / `UpdateWikiEntryCommand` / `WikiEntryView` / `CreatePrincipleRuleCommand` / `UpdatePrincipleRuleCommand` / `PrincipleRuleView`。

**`infrastructure/persistence`**：`WikiEntryJpaEntity` / `PrincipleRuleJpaEntity` / `WikiSeedStateJpaEntity`（静态 `fromDomain` + 实例 `toDomain`）+ Spring Data JpaRepository + RepositoryImpl 包一层实现端口。

### 3.2 概念预置 seeding

`entries(userId, CONCEPT)` 首次调用时，同事务内「查 `wiki_seed_state` 无该用户记录 → 批量插入预置词条 → 写标记」。幂等由标记表 PK 保证；删光预置不复活（标记仍在）。GET 带一次性批量写副作用是有意识的小取舍：换全库数据 user-scoped、CRUD 完全统一、无 NULL 行/合并逻辑。

### 3.3 web 层（全部 authenticated，不进 PublicEndpointPaths）

```
GET    /api/wiki/entries?type=        缺省全量；type=CONCEPT 触发 seeding
POST   /api/wiki/entries              201
GET    /api/wiki/entries/{entryId}
PUT    /api/wiki/entries/{entryId}
DELETE /api/wiki/entries/{entryId}
GET    /api/wiki/rules
POST   /api/wiki/rules                201
PUT    /api/wiki/rules/{ruleId}       含启停切换
DELETE /api/wiki/rules/{ruleId}
```

`currentUserId(auth)`（`((AuthenticatedUser) auth.getPrincipal()).user().id()`）提取 userId，与 journal 控制器逐字同款；用户隔离三重保障。

### 3.4 工程配套

- `PackageConventionsTest` 白名单按层 `..` 通配**无需改动**；按其 javadoc 要求同步更新《01-后端DDD分包规范》域清单（12→13 域）。

## 四、前端设计

### 4.1 `/wiki` 页面

- `app/wiki/page.tsx`：server component，`<RequireAuth><WikiBoard /></RequireAuth>`（journal 同款）；
- `components/wiki/WikiBoard.tsx`（"use client"）四 tab：**原则纪律 / 读书笔记 / 概念速查 / 研究笔记**；支持 `?tab=` 深链初始 tab（行业页跳转 `/wiki?tab=research`）；
- **原则 tab**：规则卡片列表（指标中文名 + 按单位格式化阈值 + 启停开关 + 编辑/删除）；「添加规则」表单——指标下拉（已配置指标置灰）、阈值输入按单位切换（比例类显示 `%` 输入、存储 0~1；倍数类直接数值）、说明可选；
- **三个内容 tab**（共用组件，概念 tab 编辑器多一个分类输入）：列表 + 编辑器（title + content textarea + **编辑/预览切换**）+ 详情 Markdown 渲染。

### 4.2 MarkdownView 共享组件

`components/shared/MarkdownView.tsx`：从 chat `ThreadArea` 抽出 ReactMarkdown 配置（remark-gfm、urlTransform、CodeBlock/InlineCode）；wiki 与 chat 共用，chat 自定义渲染器经 props 保留、行为不变（e2e chat 既有用例兜底回归）。

### 4.3 行业下钻页联动（IndustryDrilldown.tsx）

- 页头加「保存研究结论」按钮 → 弹窗表单：标题预填「{行业名} 研究结论」、content textarea + 预览切换、`industryCode` 自动带入 → `POST /api/wiki/entries (type=RESEARCH_NOTE)` → 成功提示 +「在知识库查看」链接跳 `/wiki?tab=research`；
- 未登录**隐藏**按钮（`useAuth()` 判空），不弹登录墙。

### 4.4 配套

- `lib/wikiApi.ts`：entries/rules CRUD 客户端；zod schema 入 `lib/schemas.ts`、类型入 `lib/types.ts`（`lib/http.ts` `request<T>` 统一出口）；
- `app/api/wiki/[...path]/route.ts`：`lib/proxy.ts` `relay` 反代（每域一文件惯例）；
- `app/layout.tsx` 顶部导航加「知识库」链接。

## 五、错误处理与边界

- 领域层 `WikiException(WikiErrorCode, message)` → 既有 `GlobalExceptionHandler` 映射 HTTP（INVALID_INPUT / NOT_FOUND / DUPLICATE_METRIC）；
- 前端 `request<T>` 非 2xx 抛响应体 message；规则表单对 DUPLICATE_METRIC 行内提示（下拉置灰为主防线，服务端兜底）；
- 乐观锁冲突沿用既有更新链路语义；
- seeding 并发（同用户双请求同时首拉）：标记表 PK 约束使后者事务失败回滚重试为纯查询，可接受。

## 六、测试策略（TDD）

| 层 | 覆盖点 |
|---|---|
| 后端域单测 | `PrincipleMetric` 阈值边界（ratio 0<t≤1、倍数 t>0）、`WikiEntry` 校验（title/content 非空与长度）、两聚合不可变与工厂语义 |
| application 集成 | CRUD 往返、越权 404（userId 隔离）、**seeding 幂等**（二次拉取不重复、删光预置不复活）、UNIQUE 冲突 → DUPLICATE_METRIC |
| 前端 vitest | WikiBoard tab 切换、规则表单 % ↔ 0~1 换算、MarkdownView 渲染、`tests/lib/wikiRoute.test.ts` 反代测试 |
| Playwright e2e | `e2e/wiki.spec.ts`：注册登录 → 概念 tab 预置词条可见 → 建读书笔记且 Markdown 渲染 → 建原则规则 → 行业下钻页存研究结论（industry.spec 空库门控范式）→ `/wiki?tab=research` 可见 |
