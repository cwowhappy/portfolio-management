# 投资知识库（wiki-knowledge-base）需求规格说明

> 创建：2026-09-22 | 里程碑：MS-11（二期） | 模块：M13 投资知识库（F01/F02/F03）
> 页面：`/wiki`（新增）+ `/industry/[industryCode]`（扩展） | 前置：无硬依赖（可与 MS-06~10 并行）

## 一、背景与目标

二期决策闭环（MS-06~09）已交付记录、分析、行业研究，但沉淀的**知识资产**无处安放：投资原则停留在纸面、读书笔记散落外部工具、经典概念无速查入口。M13 投资知识库补齐三块，并埋下三期联动钩子：

1. **投资原则与纪律设定**（M13-F01）：结构化纪律规则（如「单票不超过 20%」「PE 高于 40 不买」），**三期 MS-15 原则预警直接消费**；
2. **读书笔记**（M13-F02）：投资经典书籍的 Markdown 笔记；
3. **价值投资概念速查**（M13-F03）：护城河 / 安全边际 / 能力圈 / Mr. Market 等核心概念速查条目。

**交付物**：

1. 后端：新建 `domain/wiki`（+ application/wiki + web/WikiController + infrastructure JPA），`wiki_entry` 内容聚合 + `principle_rule` 规则聚合；Flyway V16 三表；
2. 前端：`/wiki` 页面（四 tab：原则纪律 / 读书笔记 / 概念速查 / 研究笔记）；行业下钻页加「保存研究结论」入口；
3. 概念预置：应用层首次访问 seeding 约 10 条经典概念，开箱即用。

**验收标准**（产品落地计划 MS-11）：

1. 原则规则**结构化存储**（供三期预警消费）；
2. M10 行业研究结论可保存至知识库。

## 二、需求澄清汇总（2026-09-22 brainstorming 定稿）

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | F01 规则建模 | **参数化规则模型**：指标枚举 + 阈值 + 启停，首批 4 种指标（单票仓位% / 行业仓位% / 个股 PE 上限 / 个股 PB 上限）；加新指标只加枚举值；不做通用表达式（三期预警与前端表单都无需处理操作符组合） |
| 2 | M10 联动落地 | **行业下钻页「保存研究结论」入口**：弹表单预填行业上下文，存为知识库 `RESEARCH_NOTE`；满足 MS-11 验收第二条，范围可控（完整笔记区块属三期 M10-F12） |
| 3 | F03 内容源 | **预置 + 用户可增删改**：应用层首次访问 seeding 约 10 条经典概念，开箱即用 |
| 4 | Markdown 体验 | **渲染 + 预览切换**：textarea 编辑（同 journal 惯例），列表/详情用已有 react-markdown 渲染正文，编辑时可切换「编辑/预览」；不引入编辑器库 |
| 5 | 域组织 | **方案 A：单域 `domain/wiki`**，一张 `wiki_entry` 内容表（type 列）+ 一张 `principle_rule` 规则表（journal 单表多类型先例同构）；不扩展 journal 域（M11 决策记录与 M13 知识沉淀是产品文档明确分开的模块边界） |

> #1~#5 为逐题拍板；以下为设计呈现确认（详见 02-设计规格）：

| # | 决策点 | 结论 |
|---|--------|------|
| 6 | 规则唯一性 | `UNIQUE(user_id, metric)`——每指标至多一条规则（同指标双阈值无意义，三期消费每指标取唯一阈值最简；差异化规则是三期加 scope 列的进化） |
| 7 | 概念词条字段 | 不设独立 term 列，title 即术语名 |
| 8 | seeding 机制 | `entries(userId, CONCEPT)` 首次调用同事务批量插入预置 + 写 `wiki_seed_state` 标记；幂等、删光不复活；GET 带一次性写副作用换「全库 user-scoped、CRUD 统一」 |
| 9 | 行业页未登录态 | 「保存研究结论」按钮未登录时**隐藏**（`useAuth()` 判空），不弹登录墙 |

**命名**：遵循仓库「域名 = API 前缀 = 页面路由」惯例（industry/journal 均如此）——`domain/wiki` + `/api/wiki` + 前端 `/wiki` + `lib/wikiApi.ts`。

## 三、功能需求

### A. 投资原则与纪律设定（M13-F01）

- 用户可维护**纪律规则列表**：每条 = 指标（4 种之一）+ 阈值 + 启停 + 可选说明；
- 指标与单位（校验边界固化在枚举语义）：

| metric | 含义 | 单位与边界 | 示例 |
|---|---|---|---|
| `SINGLE_POSITION_RATIO` | 单票市值占组合比例上限 | 比例 `0 < t ≤ 1` | 0.20 |
| `INDUSTRY_POSITION_RATIO` | 单一行业仓位上限 | 比例 `0 < t ≤ 1` | 0.35 |
| `STOCK_PE_MAX` | 个股 PE(TTM) 上限 | 倍数 `t > 0` | 40 |
| `STOCK_PB_MAX` | 个股 PB 上限 | 倍数 `t > 0` | 6 |

- 每用户每指标至多一条；全部规则 user-scoped；
- 前端规则表单按指标类型动态渲染阈值输入（比例类显示 `%` 输入、存储 0~1；倍数类直接数值），已配置指标在下拉中置灰（服务端 UNIQUE 兜底）；
- MS-11 **只做结构化存储**，预警消费侧属三期 MS-15。

### B. 读书笔记（M13-F02）

- 投资经典书籍读书笔记：title + Markdown 正文；
- 编辑 textarea + 「编辑/预览」切换；列表/详情 react-markdown 渲染（复用 chat 已有依赖）；
- CRUD 全套（创建/编辑/删除）。

### C. 价值投资概念速查（M13-F03）

- 概念词条：title（术语名）+ category（分类：估值/质量/行为…）+ Markdown 解释；
- **预置约 10 条经典概念**（护城河、安全边际、能力圈、市场先生、内在价值、复利、均值回归、ROE、PE、PB），首次访问自动导入，用户可增删改；
- 删除全部预置词条后不会重新导入（seed 标记幂等）。

### D. M10 研究结论联动（验收第二条）

- 行业下钻页 `/industry/[industryCode]` 页头加「保存研究结论」按钮；
- 弹窗表单：标题预填「{行业名} 研究结论」、content textarea + 预览切换、`industryCode` 自动带入；
- 保存 → `type=RESEARCH_NOTE` 入库 → 成功提示 +「在知识库查看」链接跳 `/wiki?tab=research`；
- 未登录隐藏按钮（行业页公开无 RequireAuth）。

## 四、非功能需求（NFR）

| 类别 | 要求 |
|------|------|
| 数据隔离 | 全部数据 user-scoped（Controller 提取 userId → 用例首参 → 仓储 `findByIdAndUserId` 三重保障，journal 同款） |
| 安全 | `/api/wiki/**` 全部 authenticated，**不进** `PublicEndpointPaths`（知识库是个人数据） |
| 幂等 | 概念 seeding 幂等可重跑（标记表 PK 保证） |
| 覆盖率 | 后端 JaCoCo / 前端 V8 ≥80%，`make test` 通过（无 collector 变更） |
| e2e | 预置词条可见、markdown 渲染、规则 CRUD、行业联动存结论（空库门控范式） |
| 三期可消费 | `PrincipleMetric` 枚举 + 阈值单位语义是稳定契约，MS-15 预警直接遍历消费 |

## 五、验收标准（沿用产品落地计划 MS-11）

1. **原则规则结构化存储**（供三期预警消费）——`principle_rule` 表 + 指标枚举 + 阈值边界校验；
2. **M10 研究结论可保存至知识库**——下钻页入口 → `RESEARCH_NOTE` → `/wiki` 可见；
3. `make test` 三端全绿 + Playwright e2e 全绿；无新外部数据源，`make smoke` 不重跑（口径同 MS-07/08/09）。

## 六、明确不做（YAGNI）

- **三期 MS-15 预警消费侧**（本里程碑只保证规则结构化落库可供消费）；
- **M10-F12 完整行业研究笔记区块**（编辑/列表/行业关联展示，三期）；
- **富文本/所见即所得编辑器**（维持 textarea + 预览切换，不引入 react-md-editor 类依赖）；
- **概念词条 term 独立列**（title 即术语名）；
- **同指标多条规则 / 规则作用域 scope**（差异化规则是三期进化）；
- **AI 工具入口**（M05 系列属 MS-12）；
- **规则触发的实时检查/提醒**（消费属 MS-15）。

## 七、依赖与风险

| 事项 | 影响 | 对策 |
|------|------|------|
| GET 带 seeding 写副作用 | 首次概念拉取多一次批量 INSERT | 同事务 + 标记表 PK 幂等；一次性成本，接受（换取无 NULL 行/无合并逻辑） |
| chat ThreadArea 抽取 MarkdownView | 重构既有对话渲染路径 | 自定义渲染器经 props 保留、行为不变；e2e chat 既有用例兜底回归 |
| 预置词条内容质量 | 内容即「开箱即用」的官方内容 | 落 `resources/wiki/preset-concepts.json`（classpath 随 jar），Wiki 域测试断言条目数与结构 |
| 行业下钻页 e2e 依赖库有数据 | 空库时联动用例无法走通 | 沿用 industry.spec 空库门控 skip 范式 |
