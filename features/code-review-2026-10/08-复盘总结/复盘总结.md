## 2. 经验（值得固化）

1. **并行修复代理间的「契约接缝」是主代理的核心收口工作**。本批两处：①BE-B 改了 `UserToolkitFactory` 构造签名但主装配未供给 Duration bean，全部 @SpringBootTest 上下文加载失败（靠 BE-C 在测试里加兜底 bean 才暴露）；②BE-C 的会话 GET/PUT 新契约与 FE-A 并行开发未咬合，前端仍按旧 shape 解析。教训：**改构造签名必须 grep 全部调用点（含 @Bean 装配）；并行跨端任务必须把「wire 契约」显式列给某一方的收尾清单**。
2. **TDD 证据让审查修复可审计**。每个代理先红后绿并回传失败摘要（如 TWR 修复红时 actual `1.0000000000` expected 0，与 bug 机理吻合），主代理无需复跑即可信。
3. **目录隔离 + 后端串行是正确的并行粒度**。本次 3 后端 + 1 前端 + 1 主代理同树工作零文件冲突；后端串行避免 Gradle 构建目录竞争。
4. **死配置是「静默失败」模式在新层的复发**。`toolTimeout`/`poolMaxSize` 声明零引用（审查清单老条目在 agent 层复发）——修复方式不是补文档而是接线或删除。
5. **测试固化 bug 时要改测试口径而非迁就**。B5 的 `EmailCodeServiceTest` 四分支断言固化了枚举行为，修复 = 测试按新契约重写，而不是保留旧断言找变通。
