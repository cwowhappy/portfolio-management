## 契约决策（规格 §2 落地形态）

1. **B1**：`execute` 拒收 catch 内 `liveProcess.destroyForcibly()`（进程已 start 成功）+ `markFailed(runId, ...)` + 释放互斥；不吞异常原因（日志留痕）；单测用已 shutdown 的 watchExecutor 触发 RejectedExecutionException。
2. **B2**：五 Raw record 形状见规格决策 2；`EastmoneyMarketDataPort` 替代 `EastmoneyQuotePort`（同名端口改名，impl 同步；@Component 名不变）；fixture 平移后 domain 侧测试改 Raw→DTO 构造；MarketDataParserTest 中断言语义不变。
3. **B3**：`WhereClauseBuilder` 形态：`andIfNotBlank(field, value)`/`andDayStart/andDayEnd` 链式，内置参数收集；五 impl 只描述字段映射；JPQL 字符串产出与原逐字等价（用现有测试钉）。
4. **C3**：二选一优先级——先评估「YAML 显式禁用超时包裹」（纯 DB 操作不需要，改动最小）；若该任务实际也走网络则改「UPDATE 移出 fetch」。
5. **C1**：http_guard 包装保留 requests 模块原属性访问（get/post 可正常 monkeypatch 还原）；幂等安装用模块级标记；90s 只注缺省。
6. **F2**：ProjectDetail 在途禁用只加 `disabled={acting}`（acting=PATCH 在途）；不引入新状态机。
