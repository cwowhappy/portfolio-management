## 1. 背景与目标

第四轮审查（2026-10-15）对上轮 31 条目复发检查零复发，新发现 8 项 + 三项遗留专项（L1/L2/L3）。**本特性目标：17 条目全部落地，三端全量验证收口，本轮审查发现清零。**

本批特点：一项真实并发缺陷（EvalScheduler 孤儿窗口）+ 两项 collector 高（超时无界、僵尸写）为正确性修复；其余为结构债收口。

## 2. 澄清决策汇总（审查发现 → 修复方案拍板）

| # | 决策点 | 拍板结论 |
|---|---|---|
| 1 | EvalScheduler 孤儿窗口 | `watchExecutor.execute` 包 try/catch：`RejectedExecutionException` → `destroyForcibly()` + `markFailed(runId)` + 释放互斥；补「executor 已 shutdown 时触发」单测 |
| 2 | L2 字段码下沉 | 照 RawQuote 已验证模式：domain 新增 5 中间 record（RawIndexQuote/RawStockHit/RawKlineBar/RawFinancialIndicator/RawNewsItem），`EastmoneyFormat` 增 5 extract 方法，`MarketDataParser` 五方法改签 `List<Raw*>`，`EastmoneyQuotePort` 扩为 `EastmoneyMarketDataPort`（五方法，注入点不变）；**红线：异常语义逐字保持**（data 缺失/空数组抛 BAD_RESPONSE 的文案与触发点不变）；JsonNode fixture 平移到 EastmoneyFormat 侧；新浪/腾讯文本兜底解析不做（L2-二期） |
| 3 | persistence 誊写簇 | 抽 `WhereClauseBuilder`（条件短语 append + args 占位 + dayStart/dayEnd 内置），5 个 RepositoryImpl 收敛，预计 -150 行 |
| 4 | C3 僵尸写 | 按报告倾向方案执行：EtfTrackingErrorSource 是纯本地 DB 操作本不需要超时保护 → YAML 显式 `timeout_seconds` 大到永不触发放弃（禁用包裹更清晰），或 UPDATE 移出 fetch，由执行代理按实况二选一（选改动小且语义明确的） |
| 5 | L3 超时收口 | `sources/http_guard.py` 的 `install_default_http_timeout(90)` 包装 requests.get/post（缺省注入、显式传参不覆盖、进程级幂等）；`cli.py` 与 `jobs.py` 两入口各装一次（C1 单入口纪律）；**不用 socket.setdefaulttimeout（实证无效）**；psycopg 7 处加 `connect_timeout=10` |
| 6 | F1 死代码删除 | 删前全仓 grep 再确认零消费方后执行 |
| 7 | F2 在途输入禁用 | ProjectDetail 标题/阶段输入在 PATCH 在途期间禁用——属规格明示的行为微变更（消灭回填覆盖竞态），e2e 如有依赖在途输入的断言需同步 |
