## 3. 功能需求

### 3.1 后端（12 条目 · 14 项修复，FR-B1~B14）

- **FR-B1（N+1/无界载入）**：analytics replay 与 journal timeline 的逐持仓查询改批量端口（`findTradesByPortfolioIdInRange` 一类，含分红同口径）；journal 侧 portfolio 部分下推日期，与 journal 已下推口径对齐。验收：集成测试断言查询次数不随持仓数线性增长（或仓储层批量方法有直接单测）。
- **FR-B2（deletePosition 影响预检）**：删除前置检返回关联交易笔数、分红笔数、已实现盈亏；前端确认弹窗明示「将永久删除 N 笔交易、M 笔分红及全部历史」。验收：有历史持仓删除前弹窗数字与实际一致。
- **FR-B3（buy/现金转出 TOCTOU）**：buy 与现金转出入口先锁组行（悲观写锁）再读算校验。验收：并发双买同组不同股票的集成测试——仅一笔成功，另一笔 INSUFFICIENT_CASH。
- **FR-B4（industryDistribution 未映射桶）**：行业分布含「未映射」桶，合计 = 总资产。验收：存在未映射持仓时分布合计与总资产相等。
- **FR-B5（retOf O(n²)）**：BacktestEngine.retOf 改线性。验收：等价性测试（改前改后同输入同输出）+ 大窗口不超时。
- **FR-B6（激活冲突 409）**：并发激活撞生效唯一索引返回 409 CONFLICT（不再 400）。验收：集成测试双并发激活一胜一 409。
- **FR-B7（screening LIKE 转义）**：关键字中 `%`/`_`/`\` 转义后拼接。验收：含 `%` 关键字查询不返回全表。
- **FR-B8（验证码消费原子化）**：`verify` 改 `tryConsume`（UPDATE ... WHERE used_at IS NULL 行数判定，照绑定码先例）。验收：并发同码仅一次成功。
- **FR-B9（ActiveUserFilter 缓存）**：短 TTL 缓存（60s）+ 用户停用/管理操作事件失效；停用最长 60s 生效。验收：缓存命中不查库 + 失效事件后立即拒。
- **FR-B10（飞书入站韧性）**：队列有界（满则丢弃并计数告警）；非 owner 消息不入队；绑定命令按 open_id 冷却（60s 窗口）。验收：三行为各有单测。
- **FR-B11（留痕表治理）**：`intelligence_push_log` 加 `(push_type, ref_table, ref_id, user_id)` 索引（新迁移）+ 90 天滚动清理；`verification_code` 过期滚动清理（对齐新闻 90 天先例的机制模式）。验收：迁移可重复执行；清理任务幂等有测。
- **FR-B12（时钟注入统一）**：`ResearchApplicationService.writeEvent`、`IntelligenceSubscription` 直用 `Instant.now()` 改注入 Clock（对齐项目 A3 规则）。验收：测试可注入固定时钟断言时间字段。
- **FR-B13（告警邮件降级）**：backend 三处调度告警（原则预警/证伪提醒/宏观源降级）飞书发送失败时降级 SMTP 发送（复用 account-email 通道，收件人环境变量 `ALERT_MAIL_TO`；情报推送类不降级——push_log FAIL 行已有留痕可查）；降级发生留 WARN 日志。验收：飞书不可用时邮件可达（测试用假 sender 断言调用）。
- **FR-B14（重置密码吊销会话）**：密码重置成功后吊销该用户全部现有会话（含 remember-me）。验收：重置后旧会话请求返回 401。

> 注：条目计数中「后端业务域小项」（FR-B5/B6/B7）在审查报告为一条 bullet 下三处修复；FR-B13 告警降级同时覆盖 collector 侧（见 FR-C5 配合）。

### 3.2 前端（6 条目，FR-F1~F6）

- **FR-F1（图表深链）**：`/market` 挂载时读 `?code=` → 触发搜索并选中标的；行业页图表点击跳行情台联动恢复。验收：e2e 从行业页点击落行情台且标的已选中。
- **FR-F2（回灌失败错误态）**：会话历史 hydrate 失败时渲染可操作错误态（重试/新会话），不再静默锁死输入区。验收：组件测试模拟 hydrate 失败呈现错误 UI，重试动作可触发。
- **FR-F3（flushPersist 序号守卫）**：flush 快照带单调序号，旧快照后到不得覆盖新快照。验收：单测模拟乱序完成。
- **FR-F4（工具卡外链消毒）**：抽共用 `safeUrl()`（仅放行 http/https，与 MarkdownView 信任模型一致），工具卡三处 `url/pdfUrl` 渲染统一走它。验收：`javascript:` 前缀渲染为纯文本/无 href。
- **FR-F5（catch-all 反代重编码）**：`app/api/**/[...path]` 逐段 `encodeURIComponent` + 拒绝 `..` 段。验收：`%2F`/`%3F` 注入与 `../` 逃逸均 400/404，正常路径行为不变。
- **FR-F6（设置页三件）**：settings/{mcp,skills,intelligence} 包 RequireAuth；McpSettingsPage 防连点（pending 期 disabled）、加载/错误态不渲染 undefined、色值改 CSS 变量。验收：匿名访问设置页跳登录；深色主题设置页无硬编码色。

### 3.3 collector（5 条目 · 6 项修复，FR-C1~C6）

- **FR-C1（depends_on 前置检查）**：任务 YAML 可声明 `depends_on: [task_code...]`；runner 执行前查上游当日无 success/partial run（partial 已落数据，对齐 `never_succeeded` 先例口径）则跳过并告警留痕（skipped 状态，不入失败口径）。验收：上游失败日下游 skipped 且有告警；上游正常不受影响。
- **FR-C2（悬挂 running reaper）**：启动时将 `started_at < now() - 1 day` 的 running 记录批量置 failed（原因标 reaper）。验收：预置悬挂记录启动后被置 failed。
- **FR-C3（告警风暴抑制）**：按 (task_code, 错误签名) 滑动窗口合并（同签名 30 分钟内只发一次，计数聚合）。验收：同错误连续 retry 只一张卡；不同错误不合并。
- **FR-C4（validator range hard 语义）**：range 规则 hard 级命中时剔除数据并记 issue（对齐其余规则语义），soft 维持现状。验收：hard 越界行被剔、YAML 现全 soft 行为不变。
- **FR-C5（节假日备源空帧保护）**：spot 备源对齐 EtfCloseSource 空帧保护——非交易日空数据不写行。验收：空数据帧返回不落库不报错。
- **FR-C6（collector 告警邮件降级）**：飞书发送失败重试一次仍失败走 SMTP 轻客户端（`MAIL_*` 环境变量，同 backend 命名先例）；与 FR-B13 同属决策 #5 的 collector 侧。验收：飞书不可用时邮件发送被调用（假 sender 单测）。

## 4. 非功能需求

- **NFR-1 严格 TDD**：每条修复先写失败测试并确认红（错因正确），再最小实现转绿；行为断言而非实现断言。
- **NFR-2 覆盖率门槛不破**：三端 ≥80% 由全量 `make test` 收口，禁止 `| tail` 吞退出码。
- **NFR-3 架构约束不破**：不引入新的跨层依赖；ArchUnit 白名单不改（domain 子包通配覆盖；悲观锁方法落在 infrastructure 仓库实现）。
- **NFR-4 契约变更全链路同步**：README 端点表、模块文档 03-接口设计、e2e 断言、zod schema 同分支更新。
- **NFR-5 并行分工按目录隔离**：三 PR 目录不相交（backend/frontend/collector），分支自 main 切出顺序合并；后端内部并行共享 Gradle 构建目录需串行跑测试。
- **NFR-6 数据迁移幂等**：新 Flyway 迁移可重复执行（幂等索引创建模式沿用先例）。

## 5. 验收标准（特性级）

1. 三个 PR 全部合并，全量 `make test` 三端 EXIT=0；
2. 23 条目每条有先红后绿的测试证据（复盘总结 TDD 符合性清单）；
3. 审查报告 P2 清单逐条勾销（复盘总结对照表），MS-28 规划节回填交付注记；
4. 告警降级路径在部署机人工验证一次（飞书凭证故意留空触发邮件）——上线项，不阻塞合并。
