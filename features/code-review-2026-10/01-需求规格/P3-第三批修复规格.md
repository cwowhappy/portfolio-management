> 性质：跨里程碑工程项（阶段三 MS-28 工程前置，归属模块 M14 系统与工程）。

## 1. 背景与目标

2026-10-12 第三轮三服务深度审查产出：backend 5+4 项、collector 6 项、frontend 5 项（含 P1/P2/P3 混合分级，编号见下）。**本特性目标：全部 20 项落地，三端 `make test` 全量收口，本轮审查发现清零（文档漂移项同步完成）。**

本批与前批差异：无高危项，全部为结构债与契约债；重点是三类跨服务共性模式——双真源收敛、god module 拆分、静默失败留痕。

## 2. 澄清决策汇总（审查发现 → 修复方案拍板）

| # | 决策点 | 拍板结论 |
|---|---|---|
| 1 | AlertMailer 位置 | 横切组件放 `application/` 横切包（4 处使用方均在 application 层），具体形态参照仓库既有邮件发送实现与 DDD 依赖方向；语义 = 「发告警邮件，失败降级留痕，异常不外泄」，4 处调用方只留一行调用 |
| 2 | intelligence 抽取归一 | 抽 `ExtractionBatchService<T>` 模板（批调度/单条跳过续抽/话术）+ 共享 CSV 解析骨架；News/Policy/Announcement 三套 extractor/service/repository 收敛为模板实例；**红线：既有测试全绿，测试断言语义不改** |
| 3 | HarnessAgentFactory 双链 | 抽 `baseBuilder(userId)` 私有方法，build 与 buildReportAgent 只覆盖差异点（name/prompt/maxIters/toolkit/middleware）；同包字节比对测试（若存在）必须继续通过 |
| 4 | parseAsOf 收敛 | 提升为 `agent/trust` 包公有静态方法（ConfidenceScorer 同包），ReportWorkflowOrchestrator 删除就地同构实现直引之 |
| 5 | 8 处 `@Modifying` | 逐条分析调用方事务内是否「批量 update + 同上下文 save 同实体」：是 → 补 `clearAutomatically = true` + 回归测试；否 → 加注释说明为何安全（对照 AllocationPlanJpaRepository.java:15 正确先例） |
| 6 | 大类拆分 | ResearchApplicationService / IntelligenceQueryService 按用例族纯搬移拆分，不改行为；InvestTools 采用「门面 + 域子组件」模式（参考 UserInvestTools 拆分先例），`@Tool` 暴露面字节不变 |
| 7 | frontend types.ts | 逐域迁移 `z.infer` 派生（researchSchemas 模式），保留纯前端模型（ChatMessage 等）；diff 最小化，类型断言一处不动只换导出源 |
| 8 | research 页面下沉 | 三个 page 的业务逻辑迁入 `components/research/`（域内已有 14 文件生态），page 回归 ≤40 行薄壳；渲染期 setState 镜像收敛为提取 `useDraftSync` hook 或加载点统一初始化；迁移后组件补 vitest |
| 9 | collector 停牌语义 | 表注释/模块 docstring 写明「daily_basic 缺席即停牌」契约 + 后端消费方文档同步；`stock_valuation_daily` 补 close>0、turnover≥0 soft range（现有 rules 能力，仅加 YAML 行 + 回归用例） |
| 10 | collector C3 | `load()` 增加 per-command 必需键参数；list/history/seed 只要求 DATABASE_URL；数据源相关命令才要求 TUSHARE_TOKEN |
| 11 | writer 缺列 | upsert 前校验首行 keys ⊇ 表列（缺口径可空列白名单），缺列抛 StoreError 而非静默 NULL |
| 12 | 文档同步 | backend 分包规范补 trust/observability 子系统、17 域、26 条规则；collector 规范 C3 标注已落实；本轮 features 文档登记索引 |
