## 做得好的

- **存储契约早有伏笔**：`auth_secret_enc` 字段名与 README 规划语义（base64 32B、缺失不阻断、调用时报错）在交付前已写死，实现只是兑现口径——brainstorming 阶段照单全收，零口径发明。
- **e2e 兜底再次兑现**：单测/切片全绿的情况下，e2e 抓出 admin 反代 route 只导出 GET/POST、缺 PUT 的真 bug（405 以无 message 的「请求失败」面穿到页面）——mock 类测试对该缺陷全盲（vitest mock 的是 lib/adminApi 层，不经反代）。与「e2e 旧构建与 mock 盲区」教训互证：**反代层（app/api/**）改动必须真浏览器验证**。
- BDD 先红后绿复用 503 路径：场景初跑 `expected:<204> but was:<503>` 精确验证了「密钥缺失→SERVICE_UNAVAILABLE」全链映射，加测试密钥后转绿——一次 RED 覆盖两个行为。

## 教训

1. **GWT 命名规约是构建红线**：codec 首轮 12 个测试方法用动作命名（`roundTrip` 等），全量单测被 `TestSourceSetConventionsTest` G6 拦下——新测试类应直接照 GWT 起名，别等 ArchUnit 教做人。
2. **`@SpringBootTest(properties=...)` 只认编译期常量**：测试密钥想用 `Base64.encode()` 运行时生成 → 注解编译失败；固定 base64 字面量（32 零字节）即可。
3. **注解属性/构造器参数变更的涟漪面要用全仓 grep 收**：`UserToolkitFactory` 构造器变更在 integrationTest 还有一处（AguiInterruptIntegrationTest TestConfiguration），IDE 诊断提示后全仓 `grep "new UserToolkitFactory("` 收口。

## TDD 纪律备注（如实记录）

一处顺序偏差：repository 的 `updateProviderSecret`（JPQL 批量更新）由服务层单测（mock repo）驱动实现后，才补 PG 集成测试且首跑即绿——未目击其红。其失败牙齿依赖 Hibernate 启动期查询校验（实体/属性名错误会使整个 @DataJpaTest 切片失败），非零防御，但严格意义上非先红后绿。后续同类（ORM 查询方法）应先写集成红再实现。
