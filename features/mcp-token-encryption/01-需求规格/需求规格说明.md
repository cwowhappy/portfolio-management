# MCP Token 加密（P1-10）需求规格说明

> 创建：2026-10-03 | 来源：P1-10 悬空项收口（发布计划「排期进二期」→ 单开小特性拍板）
> 状态：已定稿（2026-10-03 brainstorming 两项用户拍板 + bounded 设计获批）

## 一、背景与决策

`mcp_provider.auth_secret_enc` 当前全库明文（seed 留 NULL，真实 token 部署脚本直填 DB），读点仅 2 处（`UserToolkitFactory` 工具装配、`McpConfigApplicationService.test` 连通性测试），视图层不回显。本特性按 README 既有规划语义落地 AES-256-GCM 加密。

**用户拍板（2026-10-03）**：

| # | 决策点 | 结论 |
|---|---|---|
| D1 | token 写入路径 | Admin API + 设置页小块（符合 14-系统与工程「admin UI 配置时加密」愿景；明文只在请求体一次经过、落库即密文、永不出参） |
| D2 | NFR「统一收纳」边界 | 只收 MCP；SMTP 密码、飞书 secret 维持 env 口径（同机同文件加密无增益），NFR-6/NFR-4 关单 |

## 二、功能需求

| # | 需求 | 说明 |
|---|---|---|
| FR-1 | 加解密设施 | `domain/mcp` 接口 `McpSecretCodec` + `infrastructure/security` 实现 `AesGcmSecretCodec`：JDK AES/GCM/NoPadding，密文格式 `v1:` + base64(12B 随机 nonce ‖ 密文 ‖ 16B tag)，每次加密 nonce 随机 |
| FR-2 | 密钥语义 | `invest.mcp.secret-key` ← `${MCP_SECRET_KEY:}`（base64 32B）。缺失/空白：不阻断启动，调用 encrypt/解密 `v1:` 密文时报 `SECRET_KEY_MISSING`；非空白但格式错（非 base64 / ≠32B）：构造即失败（fail fast） |
| FR-3 | 明文兼容 | 无 `v1:` 前缀的存量值 → 明文直读 + 每值一次 warn 日志；不做迁移仪式，文档引导用 admin 端点覆写 |
| FR-4 | Admin 写入 | `PUT /api/admin/mcp/providers/{code}/token`（ADMIN 守卫）：token 非空 ≤512B 校验 → 加密落库（repository `updateProviderSecret`）→ 204；审计日志只记 provider code 不含明文 |
| FR-5 | 读路径改造 | 两读点经 `codec.decrypt()`：工具装配处解密失败 → 跳过该 provider + warn（与「secret 空」同模式）；连通测试解密失败 → `TestResult.fail`（既有 McpException 通道） |
| FR-6 | 前端 | admin 页「MCP 数据源 Token」小块：每 provider 一行（code/name/authType + 已设置状态点 + 设置/更换输入框），不显示已存值；走 lib/api 不直连 fetch |

## 三、非功能需求

| # | 需求 | 说明 |
|---|---|---|
| NFR-1 | 不回显 | 任何 API 响应与日志不得出现 token 明文/密文（审计日志仅 provider code） |
| NFR-2 | 覆盖率 | 三层测试照常 ≥80%（codec 单元 + 服务/切片 + BDD + 前端 vitest/e2e） |
| NFR-3 | 文档同步 | `.env.example` / README 环境变量表（「规划中」→已实现 + key 生成命令）/ `发布方案.md` / `发布计划.md` / `14-系统与工程.md` / 两 NFR 规格文案，七处收口 |

## 四、非目标

- SMTP 密码、飞书 webhook/app secret **不**搬库（D2；threat model：DB 备份/导出泄露只对库内密文成立）
- token 轮换后 `McpClientPool` 缓存 evict 不做——重启生效（单管理员低频操作；Spring 事件方案留痕备选）
- 密钥轮换机制不做（`v1:` 前缀已留余地）

## 五、验收清单

1. codec 单元：round-trip / 随机 nonce / 错 key / 坏格式 / 截断 / 空 key 三态 / 明文兼容 / 构造 fail-fast
2. admin 端点：ADMIN 可设、USER 403、匿名 401、404、空值 400、落库为 `v1:` 密文（集成断言）
3. 读路径：明文/密文两态装配可用，解密失败跳过 + 测试失败态
4. BDD 中文场景一条：管理员设置 token → 库内密文 → 工具装配可用
5. `make test` 三端全绿；七处文档收口
