
## 二、数据与端口设计（F11 核心）

### 2.1 读侧端口：`domain.market.FinancialRecordRepository`

```java
/** 个股财务指标季记录（stock_financial 表读侧值对象）。 */
public record FinancialRecord(
        LocalDate reportDate, Double roe, Double roa, Double grossMargin,
        Double debtToAssets, Double currentRatio, Double revenueYoy,
        Double netprofitYoy, BigDecimal revenue) {}

public interface FinancialRecordRepository {
    /** 按报告期降序取近 N 季（采集端回填 12 季，N 由调用方定）。 */
    List<FinancialRecord> findByCodeLatest(String stockCode, int limit);
}
```

- `infrastructure/persistence/FinancialRecordRepositoryImpl`：JdbcTemplate 直查 `stock_financial`（ScreeningRepositoryImpl 跨域读先例同款——该表 owner 是 collector，后端只读）；
- **无 JPA 实体**（纯读投影，不参与写路径），ArchUnit JPA 规则不受影响。

### 2.2 杜邦纯函数：`domain.market.DuPontAnalysis`

```java
/** 杜邦三因子拆解：ROE = 净利率 × 总资产周转率 × 权益乘数。 */
public record DuPontResult(Double netMargin, Double assetTurnover, Double equityMultiplier,
                           Double roe, String reportDate, List<String> missingFactors) {}

public static DuPontResult of(Double netMargin, Double roa, Double debtToAssets, Double roe, String reportDate)
```

- 推导：权益乘数 = `1/(1−debtToAssets)`；周转率 = `roa/netMargin`（roa=净利润/平均总资产 ÷ 净利率=净利润/营收 ⇒ 营收/平均总资产）；
- 任一因子缺数据 → 该因子 null 且记入 `missingFactors`（部分拆解仍可展示，不整体失败）；
- 纯函数零依赖，单测钉住数学口径。

### 2.3 两源合并规则（F11）

| 因子 | 来源 | 期口径 |
|---|---|---|
| 净利率 | 东财 live `Financials`（netProfit/totalRevenue） | 最新报告期（随 live） |
| ROA / 资产负债率 / ROE / 趋势序列 | `stock_financial` 库表 | 最新季（降序首条） |
| 周转率 / 权益乘数 | 推导 | 同库表最新季 |

输出摘要标注各因子报告期；库表空 → 降级文案（只回 live 财务 + 「库表趋势数据积累中」）。

## 三、后端 agent 设计

### 3.1 `InvestTools` 追加 3 工具（无用户态）

| 工具名 | 参数 | 消费 | emit（SSE 全量） | 返回（LLM 摘要） |
|---|---|---|---|---|
| `screen_stocks` | 15 维可空条件 + `industryCode` + `indexCode`(白名单 000300/000905) + `sortBy`(白名单 `SORTABLE_FIELDS`) + `sortDirection` + `limit`(默认 20，上限 50) | `ScreeningApplicationService.screen` | `ChartSpecs.screeningTable(results)` | 命中数 + top5 名称/代码/关键指标 |
| `analyze_financials` | `code`(6 位) | 新 `FinancialQueryService`（端口+东财 live 合并） | `ChartSpecs.financialTrendTable(records)` | 杜邦三因子（含报告期与缺失因子说明）+ 趋势结论要点 |
| `analyze_industry` | `industryCode` 可空 | `IndustryApplicationService.board()/stocks(code, sortBy, dir, limit)` | 空码 `industryBoardTable(board)`；带码 `industryStocksTable(stocks)` | 空码：估值分位 top/bottom 行业；带码：行业估值位 + 头部企业要点 |

- 工具层守卫：`screen_stocks` 无任何条件 → 返回错误 JSON（不调服务，提示至少一个条件）；
- 空数据 emit 前守卫沿用（`get_kline` 先例）：空结果返回安全摘要不 emit；
- `@Tool(readOnly = true, concurrencySafe = true)` 与既有 7 工具一致。

### 3.2 新 `agent/UserInvestTools`（用户态，F09/F10）

```java
/** 用户态投研工具：userId 经 UserToolkitFactory 构造注入，不进 LLM 上下文。非 Spring bean。 */
public class UserInvestTools {
    public UserInvestTools(Long userId, PortfolioApplicationService portfolio,
                           AllocationApplicationService allocation, ObjectMapper mapper) { … }

    @Tool(name = "analyze_portfolio", description = "读取当前用户持仓组合：总览（市值/成本/盈亏）、资产配置、行业分布、集中度与持仓明细。用户问「我的持仓/组合怎么样」时调用。", readOnly = true, concurrencySafe = true)
    public ToolResultBlock analyzePortfolio(ToolEmitter emitter) { … }

    @Tool(name = "suggest_allocation", description = "基于用户风险测评结果推荐资产配置模板，并结合当前持仓给出偏离提示。未完成测评时返回引导提示。", readOnly = true, concurrencySafe = true)
    public ToolResultBlock suggestAllocation(ToolEmitter emitter) { … }
}
```

- `analyze_portfolio`：`overview` + `allocation` + `industryDistribution` + `concentration` 四读一次取齐；emit `ChartSpecs.portfolioPie(allocation)`；空持仓不 emit 返回「暂无持仓」摘要；
- `suggest_allocation`：`latestAssessment` 空 → 返回「先完成风险测评」提示（不 emit）；有测评 → `RiskProfile.recommendedWeights`（五档风险画像内置权重：保守/稳健/平衡/成长/进取）对照 `PortfolioApplicationService.allocation` 当前分布 + `deviation`（有活跃方案时），emit `ChartSpecs.allocationDeviationTable(...)`；
- `UserToolkitFactory.build(userId)` 追加一行 `toolkit.registerTool(new UserInvestTools(userId, portfolioService, allocationService, mapper))`；错误兜底复制 `runBlock` 模式（用户态服务异常 → 错误 JSON，不抛出）。

### 3.3 `application.market.FinancialQueryService`（新，薄编排）

- `financialRecords(code, limit)` → 端口查询 + 东财 live（`MarketDataService.financials`）合并为 `FinancialAnalysisView`（records 序列 + live 最新净利率 + `DuPontAnalysis` 结果）；
- 只做取数与合并，不做解读（解读归 LLM）——与「数据真实」回答规范的职责分界。

### 3.4 ChartSpecs 扩展（5 个静态构造）

`screeningTable` / `financialTrendTable` / `industryBoardTable` / `industryStocksTable`（table spec，`financialsTable` 先例同款）/ `portfolioPie`（pie spec——前端 `lib/chart-spec.ts` zod pie 既有，chat 图表卡可渲染）；对应 `*Summary` 摘要方法。SPEC_VERSION 不变（无契约破坏）。

### 3.5 提示词（`InvestSystemPrompt`）

工具使用规范追加（编号续既有 5 条）：

- 选股/筛选 → `screen_stocks`（至少一个条件；结果按命中数与头部概述）；
- 「我的持仓/组合」→ `analyze_portfolio`（私有数据，仅本人会话）；
- 「怎么配置/建议仓位」→ `suggest_allocation`（无测评时引导完成 M07 测评，不虚构建议）；
- 「XX 财报怎么样/赚钱能力拆解」→ `analyze_financials`（杜邦+趋势；名称先 `search_stock`）；
- 「XX 行业怎么样」→ `analyze_industry`（先无参板面对齐行业码，再带参下钻）；
- 私有数据口径：F09/F10 结果含用户私有数据，**禁止**将其作为参数传给任何 MCP 工具。

## 四、前端设计

- `components/chat/ToolCallCard.tsx`：`TOOL_LABELS` +5（筛选选股 / 持仓分析 / 配置建议 / 财报解读 / 行业分析）+ 第二映射表（建议问句）同步；
- `components/chat/toolRenderers.tsx`：表格/饼图渲染既有通道零改动（新 spec 类型复用 table/pie）；若渲染分支按工具名分派则补 5 行映射；
- 无新页面、无新 API 路由、无 relay 改动。

## 五、错误处理与边界

| 场景 | 行为 |
|---|---|
| 筛选无条件（F08） | 工具层拦截返回错误 JSON（「请至少给出一个筛选条件」），不调服务 |
| 库表无该股（F11） | 降级：live 财务 + 「趋势数据积累中」摘要，不 emit 空表 |
| 空持仓（F09）/ 无测评（F10） | 不 emit，返回引导性摘要文本 |
| 服务异常（F09/F10） | `runBlock` 模式翻译为错误 JSON（前端 ChartCard 嗅探降级既有机制） |
| 板面空库（F12） | `board()` 空列表 → 安全摘要（同 valuation 冷库先例） |
| 指数/排序白名单外值 | `ScreeningCriteria` 紧凑构造器既有校验抛 `ScreeningException` → 工具 catch 转错误 JSON |
