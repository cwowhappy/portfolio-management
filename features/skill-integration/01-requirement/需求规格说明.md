# 系统内置 Skill · 需求规格说明

> 状态：已确认需求（2026-09-07）。Harness Skill 机制调研见 [docs/technology/research/agentscope/skill.md](../../../docs/technology/research/agentscope/skill.md)；设计见 `02-design/设计规格说明.md`。
> 与已合并的 MCP 特性（`features/mcp-integration/`）同属「系统内置目录 + 用户选择 + 每请求按用户装配」范式。

## 背景与目标

当前投研 Agent 有 7 个内置 `@Tool`（行情/K线/财务/新闻/大盘/估值）+ 可选的 MCP 数据源（妙想/Tushare/Wind），但「如何组合这些工具完成一类分析」的经验只散落在 `InvestSystemPrompt` 的静态规约里，无法按用户需要扩展或收敛。

AgentScope 提供 **Skill** 机制：一段 Markdown 指令集（`SKILL.md`），教 Agent 用已有工具完成某类工作流，**不新增工具调用面、不写新工具代码**——Skill 只进提示词，由 Agent 经自动注册的 viewer tool 按需读取后，用现有工具执行。

**目标**：把这种「过程知识」做成**系统内置 Skill 目录**，由**用户按需启用**；对话时只把启用的 Skill 注入 Agent。一期内置 2 个 Skill（`tushare_data`、`wind_finance`），分别落地 Tushare、Wind 两个数据源的能力边界。

## 关键决策（已确认，2026-09-07）

1. **Skill = classpath 资源，不是 DB 记录**：内容随服务发布，经 `ClasspathSkillRepository` 只读加载；DB 只存**用户选择**，无 `skill` 目录表（classpath-only）。区别于 MCP（provider 有 URL/Token 运行期可变属性须入 DB），Skill 内容静态。
2. **目录元数据来自 SKILL.md frontmatter**：`name`/`description` 是框架必读字段，另约定 `category`（分组）、`default_enabled`（默认开关）等自定义字段，由应用层读取。
3. **用户选择 = `skill_user_config` 表**（user_id, skill_code, enabled），只存显式选择；无行时回落 frontmatter 的 `default_enabled`。
4. **装配 = `SkillFilter.only(effectiveEnabled)`（白名单，opt-in）**：`HarnessAgent.builder().skillRepository(单例 repo).skillFilter(...).disableDefaultWorkspaceSkills().disableDynamicSkills()`，使「技能面 = 系统内置目录 ∩ 用户启用」。
5. **首批 2 个内置 Skill**（均 `default_enabled: false`，按需启用）：`tushare_data`（Tushare 全品类金融数据补充）、`wind_finance`（Wind 机构级金融数据与文档）。详见设计 §十一。
6. **一期纯指令集，不捆绑工具组**；不开 curator/自治（Agent 不产生新 skill）。

### Grilling 澄清结论（2026-09-07，两轮）

7. **依赖软提示，不硬耦合**：skill 引用未启用的 provider 时不校验、不联动；依赖关系经 frontmatter `depends_on_provider` 声明、目录 API 透出，前端卡片据此提示。
8. **提示词管全局路由，skill 管数据源内工作流**：一期不精简 `InvestSystemPrompt`，只加兜底规约。
9. **软触发 + 兜底约束**：不改显式点名；提示词加「仅当内置工具与已启用 MCP 专项工具无法覆盖时才加载数据源类 skill」。
10. **独立 `/settings/skills` 页**（与 `/settings/mcp` 并列）。
11. **强制数据来源声明**：引用 Tushare/Wind 数据时标注来源。
12. **Tushare 与 Wind 重叠域分工**：提示词加明确分工（公告/新闻/EDB/聚合 → Wind；期货/港美股/债券/三表/指数成分 → Tushare；重叠 A股行情财务 → 内置工具优先，MCP 兜底默认 Wind）。
13. **skill 正文统一五节模板**：`定位 / 触发条件 / 覆盖域 / 流程 / 来源声明`。

## 用户故事

- 作为**用户**，我在「Skill 设置」看到系统内置的 2 个 skill（Tushare 数据补充 / Wind 数据与文档），启用 Wind 后，对话遇到公告/新闻/宏观类问题会按 Wind 数据源流程作答。
- 作为**用户**，我可以随时停用某个 skill，停用后立即不再触发。
- 作为**用户**，我未启用任何 skill 时，对话体验与现状一致（仅 7 内置工具 + 本人已启用的 MCP 数据源）。

## 功能需求

| 编号 | 需求 |
|---|---|
| FR-1 | 内置 skill 目录：从 classpath 枚举 `resources/skills/**/SKILL.md`，返回 name/description/category/default_enabled + 我的当前启用状态（合并返回）；只读，用户不可增删改内容 |
| FR-2 | 用户配置：每用户对每个 skill 保存启用/停用；无行时按 frontmatter `default_enabled` 回落 |
| FR-3 | 对话按用户装配：`SkillFilter.only(effectiveEnabled)`，只把启用的 skill 注入 Agent；未启用任何 skill 时等同现状 |
| FR-4 | 技能面收敛：`disableDefaultWorkspaceSkills()` + `disableDynamicSkills()`，避免工作区/动态 skill 混入目录外技能 |
| FR-5 | 配置变更即时生效：每请求现建 Agent，用户改启用状态后下次对话即生效 |
| FR-6 | 单例 `ClasspathSkillRepository`：随 Spring 生命周期管理，不 per-request new/close（JAR 虚拟文件系统引用计数） |

## 非功能需求

- **性能**：skill 只把 name+description 清单注入系统提示词，全文经 viewer tool 按需加载，上下文成本低；`SkillFilter` 计算 O(1)（按 name 集合）。
- **可靠性**：`ClasspathSkillRepository` 在 dev classpath 与 bootJar（fat jar）下均能枚举 skill；目录解析失败不阻塞 Agent 启动。
- **可观测**：skill 枚举结果、每用户生效集合有日志（不含敏感信息）。
- **架构合规**：遵循 DDD 分包规范（`domain.skill` / `application.skill` / `web` / `infrastructure` / `agent`），ArchUnit 全绿。

## 验收标准

1. 用户启用 `wind_finance` 后，对话遇到公告/新闻/宏观问题会按该 skill 流程作答；停用后不再体现。
2. 未启用任何 skill 的用户，对话行为与现状一致（仅 7 内置工具 + 已启用 MCP）。
3. `GET /api/skills` 正确枚举 classpath 内置 skill，并合并返回我的启用状态（无行回落 `default_enabled`）。
4. `PUT /api/skills/config` 保存后，下一次对话装配的 skill 集合立即变化。
5. 覆盖率门槛不降级（后端 JaCoCo ≥80%），ArchUnit 全绿。

## 范围外（一期不做）与后续计划

**范围外（一期不做）**：

- `skill` 目录表（admin 系统级开关/排序/隐藏）——目录元数据仅 classpath
- Skill 捆绑专属工具（`SkillToolGroup` 按需披露）
- Skill curator/自治（Agent 从成功模式自建 skill）、skill 审批门控
- 用户自定义 skill（自建/上传 SKILL.md）
- 第三方技能市场/订阅

**后续计划（演进方向）**：

- **admin UI 管理系统级 skill 开关**：二期加 `skill` 表，补 admin 端点 + 目录一致性校验
- **SkillToolGroup**：某 skill 需要专属工具（写文件/画图等）时，启用按需披露
- **用户自定义 skill**：利用 harness `WorkspaceSkillRepository`，把用户工作区 skill 纳入装配
- **Skill curator**：从成功对话模式沉淀候选 skill，经审批门控晋升为内置目录
- **更多内置 skill**：在 `tushare_data`/`wind_finance` 之上，按产品需要扩展分析工作流类 skill（`category: analysis`）
