## §1 ClasspathSkillRepository 枚举与元数据读取（Task 1）

**结论：PASS** — `ClasspathSkillRepository(String resourcePath)` 从 classpath 读父目录下 `*/SKILL.md`，`getAllSkillNames()`/`getSkill(name)`/`getAllSkills()` 委托 `SkillFileSystemHelper`；`AgentSkill.getMetadata()` 含 frontmatter 全部自定义字段。

### jar/dir 两种 URI 分支（源码核实）

构造器 `ClasspathSkillRepository(String resourcePath)`（`io/agentscope/core/skill/repository/ClasspathSkillRepository.java`）：

- `URL resourceUrl = classLoader.getResource(resourcePath)`；`resourceUrl == null` 时抛 `IOException("Resource not found: ...")`。
- `URI uri = resourceUrl.toURI()` 后按 scheme 分支：
  - `"jar"` scheme → `isJar=true`：`toFileSystemUri(uri)` 截到最后一个 `!` 得到 jar FS URI，`acquireFileSystem(...)` 挂载（内部 `FileSystems.newFileSystem`，静态 `SHARED_FILE_SYSTEMS` 按 URI 引用计数）；`skillBasePath = fileSystem.getPath(actualResourcePath)`（`!` 之后路径）。
  - 否则（dev classpath，`file:` scheme）→ `isJar=false`，`skillBasePath = Path.of(uri)`。
- `source` 缺省为 `classpath-<resourcePath 最后一段>`（如传 `"test-skills"` 得 `classpath-test-skills`）。

`getSkill`/`getAllSkills`/`getAllSkillNames`/`skillExists` 全部委托 `SkillFileSystemHelper`（`io/agentscope/core/skill/util/SkillFileSystemHelper.java`）：

- `getAllSkillNames()` 用 `Files.list(baseDir)` 列出子目录，逐个读 `SKILL.md` frontmatter 的 `name` 字段（`MarkdownSkillParser.parse` → metadata `name`），按 `String::compareTo` 排序。
- `loadSkill` 按 `name` 定位 skill 目录（`findSkillDirectoryByName`），`loadSkillFromDirectory` 读 `SKILL.md`，`SkillUtil.createFrom` 组装 `AgentSkill`（含 `originDir`）。

### frontmatter 自定义字段

`MarkdownSkillParser`（`io/agentscope/core/skill/util/MarkdownSkillParser.java`）用 SnakeYAML `SafeConstructor` 解析 frontmatter；`name`/`description` 之外的自定义字段（`category`/`default_enabled`/`depends_on_provider`）全部保留进 `AgentSkill.getMetadata()`（`Map<String,Object>`）。

## §2 SkillFilter 语义（Task 2）

**结论**：`SkillFilter`（`io/agentscope/core/skill/SkillFilter.java`）分两类工厂——standalone（完整策略）与 overlay（部分覆盖，仅 `overlay()` 合并时用）：

| 模式 | 工厂 | `isAllowed(name)` 语义 |
|---|---|---|
| ALL | `all()` | 恒 true（**无 filter 时的默认**） |
| NONE | `none()` | 恒 false |
| WHITELIST | `only("a","b")` | `skillNames.contains(name)` |
| BLACKLIST | `except("a")` | `!skillNames.contains(name)` |
| OVERLAY_ENABLE | `enable("a")` | `skillNames.contains(name)` |
| OVERLAY_DISABLE | `disable("b")` | `!skillNames.contains(name)` |

合并规则 `overlay(runtimeOverlay)`：

- `runtimeOverlay == null` → 返回 base（不变）。
- `runtimeOverlay` 非 overlay（即 standalone）→ **直接替换** base 为 runtimeOverlay。
- `runtimeOverlay` 为 overlay → 「被 overlay 点名的 skill 用 overlay 决策，其余落到 base」；返回的合并 filter 恒 `isOverlay()=false`。

对本设计的影响：用户选择 = `SkillFilter.only(effectiveEnabled)`（WHITELIST，opt-in）。因默认（不配 filter）= `all()`，必须显式传 filter 才能表达「只启用部分」；空集合的语义见 §4。

## §3 HarnessAgent.Builder 的 skill 装配点（Task 3）

**结论**：`HarnessAgent$Builder`（`javap` 核对 `agentscope-harness-2.0.1.jar`，无 sources）存在设计所需的全部 skill 装配点，组合语义与设计 §四一致。

### 精确签名（javap）

```text
public HarnessAgent$Builder skillRepository(AgentSkillRepository)
public HarnessAgent$Builder skillRepositories(List<AgentSkillRepository>)
public HarnessAgent$Builder projectGlobalSkillsDir(Path)
public HarnessAgent$Builder skillFilter(SkillFilter)
public HarnessAgent$Builder enableSkills(String...)
public HarnessAgent$Builder disableSkills(String...)
public HarnessAgent$Builder skillsEnabled(boolean)
public HarnessAgent$Builder disableDefaultWorkspaceSkills()
public HarnessAgent$Builder disableDynamicSkills()
```

实例侧：`public List<AgentSkillRepository> getSkillRepositories()` 存在（另有 `getSkillUsageStore()`/`runCuratorOnce()`/`promoteSkill(...)`/`queryAudit(...)` 属 curator 治理面，本特性不用）。

### 推论（与设计 §四一致）

1. `skillRepository(repo)` + `skillFilter(SkillFilter.only(enabled))` 表达「系统内置目录 ∩ 用户启用」。
2. Builder 中存在 `workspace` field 与默认 `WorkspaceSkillRepository` 装配（`disableDefaultWorkspaceSkills`/`disableDynamicSkills` 两 no-arg 开关存在），故必须显式 `.disableDefaultWorkspaceSkills().disableDynamicSkills()` 才能把技能面收敛到系统内置目录，避免混入工作区/动态 skill。
3. 自治入口（`enableSkillManageTool`/`enableSkillCurator`/`enableSkillPromotionGate`）默认关闭，本特性不调用即不启用。

## §4 空 skill 列表与 fat-jar 行为（Task 4）

**结论**：

1. **空列表语义**：`SkillFilter.only()`（空集合）→ `Mode.WHITELIST` 且 `skillNames` 为空 → `isAllowed(name)` 恒为 `skillNames.contains(name)` = false → **无任何 skill 注入**（等同「用户未启用任何 skill」= 现状）。两条注入路径均兜底：
   - `DynamicSkillMiddleware.reloadSkills`（`io/agentscope/core/skill/DynamicSkillMiddleware.java`）：`repositories` 为空 → 直接置 `currentSkillBox=null` 返回；过滤后无可见 skill（`filterVisible` 返回空）同样置空，`onSystemPrompt` 不追加 skill 提示词。
   - 白名单空集合在 `resolveFilter`→`builderFilter.overlay(runtime)` 后 `isAllowed` 恒 false，skill 清单为空。
   - → FR-3「未启用任何 skill 时等同现状」成立。

2. **fat-jar 分支**：`ClasspathSkillRepository` 在 `jar` scheme 下经 `acquireFileSystem`/`releaseFileSystem`（静态 `SHARED_FILE_SYSTEMS` + `SharedFileSystemRef.refCount`）引用计数管理虚拟 FS：
   - `acquireFileSystem`：已有开放 FS → `refCount++` 复用；否则 `FileSystems.newFileSystem(uri)` 新建并置 `closeWhenUnused=true`。
   - `releaseFileSystem`：`refCount--`，归零才 `remove` 并按 `closeWhenUnused` 关闭 FS。
   - `close()`（`AutoCloseable`）幂等：`closed.compareAndSet(false,true)`，仅 jar 环境调用 `releaseFileSystem`。

   → **必须单例共享、随 Spring 生命周期管理，绝不可每次 `build()` 时 new/close**，否则反复挂载/卸载 jar FS（bootJar 部署时尤其致命）。与设计 §四 4.1 一致。
