# 用户管理功能设计

- 日期：2026-08-21
- 状态：待实施
- 相关 ADR：[ADR-0007 用户管理与认证](../../docs/technology/decisions/0007-user-auth.md) · [ADR-0008 会话持久化](../../docs/technology/decisions/0008-conversation-persistence.md) · [ADR-0009 后端分层 DDD](../../docs/technology/decisions/0009-backend-ddd-layering.md)

## 一、背景与目标

一期系统为 A 股投研对话助手，当前**无任何用户/认证体系**：行情台与 AI 对话全站公开；后端无数据库（行情数据来自外部接口）；AI 会话历史存浏览器 localStorage（ADR-0004 前端持有历史）。

本次新增**用户管理功能**：

1. 用户注册与登录（用户名 + 密码）；
2. 注册需**管理员审核通过**后方可使用 AI；
3. **仅 AI 对话需登录**，行情台保持公开；
4. AI 会话历史**服务端持久化、归属账号**，换设备可见。

## 二、需求澄清汇总

| # | 需求点 | 决策 |
|---|---|---|
| 1 | 保护范围 | 行情台公开；仅 AI 对话（`/agui/run`）需登录 |
| 2 | 身份凭据 | 用户名 + 密码（注册仅这两项） |
| 3 | 状态机 | PENDING → APPROVED / REJECTED；待审/被拒均不能登录 |
| 4 | 被拒重注册 | 允许；**复用同一行**更新为 PENDING（可复用原用户名） |
| 5 | 管理员引导 | env（`ADMIN_USERNAME`/`ADMIN_PASSWORD`）启动**幂等种子**，与普通用户隔离 |
| 6 | 管理员能力 | 查看用户列表、停用/启用、重置密码（不做多管理员管理） |
| 7 | AI 会话归属 | 服务端持久化到账号，换设备可见 |
| 8 | 登录会话 | 记住我：勾选 30 天 / 不勾选关浏览器失效 |
| 9 | 密码策略 | ≥8 位，且含字母 + 数字 |
| 10 | 术语 | 领域实体 `Conversation`（conversation 表）；协议层 `threadId` 不变 |

## 三、总体架构

采用 **DDD 洋葱分层 + 独立能力域**（ADR-0009）：`agent` 保持独立能力域不变；`market` 迁入 DDD 分层；新增 `user`、`conversation` 两个信息管理域。

### 3.1 包结构

```
com.portfolio.invest                    # 根包：仅启动类
├── web/                                # 接入层：HTTP 接口与异常映射
│   ├── AuthController                  #   注册/登录/登出/me
│   ├── UserAdminController             #   管理员操作
│   ├── ConversationController          #   会话 CRUD + 消息
│   └── MarketController / HealthController（既有，改依赖 application）
├── application/                        # 应用层：用例编排、事务、对外 DTO
│   ├── auth/        AuthApplicationService
│   ├── useradmin/   UserAdminApplicationService
│   ├── conversation/ ConversationApplicationService
│   └── market/      MarketDataService（主源/兜底编排；web 与 agent 均依赖）
├── domain/                             # 领域层：纯业务，零 Spring/JPA 依赖
│   ├── user/         User、UserRole、UserStatus、UserRepository（接口）
│   ├── conversation/ Conversation、ChatMessage、ConversationRepository（接口）
│   └── market/       Quote/KlineBar/Financials 等值对象（原 market.dto 迁入）、
│                     StockRef、MarketDataParser、MarketDataException、
│                     MarketDataSource（端口接口）
├── infrastructure/                     # 基础设施层
│   ├── persistence/   JPA 实体 + 仓库实现 + 映射器 + Flyway
│   ├── security/      SecurityConfig、UserDetailsService、remember-me
│   ├── seed/          AdminSeedRunner（env 幂等种子）
│   └── market/        EastmoneyClient/SinaClient（实现 MarketDataSource）、
│                      TtlCache、RateLimiter、RestClientFactory、缓存/限流装饰器
├── agent/                              # 独立能力域（不变）
└── config/                             # 纯配置属性（不变）
```

### 3.2 依赖方向（ArchUnit 重写）

```
web → {application, agent, config}             application → {domain, config}
domain →（不依赖任何项目内包）                    infrastructure → {domain, application, config}
agent → {application, domain, config}           market 顶层包消失，并入 domain/application/infrastructure
config →（无）
```

要点：

- `domain` 层纯 POJO（无 `@Entity`/`@Column`），`infrastructure` 用独立 JPA 实体 + 映射器实现 `domain` 定义的仓库接口，领域逻辑可脱离 DB 单测；
- `infrastructure` 最外层：`EastmoneyClient`/`SinaClient` 实现 `MarketDataSource` 端口；**缓存 + 限流用装饰器包裹** `application.market.MarketDataService`，保证依赖方向干净；
- `PackageConventionsTest` 全量重写；`market.dto.*` import 全部改为 `domain.market.*`，market 相关测试同步迁移（纯结构性，行为不变）。

## 四、数据模型（PostgreSQL + Flyway）

| 表 | 关键列 | 说明 |
|---|---|---|
| `app_user` | id BIGSERIAL PK、username VARCHAR 唯一、password_hash（BCrypt）、role（ADMIN/USER）、status（PENDING/APPROVED/REJECTED）、enabled BOOLEAN、created_at、updated_at | 停用 = enabled=false |
| `conversation` | id UUID PK（复用 AG-UI threadId）、user_id FK、title、created_at、updated_at | 会话归属用户 |
| `chat_message` | id BIGSERIAL PK、conversation_id FK、role、content、payload JSONB（工具调用等 AG-UI 扩展）、created_at | 按 conversation 有序 |
| `persistent_logins` | series PK、username、token、last_used | Spring Security 记住我 |

索引：`conversation(user_id)`、`chat_message(conversation_id)`。

唯一约束 `username`：被拒后同名重注册 = **更新复用同一 REJECTED 行**（置回 PENDING + 换新密码），不产生垃圾数据。

## 五、认证与授权

- **认证机制**：Spring Security 会话认证（JSESSIONID cookie，HttpOnly + SameSite=Lax）+ remember-me 令牌（30 天）。勾选"记住我"→ 服务端签发 remember-me 令牌（存 `persistent_logins`）；未勾选 → 仅会话 cookie，关浏览器失效。
- **密码**：BCrypt 哈希；策略 ≥8 位、含字母 + 数字（前后端双重校验）。
- **注册流程**：校验（用户名非空唯一、密码合规）→ 新建 PENDING，或被拒行复用置回 PENDING → 返回"等待审核"。
- **登录流程**：认证后按状态分流——REJECTED→"已被拒绝，请重新注册"；PENDING→"待审核"；APPROVED 且 enabled→放行；停用→"已被停用"。
- **登出**：销毁会话 + 清 remember-me。
- **`/api/auth/me`**：返回当前用户（未登录 401）。
- **停用即时生效**：受保护接口（`/agui/run`、`/api/conversations/**`）每次请求从 DB 校验当前用户 `status/enabled`，停用或改为 REJECTED 后**立即拒绝**（401），无需等会话过期。
- **管理员操作**：受角色保护，且**不能对 ADMIN 账号审核/停用**（保护内置管理员）。
- **会话归属**：conversation 接口按登录用户 id 过滤，非本人返回 404（不泄露存在性）。
- **CSRF**：关闭。理由：同源 JSON API（全部经 Next.js 反代）+ SameSite=Lax cookie，跨站状态变更请求不会携带 cookie，CSRF 风险可控；见 ADR-0007。

## 六、接口清单

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| POST /api/auth/register | 公开 | 注册 → PENDING |
| POST /api/auth/login | 公开 | 登录，body 含 rememberMe |
| POST /api/auth/logout | 登录 | 登出 |
| GET /api/auth/me | 登录 | 当前用户 |
| GET /api/admin/users | 管理员 | 用户列表（含状态） |
| POST /api/admin/users/{id}/approve | 管理员 | 通过 |
| POST /api/admin/users/{id}/reject | 管理员 | 拒绝 |
| POST /api/admin/users/{id}/enable | 管理员 | 启用 |
| POST /api/admin/users/{id}/disable | 管理员 | 停用 |
| POST /api/admin/users/{id}/reset-password | 管理员 | 重置密码 |
| GET /api/conversations | 登录 | 我的会话列表 |
| POST /api/conversations | 登录 | 新建会话，返回 threadId |
| GET /api/conversations/{id}/messages | 登录+归属 | 加载消息 |
| PUT /api/conversations/{id}/messages | 登录+归属 | 全量替换保存消息 |
| DELETE /api/conversations/{id} | 登录+归属 | 删会话 |
| POST /agui/run | 登录（经 CopilotKit 反代） | AI 对话，未登录 401 |

**会话持久化流程**：前端仍作为当前对话的**工作内存**（ADR-0004 的交互模式保留：每轮请求携带全量历史到 `/agui/run`），每轮 assistant 回复完成后 **PUT 全量消息**到服务端；打开会话时 **GET 加载**并继续。多端同时修改 = 后写覆盖（接受）。

**标题生成**：首次保存用户消息时，若 `conversation.title` 仍为默认值"新会话"，则取第一条用户消息前 24 字设为标题（沿用现状逻辑）。

## 七、前端改动

- **新增路由**：`/login`、`/register`（公开）、`/admin`（仅管理员）；首页 `/`（对话）未登录跳 `/login`；`/market` 保持公开。
- **AuthProvider**（React context）：挂载时 `GET /api/auth/me`，暴露 `user / login / logout / register`。
- **替换 localStorage 会话**：`lib/sessions.ts` → 服务端 API（`listConversations / createConversation / loadMessages / saveMessages / deleteConversation`），`threadId = conversation.id`；侧边栏数据来自服务端。
- **登录/注册表单**：前端密码校验（≥8 位、字母+数字）。
- **`/admin` 页**：待审列表（通过/拒绝）+ 用户列表（停用/启用/重置密码）。
- **新增 Next.js 反代路由**：`/api/auth/**`、`/api/admin/**`、`/api/conversations/**` → 后端；**必须透传 Set-Cookie 与 Cookie 头**（登录态 cookie 经反代落地到浏览器）。
- **401 处理**：AI 请求 / me 接口 401 → 跳登录。
- **旧 localStorage 数据不迁移**（系统尚未正式发布，可接受）。

## 八、测试策略

**后端**（覆盖率仍 ≥80%）：

- `domain` 纯单测：状态流转、密码策略、归属校验（纯 POJO，无需 DB）；
- `application` 单测：mock 仓库接口；
- 仓库/集成测试：**Testcontainers PostgreSQL**（真实 PG、无方言漂移；测试环境需 docker）；
- 安全集成测试：注册→审核→登录→me→对话受保护；拒绝/待审/停用登录被拒；admin 接口越权 403；
- **ArchUnit 重写**：新依赖方向白名单。

**前端**：

- Vitest：AuthProvider、表单校验、api client schema、会话侧边栏；
- Playwright e2e：注册 → 管理员（env 种子）审核 → 登录 → 对话 → 会话跨端可见；拒绝/停用流程。

## 九、部署与运维

- docker-compose 增加 `db`（postgres:16-alpine）+ 数据卷 + healthcheck；backend `depends_on: db healthy`；
- env：`POSTGRES_USER/PASSWORD/DB`、`ADMIN_USERNAME/ADMIN_PASSWORD`（启动幂等种子管理员）、`SPRING_DATASOURCE_URL`；
- Flyway 启动时建表；本地 `make dev` 需先 `docker compose up -d db`；
- 文档更新：`docs/technology/` 接口与架构、`docs/function/` 产品功能。

## 十、明确不做（YAGNI）

- 多管理员管理（新增/移除管理员）；
- 邮箱/手机号注册、短信或邮件通知；
- 用户自助找回/修改密码（仅管理员重置）；
- localStorage 旧会话迁移；
- 多端实时同步（会话采用后写覆盖）。

## 附：术语

| 术语 | 含义 |
|---|---|
| Conversation | 领域实体：用户的一段持久化对话（服务端存储） |
| threadId | AG-UI/CopilotKit 协议层对话标识，等于 Conversation.id |
| session | 登录态（Spring Security 会话 / remember-me），与对话无关注定不用作对话术语 |
