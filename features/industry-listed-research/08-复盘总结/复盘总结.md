## 二、经验（做对了什么）

1. **外部接口字段语义实测校准先行**：P1 Task 1 先用真实 token 探测 `income`（两股样本），推翻计划三处先验（单位为元非万元、同 end_date 多行来自 `update_flag` 非 report_type、`start_date` 是公告日窗口），常量与去重规则全部落定于调研报告、实现只消费结论——避免「按记忆写死常量」带病上线。
2. **同一口径双实现必配一致性测试**：重算 SQL 与每日快照 `IndustryValuationCalc`（Python）双实现，用同一组样例行（pg 真库 × pytest）断言逐值相等——**该测试当场逮住设计稿 pb 分母口径笔误**（写成条件加权，实际 calc 是无条件 Σ市值），一致性不变量优先、SQL 向在产口径看齐。
3. **评审链 + git 归因拦住计划缺陷**：三处计划漏排（writer E501 换行、域测试 GWT 命名 + `@DisplayName` 守护、Flyway 版本断言 `containsExactly` 未排 V15）均由评审链/守护测试拦在合并前；E501 归因两轮评审均误，最终 `git log -S` 铁证定位到引入任务后由其实现者修复。
4. **CI 空库门控的「精确 skip」范式**：e2e 新用例先探测 `/api/industry/board`，空数组才 skip（CI 空库常态）、接口非 200 不门控——本地全量真实跑、CI 不假红也不掩盖后端回归。
5. **执行时再验数据前提**：brief 假设 dev 库「约 3 周快照」，实测基线本有 2016 起全量 9.96M 行——回填按幂等重写执行并如实记录前提偏差，生产 runbook 同步标注「空库从零回填」语义。

## 三、不足

1. **计划先验未经实测即落盘**：income 单位锚点（「工行 ≈6.58 万亿」实为 0.82 万亿量级口径混用）、`start_date` 语义均写错——虽有 T1 校准兜住，但计划样例代码注释按万元写、派发时须带修正裁决，计划文本本身返工一轮。
2. **设计稿 SQL 口径笔误**：pb 分母条件加权 vs calc 无条件 Σ市值——若无双实现一致性测试，历史重算数据会与每日快照口径漂移且难以察觉（数值差异小、无报错）。
3. **BDD 套件级互扰未预防**：`CURRENT_DATE` 种子与 screening 共享全局 `max(trading_day)` 互扰、cucumber-spring `@Transactional` 无场景回滚的语义先验错误——靠执行期排障发现，套件约定（固定日/键位错开）未提前文档化。
4. **分段回填脚本单段失败即整体中止**：`make` 循环 `check=True` 在段 6 限流失败后中止后续段，被迫逐段手动续跑；且 tushare 分钟级限流的即时报错与熔断冷却叠加，advisory lock 一度悬挂近 40 分钟。
5. **动态路由首例的经验只在本特性内闭环**：Next 15 params Promise 的核验发生在 P3 实现期（设计规格已预警），但「mock 单测对库内行为全盲」的既有教训靠 e2e 深链用例兜底——若 P3 未坚持真浏览器验证，params 形态错误会漏到线上。

## 四、优化建议

1. **凡涉及外部接口字段语义（单位/去重/窗口参数），计划阶段即执行实测校准并产出 09-调研报告**，计划文本引用调研结论而非先验锚点（本次先验三处全错即证明）。
2. **「同一口径两处实现」必须配一致性测试**（SQL vs Python calc、后端 vs 前端推算同类）——口径漂移无报错，只有不变量断言能拦。
3. **BDD 共享库互扰防范固化**：固定日种子 + 键位错开 + 「不依赖 max(trading_day) 全局态」写入测试架构约定（03-后端测试架构.md 后续补）。
4. **分段运维脚本改段间容错**：单段失败记录断点继续后续段（或输出「从段 N 重跑」提示），勿整体中止；限流失败等待窗口单独重跑该段即可。
5. **生产 runbook 前置检查清单**：新任务 YAML 需先 `python -m collector.cli seed` 登记 `collector_task`，否则 `make collect-run` 报「任务不存在」——此类部署顺序依赖写入发布方案。
