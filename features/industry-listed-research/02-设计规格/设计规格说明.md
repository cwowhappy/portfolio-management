# 行业研究·上市公司深化（industry-listed-research）设计规格说明

> 创建：2026-09-17 | 对应 [01-需求规格](../01-需求规格/需求规格说明.md) | 里程碑 MS-09
> 设计前提：以下引用的既有代码均经三个探索子代理逐一 Read 核实（file:line 为本文写作时点，分支 feature/industry-listed-research）。

## 一、总体架构

三条主线，一条底线：

1. **collector 底座两改**：`stock_financial` 并入 tushare `income` 营收列（同源同行写入）；新增**行业估值历史重算任务**（纯 SQL 重算缺失日期，幂等自愈）＋ 一次性 5 年个股估值分段回填（既有 CLI，新增 Makefile 封装）。
2. **后端新建 `domain/industry` 读侧域**：聚合 board 端点（四指标 + 5y 分位 + 景气）与行业成员端点（排名表）。`PackageConventionsTest` 白名单为**按层通配**（`PackageConventionsTest.java:47` `DOMAIN = ROOT + ".domain.."`），新子包自动覆盖、**测试零改动**；按其 javadoc（`PackageConventionsTest.java:34`）同步更新《01-后端DDD分包规范》域清单即可（此点修正需求规格 §一交付物的表述）。
3. **前端一扩一新增**：board 切聚合端点并新增 IndustryBoardTable（**不动** `/valuation` 共用的 `IndustryTable`）；`/industry/[industryCode]` 下钻页为 app router **首个页面级动态路由**（仓库无先例，参数形态以实际 Next 版本为准）。

**底线**：域间零依赖——`domain/industry` 不 import `domain/valuation`（后者已有 `IndustryValuation`/`Percentile` 读模型与工具，本域自建窗口化分位，见 §4.2）。

## 二、数据模型与迁移（Flyway V15）

```sql

-- 个股财务季数据补营收绝对额（MS-09 F03 排名维度）。
-- 本 schema 为 Python 采集服务写入的跨服务契约：加列可空、纯增量，不改既有列（V7 契约注释口径）。
ALTER TABLE stock_financial ADD COLUMN revenue NUMERIC(20,4);  -- 元，报告期累计
```

`industry_valuation`（V3）**不动**：历史行由重算任务只补**缺失日期**（见 §3.3，避免 upsert 覆盖已有 roe/股息率）；`stock_valuation_daily` 不动（回填走既有列）。

**关键语义**（`writer.py:104-128`）：每表单条硬编码 SQL 全列 SET，`r.get(c)` 缺值即 None——**两接口数据必须在同一次 fetch 合并成同一行再 upsert**，分开写会用 None 覆盖对方列。合并键 `(stock_code, report_date)`。

**实测校准（P1 首步，禁止凭记忆写死）**：① `income` 同一 `end_date` 返回多 `report_type`（合并/单季/调整），取**合并报表**口径过滤；② `revenue` 单位（万元/元）以一次真实响应确认，若为万元在 source 选列阶段 ×10000 换算为元（对齐 `total_mv` 换算先例 `plugins.py:309-310`）。限流复用同一 `self.limiter`（`plugins.py:372-377`，0.35s/次），每股两次调用后任务时长 ~60 分钟/轮（`trading_day_gated: false`，cron 15:40 起）。

### 3.2 一次性 5 年个股估值回填（运维操作 + Makefile 封装）

既有能力直用：`make collect-backfill TASK=stock_valuation_daily --start --end`（`cli.py:35-39` → `backfill.py:5-16`；源内自循环交易日 `plugins.py:317-331`）。**不整段跑**：源回填是全量 DataFrame → 单次 `executemany` + 单事务（`executor.py:118`、`writer.py:121`），5 年 ~6-7M 行单事务风险高——按**半年一段 × 10 次**分段执行。新增 Makefile 目标 `industry-stock-backfill`（循环分段调用既有 `collect-backfill`，段间 sleep 无需），交付时实跑并记录耗时/行数进复盘。

### 3.3 行业估值历史重算任务（新增，幂等自愈）

- **任务**：`tasks/industry_valuation_backfill.yaml`——`source_ids: [{source_id: industry_valuation_backfill, type: plugin, class: ...}]`，`converter`: 直通（若 converter registry 无现成 identity，按 `field_mapping_*` 模式新增直通函数，以 `jobs.py` registry 现状为准），`calc: null`，`validator: null`（**禁用 min_rows hard**：稳态 0 行是正常态，二次起无缺失日期即 0 行），`target_table: industry_valuation`，`schedule: {type: interval, days: 7}`，`enabled: true`，`trading_day_gated: false`。
- **源**：`IndustryValuationBackfillSource`（plugins.py 新类），`supports_range = False`（不走 backfill CLI，常规调度即可）。**DB 内直读直算**（先例：`IndustryUniverseSource` 在 fetch 内查库，`plugins.py:152-168`）：

```sql
INSERT INTO industry_valuation (trading_day, industry_code, industry_name, pe, pb, roe, dividend_yield)
SELECT d.trading_day, m.industry_code, MAX(m.industry_name),
       SUM(d.pe_ttm * d.total_mv)
         / NULLIF(SUM(CASE WHEN d.pe_ttm > 0 THEN d.total_mv END), 0),
       SUM(d.pb * d.total_mv)
         / NULLIF(SUM(CASE WHEN d.pb IS NOT NULL THEN d.total_mv END), 0),
       NULL, NULL
FROM stock_valuation_daily d
JOIN shenwan_industry_mapping m ON m.stock_code = d.stock_code
WHERE d.pe_ttm > 0 AND d.total_mv IS NOT NULL          -- 记录级过滤，对齐 IndustryValuationCalc（snapshot.py:25-27）
  AND d.trading_day < (SELECT COALESCE(MIN(trading_day), '2999-12-31') FROM industry_valuation)
GROUP BY d.trading_day, m.industry_code
ON CONFLICT (trading_day, industry_code) DO NOTHING;
```

- **只补快照出现之前的缺失日期**（`< MIN(trading_day)`）：永不与每日任务冲突 → 不触发 upsert SET → **不会把已有日期的 roe/股息率覆盖成 NULL**；`DO NOTHING` 为双保险；幂等（重跑 0 行）；后续加深 10 年自动覆盖。
- 输出 ~31 行业 × ~1200 日 ≈ 37K 行，单事务可承受；`trading_day` 由源自带（不依赖 `executor.py:116` setdefault）。
- **口径一致性双实现测试**：同一组样例行分别过 `IndustryValuationCalc`（Python，`snapshot.py:22-67`）与上述 SQL（pg 真库），断言输出逐值相等——含「pe 无效整行剔除但 pb 仍有值」的边界（`snapshot.py:25-27` 记录级过滤 + `:42-52` pb 条件加权的微妙差异）。
- **字段口径核对（P1 实测校准项）**：每日路径 `_daily_basic_spot` 的中文列「市盈率-动态」（`plugins.py:853-896`）与回填所用 `stock_valuation_daily.pe_ttm`（V7 映射自 daily_basic `pe`）须核对为同一接口同义字段——同为 `pro.daily_basic` 的 `pe` 列则口径一致；若「市盈率-动态」实为不同口径（如动态市盈率非 TTM），回填 SQL 须改用一致字段并在口径标注中说明。
- **冷启动注意**：新任务 `never_succeeded` 会在调度器启动时立即跑一次（`jobs.py:129-132`）——期望行为（部署即自动补历史），文档标注。
- 依赖顺序：§3.2 个股回填完成后本任务才有料；顺序颠倒无害（0 行幂等）。

### 4.2 board 聚合端点（M10-F04/F05 行业级）

- `GET /api/industry/board` → `List<IndustryBoardView>`：31 行业 × {四指标（最新日 `industry_valuation`）、pePercentile/pbPercentile（5y 窗口）、prosperity、prosperityInputs（ROEΔ 中位数、营收增速中位数，供 tooltip 解释）}。
- **分位**：`findValuationHistorySince(今天−5年)` 全量拉取（~37K 行）→ 应用层按行业分组 → `WindowedPercentile.of(序列, 当前值)`；窗口参数化（常量 5y，10y 预留）；序列 <250 交易日返回 null（前端「—」）。**不 import valuation 域 `Percentile`**（域间零依赖；语义一致性由单测同断言锚定）。
- **景气聚合 SQL**（repository 内，窗口函数 + 中位数）：

```sql
WITH per_stock AS (
  SELECT stock_code,
         AVG(roe) FILTER (WHERE rn <= 4)  AS roe_recent,
         AVG(roe) FILTER (WHERE rn BETWEEN 5 AND 8) AS roe_prior,
         MAX(revenue_yoy) FILTER (WHERE rn = 1)     AS revenue_yoy
  FROM (SELECT stock_code, roe, revenue_yoy,
               ROW_NUMBER() OVER (PARTITION BY stock_code ORDER BY report_date DESC) AS rn
        FROM stock_financial) t
  GROUP BY stock_code
)
SELECT m.industry_code,
       PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY (p.roe_recent - p.roe_prior)) AS roe_delta_median,
       PERCENTILE_CONT(0.5) WITHIN GROUP (ORDER BY p.revenue_yoy)                AS revenue_yoy_median,
       COUNT(p.stock_code) FILTER (WHERE p.roe_recent IS NOT NULL AND p.roe_prior IS NOT NULL) AS sample_size
FROM per_stock p JOIN shenwan_industry_mapping m ON m.stock_code = p.stock_code
GROUP BY m.industry_code;
```

  阈值判定在域内 `Prosperity.of`（UP: Δ≥+1 且 增速≥+10；DOWN: Δ≤−1 **或** 增速≤−10；样本 0 → null）。`sample_size` 供 tooltip「基于 N 家成员中位数」。
- **缓存**：`cached()` 模式（`ValuationApplicationService.java:124-134`），key `industry:board:{当日}`，TTL 5min。
- board 响应同时喂 F01 表格与 F02 热力图（四指标齐全），`/industry` 页单请求。

### 4.3 行业成员端点（M10-F03 + F05 个股级）

- `GET /api/industry/{industryCode}/stocks?sortBy=&sortDirection=&limit=`：`sortBy ∈ {total_mv, revenue, roe}`（白名单，默认 `total_mv` DESC）、`limit` 默认 1000 上限 1000；`industryCode` ∉ `shenwan_industry_mapping` → 404 `INDUSTRY_NOT_FOUND`。
- SQL 与筛选域 `BASE_SQL` 同构（`ScreeningRepositoryImpl.java:30-71`）：`stock_valuation_daily` 最新交易日主表 ⋈ `stock_financial` `DISTINCT ON ... - 缓存 key `industry:{code}:stocks:{sortBy}|{dir}|{limit}`，TTL 5min。

## 六、错误处理与边界

| 场景 | 行为 |
|---|---|
| `industryCode` 不在申万映射 | 404 `INDUSTRY_NOT_FOUND`，前端提示返回 board |
| `sortBy`/`limit` 越界 | 400 `INDUSTRY_INVALID_SORT` / `INDUSTRY_INVALID_LIMIT` |
| 回填未执行（序列 <250 日） | 分位 null →「—」+ 口径提示（dev 环境常态） |
| 某行业景气样本 0（成员全为次新） | prosperity null →「—」 |
| 个股 ROE 不足 8 季 | 该股不参与中位数、自身不标注 |
| income 某股无数据（未披露） | revenue null →「—」，其余列不受影响（同行合并时该键置 None） |
| 混合报告期 | 每股最新可得，营收列角标报告期 |
| board/成员接口后端 5xx | 沿用 `lib/http.ts:22-31` 错误文案 + e2e error-states 模式 |
| 重算任务与每日任务并发 | advisory lock（`runner.py:18-19`）+ 只补 `< MIN(trading_day)` 日期，无交集 |
