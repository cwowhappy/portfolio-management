# 后端测试体系优化计划

日期：2026-09-04
分支：`chore/code-review-2026-09-03`
状态：**已完成**（2026-09-04 全量 `make test-backend` 绿，见文末「实施结果」）

## 背景与现状

2026-09-04 对后端四层测试体系做全量盘点（63 个 test / 18 个 integrationTest / 8 个 feature 12 个 BDD 场景，聚合指令覆盖 98.6% / 分支 97.1%）。体系整体成熟，存在 8 处可优化点。本文档记录优化方案与实施计划，完成后回填实施结果并更新 `docs/technology/architecture/03-后端测试架构.md`。

### 做得好的（保持，不动）

1. 分层边界有机器强制：ArchUnit 18 条规则 + `TestSourceSetConventionsTest` 守「单测/切片零 Docker」
2. 覆盖率门禁只挂 `check` 不挂 `test`，聚焦跑不被误伤
3. 时钟/sleep 全可注入；并发测试用 CyclicBarrier/双 CountDownLatch 确定性编排；HTTP 用 MockRestServiceServer + 真实抓包 fixture
4. 共享容器基座 `PostgresTestSupport` 双轨消费，不起第二个 PG
5. 错误模型统一（异常类型 + 错误码枚举）；归属隔离一律 404 的安全约定各层一致锁定
6. BDD 双轨步骤务实，外部依赖全可控

### 不足（本次优化对象）

| # | 不足 | 证据 |
|---|---|---|
| 1 | BDD 业务域缺口：会话管理域无场景；重置密码→remember-me 吊销旅程只在单测/集成 | `src/bdd/resources/features/` 无 conversation/admin_reset 相关 feature |
| 2 | web 层双轨（standalone `*Test` vs `@WebMvcTest` 的 `*SliceTest`）靠注释区分，选型无强制 | `web/` 包 16 个测试类两种风格并存 |
| 3 | 两个 TTL 缓存实现并存，测试重复 | `infrastructure/cache/TtlApplicationCache` vs `infrastructure/market/TtlCache` |
| 4 | 并发/集成测试种子与清理全手写 JdbcTemplate，高位哨兵 id 靠注释约定 | 3 个并发测试类各自复制粘贴种子/清理模板 |
| 5 | 断言质量无验证（无 mutation testing） | 98.6% 覆盖率下「测试绿但断言空」无法发现 |
| 6 | fixture 抓包无新鲜度机制，上游接口漂移测试仍绿 | 仅靠 `make smoke` 人工兜底 |
| 7 | Cucumber 遮蔽补丁需跟踪上游修复 | `src/bdd/java/io/cucumber/core/runner/Runner.java` |
| 8 | 文档与实际漂移无防线 | 本次发现 BDD 场景数、迁移版本两处过时（已修复） |

## 优化方案（已确认全部执行）

### P0 — 补 BDD 关键旅程缺口

- 新增 `conversation_journey.feature`：注册 → 审核 → 建会话 → 存消息 → 读回 → 非本人访问 404
- 新增 `admin_reset_password.feature`：管理员重置密码 → 旧 remember-me 令牌失效 → 新密码可登录
- 复用 AuthSteps/AguiSteps/ScenarioContext 模式，新增 ConversationSteps / UserAdminSteps（如需要）

### P1 — 结构债清理

- 对比两个 TTL 缓存语义差异后合并为一个实现，删除重复测试
- 抽 `ConcurrencyTestSupport` 基座（提交态种子 + 清理模板 + 哨兵 id 常量），收敛 3 个并发测试
- 新增 ArchUnit 规则：web 包下 `*SliceTest` 必须带 `@WebMvcTest`/`@JsonTest`，双轨分工从注释升级为强制

### P2 — 质量增强

- 引入 PIT mutation testing（`info.solidsoft.pitest` + JUnit 5 插件），目标类限定核心域（`Position` / `ValuationApplicationService` / `MarketDataParser`），作为非阻塞手动任务（Makefile 新目标），不设硬门槛
- `make smoke` 增加 fixture 新鲜度检查：真实上游响应 vs fixture 关键字段比对，接口漂移时冒烟先红
- 检查 Cucumber 上游修复状态：若已修复则升级版本并删除遮蔽补丁；未修复则在文档中登记跟踪项

### 明确不做

- 不追 100% 覆盖率；不把 BDD 扩到技术细节层；不改双轨 web 测试格局（只加命名约束）

### 阶段 4：收尾

- `./gradlew check` 全绿（含覆盖率双 80% 门槛）

## 实施结果

2026-09-04 全部完成，`make test-backend`（三层 + 覆盖率门槛）全绿：

- **P0**：新增 `conversation_journey.feature`、`admin_reset_password.feature` 各 1 场景 + `ConversationSteps`/`AdminResetPasswordSteps`，ScenarioContext 扩 3 字段；`./gradlew bdd` 13 场景全绿。实施中发现一处生产疑点：remember-me 的 `loginSuccess` 内部再校验 `remember-me` 请求参数，前端只发 JSON `rememberMe` 字段，真实浏览器链路下「记住我」可能静默不生效——已登记 03 文档第 7 节待确认。
- **P1 TTL 合并**：对比确认 `TtlApplicationCache` 只是 `TtlCache` 的零语义差异薄适配器；`TtlCache` 迁入 `infrastructure/cache` 并直接实现 `ApplicationCache`，删除适配器与重复测试（63 → 62 个测试类），`CacheConfig`/`CachedMarketDataService`/两处测试同步改引用。
- **P1 并发基座**：新增 testFixtures `ConcurrencyTestSupport`（继承 PostgresTestSupport：JdbcTemplate 注入、哨兵 id 常量、`insertUser`、`race()` CyclicBarrier 齐放）；3 个并发测试收敛（如 Portfolio 76→48 行），种子链/清理差异大刻意不抽象；testFixtures 补 `spring-beans`/`spring-jdbc` 依赖。
- **P1 ArchUnit**：`TestSourceSetConventionsTest` 新增第 2 条规则——`*SliceTest` 必须带 `@WebMvcTest`/`@JsonTest`（按注解简单名判断），7 个既有切片类全部合规；规则总数 19 → 20。
- **P2 PIT**：`info.solidsoft.pitest` 1.19.0 + pitest 1.30.0 + junit5 插件 1.2.3，targetClasses 限定 Position / application.valuation.* / MarketDataParser，不挂 check 无门槛；Makefile 新增 `test-backend-mutation`。两处必要配套：junit-platform-launcher 对齐 6.0.3 的 `eachDependency` 规则、`addJUnitPlatformLauncher = false`（否则 Boot 4 依赖管理压版导致引擎混代全灭）。基线 kill 率 84%（208 变异体）。注意需经 make（钉 JDK 21）运行，默认 shell 的 JDK 25 会起不动 minion。
- **P2 fixture 新鲜度**：`scripts/smoke.sh` 新增第 2 步——直连东财真实接口（UA/Referer 与后端客户端对齐）比对 parseQuote 依赖的 14 个字段，缺失即 fail。离线正反例验证通过；本环境网络到东财 API 被重置，线上全绿一跳未实测。
- **P2 Cucumber 补丁**：核查上游——7.34.7 仍是最新发布版，main 分支未修复且无登记 issue，补丁保留，登记跟踪（见 03 文档第 7 节）。
- **追加修复（remember-me 生产 bug）**：BDD 实施暴露「登录是 JSON API、无 remember-me 表单参数，`loginSuccess` 内部二次校验该参数导致 cookie 静默不下发」。TDD 修复：先加 `AuthControllerIntegrationTest.rememberMe仅传JSON字段也下发cookie`（红：`No cookie with name 'invest-remember-me'`）→ `SecurityConfig` 的 remember-me 服务 `setAlwaysRemember(true)`（签发与否仍由 `AuthController` 按 body 字段把关）→ 绿；同时移除 `AdminResetPasswordSteps` 的 `.param("remember-me","true")` 绕行，BDD 按真实前端链路锁定。`make test-backend` 全绿。
