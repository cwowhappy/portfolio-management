## 四类测试职责（已确认）

| 类型 | 职责 | 边界 | Source Set |
|---|---|---|---|
| 单元测试 | 证「逻辑对」：纯业务规则与编排 | 零 Spring/零真实 I/O，mock 只打端口接口 | `test` |
| 切片测试 | 证「接线对」：单层与框架的装配契约（绑定/校验/序列化/安全规则/异常映射） | `@WebMvcTest`/`@JsonTest`/`@DataJpaTest` 部分上下文，无 Docker | `test` |
| 集成测试 | 证「依赖对」：跨层与真实依赖协同（事务/约束/并发/迁移/装配/SSE 流） | Testcontainers 真实 PG，窄端到端 | `integrationTest` |
| BDD | 证「流程对」：中文 Gherkin 锁定关键用户旅程（5 场景起步，不贪多） | Cucumber JVM + 真实 PG + 假 Model | `bdd` |

## 分包方案（已确认）

```
backend/src/
├── testFixtures/java/com/portfolio/invest/support/
│   └── PostgresTestSupport.java        # 现 IntegrationTestBase 迁入改名（JVM 单例容器）
├── test/java/...                        # 单元 + 切片（禁 Docker、禁完整 @SpringBootTest）
├── integrationTest/java/...             # 集成测试，依赖 testFixtures
└── bdd/                                 # Cucumber：java/ 下 runner+steps，resources/features/ 下中文 Gherkin
```

命名约定：`*Test`（单元）/ `*SliceTest`（切片）/ `*IntegrationTest`（集成）/ `*Steps` + `*.feature`（BDD）。
`check` 聚合三个测试任务；JaCoCo 合并三任务 exec，仍只有一道 ≥80% 聚合门槛挂 `check`。

## Spring Boot 4 关键事实（调研核实）

- `@WebMvcTest` 需类路径有 `spring-boot-starter-security-test` 才挂安全过滤器链（否则 401/403 断言失真）
- `@MockBean`/`@SpyBean` 已删除，用 `@MockitoBean`/`@TestBean`（不可写在 `@Configuration` 类里）
- Jackson 2 项目下 `@JsonTest`/`@WebMvcTest` 自动走 Jackson 2 ObjectMapper，与生产序列化一致
- `@DataJpaTest + @ServiceConnection + Replace.NONE` 为官方推荐的持久化切片写法

## 实施计划（每步保持构建绿）

### 阶段 1：分包基建 + 依赖修正 ✅
- build.gradle：`java-test-fixtures` + `testing.suites` 声明 `integrationTest`/`bdd`（任务名与 source set 同名）；JaCoCo 聚合三任务 exec；Cucumber 依赖只进 bdd suite
- 依赖修正三条：`spring-security-test` → `spring-boot-starter-security-test`；删冗余 `spring-boot-starter-test`；`spring-boot-starter-web` → `spring-boot-starter-webmvc`
- `IntegrationTestBase` → `testFixtures` 的 `PostgresTestSupport`；现有 10 个集成类迁移到 `integrationTest`（内容不动）
- 4 个仓库测试改造为 `@DataJpaTest + @ServiceConnection + Replace.NONE`（`@Import` 装配 RepositoryImpl 适配器）
- ArchUnit 测试侧规则：`test` source set 禁依赖 Testcontainers
- Makefile 增加 `test-backend-unit`/`test-backend-integration`/`test-backend-bdd`
