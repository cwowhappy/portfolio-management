## 一、规划范围

本项目（A 股投研对话助手）v1 已于 2026-10-03 收官：一期 MS-00~19 共 115 功能点 + 阶段二 MS-20~27 共 34 功能点全部交付，系统进入「v1 后打磨期」。本规划基于调研结论，整理 v1 之后的功能迭代方向与优先级路线图，回答「下一步往哪迭代」。各方向的行业依据与现状差距分析见依据文档。

## 二、功能迭代方向（8 个方向）

### D1. 可信溯源与幻觉治理 【P0】

**趋势依据**：T4（合规准入门槛、可信锚定、数字精度控制）。
**现状差距**：工具返回数据经图表双通道完整呈现，但 LLM 文本结论与数据之间无强制绑定；无数字一致性校验。

功能点：
1. **结论引用锚定**：Agent 输出中每条数据性结论标注来源工具 + 调用参数 + 数据时间戳（扩展 AG-UI 事件 metadata，前端渲染溯源小标）。
2. **数字一致性校验器**：轻量校验层比对「文本陈述数字 vs 工具实际返回值」，不一致即拦截修正或显式标注（事实校验 Agent 的单机轻量版，先于 D2 落地）。**MVP 范围（已确认 2026-10-04）**：仅比对「直接引用值」（工具返回值被原文引用的数字）；Agent 二次计算值（如据工具价推导涨幅）的校验后置。
3. **置信度与免责标准化**：低置信回答显式提示 + 给出核实路径；投资建议 disclaimer 统一模板。
4. **幻觉率指标进 eval 基线**：agent-testing 增补幻觉诱导用例集（见 D4）。

### D2. 深度研究（DeepResearch）工作流 【P1】

**趋势依据**：T2（多 Agent 协同）、T3（分钟级研报、假设跟踪、数据自动刷新）。
**现状差距**：`research_draft` + SOP 四阶段 + 多源数据已备，但 Agent 只有单轮 ReAct 工具调用，无多步任务编排与产出物生命周期。

功能点：
1. **研报生成任务流**：选题 → 多源数据收集（行情/财务/情报/公告/wiki）→ 分析 → 草稿 → 人工确认（复用 HITL 审批机制），产出挂到 SOP 研究项目。
2. **关键假设数据跟踪**：研报内的数字声明绑定数据源，数据刷新后提示过期（T3「图表数据自动刷新」的持仓版）。
3. **草稿过校验器**：产出前强制走 D1 校验层。
4. **架构路径（已确认 2026-10-04）**：先做「单 Agent 多步工作流 + 独立校验器」，验证价值后再演进到多 Agent 分工——避免过早引入分布式编排的调试成本。

### D3. 记忆与用户个性化 【P1】

**趋势依据**：T5（记忆成为基础设施与差异化核心）。
**现状差距**：长期记忆已落盘但用户不可见/不可管/无画像注入——金融场景下「不可解释的记忆」本身即是信任风险。

功能点：
1. **长期记忆管理界面**：查看/编辑/删除（透明可控是金融场景的前提）。
2. **画像注入**：经用户授权，投资风格、关注行业、自选股、当前持仓上下文按需注入系统提示（持仓数据系统内已有，联动成本低）。**护栏（已确认 2026-10-04）**：注入后复核「私有数据禁传 MCP」提示词规范的执行。
3. **事件驱动记忆**：调仓、分红、交易日志事件自动摘要写入记忆（与 portfolio/journal 域联动）。

### D4. Agent 评测与可观测性加固 【P0】

**趋势依据**：T7（evals 生产化）、T4（持续幻觉监控）。
**现状优势**：agent-testing eval 基线已建立，起步早于多数同类项目。

功能点：
1. **eval 集扩充**：金融 QA 基准三类——行情事实类、指标计算类、幻觉诱导类（诱导模型编造不存在的数据/政策）。
2. **eval 回归触发（已确认 2026-10-04）**：不阻塞每个 PR（真 LLM 评测成本高且模型侧有抖动）——提示词/模型变更时手动触发 + 每晚定时跑，超阈值告警留痕。
3. **工具提示词版本化**：现靠人工维护（已 5→11 条演进），入库 + 变更历史 + 评测关联。
4. **线上观测**：工具调用链 trace、token 成本、时延看板（轻量，复用现有日志）。

### D5. 写类工具与主动式 Agent 【P2】

**趋势依据**：T1（Agent 从问答走向操作与陪伴）、T6（Tool-Call 普遍化）。
**现状优势**：HITL 审批机制（ADR-0010）已为写工具铺好路；「情报→交易动作直达」已在阶段二预留。

功能点：
1. **首批写工具（全走 HITL）**：投研日志自动建档、自选批量增删、SOP 检查单自动核对、情报订阅规则配置——从「Agent 建议、人去做」到「Agent 代办、人审批」。
2. **主动触达对话化**：持仓异动 / 再平衡偏离 / 证伪条件触发 → 飞书/站内卡片 → 一键转对话并带上下文（把盘前摘要从「播报」升级为「可追问」）。
3. **情报情感指数**：阶段二预留项，市场情绪聚合指标入对话工具与估值页。

### D6. 数据源与文档多模态 【P2】

**趋势依据**：T1（多模态数据源已成券商标配）、T4（数据层治理）。
**现状差距**：行情源无官方授权是最大单点风险；公告 PDF 仅存抽取文本未结构化利用。MCP 方向的具体对接候选与优先级见 [国内金融 MCP 资源盘点](../research/2026-10-04-国内金融MCP资源盘点.md) 第五节。

功能点：
1. **财报/公告 PDF 结构化解析**：抽取文本 → 结构化要点入研报素材与 wiki（多模态的第一步先做文档，而非图像/音视频）。**与 MS-21 边界（已确认 2026-10-04）**：MS-21 已交付业绩公告六字段抽取（快报类）；本方向做年报/半年报等定期报告全文要点，不重复建设。
2. **授权数据源接入位**：MCP provider 目录化扩展流程化（现需 DB 加目录 + 发版）；企查查预留位激活，未上市策展从人工月度摘录升级为自动补全。
3. **行情源健康度面板**：降级事件、字段漂移告警可视化（兜底机制已有，缺呈现）。

### D7. 模型层韧性 【P2】

**趋势依据**：T4（模型间幻觉率差异 3.3%–23.5%）、T7。
**现状差距**：DeepSeek 单供应商且由系统统一提供，升级即全量风险敞口，用户无选择权。

功能点：
1. **用户自备模型提供方（BYOK，已确认 2026-10-04）**：模型提供方由用户配置、系统不再统一提供——内置提供方目录（DeepSeek 为首、可扩展），用户在设置页配置自己的 API key（AES-256-GCM 加密存储，参照 MCP token 先例）；`AgentConfig` 由系统级单例装配改为按用户构建 Model（装配模式参照 `HarnessAgentFactory.build(userId)` 按请求构建的先例）。
2. **关键数字交叉校验**（可选高成本模式）：研报等正式产出场景，双模型校验关键数字一致性。
3. **立项待澄清**：系统级后台任务（情报 LLM 结构化抽取、盘前摘要、eval 回归）的模型来源——用户 key 不适合服务端批量任务，建议管理员级系统 key 仅用于后台任务（立项时拍板）。

### D8. 生态开放（MCP Server 化） 【P3 · 长期】

**趋势依据**：T1（券商接入平台智能体生态、可治理统一入口）。
**定位**：把本系统从 MCP **client** 升级为同时可作为 **server**——让外部 Agent（Kimi/WorkBuddy/自研脚本）经 MCP 调用本系统的行情/估值/持仓/情报工具。对个人投研工具链是差异化卡位，但依赖前序方向打牢，列为长期观察项。

## 三、建议路线图

| 批次 | 内容 | 理由 |
|---|---|---|
| **P0（下个迭代启动）** | D1 可信溯源 MVP（引用锚定 + 数字校验）+ D4 eval 扩充与回归触发 | 可信是金融 Agent 的准入门槛，且全部复用现有机制（图表双通道已有全量数据、eval 基线已建），投入产出比最高 |
| **P1** | D3 记忆管理 + D2 深度研究工作流（先单 Agent 工作流 + 校验器） | 形成「可信深度研究」产品差异化；组件齐备，主要是编排与 UI |

| **P3** | D8 MCP Server 化生态开放 | 长期卡位，视产品定位再裁决 |

## 四、风险与边界

- **合规边界**：非持牌系统，坚持「投研辅助」定位——D5 写工具严格限定在系统内部数据管理（日志/自选/订阅），**不触碰真实交易接口**；所有输出保留 disclaimer。
- **数据授权**：行情源无官方授权是存量风险，D6 授权源接入应优先于多模态扩展。
- **成本控制**：D7 BYOK 后对话 token 成本由用户自负，系统侧成本集中于后台任务（来源见 D7 立项待澄清）；深度研究工作流与双模型校验是 token 大户，需配额与缓存策略（系统已有 TTL 缓存基础）。
- **复杂度纪律**：多 Agent 编排调试成本高，坚持 D2 的「先工作流、后多 Agent」路径；每个方向立项时过 YAGNI。
