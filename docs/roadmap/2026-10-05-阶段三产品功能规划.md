## 一、阶段定位与总体目标

**阶段一**（MS-00~19）交付「数据与记录」闭环——答「数据在哪、赚了多少」；**阶段二**（MS-20~27）交付「信息消化与决策流程」——答「信息怎么消化、决策怎么做」。

**阶段三**交付**「可信与个性化的深度研究底座」**：

1. **工程前置**：集中还清 2026-10 全量审查的 P2 质量债，动 Agent 内核前清障；
2. **可信底座（P0）**：D1 可信溯源与幻觉治理 + D4 评测与可观测加固——金融 Agent 的合规准入门槛；
3. **差异化（P1）**：D3 记忆与用户个性化 + D2 深度研究工作流——形成「可信深度研究」产品差异化。

一句话：**答「结论可不可信、研究怎么深入」**。

## 三、架构决策（2026-10-05 已决）

> 方向级决策（数字校验 MVP 范围、eval 不挂 PR、D2 单 Agent 先行、画像注入护栏、D6 与 MS-21 边界、BYOK 形态）见[方向规划文档](2026-10-04-投研Agent功能迭代方向规划.md)决策记录 #1~#6，本节不重复；以下为里程碑编排级决策。

**决策 #1（编排范围）**：P0+P1 细化为 MS-28~32 里程碑与功能点草案；P2/P3（D5/D6/D7/D8）方向级占位，立项时再细化——避免细节未定（如 D6 目录化形态）时细排必然返工。

**决策 #2（工程前置编排）**：code-review-2026-10 P2 第二批（真缺陷）排先行工程里程碑 MS-28 集中收口（同平台增强批次先例）；P3 打磨项不占里程碑，按域分摊到 MS-29~32 落地时顺带清理（§8.2 台账跟踪）。

**决策 #3（后台任务模型来源，即方向规划 D7 待澄清项）**：BYOK 落地后，管理员级**系统 key 仅限全局调度任务**（情报抽取、盘前摘要、eval 回归、数据刷新巡检等系统调度器发起的批任务）；**一切用户会话内路径**（含 D2 研报工作流、写工具、画像注入对话）走用户 key。边界判据单一：任务发起方是系统调度器还是用户会话。

**决策 #4（预留口子归位）**：SOP v2 → D2 承接（MS-32 占位节）；趋势/技术面 v2 保持独立立项口子、不入 D1–D8（与 Agent 能力建设主线正交，待产品定位再裁）；「RAG 增强批次」从衔接列表剔除（阶段二决策 #4 已弃用且明言后续批次不预留）。

**决策 #5（P0 范围口径）**：D1/D4 各一个**完整**里程碑（D1 全 3 功能点、D4 全 4 项）——D4.3 工具提示词版本化是 eval 评测关联的前置（评测结果不锚定提示词版本则回归比对无基准），D1.3 免责标准化与 D4.4 观测看板均轻量，后置反留「方向开而不全」跟踪债。

**决策 #6（功能点口径）**：MS-28/MS-30 为跨里程碑工程项，归属 M14 系统与工程，**不计入产品功能点口径**（沿平台增强批次、MCP token 加密工程加固先例）；产品功能点仅 M17~M19 共 9 点（草案）。

- **目标**：eval 从「抽取质量基线」升级为「三类金融 QA 基准 + 版本化 + 定时回归 + 线上看板」的生产化评测体系。
- **交付范围**（工程项，M14，方向 D4）：

  - [ ] 工具提示词版本化：提示词入库 + 变更历史 + 评测结果关联版本（现 11 条人工维护）
