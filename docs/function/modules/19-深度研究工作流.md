## 一、模块定位

把 Agent 从「单轮 ReAct」升级为**多步研报任务流**：研究页发起 → 单 Agent 异步多步工作流（收集→分析→草稿）→ 草稿过校验门落库 → 人工确认挂研究项目；关键假设与数字锚点持久化、打开时可重查过期。一句话：选题到定稿全程可溯源（数字必须过 fail-closed 校验门才出稿）、假设可跟踪（锚点四态）、成本有护栏（token 双层配额）——补齐阶段三「可信 + 个性化 + 深度」的最后一块。

## 三、功能点详情（MS-32 单里程碑，交付说明 2026-10-11）

- **F01 研报生成任务流**：`ReportTaskController` 五端点（发起 202 `{taskId, quotaRemaining}` / latest 轮询 / 研报列表 / 详情 / 确认分派；402 日配额耗尽、409 活跃任务或终态再操作、非本人 404）。执行链 `ReportApplicationService.startTask`（配额软检查 + 单任务约束）→ `agent/report/ReportWorkflowOrchestrator.submit`（有界 0 队列线程池，拒绝同步 `FAILED(AGENT_ERROR, 队列已满)`）。编排器驱动 `HarnessAgentFactory.buildReportAgent`（独立变体：`maxIters` 15/轮、三轮 call 续会话 `report-<taskId>`、**MCP 结构排除** `buildWithoutMcp`——写 MCP 工具在独立 call 下触发 ASK 门无应对方、挂死风险；深研指引 `ReportWorkflowPrompt` 恒注入并登记版本资产 `system.invest.report`；画像注入经 build 自动生效）。任务四态 `PENDING→RUNNING(阶段 COLLECTING/ANALYZING/DRAFTING/VALIDATING)→SUCCEEDED/FAILED`，前端 5s 轮询（EvalRunsPanel 先例）；进程重启由 `ReportTaskRecoveryRunner` 批量标 FAILED 可重试（D3 失败重来）；终态清理 report-* state 会话文件（stateStore 零残留）。
- **F02 关键假设数据跟踪**：V8 落 `research_report`（定稿全文 + limitations）+ `research_report_anchor`（锚点审计真相，创建后不可变）+ `research_report_assumption`（`UNIQUE(report_id, seq)`，`anchor_id` 门拦不可能为 NULL）三张产物表；「关键假设」章节由 LLM 生成、绑定由门后处理自动完成（数字与锚点容差匹配，无需 LLM 输出锚点 id）。打开研报（detail 端点）触发 `ReportStalenessService` 重查：`ReportAnchorRechecker` 按工具白名单**直调 InvestTools/UserInvestTools 实例方法**（绕过装饰器不污染真值池），现值 vs 锚定值容差内再现=FRESH、超阈=CHANGED、asOf 超 stale 线=STALE、工具失败/白名单外=UNVERIFIABLE；结果整体缓存 TTL 5m，不回写正文（原文不可变），仅作徽标与浮层（工具/参数/锚定值 vs 现值对照，沿 M17 溯源浮层形态）。
- **F03 草稿过校验器**：`ReportValidationGate`（纯 POJO）在 VALIDATING 阶段以任务累积真值池调 `ConsistencyValidator.correct`（M17-F02 复用，零新建比对逻辑）——独立严格档 `invest.report.validation`（relative 0.01 / absolute 0.03 / price 0.005 / unverified-ratio-max 0.10，均严于对话档且**对话档 `invest.trust.*` 零改动**）；`correctionFailures` 非空或假设零锚点绑定 → 回炉轮（≤1，失败清单反馈自纠）→ 仍败 `FAILED(VALIDATION_FAILED)`；payload 围栏 JSON 解析失败格式反馈重试 1 轮 → `PARSE_FAILED`。**fail-closed**：门内部异常、真值池空（收集轮全失败）任何路径不得产出 PENDING_CONFIRM 研报——与对话档 fail-open 刻意相反；自动修正项（原位替换+⚠注记）进定稿文本。

## 四、关键机制与约束

- **真值池 POST_CALL 快照通道**（Ruling-21 ③）：`HarnessAgent.call` 对编排器裸 rc 恒派生新实例（工具记录与 hook 同见派生 rc，编排器自有 rc 直读恒空池——S1 真 LLM 实证 + 字节码归因）→ `ReportUsageMiddleware` 在 POST_CALL 时点快照（PR #111 hook 迁移后由中间件承担，原名 ReportUsageHook） `TrustContext` 真值进并发队列，编排器每轮 call 返回后 `drainTruthInvocations()` 排空入任务级累积池（防跨轮重复）；门只吃累积池（`research_draft` 回显排除维持）。
- **配额双层**（D7）：per-user 自然日预算 500,000（`report_token_quota` 落库 settle upsert，重启不丢；超限拒绝发起 402 提示次日恢复）+ 单任务上限 400,000（Ruling-21 ① 实测校准：真 LLM 五跑 168k~285k，原 150k 系统性撞线、初裁 250k 复被击穿，峰值 +40% 余量上调）；token 读数口 `ReportUsageMiddleware`（POST_REASONING/POST_SUMMARY usage 事件累计）。
- **schema**：V8__ms32_deep_research.sql 五表——研报产物四张（`research_report_task`（部分唯一索引 `uq_report_task_active` 钉单活跃任务）/`research_report`（确认状态机 PENDING_CONFIRM→CONFIRMED/REJECTED）/`research_report_anchor`/`research_report_assumption`）+ `report_token_quota` 日配额；实体落 `domain/research` 扩展（纯 POJO，Clock 注入）。
- **对话链路零变更红线**：`build(Long)`/`systemPrompt(userId)` 逐字节回归钉死；MCP 排除只增 `buildWithoutMcp` 变体不动 `build` 装配。
- **P3 时钟归一**（D5）：domain 全域 37 处 `Instant.now()` 直调清零（grep 零命中验收），方法参数 `Instant now` 注入、不引 Clock 进字段。
- **SOP v2 轻量并入**（D4）：对话内 DraftCard「保存到项目」经项目选择对话框接既有研究域 REST，恒抛错桩解除；`search_wiki` 新工具（readOnly 不触发审批）补齐研报五源。
- **测试锚**：fake runner 脚本化驱动编排器全状态机（零 LLM）+ BDD 中文三场景（确认挂项目/数字不一致不出稿/假设过期提示）+ e2e `research-report.spec.ts` 真浏览器（确认/拒绝双流/进度轮询/配额拒绝/背板关闭）+ smoke 研报节真 LLM 全链。
