# 05 · 用户管理与会话持久化

## 1. 定位

系统引入**用户体系**：AI 对话消耗 LLM token，需**注册并审核通过**后方可使用；行情数据本身公开，保持免登录。AI 对话历史**服务端持久化、归属账号**，换设备可见。

## 2. 身份与凭据

- **凭据**：用户名 + 密码（注册仅这两项）。
- **密码策略**：≥8 位，且同时含字母与数字（前后端双重校验），BCrypt 哈希存储。
- **角色**：`ADMIN`（管理员）/ `USER`（普通用户）。
- **会话**：同源 Cookie 会话（`JSESSIONID`，HttpOnly + SameSite=Lax）+「记住我」令牌（勾选 30 天，否则关浏览器失效）。

## 3. 用户状态机

```
注册 ──→ PENDING（待审核）──审核──→ APPROVED（通过，可登录用 AI）
                        └──拒绝──→ REJECTED（被拒，可重新注册，复用原用户名）
```

- **待审 / 被拒均不能登录**；被拒用户重新注册时，原记录更新复用（换新密码、置回 PENDING）。
- **登录条件**：`status=APPROVED AND enabled=true`。
- **停用**（`enabled=false`）即时撤销 AI 资格——受保护接口每次请求校验用户状态，无需等会话过期。

## 4. 功能清单

### 4.1 用户侧

| 能力 | 说明 |
|---|---|
| 注册 | `/register` 填用户名 + 密码 → 「等待管理员审核」 |
| 登录 | `/login` 用户名 + 密码 + 可选「记住我」 |
| 登录状态 | 顶部导航显示当前用户；未登录访问对话页跳转 `/login` |
| 会话历史 | 侧栏会话列表来自服务端，换设备可见；标题取首条消息前 24 字 |

### 4.2 管理员侧（`/admin`，需 ADMIN）

| 能力 | 说明 |
|---|---|
| 待审列表 | 查看 PENDING 用户，逐一「通过 / 拒绝」 |
| 用户列表 | 全部用户（用户名 / 角色 / 状态 / 启用） |
| 停用 / 启用 | 立即撤销 / 恢复 AI 使用资格 |
| 重置密码 | 代为重置（校验密码强度） |

### 4.3 保护

- **管理员不可被审核/停用/重置**（保护内置管理员账号）。
- **会话归属隔离**：所有会话读写校验 `user_id`，非本人一律 404（不泄露存在性）。

## 5. 管理员引导

- 系统无初始账号时，通过 env `ADMIN_USERNAME` / `ADMIN_PASSWORD` **启动幂等种子**一个 ADMIN 账号（不存在才创建，与普通用户隔离）。
- 未配置则不创建管理员（此时无法审核注册用户，需补配后重启）。

## 6. 会话持久化模型（ADR-0008）

- 领域实体 `Conversation`（`conversation` 表），`id` 复用 AG-UI 协议层 `threadId`；消息存 `chat_message` 表（精简历史：仅 user/assistant 纯文本，`payload` 预留工具调用扩展）。
- 交互模型为「前端工作内存 + 服务端存储」：前端仍持有当前对话消息作为工作内存、每轮携带全量历史到 `/agui/run`；每轮 assistant 回复完成后 **PUT 全量消息**到服务端，打开会话时 **GET 回灌**。
- 多端同时编辑同一会话 = **后写覆盖**（不做并发合并）。
