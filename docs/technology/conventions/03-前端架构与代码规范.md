# 03 · 前端架构与代码规范

> 适用范围：`frontend/`（Next.js 15 App Router + React 19 + TS strict + CopilotKit + Tailwind 4 + vitest/Playwright）。
> 定位前提：本前端是**纯动态的同源反代应用**——页面零静态化价值、数据全部鉴权后取、核心是流式会话。规范围绕此定位收敛。
> 每条规则含：理由 / 佐证 / 约束方式（人工评审 / lint 强制 / 测试强制）。标注【决策】的条目为已拍板的设计取舍。

## 一、目录与分层

**1.1 `app/**/page.tsx|layout.tsx` 保持无逻辑薄壳，业务组件一律放 `components/<域>/`。**
理由：page 是框架接线层，逻辑下沉到 `components/` 才能被 vitest 覆盖（`vitest.config.ts` include 只含 `components/`、`lib/`、`app/api/`）。佐证：`app/market/page.tsx` 5 行壳。约束：人工评审 + 覆盖率配置天然施压。

**1.2 `lib/` 是唯一数据访问层：组件不直接 `fetch`，一律经 `lib/*Api.ts|conversations.ts|auth.tsx`。**
理由：zod 边界校验、错误归一、`no-store` 约定都在这一层收口。约束：**lint 强制**（`no-restricted-syntax` 禁 `components/**` 出现 `fetch(`）。

**1.3 `app/api/**` 只做反代，不承载业务逻辑。** 理由：Route Handler 定位是 cookie 会话桥（ADR-0007），混入业务会造成双后端。约束：人工评审。

## 二、数据获取与反代

**2.1 新增反代路由必须走 `lib/proxy.ts` 的 `relay()`，禁止手写裸 fetch 转发。**
`relay()` 统一了四件易错事：多值 Set-Cookie 逐个 append、204/205/304 置空 body、15s `AbortSignal.timeout`、catch→502 JSON。约束：人工评审 + 测试强制（§7.3）。

**2.2 全站约定动态渲染：Route Handler 导出 `export const dynamic = "force-dynamic"`，客户端 fetch 一律 `cache: "no-store"`；禁止私自 opt-in 缓存（需缓存先过评审）。**
理由：响应依赖 cookie 会话且数据强时效；显式声明防 Next 默认值升级漂移。

**2.3 反代透传三件套：状态码原样、上游 Content-Type 原样（不强制 JSON）、Set-Cookie 全量 append。** 约束：测试强制（每条路由有透传断言）。

## 三、状态与流式（本项目最高危区）

**3.1 一切异步 effect 必须有取消守卫（`cancelled` flag），一切可并发触发同一资源的请求必须用序号守卫丢弃过期响应。**
佐证：`MarketBoard.tsx` requestSeqRef、`RuntimeProvider.tsx` cancelled flag。约束：人工评审（审查清单固定项）。

**3.2 防抖/节流持久化必须在 cleanup 与"运行停止"边沿 flush，不能只 clearTimeout。**
佐证：`ThreadArea.tsx` 双 flush（isRunning true→false 立即 flush + 卸载 keepalive flush）。约束：人工评审 + 回归测试。

**3.3 流式渲染必须节流 + 按消息 memo 隔离；禁止每 token 全树重渲染。**
佐证：`useAgent throttleMs: 150` + `AssistantMessage` memo。约束：人工评审。

**3.4 运行中（`isRunning`）禁止切换/新建/删除线程，切换前 `abortRun()`。** 约束：测试强制（RuntimeProvider/Sidebar 测试覆盖）。

**3.5 写 localStorage 等无界浏览器存储必须设容量上限并清最旧。** 佐证：FeedbackBar 上限 200 条。

## 四、组件与 hooks

**4.1 `"use client"` 只标在真正需要交互/浏览器 API 的组件上，page/layout 保持 Server Component 薄壳；Provider 集中在 `app/providers.tsx`。**【决策：维持纯客户端取数——登录墙后应用，SSR 无收益】

**4.2 Context value 必须 `useMemo`；Provider 内回调用 `useCallback`；高频订阅源（数组/对象字面量）提升为模块级常量。** 约束：**lint 强制**（react-hooks 规则集）。

**4.3 服务端与客户端首帧状态必须一致（空态），真实数据挂载后拉取；未就绪前渲染占位而非条件性返回不同树。** 佐证：`RuntimeProvider.tsx` hydration 注释。

**4.4 hooks 规则零豁免：禁止 eslint-disable rules-of-hooks / exhaustive-deps（确需豁免必须注释理由并经评审）。** 约束：lint 强制。

## 五、类型与校验

**5.1 所有跨网络边界的响应必须 zod 校验；schema 放 `lib/schemas.ts`（或就近 Api 文件），类型用 `z.infer` 派生；禁止 `as` 断言与 `Promise<any>`。**
理由：schema drift 在边界报错而非深渲染崩溃。约束：人工评审 + **lint 强制**（`no-explicit-any`）。

**5.2 TS strict 保持全开不降级；`import type` 与值导入分开。** 约束：tsc 构建强制（已生效）。

## 六、安全

**6.1 安全响应头集中维护在 `next.config.ts`（nosniff / Referrer-Policy / X-Frame-Options / frame-ancestors），新增页面默认继承。【决策：维持四件套，完整 nonce CSP 列为独立改进项】**

**6.2 Markdown 渲染禁止开启 `rehype-raw`、禁止 `dangerouslySetInnerHTML`；外部链接一律 `target="_blank" rel="noreferrer"`。** 约束：**lint 强制**（`react/no-danger` + 禁 `rehype-raw` 导入）。

**6.3 错误 UI 不直接展示 `error.message`/堆栈，映射为通用文案 + console 留细节。** 佐证：`app/error.tsx`（生产只显示通用文案 + digest）。

**6.4 管理操作禁止用 `window.prompt` 等明文输入口令；敏感操作走表单组件。** 佐证：重置密码弹窗（复用 checkPassword + 二次确认）。

## 七、测试

**7.1 分层分工：vitest 管组件行为 + lib 逻辑 + 反代路由契约；Playwright 只管真实浏览器用户流（导航/鉴权/对话/会话持久化）；两者不互相替代。**

**7.2 覆盖门槛 80%（语句/分支）保持；覆盖率 include 限 `components/`、`lib/`、`app/api/` 三个业务目录；页面壳靠 smoke/e2e。** 约束：vitest thresholds 强制（已生效）。

**7.3 新增反代路由必须配路由级单测：拼路径/方法、Cookie 透传、Set-Cookie 透传、不可达→502 四条断言起步。** 模板：`tests/lib/routes.test.ts`。

**7.4 修复性提交必须带回归测试；禁止把错误行为断言为"正确"（审查测试断言本身）。**

**7.5 时序类逻辑（防抖/节流/序号守卫）测试用假时钟或可注入时序，禁止真实 sleep。**

## 八、命名与风格

**8.1 文件命名：组件 PascalCase（`MarketBoard.tsx`），lib/工具 camelCase（`adminApi.ts`），路由固定 `route.ts`，测试与被测同名。**

**8.2 注释写"为什么"不写"是什么"；涉及权衡/有意取舍处引 ADR 或审查条目。** 佐证：`RuntimeProvider.tsx` 引 ADR-0004。

**8.3 模块级注释说明文件职责与边界（每个 lib/路由文件头部一行）。**
