# 04 · 采集服务（collector）架构与代码规范

> 适用范围：`collector/`（Python 3.12，psycopg3 / APScheduler / alembic / pandas·akshare·tushare / pytest+testcontainers）。
> 分层骨架：sources → converters → validators → calc → store，executor/scheduler 编排，repositories 纯 SQL，YAML 声明式任务。
> 每条规则含：理由 / 佐证 / 约束方式（人工评审 / 测试强制 / 工具强制）。标注【决策】的条目为已拍板的设计取舍。

## 一、分层与扩展点

**L1. 分层固定为 sources → converters → validators → calc → store，单向依赖；executor/scheduler 只做编排，repositories 只做 SQL，model 不依赖任何层。** 约束：人工评审 + import-linter 合约强制。

**L2. 新增能力只走"注册表 + YAML 声明"，禁止在 executor/runner/scheduler 出现任务特例分支。** 佐证：`jobs.py assemble_collector` 是唯一装配点。

**L3. 组件接口契约为强约束：`Source.fetch → pd.DataFrame`（原始数据）、`Converter.convert → list[dict]`、`Validator.validate → (records, issues)`（hard 违规抛 SourceError、soft 记入 issues）、`Calc.compute` 在 validate 之后执行。** 约束：测试强制（各层契约测试）。

**L4. Source 内直连目标库是受限破例，仅限"JOIN 源"模式（读本服务已写入的映射表）：docstring 必须声明依赖的任务与表，禁止写目标表，且必须有"上游表为空"的用例（产出 0 行、经 min_rows hard 判失败）。** 佐证：`IndustryUniverseSource`。落实：mock 级用例 `test_industry_universe_empty_upstream_table_*`（test_plugins.py）已覆盖冷启动缝隙；真实 PG 集成级待补。

**L5. YAML 任务字段集是封闭契约：`task_code/task_name/source_ids/converter/calc/validator/target_table/schedule/enabled/trading_day_gated/retry_max/retry_backoff`；seed 必须校验必填键、拒绝未知键，缺键/未知键 fail-fast 抛 ValueError（强制条款，已实现为 `jobs.TASK_DEF_KEYS` + `_validate_task_keys`）；`retry_max` 语义固定为"重试次数"（总尝试 = retry_max+1）。【决策：手写键集合校验，不引 pydantic】** 理由：配置字段与代码消费必须一一对应（死配置教训）。约束：测试强制——全量 YAML 装配冒烟（`test_yaml_assembly.py`：真实 tasks/ 目录走 load_task_defs → build_registries → assemble_collector 全链路，兼覆盖四个 registry 的 get 与 make_trigger）+ 键校验单测 + 存量 YAML 必过校验的回归用例。

## 二、数据源与降级

**D1. 第三方库原生异常不得逸出 Source 边界：统一包装为 `SourceError`（换源降级）或 `StoreError`（整任务重试），禁止第三种去向。** 约束：每个新源必须有"抛原生异常 → 断言 SourceError"用例。

**D2. 熔断语义固定：连续失败 3 次 open、冷却 600s 后半开、半开探针仅在无健康候选时兜底；熔断计数按"任务运行"计，重试不放大计数。** 约束：测试强制。

**D3. 源必须显式声明 `supports_range`；backfill 遇到 `supports_range=False` 的源必须拒绝执行，禁止静默降级。** 约束：测试强制（已有回归）。

**D4. 增量源以"已入库最大业务键"为水位线（如 `max(trading_day)`），水位语义必须文档化：backfill 早于水位的区间不会回补旧数据。** 佐证：`TreasuryCurveSource`。

**D5. 跨边界日期/代码格式归一化集中在边界函数（`normalize_date`），内部一律 `dt.date`，字符串只存在于外部接口。** 约束：测试强制。

## 三、事务与幂等（铁律区，全部测试强制）

**T1. 捕获 `psycopg.Error` 后必须 `rollback()` 或丢弃连接；任何代码路径不得让连接停留在 aborted transaction 状态继续被使用。**（本项目唯一 P0 的教训）约束：真实 PG 回归测试强制——mock 连接不会进入 aborted 状态，**mock 通过 ≠ 真实通过**。

**T2. 重试不得复用失败连接：每次任务尝试新建连接、用完即弃；连接生命周期 = 一次任务尝试。【决策：维持新建连接，不引连接池——任务日级低频】**

**T3. 写库必须幂等：`UPSERT_SQL[table]` 的 ON CONFLICT 键与表唯一约束一一对应；新增目标表顺序固定为"先迁移建唯一约束 → 再注册 UPSERT_SQL/TABLE_COLUMNS → 再挂任务"。** 约束：每表一条"重复 upsert 不产生重复行"真实 PG 用例。落实：6/6——valuation_snapshot 在 `test_writer.py`，其余 5 表在 `test_writer_idempotency.py`。配套约定：**集成测试 schema 必须由真实迁移构建**（conftest `pg_schema` fixture：collector alembic upgrade head + 回放后端 Flyway V3/V4 SQL），禁止手工复制 DDL（副本会与真实迁移漂移）。

**T4. 业务写与运维写事务边界分离：运维记录（run/health）独立 commit，数据写失败绝不能连带运维记录丢失。**

**T5. `UPSERT_SQL` 与 `TABLE_COLUMNS` 双份定义加一致性测试兜底（键集相同、列名对应）。【决策：一致性测试，最小改动】**

## 四、调度

**S1. 每个 job 显式设置 `coalesce=True`、`max_instances=1`、`misfire_grace_time`（日级 3600s、日历刷新 86400s），禁止依赖 APScheduler 默认值。** 约束：测试强制（build_scheduler 属性断言）。落实：`test_task_job_scheduler_attributes`（test_jobs.py）逐项断言任务 job 与日历刷新 job 的三项属性。

**S2. 凡 interval/低频 cron 任务必须回答"首次数据何时产出"；从未成功运行的任务启动时立即补跑（`next_run_time=now`），机制集中在 `never_succeeded` 一处。**

**S3. 调度 job 函数必须自己兜底所有异常（`except Exception: logger.exception`），异常逃出 job 即该任务静默丢调度。** 落实：任务 job 统一经 `jobs._run_task_job` 包装（try/except 兜底 + logger.exception），新增调度 job 必须走同一包装；回归用例 `test_task_job_swallows_runner_exception_and_logs`（断言不外抛、记 ERROR 日志）。

**S4. 多副本互斥统一用 PG advisory lock（`hashtextextended`），锁的获取/释放在同一连接生命周期内。**

**S5. 时钟逻辑可注入/可参数化：`run_date(params)` 集中处理 `--date` 门控，交易日判断只经 `TradingCalendar`；测试用固定日期，禁止真实 sleep 退避。**

**S6. 交易日历是基础设施级依赖：月度定期刷新 + 陈旧度告警（落后 >15 天 warning）为固定机制；新增基础数据任务时必须同时回答"它如何自我更新"。**

## 五、配置与密钥

**C1. 配置唯一入口是 `config.load() → Config`（frozen dataclass）；业务代码禁止直接 `os.environ`；`load_dotenv()` 只在入口调用，禁止 import 期副作用。**

**C2. 密钥只走环境变量，不进 YAML、不进 DB、不进日志与异常消息。**

**C3. 配置校验 fail-fast 且按命令分级：每命令声明所需键，`list`/`history` 等只读命令不强制数据源密钥；缺配置报错必须列出缺失项与修复指引。【决策：每命令声明所需键】**

## 六、日志与可观测性

**O1. 统一 stdlib `logging`：`getLogger(__name__)` 按模块取 logger，`basicConfig` 只在入口调用一次；库代码禁止 print（CLI 用户输出除外）。** 约束：ruff `T201` 强制。

**O2. 每次任务运行双通道留痕：DB（collector_task_run 含 status/source_used/rows_written/error）+ 日志（task_code、attempt、source、rows、耗时）；失败路径留痕完整性与成功路径同等要求。**

**O3. 可预期跳过（非交易日、锁占用）记 INFO + RunResult(SKIPPED)；FAILED 必须 error 日志 + failed run 记录——不允许"只 log 不记录"或"只记录不 log"。**

**O4.【决策】暂不引入 structlog/JSON 日志：单容器 stdout 无聚合下游，接入日志聚合时再重估。**

## 七、测试

**E1. 分层固定：纯逻辑（selector/calc/converters/validators/backoff）用单测 + mock；凡涉事务、连接、锁、SQL、序列化的行为，至少一条真实 PG（testcontainers/CI service）窄集成测试。** 评审清单第一项："失败路径有没有真实依赖测试？" 集成测试 schema 与生产同源：session 级 `pg_schema` fixture 跑真实迁移（collector alembic upgrade head + 后端 Flyway V3/V4 SQL 整段回放），`pg_conn` 只做 10 表 TRUNCATE，禁止维护手工 DDL 副本；迁移测试（`test_migrations.py`）复用 `pg_url`（drop 运维表后重迁 head），本地 testcontainers 可直接跑，不再依赖 DATABASE_URL 环境变量。

**E2. 修复 bug 的 PR 必须含回归测试，且审查测试断言本身——禁止把错误行为断言为"正确"。**（test_backfill 反向固化的教训）

**E3. 覆盖率门槛 80% 在 `make test` 与 CI 双线强制；新模块合入即纳入统计，不允许先合后补。** 现状（2026-08-31 测试体系加固后）：148 用例全绿（含真实 PG），总覆盖率 95.56%（901 语句 / 40 未覆盖），四个 registry 均 ≥86%。

**E4. 新任务 YAML 合入配套最低测试集：converter 真实字段映射用例、validator hard/soft 各一、seed 校验通过、（新表）upsert 幂等用例。**

## 八、类型与风格

**Y1. 公共接口（各层基类、Registry、Repository、Store、TaskRunner、Executor 公开方法）签名必须有类型注解；内部实现渐进补充。模型层用 dataclass，配置/不可变模型 `frozen=True`。**【决策：人工评审 + ruff ANN 仅公共接口；mypy 暂缓，注解密度足够后 baseline 模式渐进引入】

**Y2. 目标语法 Python 3.12：联合类型用 `X | None`，禁用 `typing.Optional`；标准库优先，不为小功能加依赖。** 约束：ruff `UP` 规则强制。

**Y3. 注释写"为什么"不写"是什么"；修复 bug 引入的非显然逻辑，注释必须引用原因。**

## 九、工具链

**G1.【决策】ruff（lint + format 一体）为强制工具**：配置存 `collector/pyproject.toml`，规则集 `E,F,W,I,UP,B,SIM,T201`，纳入 CI 与 `make collect-test`（`ruff check && ruff format --check`）。

**G2.【决策】依赖全量锁定**：`uv pip compile` 从 `pyproject.toml` 生成锁定版 `requirements.txt`（含传递依赖），Docker/CI 安装命令不变（仍 `pip install -r`）；升级流程 = 改声明 → 重新 compile。

**G3.【决策】import-linter 分层合约**入 CI：固化 L1 的单向依赖（与后端 ArchUnit 理念对齐）。

**G4. pre-commit 可选不强制**（ruff 已由 CI 强制）。
