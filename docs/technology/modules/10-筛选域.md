# 10 · 筛选域

> 价值投资筛选器后端：对全市场个股按估值/盈利/财务健康/成长/市值流动性指标做 AND 组合宽扫，可排序限条。
> 功能口径与 [../../function/modules/09-价值投资筛选器.md](../../function/modules/09-价值投资筛选器.md) 同源；数据底座（个股估值日快照/财务指标）见 [../architecture/05-数据类型与来源.md](../architecture/05-数据类型与来源.md)；行业估值侧见 [09-估值域.md](09-估值域.md)。
> 对应代码：`backend/src/main/java/com/portfolio/invest/domain/screening/`（`ScreeningCriteria`、`StockScreeningResult`、`ScreeningRepository`、`SortDirection`）、`application/screening/ScreeningApplicationService.java`、`web/ScreeningController.java`、`infrastructure/persistence/ScreeningRepositoryImpl.java`；迁移 `db/migration/V7__stock_fundamental.sql`、`V3__valuation.sql`（申万映射，与估值域共用）；前端 `frontend/app/screener/page.tsx`。

## 1. 概述

单端点宽扫域：`GET /api/screening/stocks` 接收 **12 项指标条件 + 行业范围**（共 13 个筛选参数）全部可选，SQL 侧 AND 拼接；**至少一个条件**否则 400。公开只读（`/api/screening/` 在 `PublicEndpointPaths.PREFIXES` 公开前缀清单中，无用户态），宽扫结果按完整查询条件做应用级缓存（TTL 默认 5 分钟）。

## 2. 架构与数据流

### 2.1 数据底座（collector 写、后端读）

| 表 | 迁移 | 粒度 | 筛选用列 |
|---|---|---|---|
| `stock_valuation_daily` | V7 | 交易日 × 个股（`UNIQUE(trading_day, stock_code)`） | `pe_ttm`、`pb`、`dividend_yield`、`total_mv`（单位：元）、`turnover_rate` |
| `stock_financial` | V7 | 报告期 × 个股（`UNIQUE(report_date, stock_code)`） | `roe`、`roa`、`gross_margin`、`debt_to_assets`、`current_ratio`、`revenue_yoy`、`netprofit_yoy` |
| `shenwan_industry_mapping` | V3 | 个股（`stock_code` 唯一） | `industry_code`、`industry_name`（与估值域共用，见 [09-估值域.md](09-估值域.md)） |

取数口径（`ScreeningRepositoryImpl.BASE_SQL`）：`stock_valuation_daily` 固定取**库内最新交易日**（`WHERE trading_day = (SELECT max(trading_day) ...)`）为主表；`stock_financial` 经 `DISTINCT ON (stock_code) ... ORDER BY report_date DESC` 取每股**最新报告期**左连接；申万映射再左连接（无映射个股行业列为 null）。来源与采集节奏见 [../architecture/05-数据类型与来源.md](../architecture/05-数据类型与来源.md)。

### 2.2 筛选条件（与实现一一对应，ScreeningController 13 参数）

| 参数 | 列 | 比较 | 维度 |
|---|---|---|---|
| `peTtmMax` | `d.pe_ttm` | ≤ | 估值 |
| `pbMax` | `d.pb` | ≤ | 估值 |
| `dividendYieldMin` | `d.dividend_yield` | ≥ | 估值 |
| `roeMin` | `f.roe` | ≥ | 盈利 |
| `roaMin` | `f.roa` | ≥ | 盈利 |
| `grossMarginMin` | `f.gross_margin` | ≥ | 盈利 |
| `debtToAssetsMax` | `f.debt_to_assets` | ≤ | 财务健康 |
| `currentRatioMin` | `f.current_ratio` | ≥ | 财务健康 |
| `revenueYoyMin` | `f.revenue_yoy` | ≥ | 成长 |
| `netprofitYoyMin` | `f.netprofit_yoy` | ≥ | 成长 |
| `totalMvMin` | `d.total_mv` | ≥ | 市值与流动性（元） |
| `turnoverRateMin` | `d.turnover_rate` | ≥ | 市值与流动性（%） |
| `industryCode` | `m.industry_code` | = | 行业范围 |

以上即功能文档 F01「多条件组合筛选」的全部已实现条件——**不存在** PE 分位、ROE 连续 N 年、经营现金流比、日均成交额等未实现条件。

### 2.3 校验、排序与缓存（ScreeningApplicationService）

- **至少一个条件**：13 个筛选参数全空 → `SCREENING_NO_CONDITION`（400）。`ScreeningCriteria.hasAnyCondition()` 判定。
- **排序**：`sortBy` 必须在 `SORTABLE_FIELDS`（12 个指标列的 snake_case 名）内否则 `SCREENING_INVALID_SORT`（400）；`sortDirection` ASC/DESC；SQL `ORDER BY ... NULLS LAST`。
- **限条**：`limit` 默认 200，有效区间 1~200，越界 `SCREENING_INVALID_LIMIT`（400）。无分页 offset。
- **缓存**：key = `screening:stocks:` + 全部 16 个参数值以 `|` 拼接（条件+行业+排序+方向+limit），TTL `invest.app-cache.ttl`（默认 5 分钟）——匿名公开端点的宽扫结果防同条件反复全市场扫描。

## 4. 端点（统一前缀 `/api/screening`，公开只读）

| 端点 | 说明 |
|---|---|
| `GET /api/screening/stocks` | 宽扫查询。Query 参数 = 上表 13 个 + `sortBy`（默认 `pe_ttm`）+ `sortDirection`（默认 `ASC`）+ `limit`（默认 `200`）；返回 `StockScreeningResult[]` |

错误码（`GlobalExceptionHandler` 映射，均 400）：`SCREENING_NO_CONDITION` / `SCREENING_INVALID_SORT` / `SCREENING_INVALID_LIMIT`。

## 6. 已知限制

- **财务指标固定最新报告期**：无法按报告期回看或选同比期；财务列缺失（`f.*` 为 null）的股票在对应条件筛选时被排除（SQL null 比较不成立）。
- **单查询无分页**：只有 `limit ≤ 200` 截断，无 offset/游标，前端翻页需自行切页或收紧条件。
- **估值面只取最新交易日**：筛选无历史时点参数（回测式筛选不可用）。
- **`StockScreeningResult` 直接作响应契约**（A1 显式取舍）：仓库行结构变化即 API 变化。
- **无自选/导出**：功能文档 F03（自选观察列表）、F04（CSV 导出）、F05（成分股范围限制）、F06（基金筛选）均为 ⏳ 未实现项，本域不含。
