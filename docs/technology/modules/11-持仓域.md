# 11 · 持仓域

> 持仓组合管理后端：分组账户记账（买/卖/现金/股票分红/现金存取），`Position` 聚合内置成本盈亏引擎（加权平均 + 分红降成本），并派生总览/资产配置/行业分布/集中度四类聚合视图。
> DDD 分层与聚合取舍见 [../decisions/0009-backend-ddd-layering.md](../decisions/0009-backend-ddd-layering.md) 与 [../conventions/01-后端DDD分包规范.md](../conventions/01-后端DDD分包规范.md)；行情批量取价依赖 [02-行情数据服务.md](02-行情数据服务.md)；功能视角见 [../../function/modules/08-持仓组合管理.md](../../function/modules/08-持仓组合管理.md)；下游消费方见 [12-资产配置域.md](12-资产配置域.md)（偏离度）与 [13-投研日志域.md](13-投研日志域.md)（时间线）。
> 对应代码：`backend/src/main/java/com/portfolio/invest/domain/portfolio/`（`Portfolio`、`HoldingGroup`、`Position`、`Trade`、`Dividend`、`CashTransaction` + 5 个枚举）、`application/portfolio/`（`PortfolioApplicationService`、`PortfolioCreationService` + 命令/视图 record）、`web/PortfolioController.java`、`infrastructure/persistence/PortfolioRepositoryImpl.java` + JPA entity；迁移 `db/migration/V5__portfolio.sql`、`V9__optimistic_locking.sql`；前端 `frontend/app/portfolio/page.tsx`。

## 1. 概述

后端最大业务域。核心设计：

- **单组合/用户**：每用户至多一个 `Portfolio`（`user_id` UNIQUE），首次访问任一端点自动幂等创建（`PortfolioCreationService.ensureCreated` → `insertPortfolioIfAbsent` 原子插入，并发首访只一行生效）。
- **分组两类**：`HoldingGroup` 分 `ACCOUNT`（现金账户——现金流水与现金余额挂在此类分组）与 `TAG`（标签分组）。
- **成本口径单一**：`CostMethod` 枚举现仅 `WEIGHTED_AVG`（`portfolio.cost_method` 默认值），全部计算在 `Position` 聚合内完成。
- **事件溯源式重放**：交易/分红是不可变事件行；编辑交易或补录分红时按日期重放全部事件重建持仓（`replay`），账本永不漂移。
- 全部端点需登录（不在 `PublicEndpointPaths` 公开清单），归属过滤 userId→portfolioId→groupId/positionId 在用例层逐跳校验（仓库接口层再过滤一次，双重保障）。

## 2. 架构与数据流

### 2.1 数据模型（V5 + V9 乐观锁）

| 表 | 粒度 | 关键列/约束 |
|---|---|---|
| `portfolio` | 用户（`user_id` UNIQUE） | `cost_method` 默认 `WEIGHTED_AVG` |
| `holding_group` | 组合下 1..N 分组 | `name`、`type`（ACCOUNT/TAG） |
| `position` | (portfolio, group, stock_code) UNIQUE | 数量/成本/累计金额六态列（见 §2.2）+ `version`（V9） |
| `trade` | 持仓下不可变事件 | `type`（BUY/SELL）、`trade_date`、`price`、`quantity`、`fee` |
| `dividend` | 持仓下不可变事件 | `type`（CASH/STOCK）、`ex_date`、`cash_per_share` 或 `stock_ratio` |
| `cash_transaction` | 分组下现金流水 | `type`（DEPOSIT/WITHDRAW）、`amount`、`tx_date`、`note` |

V9 为 5 张聚合表（portfolio/holding_group/position/allocation_plan/journal_entry）加 `version` 列，JPA `@Version` 乐观锁——「读-改-整行 merge 写」版本不符 → 409 Conflict（`GlobalExceptionHandler.optimisticLock`）。

### 2.2 成本盈亏引擎（domain/portfolio/Position，聚合根）

`Position` 不可变，`apply*` 返回新实例；金额/数量统一 4 位小数 HALF_UP（`SCALE=4`），摊薄成本价 2 位。六个持久化状态列：

| 状态列 | 语义 |
|---|---|
| `quantity` | 持仓数量 |
| `costBasis` | 剩余持仓成本总额（摊薄口径） |
| `totalBuyCost` | 历史买入总成本（含费，只增不减）——总览「总成本」用它 |
| `cumulativeCashDividend` | 累计现金分红 |
| `realizedPnl` | 累计已实现盈亏 |
| `netCashFlow` | 持仓净现金流（买入 −、卖出 +、现金分红 +） |

四条事件规则：

| 事件 | 规则 |
|---|---|
| **买入** `applyBuy(price, qty, fee)` | `cost = price×qty + fee`；quantity、costBasis、totalBuyCost 各 +cost；netCashFlow −cost（手续费计入成本） |
| **卖出** `applySell(price, qty, fee)` | `proceeds = price×qty − fee`；costBasis 按剩余数量**同比例**扣减（摊薄成本价不变）；`realized += proceeds − 移除成本`；netCashFlow +proceeds；卖出数量超过持仓 → `SELL_EXCEEDS_QUANTITY` |
| **现金分红** `applyCashDividend(totalAmount)` | costBasis −= 分红总额（**分红降成本**）；cumulativeCashDividend +；netCashFlow +（金额 = 每股分红 × 当时数量） |
| **送股** `applyStockDividend(ratio)` | quantity ×= (1+ratio)，costBasis 不变（每股成本被稀释）；无现金流 |

派生值：`avgCost() = costBasis / quantity`（数量为 0 时 null）。

### 2.3 重放（PortfolioApplicationService.replay）

`editTrade` / 补录两类分红统一走 replay：按 `tradeDate`/`exDate` 升序归并重放全部交易与分红，**同日先交易后分红**（分红按当时股数/成本作用）；重建六态列但保留原 id/createdAt/version。效果：改历史交易或补录历史除息分红后账本仍自洽。

### 2.4 现金与聚合口径

- **账户现金** = Σ(账户分组内各持仓 `netCashFlow`) + Σ(DEPOSIT − WITHDRAW)。只有 ACCOUNT 分组参与（TAG 不计现金）。
- **总览**（`overview`）：`totalAssets = Σ(现价×数量) + 账户现金`；`totalCost = Σ totalBuyCost`；`totalPnl = Σ(市值 − costBasis + realizedPnl)`；`todayPnl = Σ(现价 − 昨收)×数量`；另含 `totalCashDividend`、持仓数（仅未清仓）、分组数。
- **资产配置**（`allocation`）：股票市值（Σ 现价×数量）vs 现金两片的市值与百分比。
- **行业分布**（`industryDistribution`）：经 `shenwan_industry_mapping` 映射行业，按市值聚合降序；**无映射或无行情的持仓不进分布**。
- **集中度**（`concentration`）：有市值的持仓降序 Top5 + `top5Ratio`。

取价经 `marketDataService.quoteBatch`（NFR：批量、禁止逐只串行），未实现方返回 null 时逐只兜底；单只行情失败 `quoteQuietly` 吞掉并 `log.warn`——**该持仓市值/盈亏不计入聚合，总资产可能被低估**。读侧统一过滤已清仓持仓（`openPositions`，quantity=0 不展示），写路径仍可按 id/code 寻址已清仓行以便重新买入。

### 2.5 编辑与删除保护

- `editTrade` 仅可编辑**属于该持仓的买入交易**（卖出/他人交易一律 NOT_FOUND，不泄露存在性）；可顺带移动分组（FR-A2）——目标分组须同组合且无同代码持仓，否则 `INVALID_INPUT`。
- `deleteGroup` 两道闸：分组内有持仓 → `GROUP_NOT_EMPTY`；有现金流水 → `GROUP_HAS_CASH_FLOW`（防 ON DELETE CASCADE 静默删光账户现金账本）。现金流水本身只能新增，无编辑/删除端点。

## 4. 端点（统一前缀 `/api/portfolio`，需登录）

`PortfolioController` 共 20 处 `@*Mapping` 注解 = 类级 `@RequestMapping` 1 处 + 方法级端点 **19 个**：

| # | 端点 | 说明 |
|---|---|---|
| 1 | `GET /overview` | 组合总览（§2.4 八字段） |

| 6 | `DELETE /groups/{groupId}` | 删分组（两道闸，见 §2.5）→ 204 |
| 7 | `POST /positions/buy` | 买入（`{groupId, stockCode, stockName, tradeDate, price, quantity, fee}`）；同组同代码无持仓则新建 → 201 |
| 8 | `POST /positions/sell` | 卖出（`{positionId, ...}`）→ 201 |
| 9 | `POST /positions/cash-dividend` | 现金分红（`{positionId, exDate, cashPerShare}`，按当时数量重放）→ 201 |
| 10 | `POST /positions/stock-dividend` | 送股（`{positionId, exDate, stockRatio}`）→ 201 |
| 11 | `DELETE /positions/{positionId}` | 删持仓（级联删其交易/分红行）→ 204 |
| 12 | `GET /positions/{positionId}/trades` | 该持仓全部交易 |
| 13 | `PUT /positions/{positionId}/trades/{tradeId}` | 编辑买入交易（可改分组）+ replay |
| 14 | `GET /positions/{positionId}/dividends` | 该持仓全部分红 |
| 15 | `POST /cash-transactions` | 现金存取（`{groupId, type, amount, txDate, note?}`）→ 201 |

| 17 | `GET /allocation` | 资产配置两片（股票/现金） |

## 6. 已知限制

- **成本方法不可选**：`CostMethod` 仅 `WEIGHTED_AVG` 一值，无移动平均/后进先出等口径切换（列保留扩展位）。
- **行情缺失低估总资产**：单只行情失败只 `log.warn` 跳过，聚合视图不含该持仓市值（`totalPnl` 仍计 realizedPnl）；无「行情不可用」显式标记。
- **行业分布有盲区**：未入申万映射或无行情的持仓不进分布，占比分母只含已映射且有价的市值。
- **现金流水不可改**：只能新增（无编辑/删除端点），记错只能反向冲正一笔。
- **TAG 分组不持现金**：现金只挂 ACCOUNT 分组，TAG 仅作持仓标签；`POST /cash-transactions` 未在用例层拒绝 TAG 分组（依赖前端约束）。
- **集中度固定 Top5**：条数与口径（市值降序、仅未清仓）不可配。
- **编辑交易仅限买入**：卖出交易不可改（防已实现盈亏口径漂移），只能删持仓重记。
