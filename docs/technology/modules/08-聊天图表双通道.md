# 08 · 聊天图表双通道

> 聊天流图表：单一 ChartSpec 双端契约 + ToolEmitter 双通道（SSE 全量进前端渲染、摘要进 LLM），前端 ECharts 按需渲染与体积门禁。
> 设计规格见 [chat-rich-content 设计规格](../../../features/chat-rich-content/02-design/设计规格说明.md)，字段级技术依据见 [../research/05-富文本场景技术方案.md](../research/05-富文本场景技术方案.md)；工具清单见 [01-Agent实现.md](01-Agent实现.md)。
> 对应代码：`backend/src/main/java/com/portfolio/invest/agent/chart/ChartSpec.java`、`backend/src/main/java/com/portfolio/invest/agent/chart/ChartSpecs.java`、`backend/src/main/java/com/portfolio/invest/agent/InvestTools.java`（4 个双通道工具）、`backend/src/main/java/com/portfolio/invest/agent/AguiEventNonNullCodec.java` + `AguiWireJsonConfig.java`；前端 `frontend/lib/chart-spec.ts`、`frontend/lib/echarts-setup.ts`、`frontend/components/charts/`（EChart/useECharts/optionBuilders）、`frontend/components/chat/charts/`（ChartCard/DataTable）、`frontend/components/chat/toolRenderers.tsx`、`frontend/scripts/assert-chart-bundle.mjs`；双端契约 fixtures `features/chat-rich-content/fixtures/`。

## 1. 概述

工具全量数据（K线 120 根、财务多期指标）直接作为工具返回值会同时伤害两端：LLM 上下文被 JSON 灌满（token 浪费、摘要失焦），前端也拿不到可渲染的结构。双通道方案：

- **一份 ChartSpec 契约**（Java sealed interface ↔ 前端 zod 判别联合，双端共享 fixtures 钉住）；
- **两路分发**：`ToolEmitter.emit` 全量 spec 只进 SSE（前端渲染图表），返回值只写摘要文本（进 LLM 与 stateStore）。

## 2. 契约（ChartSpec）

`specVersion: 1` + `type` 判别联合，**契约定义 5 变体，工具实际产出 4 类**（candlestick/line/bar/table——无饼图；`pie` 变体与 `buildPieOption` 由估值/持仓等页面图表复用同一套基建）：

| 变体 | 关键字段 | 产出工具 |
|---|---|---|
| `candlestick` | `symbol`、`period`、`dates`、`klines`（**4 元组 [开,收,低,高]**，ECharts 官方约定）、`volumes`、`mas`（后端算好 MA，预热期 null） | `get_kline` |
| `line` | `categories`、`series[]`（data 允许 null 元素=数据缺口）、`unit` | `get_valuation` |
| `bar` | `categories`、`series[]`、`horizontal`、`unit` | `get_market_overview` |
| `table` | `columns[]`（key/label/align/sortable）、`rows[]`（record 值 string/number/null）、`defaultPageSize` | `get_financials` |
| `pie` | `data[]`（name/value） | —（页面图表用） |

线格式要点：每个 record 标 `@JsonInclude(NON_NULL)`——**null 字段省略**（前端 zod `.optional()` 不接受 null；Jackson 只省 null 不省空数组，必填数组空集照常发送）。日期/数值在 `ChartSpecs` 工厂层预转（ISO 字符串、元→亿元两位小数、null 保 null 不落 0）。

## 3. 双通道机制（后端）

### 3.1 ToolEmitter 语义

工具方法声明 `ToolEmitter emitter` 参数（无 `@ToolParam`，框架自动注入）：

- **emit 的块只进 SSE 事件流，永不进 LLM**；emit 过的工具其返回值增量被 skipSet 跳过——所以「全量走 emit、摘要走 return」互不重复。
- **只 emit 一次**（多次会拼接成一次调用的多张卡）；返回 `ToolResultBlock` 而非 String（String 会被 Jackson 二次包装）。

### 3.2 四工具映射（InvestTools + ChartSpecs 工厂）

| 工具 | 图（emit 全量） | 摘要（return 进 LLM） |
|---|---|---|
| `get_kline` | candlestick：K线+成交量+MA5/MA20 | 最新价与区间高低、根数 |
| `get_valuation` | line：全A PE/PB 中位数双系列历史（数据来自 `history()`） | overview 标量：分位、ERP、温度计、指数估值 |
| `get_market_overview` | bar：仅涨跌幅（点位不进图） | 三大指数点位与涨跌幅 |
| `get_financials` | table：7 列财务指标（元→亿元） | PE/PB + 最新报告期核心值 |

`search_stock`/`get_quote`/`get_news` 维持 JSON 文本返回不动（候选代码是后续工具调用的依据，不可摘要化）。

### 3.3 守卫与失败路径

- **空数据不 emit**：空 K线/空指标/估值冷库期返回安全摘要文本（`klineEmptySummary` 等），SSE 不发空 spec。
- **失败不 emit**：`runBlock` 捕获异常返回 `{"error":...,"hint":...}` JSON 文本，由前端嗅探降级（§4.3）。

### 3.4 线格式（AguiWirejsonConfig / AguiEventNonNullCodec）

启动期把全局 `JsonCodec` 换为 `AguiEventNonNullCodec`：`AguiEvent` 序列化走 NON_NULL 副本（null 字段省略），其余全部委托默认实现（LLM 请求体/stateStore/工具参数字节不变）。起因是 HITL 中断 `expiresAt: null` 被前端 zod 拒收（#25，详见 [07-HITL人工审批.md](07-HITL人工审批.md)）；对 ChartSpec 是双保险（record 已自带 NON_NULL）。

## 4. 前端渲染链

```
SSE TOOL_CALL_RESULT → @ag-ui/client 转 role:"tool" 消息
  → ThreadArea renderToolCall（toolCall ↔ toolMessage 配对）
  → useRenderTool({ name, parameters: zod, render }) 按工具名精确注册（ChartToolRenderers）
  → ChartCard → DataTable（table） / EChart（图表）
  其余工具 → useDefaultRenderTool → ToolCallCard 兜底
```

### 4.1 ChartCard（状态机壳，三态）

| 状态 | 表现 |
|---|---|
| inProgress / executing | 骨架卡「xx 执行中…」（复用 `.tool-card` 样式） |
| complete | `JSON.parse` + `ChartSpecSchema.safeParse`：table → DataTable；其余 → `builder(spec, style)` 生成 ECOption → EChart（candlestick 高 360px，其余 240px） |
| 解析失败/错误内容 | 降级折叠卡（原始 result 截 2000 字）——聊天流不崩 |

错误嗅探 `isToolError`：错误文案（`/tool execution failed|工具执行失败/i`）或顶层 `error` 键（`^{"error"`；table 行内合法 error 键不误伤）。option 构建在单一 `useMemo` 内（不 conditional hook）。

### 4.2 图表基建（components/charts/）

- `echarts-setup.ts`：**全仓库唯一 `echarts.use()` 注册点**（pie/bar/line/candlestick + tooltip/grid/legend/dataZoom + CanvasRenderer），ESLint 禁裸 `'echarts'` 入口（树摇守卫）。
- `useECharts`：~60 行自写 hook（init/option 更新/ResizeObserver/dispose）；init 必须经 echarts-setup 值导入调用，否则空 painter 注册表整页炸（P5 e2e 实证）。
- `optionBuilders.ts`：`ChartSpec → ECOption` 纯函数（jsdom 可测，图表逻辑测试主战场）；`BuilderStyle.up/down` 涨跌色由 `chart-theme` 运行时解析 CSS 变量传入（canvas 不认 `var()`），深色 hex 为兜底。
- `EChart`：显式高度壳组件。

### 4.3 DataTable（TanStack Table v9）

`useTable` + `tableFeatures`（v9 API；非 v8 的 `useReactTable`）：列排序（`sortFn_alphanumeric`，`sortable:false` 关排）、列可见、原生 sticky 表头、可视高 360px 滚动。v9 方法挂原型，不可解构。

## 5. 体积门禁（assert-chart-bundle.mjs）

`pnpm test:bundle`（CI `.github/workflows/ci.yml` 执行）：esbuild minify bundle `scripts/chart-bundle-entry.ts` 后 gzip（level 9），**≤ 240KB**（`LIMIT_BYTES = 245_760`）——按需注册实测基线 218KB + ~10% 余量；超限即树摇回归（全量入口 379KB），提示检查 no-restricted-imports 守卫。

## 7. 已知限制

- **刷新/切线程图表卡不重放**：消息持久化只存精简文本（user/assistant），工具轨迹与 emit 内容不落库（[ADR-0008](../decisions/0008-conversation-persistence.md)）。
- **暗亮主题切换后已挂图表不自动重绘**（需触发重渲染，后续优化项）。
- **HITL 审批续跑轮不重放工具事件**（图表只配 readOnly 行情工具，不受影响，见 [07-HITL人工审批.md](07-HITL人工审批.md)）。
- **jsdom 无 canvas**：前端测试集中在 optionBuilders 纯函数与 ChartCard 状态机，真实渲染仅 e2e 覆盖。
- **`defaultPageSize` 预留未消费**（表格可视高固定 360px）。
