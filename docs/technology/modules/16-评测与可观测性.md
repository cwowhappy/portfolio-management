# 16 · 评测与可观测性

> eval 生产化（三类金融 QA 基准 + 定时回归告警 + 提示词版本化）与线上观测底座（工具调用/对话轮双层落库 + admin 看板）。MS-30 交付（2026-10-10，[features/eval-observability](../../../features/eval-observability/01-需求规格/需求规格说明.md)，M14 工程项）。
> 对应代码：`backend/src/main/java/com/portfolio/invest/application/eval/`（调度/收割/判定/登记）、`backend/src/main/java/com/portfolio/invest/application/observability/`、`backend/src/main/java/com/portfolio/invest/domain/eval/`、`backend/src/main/java/com/portfolio/invest/domain/observability/`、`backend/src/main/java/com/portfolio/invest/agent/observability/ObservabilityAgentHook.java`、`backend/src/eval/`（独立源集：runner/题库/rubric）、`backend/src/main/resources/db/migration/V5__ms30_eval_observability.sql`、`frontend/components/admin/observability/`（看板四区块）、`.github/workflows/smoke.yml`。

## 1. 概述

agent-testing 建立的 eval 设施（对话/抽取双轨 + `--compare`）是手动工具：退出码恒 0、无阈值判定、无定时、无版本锚点、零线上观测（token/时延不采集）。本模块把它升级为生产体系，四件事：

- **eval 三类基准**：行情事实 / 指标计算 / 幻觉诱导各 10 题（`src/eval/resources/questions/{market-fact,metric-calc,hallucination-induction}.yaml`），复用桩注入 + 九维结构断言（幻觉诱导扩为第十维 `hallucinationGuard`）+ LLM-judge 双层计分；`--list` 装载 64 题。
- **定时回归**：backend `@Scheduled`（每晚 02:17，`EvalScheduler`）拉起 `app-eval.jar` 子进程全量跑，收割后经 `EvalRegressionJudge` 相对回归判定，超阈值飞书告警留痕（`eval_run` 库表为准）。
- **提示词版本化（登记制）**：五类资产（系统提示词/@Tool 描述/SKILL.md/情报抽取 prompt/eval rubric）启动对账自动登记版本链（SHA-256 内容 hash），eval 运行记录全资产版本快照，回归比对锚定版本。
- **线上观测**：`RecordingAgentToolDecorator` 补 duration + `ObservabilityAgentHook` 采轮级 token/时延/trust 信号，双层落库（`tool_invocation_obs` / `turn_observation`），`/admin` 看板四区块（trace / 成本 / 时延 / 版本链+运行历史）。

核心取舍：**eval 不阻塞 PR**（真 LLM 成本，定时+手动控制）；**数据隔离走同 PG 实例独立 schema**（每轮 DROP-CASCADE 重置，部署机无 Docker 也可用）；**真相源留代码/git**，版本表只做登记对账（不做 DB 存储加载链路）。

## 2. eval 执行链

```
EvalScheduler（@Scheduled 02:17 / POST /api/admin/eval/run 手动，互斥 409）
  → ProcessBuilder：java -jar app-eval.jar --invest.eval.data-root=<dir>
    （env 白名单：DEEPSEEK_* / SPRING_DATASOURCE_* / SPRING_PROFILES_ACTIVE / TZ / EVAL_*，
     其余全剔除——三个 seeder 与飞书/邮件凭证缺席即静默，副作用禁用第一道）
  → 子进程 EvalPostgresProvisioner：DROP SCHEMA eval_schema CASCADE + CREATE（JDBC 直连）
  → Spring 上下文起（--Eval_MODE=true 门控调度/seeder，SchedulingConfig 类级
    @ConditionalOnExpression——副作用禁用第二道；currentSchema=eval_schema,public 双段）
  → Flyway 全量迁移（69 表）→ 全量题目跑（报告 schema v2：runMeta 含五类资产 hash 清单）
  → System.exit → 父进程 EvalHarvester（生产上下文）收割：eval_run 落库 + rubric 版本回流
    upsert + EvalRegressionJudge 判定 + 告警（AlertNotifier 飞书，失败降级邮件）+ baseline 候选
```

打包：`make build` 双 jar——`bootJar`（生产，零 eval 类/资源）+ `evalBootJar`（`-eval` 分类器，mainClass=EvalRunner，classpath 含 main.output 与 eval 资源）；`compileEvalJava` 挂 check 编译防漂。本地手动入口 `make eval-agent` / `make eval-extraction` 不变（JavaExec）。

### 2.1 判定算法（`EvalRegressionJudge`，纯函数）

劣化三阈值（任一命中即告警，`invest.eval.regression.*` 可配）：总通过率降幅 ≥10pp / PASS→FAIL 同题翻转 ≥3 / 三新类任一分类降幅 ≥15pp。无 baseline 输出 `NO_BASELINE` 不判劣化；题库 hash 或 rubric 版本 ≠ baseline 视为不可比（`BASELINE_INCOMPARABLE`，只判绝对完成率 <80% 告警）；上一跑劣化且本跑无命中 → `RECOVERED` + 置 baseline_candidate（生效仍需人工 PUT 确认，防抖动样本误采纳）。单题 ERROR 视同 FAIL 计入分母（防「异常多→通过率虚高」漏报）；PARTIAL 跑不任 baseline。

### 2.2 提示词版本登记（双通道）

main 侧 `PromptVersionRegistrar`（ApplicationRunner，eval 上下文缺席）启动对账：系统提示词（`InvestSystemPrompt.TEXT`）、@Tool 描述 ×16（Toolkit 枚举）、SKILL.md ×6、情报 prompt ×4（含 `LEAD_SYSTEM_PROMPT` public 常量）逐资产 SHA-256；同 hash 命中即无变化，否则 insert 新版本行（version+1，note=NULL 显示「未注记」）。eval-only 资产（rubric/题库）经报告 `runMeta` 回流由收割器 upsert（绕开生产 jar 无 rubric 资源的 classpath 边界）。

## 3. 观测采集

- **工具调用级**：`agent/trust/RecordingAgentToolDecorator.callAsync` 补 `durationMs`（`System.nanoTime` 包 delegate），回合结束随轮批量写，不逐条 INSERT。
- **对话轮级**：`ObservabilityAgentHook`（`HarnessAgentFactory` 双 hook 链第二位，priority 200 后行于 trust）——`PreCallEvent` 记起点、`PostCallEvent` 计轮时延并组装落库；`PostReasoningEvent`/`PostSummaryEvent` 逐轮累加 `ChatUsage` 三值 token；`ErrorEvent` 计 failed + 摘要；`TrustContext` 快照六键并入 `trust_stats`。
- **落库**：端口 `domain/observability/ObservabilityRecorder` → `infrastructure/persistence/observability/ObservabilityRepositoryImpl`（JdbcTemplate 风格 A，不建 JPA 门面）；**降级契约**——观测异常仅 ERROR 日志，绝不阻断对话（沿 trust hook 哲学）。
- **清理**：`IntelligenceCleanupService` 三步扩四步，两观测表按 `invest.eval.observability.retention-days`（默认 90 天）滚动 DELETE。
- 观测表 user_id 弱引用无 FK（用户删除随保留期自然过期，规避 e2e-cleanup 登记义务）。

## 4. 配置（`invest.eval.*`）

| 键 | 默认 | 说明 |
|---|---|---|
| `invest.eval.enabled` | true（`INVEST_EVAL_ENABLED`） | 定时总开关；缺 `DEEPSEEK_API_KEY` 调度静默跳过留痕 |
| `invest.eval.jar-path` | 空（`INVEST_EVAL_JAR_PATH`） | 空 = 生产 jar 同目录唯一 `*-eval.jar` 派生 |
| `invest.eval.data-root` | 空（`INVEST_EVAL_DATA_ROOT`） | 空 = `build/eval-agent`（本地）；部署机传绝对路径 |
| `invest.eval.datasource.url` | 空（`EVAL_DATASOURCE_URL`） | 空 = 回退主 datasource 同实例；schema 由 provisioner 拼 |
| `invest.eval.timeout-minutes` / `token-budget` | 120 / 5000000 | 整跑护栏（超时 destroyForcibly → 收割按 PARTIAL）；token-budget 配置已预留、执行端接线归后续批次（当前由超时护栏兜底成本） |
| `invest.eval.regression.*` | 10pp / 3 / 15pp | 相对回归三阈值 |
| `invest.eval.calc-tolerance-pct` | 2 | 计算类断言相对容差 |

**注意**：`invest.eval.observability.unit-price-cny-per-mtok` 键**无后端消费方（死配置）**——看板单价走前端环境变量 `NEXT_PUBLIC_UNIT_PRICE_CNY_PER_MTOK`（构建期注入，≤0 不显示估算行）。

## 5. 端点（`/api/admin/**` 路径级 ADMIN）

| 端点 | 说明 |
|---|---|
| `POST /api/admin/eval/run` | 手动触发：202 `{runId}` 非阻塞；进行中 409 `EVAL_RUN_IN_PROGRESS` |
| `GET /api/admin/eval/runs?limit=20` | 运行历史倒序（得分/判定/baseline/completeness；RUNNING 行供轮询） |
| `PUT /api/admin/eval/runs/{id}/baseline` | body `{baseline:bool}`；置 true 仅限 COMPLETED 非劣化跑（422 拒绝） |
| `PUT /api/admin/prompt-assets/{id}/note` | 版本变更说明补注（`{id}` 为版本行主键） |
| `GET /api/admin/observability/trace?from&to&tool&failed&page&size` | 工具调用明细分页（倒序） |
| `GET /api/admin/observability/cost?days=7` | 按日 token 消耗 + 按工具调用统计 |
| `GET /api/admin/observability/latency?days=7` | 轮整体/按日 + 按工具 p50/p95（`percentile_cont` SQL 直出） |
| `GET /api/admin/prompt-assets` | 提示词版本链（分组、组内倒序、最新 `current=true`） |

前端：`ObservabilitySection`（`AdminBoard` 挂载）四区块——TraceTable / CostCharts+LatencyCharts（EChart）/ PromptAssetPanel（未注记徽标 + 行内补注）/ EvalRunsPanel（触发按钮 + baseline 星标 + RUNNING 5s 轮询，requestSeqRef 竞态守卫）。反代走 `app/api/admin/[...path]/route.ts` 既有通配，零新增 route。

## 6. CI 冒烟（`.github/workflows/smoke.yml`）

`make smoke` 挂 `schedule`（cron `37 1 * * *` = 北京 09:37 盘中窗口）+ `workflow_dispatch`；仅默认分支生效；不挂 PR（真行情+真 LLM 成本）。腾讯 fixture 漂移探测随 schedule 兑现（code-review-2026-10 P3「评测/提示词域」唯一项，已清零）。

## 8. 已知限制与首跑观察项

- 题库锚表述分布需首跑校准：行情事实类千分位/时点表述、指标计算类 #9 分母口径、幻觉诱导类算术衍生值（「相差 41.65 点」类量化纠正可能被误判 FAIL）——首跑误报率数据回来后扩 allowedValues 或明示接受。
- 停机时 RUNNING 行残留：后端停机若恰逢 eval 子进程执行中，收割缺席留 RUNNING 行，需人工 `UPDATE eval_run SET status='FAILED' WHERE status='RUNNING'` 清扫（部署文档人工项）。
- jar-path 空派生（生产 jar 同目录唯一 `*-eval.jar`）部署机首跑需核对日志派生路径。
- CI smoke runner 到东财/腾讯的可达性依赖 GitHub 托管网络，首跑观察。
- eval 子上下文 `triggered_by` 恒 MANUAL（子进程不可知触发来源），真值由调度/收割侧落库。
