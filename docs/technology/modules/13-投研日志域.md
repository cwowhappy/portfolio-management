# 13 · 投研日志域

> 投资决策记录：四类条目（买入/卖出备忘、研究笔记、定期复盘）单表统一建模，`tradeId` 软引用反查持仓交易联动，时间线聚合日志 + 交易 + 分红三类事件。
> 持仓侧事件与归属校验依赖 [11-持仓域.md](11-持仓域.md)（`PortfolioRepository`）；功能视角见 [../../function/modules/11-投资决策记录.md](../../function/modules/11-投资决策记录.md)。
> 对应代码：`backend/src/main/java/com/portfolio/invest/domain/journal/`（`JournalEntry`、`JournalEntryType`、`PeriodType`、`JournalEntryRepository`）、`application/journal/`（`JournalApplicationService`、`TimelineEventType/View` + 命令/视图 record）、`web/JournalController.java`、`infrastructure/persistence/JournalEntryRepositoryImpl.java`；迁移 `db/migration/V8__journal.sql`、`V9__optimistic_locking.sql`；前端 `frontend/app/journal/page.tsx`。

## 1. 概述

决策留痕域。核心设计：

- **四类条目一个聚合**：`JournalEntryType` = `BUY_MEMO`（买入备忘）/`SELL_MEMO`（卖出备忘）/`RESEARCH_NOTE`（研究笔记）/`REVIEW`（定期复盘），单表存储、类型特有字段可空，类型间差异用域校验表达（见 §2.2）而非分表。
- **持仓联动**：备忘可带 `tradeId` 关联具体交易——服务端反查该交易归属当前用户（组合→交易→持仓三跳校验），股票代码/名称**以持仓为准**回填，客户端传入不一致即 400。
- **时间线**：`GET /timeline` 把日志条目与持仓域的交易、分红合流为统一事件流，按日期倒序。
- 全部端点需登录（不在 `PublicEndpointPaths` 公开清单），条目按 userId 归属隔离。

## 2. 架构与数据流

### 2.1 数据模型（V8 + V9）

单表 `journal_entry`：通用列（`user_id`、`type`、`title` NOT NULL、`content` NOT NULL、`event_date` NOT NULL）+ 类型特有可空列（`stock_code`/`stock_name`/`trade_id`、`target_price`/`stop_loss`、`period_type`/`period_start`/`period_end`）+ `version`（V9 乐观锁）。索引 `idx_journal_entry_user (user_id, event_date DESC)` 支撑时间线日期范围查询下推。

**`trade_id` 是软引用**：无外键、不级联（V8 头注释明示）——持仓删除交易后日志悬空保留，反查失效但不炸。

### 2.2 类型校验规则（JournalEntry.validate，create/update 共用）

公共：`title`/`content` 非空白、`event_date` 非空。

| 类型 | 特有规则 |
|---|---|
| `BUY_MEMO` / `SELL_MEMO` | `stockCode` 必填；`targetPrice`/`stopLoss` 可空但若填必须 > 0 |
| `REVIEW` | **不绑定个股与交易**（`stockCode` 非空或 `tradeId` 非 null 即 400）；`periodType`（`QUARTERLY`/`ANNUAL`）+ `periodStart` + `periodEnd` 必填且 start ≤ end |
| `RESEARCH_NOTE` | `stockCode` 可选，无特有必填 |

`update` 不允许改 `type`（类型不可变），其余可变字段重走同一校验。

### 2.3 tradeId 反查联动（JournalApplicationService.resolveTrade）

`tradeId == null` → 直接用客户端股票信息；否则三跳校验（任一失败 `TRADE_NOT_FOUND` → 404）：

```
findPortfolioByUserId(userId)      → 无组合 = 交易不存在
findTradeById(tradeId)             → 无交易 = 交易不存在
findPositionByIdAndPortfolioId(...) → 交易不属于该用户持仓 = 交易不存在
```

通过后以持仓的 `stockCode`/`stockName` 回填条目（服务端口径，防张冠李戴）；客户端 `stockCode` 与持仓不一致 → `INVALID_INPUT`（400）。校验防泄露：他人交易一律报「不存在」而非「无权限」。

### 2.4 时间线（timeline）

`from`/`to` 两端可空。事件来源三路合流，按日期倒序：

| 来源 | refType | 事件构造 |
|---|---|---|
| 日志条目（日期过滤**下推 SQL**，走 `(user_id, event_date)` 索引） | `JOURNAL` | type 映射四类事件之一；标题=条目标题，描述=content 截断 80 字符；`refId`=条目 id |
| 持仓交易（内存过滤 tradeDate） | `TRADE` | BUY/SELL 事件；描述「买入/卖出 X 股」；`refId`=交易 id |
| 持仓分红（内存过滤 exDate） | `DIVIDEND` | 描述「现金分红 X 元/股」或「送股 X 股/股」；`refId`=分红 id |

`TimelineEventType` 共 7 值：`BUY`/`SELL`/`DIVIDEND` + 日志四类。

## 3. 关键类与配置

| 类 | 职责 |
|---|---|
| `web/JournalController` | 6 个端点（见 §4） |
| `application/journal/JournalApplicationService` | CRUD + 时间线 + tradeId 反查（import 持仓域仓库，跨域只读） |
| `domain/journal/JournalEntry` | 聚合根：类型校验规则（§2.2）、不可变 update |
| `domain/journal/JournalEntryRepository` | 仓库端口（含日期范围下推查询 `findByUserIdInDateRange`） |
| `application/journal/TimelineEventView` / `TimelineEventType` | 时间线统一事件契约（type/date/title/description/stockCode/stockName/refId/refType） |
| 命令 | `CreateJournalEntryCommand`（type 必填）、`UpdateJournalEntryCommand`（无 type——类型不可变）；均含全部可变字段 |

配置：无本域专属配置键。

## 4. 端点（统一前缀 `/api/journal`，全部需登录）

| 端点 | 说明 |
|---|---|
| `GET /api/journal/entries?type=` | 条目列表（`type` 可选过滤四类之一） |
| `POST /api/journal/entries` | 建条目（含 tradeId 反查校验）→ 201 |
| `GET /api/journal/entries/{entryId}` | 条目详情 |
| `PUT /api/journal/entries/{entryId}` | 更新可变字段（type 不可改） |
| `DELETE /api/journal/entries/{entryId}` | 删除条目 → 204 |
| `GET /api/journal/timeline?from=&to=` | 三路合流时间线（日期倒序） |

错误码（`GlobalExceptionHandler`）：`NOT_FOUND`/`TRADE_NOT_FOUND` → 404；`INVALID_INPUT` → 400。

## 6. 已知限制

- **tradeId 悬空无治理**：交易/持仓删除后条目仍引用旧 id，无悬挂检测或清理；时间线不受影响（交易事件自然消失），但条目详情仍展示失效 tradeId。
- **时间线无分页**：全量返回（仅日期范围可收窄）；交易/分红在内存过滤，量级随持仓数 × 事件数增长。
- **时间线描述截断 80 字符**：前端展开需再查条目详情。
- **无附件/富文本**：`content` 纯文本（TEXT 列），无 Markdown 渲染约定或图片。
- **复盘不绑个股是硬校验**：跨个股的组合级复盘需拆多条或写在 content 里，无法用 stockCode 标注参考标的。
