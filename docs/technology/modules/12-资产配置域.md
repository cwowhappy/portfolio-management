# 12 · 资产配置域

> 资产配置方案管理：4 个内置经典模板一键套用、自定义方案 CRUD、单方案激活（DB 部分唯一索引兜底）、对照持仓实际算偏离度、风险测评问卷（V12：8 题三类维度评总分定五档，按档位推荐权重建 ASSESSMENT 方案）。
> 实际持仓口径来自 [11-持仓域.md](11-持仓域.md) 的 `allocation` 聚合视图；功能视角见 [../../function/modules/07-资产组合配置.md](../../function/modules/07-资产组合配置.md)。
> 对应代码：`backend/src/main/java/com/portfolio/invest/domain/allocation/`（`AllocationPlan`、`AllocationTemplate`、`AssetClass`、`PlanSource`、`AllocationPlanRepository`、风险测评 `RiskProfile`/`RiskQuestion`/`RiskOption`/`RiskAssessment`/`RiskAssessmentRepository`）、`application/allocation/`（`AllocationApplicationService` + 命令/视图 record）、`web/AllocationController.java`、`infrastructure/persistence/AllocationPlanRepositoryImpl.java`、`RiskAssessmentRepositoryImpl.java`；迁移 `db/migration/V6__allocation.sql`、`V9__optimistic_locking.sql`、`V12__risk_assessment.sql`；前端 `frontend/app/allocation/page.tsx`。

## 1. 概述

小而完整的配置域：目标端是「方案 + 权重」（权重百分比、非负、和=100 容差 ±0.01），实际端复用持仓域的两片资产视图，两端相减得偏离度。设计要点：

- **模板是代码不是数据**：4 个经典模板是 `AllocationTemplate` 枚举（无 DB 表、无管理端点），`GET /templates` 直接枚举映射；方案来源 `PlanSource.TEMPLATE/CUSTOM/ASSESSMENT` 仅作标记，套用模板=前端拿模板权重调 `POST /plans`，测评建档=拿定档推荐权重走同一 `POST /plans`（标 `ASSESSMENT`）。
- **单激活**：每用户至多一个 `active=true` 方案，靠部分唯一索引 `ux_allocation_plan_user_active ON allocation_plan(user_id) WHERE active` 在 DB 层兜底。
- 全部端点需登录（不在 `PublicEndpointPaths` 公开清单），方案按 userId 归属隔离。

## 2. 架构与数据流

### 2.1 数据模型（V6 + V9 + V12）

| 表 | 粒度 | 关键列/约束 |
|---|---|---|
| `allocation_plan` | 用户 × 方案 | `name`、`source`（TEMPLATE/CUSTOM/ASSESSMENT）、`active`（默认 false）、`version`（V9）；部分唯一索引保证单激活 |
| `allocation_plan_weight` | 方案 × 资产类 | `asset_class` + `weight NUMERIC(18,4)`，`UNIQUE(plan_id, asset_class)`，级联删除 |
| `risk_assessment`（V12） | 用户 × 最新一条 | `user_id` UNIQUE（每用户仅存最新一条，重测由仓储 upsert 覆盖）、`total_score`、`profile`（五档枚举名）、`answers` JSONB（题目枚举名 → 选项 id）、`assessed_at` |

### 2.2 内置模板（AllocationTemplate 枚举，4 个）

| 模板 | 展示名 | 权重 |
|---|---|---|
| `BALANCED_60_40` | 60/40 股债平衡 | 股票 60 / 债券 40 |
| `PERMANENT_PORTFOLIO` | 永久组合 | 股票 25 / 债券 25 / 黄金 25 / 现金 25 |
| `ALL_WEATHER` | 全天候 | 股票 30 / 债券 55 / 黄金 15 |
| `BUFFETT_90_10` | 巴菲特 90/10 | 股票 90 / 现金 10 |

资产大类 `AssetClass` 共 5 类：股票/债券/黄金/现金/REITs——模板只用到前 4 类，REITs 为预留（偏离度输出仍会带上它，实际恒 0）。

### 2.3 不变式与激活（AllocationPlan 聚合）

- **权重校验** `validateWeights`：非空、各项非负、和 = 100 ± 0.01（容差来自 DB NUMERIC(18,4) 四舍五入，如 33.3333×3）；违反 → `INVALID_WEIGHTS`（400）。create/update 均过此校验；重复资产类在用例层 `toWeights` 先拦（`INVALID_INPUT`）。
- **激活** `activatePlan`：先 `deactivateAllByUserId` 再保存 `activate()` 新实例。两步非原子，并发激活时唯一索引兜底——违例冒泡 `DataIntegrityViolationException` → 400（`GlobalExceptionHandler.dataIntegrity`）。
- 不可变聚合：`rename`/`updateWeights`/`activate`/`deactivate` 均返回新实例，JPA 整行 merge + `@Version` 乐观锁。

### 2.4 偏离度（deviation）

无激活方案返回空列表；否则取激活方案的目标权重，对照 `PortfolioApplicationService.allocation(userId)` 的实际两片——股票（EQUITY→STOCK）与现金（CASH→CASH）——按 5 类资产逐类输出 `DeviationSlice(assetClass, targetWeight, actualWeight, deviation = actual − target)`；债券/黄金/REITs 无持仓数据源，实际恒 0、偏离 = −目标。

| 类 | 职责 |
|---|---|

| `domain/allocation/RiskQuestion` + `RiskOption` | 内置题库（枚举即数据，无 DB 表）：8 题三类维度（Q1–Q4 承受能力·客观 / Q5–Q7 容忍意愿·主观 / Q8 经验），选项 A–E 计 1–5 分 |
| `domain/allocation/RiskAssessment` | 测评结果：`grade()` 纯函数校验答卷完整合法后计分定档（不完整/越界 → `INVALID_ANSWERS`） |
| `domain/allocation/RiskAssessmentRepository` | 仓库端口：`save` 为 upsert 语义（同用户覆盖、仅存最新一条）；实现 `infrastructure/persistence/RiskAssessmentRepositoryImpl` |
| 命令/视图 | `Create/UpdatePlanCommand` + `WeightInput`（`@DecimalMin(0)` + 4 位小数校验）；`Plan/Template/Weight/Deviation` 视图；测评 `SubmitAssessmentCommand` + `AnswerInput`、`Questionnaire/Question/Option/Assessment` 视图（选项视图不含分值） |

配置：无本域专属配置键。

## 4. 端点（统一前缀 `/api/allocation`，全部需登录）

| 端点 | 说明 |
|---|---|
| `GET /api/allocation/templates` | 4 内置模板（id=枚举名、展示名、权重列表） |
| `GET /api/allocation/plans` | 我的方案列表（含权重与 active 标记） |
| `POST /api/allocation/plans` | 建方案（`{name, source, weights[]}`）→ 201 |
| `PUT /api/allocation/plans/{planId}` | 改名 + 改权重 |
| `POST /api/allocation/plans/{planId}/activate` | 激活（其余自动失活） |
| `DELETE /api/allocation/plans/{planId}` | 删方案（权重级联删）→ 204 |
| `GET /api/allocation/deviation` | 激活方案 × 持仓实际的逐类偏离 |
| `GET /api/allocation/assessment/questionnaire` | 内置题库下发（8 题三类维度；选项视图不含分值，评分口径不外泄） |
| `GET /api/allocation/assessment` | 最新测评结果（总分/档位/推荐权重/答卷；无记录 → 204） |
| `POST /api/allocation/assessment` | 提交答卷（`{answers[]}`）：评分定档后 upsert 覆盖旧结果（题目重复作答 → 400） |

错误码：`NOT_FOUND` → 404；`INVALID_WEIGHTS`/`INVALID_INPUT`/`INVALID_ANSWERS` → 400；并发激活 DB 兜底 → 400（`INVALID_DATA`）。

## 6. 已知限制

- **偏离度实际端只有股票/现金两片**：债券/黄金/REITs 无持仓记账数据源，实际恒 0——含这三类的模板（永久组合/全天候）偏离度仅供参考。
- **模板无法扩展**：新模板需改代码发版（枚举内置、无 DB 目录）；用户自定义方案可覆盖大多数场景。
- **激活非原子**：`deactivateAll + activate` 两步写，并发窗口靠 DB 唯一索引兜底（表现为 400 而非自动重试）。
- **无再平衡建议**：只有偏离度读数，无目标买卖金额计算。
