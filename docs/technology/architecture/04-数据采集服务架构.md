- 相关：[05-数据类型与来源.md](05-数据类型与来源.md)（数据类型、来源接口与降级链明细）· [conventions/04-采集服务架构与代码规范.md](../conventions/04-采集服务架构与代码规范.md)（约束性条款逐条版）· [ADR-0003 行情数据源](../decisions/0003-market-data-source.md)（Java 侧实时行情链路）

## 一、背景与定位

「市场估值」「个股基本面」等特性需要每日收盘后批量产出并持久化估值/基本面数据。区别于 Java 后端的实时行情（ADR-0003：东财主源 + 新浪/腾讯兜底 + 令牌桶限流 + TTL 缓存），采集侧是一次性的、批量的、日频的数据工程任务。因此独立为 **Python 服务 `collector/`**（Python 3.12：akshare + tushare 接源、pandas 计算、psycopg 落库、APScheduler 调度）。

三条不变原则：

- **采集（写）与查询（读）分离**：collector 只写数据，读侧（`/api/valuation/**` 查询、AI 工具 `get_valuation`）由 Java 后端完成，二者共享 PostgreSQL。
- **业务 schema 单一源头**：业务表由 Java Flyway（V3/V4/V7）定义，collector 只 INSERT/UPDATE、逐字对齐列名（跨服务契约）；collector 的 alembic 只迁移自有运维表。
- **声明式扩展**：新增任务优先加一份 YAML（新源/新目标表才需要写代码），executor/runner/scheduler 不出现任务特例分支。

## 二、总体架构（框架分层）

```
collector/（Python 3.12，独立服务）
  config.py            配置入口：env DATABASE_URL / TUSHARE_TOKEN → frozen Config
  cli.py               CLI：run（手动触发，--force/--date）· list · backfill · seed · history
  backfill.py          区间回填：仅放行 supports_range=True 的源，拒绝静默降级
  model/               task.py（Collector 任务对象）· run.py（RunResult/状态）· health.py（SourceHealth）
  sources/             源层：base（Source 契约 + SourceError）· registry（YAML spec → 源实例）·
                      configurable（声明式 akshare/tushare 直调）· plugins（8 个领域源）·
                      ratelimit（RateLimiter 最小间隔限速器）
  converters/          字段映射：field_mapping_* 把各家原始列名统一为标准记录列
  validators/          规则校验：min_rows/required/not_null/type/range/unique/allowed_values，
                      hard 违规抛 SourceError（换源），soft 记 issues（run 状态 PARTIAL）
  calc/                纯计算：snapshot（全A PE/PB 中位数、破净）· industry_weighted（行业市值加权）
  store/writer.py      幂等落库：8 张目标表 UPSERT_SQL（ON CONFLICT DO UPDATE，零业务 DDL）
  executor/            executor.py（单次执行：选源→取数→转换→校验→计算→落库）·
                      selector.py（SourceSelector：健康分排序 + 熔断）
  scheduler/           jobs.py（装配与调度入口）· runner.py（TaskRunner：门控/锁/重试）·
                      calendar.py（TradingCalendar，按需查库）
  repositories/        纯 SQL：tasks（collector_task）· runs（collector_task_run）·
                      health（collector_source_health）
  tasks/*.yaml         8 个声明式任务定义（封闭字段契约，seed 校验必填/拒绝未知键）
  migrations/          alembic：运维表 collector_task / collector_task_run /
                      collector_source_health + trading_calendar
        │  写入（业务表零 DDL）
        ▼
PostgreSQL（业务表 = 后端 Flyway V3/V4/V7 拥有；运维表 = collector alembic 拥有）
```

分层单向依赖（import-linter 强制）：sources → converters → validators → calc → store，executor/scheduler 只做编排，repositories 只做 SQL，model 不依赖任何层。约束条款的逐条版（含理由与强制方式）见 [conventions/04](../conventions/04-采集服务架构与代码规范.md)，本文聚焦架构与运行机制。

## 三、任务体系（YAML 声明式）

任务字段是封闭契约：`task_code/task_name/source_ids/converter/calc/validator/target_table/schedule/enabled/trading_day_gated/retry_max/retry_backoff`。启动时 seed 幂等同步 YAML → `collector_task`，并 reconcile：YAML 中已删除的库内残留任务自动停用（保留历史可回溯）。当前 9 个任务：

| 任务 | 目标表 | 源 | 调度 | 交易日门控 |
|---|---|---|---|---|
| `all_a_valuation` | valuation_snapshot | akshare `stock_zh_a_spot_em`（主）+ tushare `daily_basic` 备源（同构输出） | cron 工作日 15:30 | 是 |
| `index_valuation` | index_valuation_history | tushare `index_dailybasic` + 股息率近似 | cron 工作日 15:30 | 是 |
| `treasury_yield_curve` | treasury_yield_curve | akshare `bond_china_yield`（中债信息网） | cron 工作日 15:30 | 是 |
| `stock_valuation_daily` | stock_valuation_daily | tushare `daily_basic`（V13 起含 close 列，个股收盘价同源写入） | cron 工作日 15:35 | 是 |
| `stock_financial` | stock_financial | tushare `fina_indicator`（逐股，4 线程 + 限速） | cron 工作日 15:40 | 否 |
| `index_close` | index_close_history | tushare `index_daily`（三基准：沪深300/中证500/中证偏股基金指数，供收益分析读侧） | cron 工作日 15:40 | 是 |
| `industry_valuation` | industry_valuation | `industry_universe` 复合 JOIN 源 | cron 工作日 15:45 | 是 |
| `shenwan_mapping` | shenwan_industry_mapping | tushare `index_classify` + `index_member_all` | interval 7 天 | 否 |
| `index_constituent` | index_constituent | tushare `index_weight` | interval 180 天 | 否 |

时序设计：估值类任务在交易日 15:30–15:45 陆续执行；`industry_valuation` 排最后（15:45），因为它 JOIN 读已落库的申万映射（周频表）与当日个股估值/财务表（L4 受限破例「JOIN 源」）；周频 `shenwan_mapping` 从未成功过的冷启动由启动补跑兜底，不会让依赖它的日任务空等一周。数据内容与接口明细见 [05-数据类型与来源.md](05-数据类型与来源.md)。

## 四、执行机制（一次任务运行）

`TaskRunner.run`（scheduler/runner.py）按序执行：

1. **交易日门控**：`trading_day_gated=true` 的任务遇非交易日直接记 SKIPPED run（`--force` 可跳过）；交易日判断只经 `TradingCalendar`（按需查库，长期运行不依赖启动内存快照）。
2. **多副本互斥**：PG advisory lock（`hashtextextended(task_code)`），上一实例运行中则本实例记 SKIPPED；锁的获取/释放与连接同生命周期，每次尝试新建连接、用完即弃。
3. **前置 running 行**：执行前先落 `collector_task_run`（running），终态回填——任何路径不留悬挂 running 记录；意外异常兜底置 failed。
4. **Executor 主链**（executor/executor.py）：`SourceSelector` 按健康分排序候选源 → 逐源 `fetch` → 数据源库原生异常统一包 `SourceError` → `convert` → **先校验再聚合**（min_rows 等规则基于明细行数）→ `calc` → `store.upsert` 幂等落库；成功回填 source_used/rows_written，soft issues 状态记 PARTIAL。
5. **失败分轨**：`SourceError` 换下一候选源；`StoreError`（DB 写入失败）不换源，由 TaskRunner **整任务重试**——退避策略按任务配置（默认指数 30×2ⁿ 秒，`retry_max` 默认 3，总尝试 = retry_max+1）；全部源失败抛 `AllSourcesFailed` 记 failed run。
6. **熔断**（executor/selector.py）：连续失败 3 次 open、冷却 600s 后半开、半开探针仅在无健康候选时兜底；熔断计数按「任务运行」计，重试不放大。健康分 = 100×成功率 − 时延惩罚（≤30）− 连败惩罚（≤40）。

## 五、限速与并发

- **RateLimiter**（sources/ratelimit.py，进程内线程安全的最小间隔限速器）：`fina_indicator` 逐股拉取前 `wait()`，间隔 0.35s（≈171 次/分钟，上游限 200 次/分钟留安全余量）。
- **并行拉取**：`StockFinancialSource` 用 `ThreadPoolExecutor(max_workers=4)` 全 A 逐股并发（executor.map 保持输入顺序），限速器在锁外等待、网络调用可重叠。
- **重试退避**：任务级指数退避（见 §4），取代旧的固定 30s。

## 六、交易日历与调度

- **启动序列**（`python -m collector.scheduler.jobs`）：alembic upgrade head → 刷新交易日历 + 陈旧检查 → seed 任务 → 装配注册表与任务 → 计算从未成功任务（冷启动补跑，`next_run_time=now`）→ BlockingScheduler 启动。
- **日历自维护**：akshare `tool_trade_date_hist_sina` 每月 1 日 03:10 定期刷新（cron `10 3 1 * *`，upsert 幂等），最新日期落后当天超过 15 天打 warning 留痕；中国节假日不再空跑。
- **调度纪律**：每个 job 显式 `coalesce=True`、`max_instances=1`、`misfire_grace_time`（日级 3600s、日历刷新 86400s）；job 函数自兜底所有异常（异常逃出 job 会被 APScheduler 静默丢弃后续调度）。
- **时区**：镜像已装 `tzdata`（Dockerfile），`TZ=Asia/Shanghai` 生效。

## 七、数据源选型要点（明细见 05）

- **国债收益率曲线**：akshare `bond_china_yield`（中债信息网，全期限含 1Y/3Y）。`bond_zh_us_rate` 已下架 1Y/3Y 期限列，**勿回退**；单次区间上限约 1 年，按 180 天切块，日常增量以 DB `max(trading_day)` 为水位线，backfill 显式区间优先于水位线。
- **ERP 股息率**：`index_dailybasic` 不返回股息率，用 `make_index_dividend_fetch` 近似——`index_weight` 最新成分权重 × 成分股 `dv_ttm` 加权均值；积分不足/无数据回退 0.0，保证不缺列不崩。
- **全 A 估值双源**：akshare `stock_zh_a_spot_em` 主源，tushare `daily_basic` 备源输出同构中文列（目标日无数据沿交易日历前溯），converter/calc 无需区分来源。
- **备源后置**：目前除全 A 估值外其余任务单源（任务 YAML 内注明「备源后置」），靠任务级重试 + 熔断兜底；同类型多供应商兜底（对齐 ADR-0003 思路）留作扩展。

## 八、部署与运维

- **部署**：`collector/Dockerfile`（python:3.12-slim + tzdata，非 root）+ docker-compose `collector` 服务，`depends_on db/backend: service_healthy`（等 Flyway 建表）；`TUSHARE_TOKEN` 经环境变量透传（`.env` git-ignored）。
- **手工运维（Makefile）**：`make collect`（列任务与最近运行状态）、`make collect-run TASK=<task_code>`（手动触发一次，可 `--force` 跳过门控）、`make collect-backfill TASK=… START=… END=…`（区间回填）、`make collect-test`（ruff + import-linter + pytest，覆盖率 ≥80%）。
- **执行历史**：`python -m collector.cli history <task_code>` 查 run 记录（状态/源/行数/错误）；`seed --dry-run` 校验任务定义。
- **可观测性**：每次运行双通道留痕——DB（collector_task_run：status/source_used/rows_written/error）+ 结构化日志（task_code、attempt、退避秒数）。已知缺口：无指标聚合与外部告警（仅日志），接入日志/监控下游时再评估。

## 附：与 Java 后端行情链路的对比

| 维度 | Java 后端（ADR-0003） | collector（本文档） |
|---|---|---|
| 数据源降级 | 东财主源 + 新浪/腾讯兜底（同类型多供应商） | 全 A 估值双源（akshare→tushare 同构备源）；其余任务单源，靠任务级重试 + 熔断 |
| 速率控制 | 令牌桶 5 req/s + TTL 缓存 | RateLimiter 最小间隔（fina_indicator 0.35s）+ 4 线程并行 + 指数退避 |
| 缓存 | TtlCache（行情热缓存） | 无缓存；映射/成分走 7 天/180 天 interval 任务天然低频 |
| 运行时段 | 在线实时（按请求） | 离线批量（交易日 15:30–15:45 陆续） |
| 定位 | 实时、低频量、面向在线查询 | 批量、日频、面向离线快照 |
