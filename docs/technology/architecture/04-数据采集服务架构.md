## 一、背景与定位

「市场估值」「个股基本面」「智能情报（新闻/公告/政策/宏观）」等特性需要每日收盘后（或日内高频）批量产出并持久化数据。区别于 Java 后端的实时行情（ADR-0003：腾讯主源 + 东财/新浪兜底 + 令牌桶限流 + TTL 缓存），采集侧是一次性的、批量的数据工程任务。因此独立为 **Python 服务 `collector/`**（Python 3.12：akshare + tushare + 页面直采接源、pandas 计算、psycopg3 落库、APScheduler 调度）。

三条不变原则：

- **采集（写）与查询（读）分离**：collector 只写数据，读侧（`/api/valuation/**` 查询、AI 工具 `get_valuation`）由 Java 后端完成，二者共享 PostgreSQL。
- **业务 schema 单一源头**：业务表由 Java Flyway（V1 基线 squash + V2~V8 增量）定义，collector 只 INSERT/UPDATE、逐字对齐列名（跨服务契约，writer 白名单缺列 fail-fast 拒写）；collector 的 alembic 只迁移自有运维表。
- **声明式扩展**：新增任务优先加一份 YAML（新源/新目标表才需要写代码），executor/runner/scheduler 不出现任务特例分支。

## 二、总体架构（框架分层）

```
collector/（Python 3.12，独立服务）
  config.py            配置入口：env DATABASE_URL / TUSHARE_TOKEN → frozen Config（connect_timeout=10）
  cli.py               CLI：run（手动触发，--force/--date）· list · backfill · seed · history
  backfill.py          区间回填：按自然月分片 + collector_backfill_progress 记进度断点续采；
                      仅放行 supports_range=True 的源，拒绝静默降级
  model/               task.py（Collector 任务对象）· run.py（RunResult/状态）· health.py（SourceHealth）
                      · records.py（CanonicalRecord = dict）
  sources/             源层：base（Source 契约 + SourceError + last_warnings 观测通道）·
                      registry（YAML spec → 源实例）· configurable（声明式 akshare/tushare 直调）·
                      stock / index / etf / industry / news / announcements / macro / policy
                      （八个域源模块）· common（跨域工具）· constants（运营常量：码表/URL/限速）·
                      http_guard（进程级 requests 90s 缺省超时注入）· ratelimit（最小间隔限速器）
  converters/          字段映射：FieldMappingConverter 行级映射 + 类型强转
                      （17 套映射表定义在 jobs.py）
  validators/          规则校验：min_rows/required/not_null/type/range/unique/allowed_values，
                      hard 违规抛 SourceError（换源），soft 剔行记 issues（run 状态 PARTIAL）
  calc/                纯计算：snapshot（全A PE/PB 中位数，剔 PE≤0 与 >100）·
                      industry_weighted（行业市值加权 PE/PB/ROE/股息率）
  store/writer.py      幂等落库：14 张目标表 UPSERT_SQL（ON CONFLICT DO UPDATE，零业务 DDL；
                      白名单缺列 fail-fast；index_constituent 先删后插快照语义）
  executor/            executor.py（单次执行：选源→取数→转换→校验→计算→落库；fetch 由
                      daemon 线程包裹 + 超时，防源端挂死）· selector.py（健康分排序 + 三态熔断）
  scheduler/           jobs.py（装配与调度入口）· runner.py（TaskRunner：门控/depends_on/锁/重试）·
                      alerts.py（告警链：飞书 > webhook > 邮件，30 分钟去重）·
                      patrol.py（新鲜度巡检：8 表日终对账）· calendar.py（TradingCalendar）
  repositories/        纯 SQL：tasks（collector_task）· runs（collector_task_run）·
                      health（collector_source_health）· backfill（collector_backfill_progress）
  tasks/*.yaml         30 个声明式任务定义（13 字段封闭契约，seed 校验必填/拒绝未知键）
  migrations/          alembic：运维表 collector_task / collector_task_run /
                      collector_source_health / trading_calendar / collector_backfill_progress
                      （0001 基线）+ collector_task.depends_on（0002）
        │  写入（业务表零 DDL）
        ▼
PostgreSQL（业务表 = 后端 Flyway V1~V8 拥有；运维表 = collector alembic 拥有）
```

分层单向依赖（import-linter 强制）：cli →（scheduler | backfill）→ executor →（store | repositories）→（calc | validators | converters）→ sources →（model | config）。约束条款的逐条版（含理由与强制方式）见 [conventions/04](../conventions/04-采集服务架构与代码规范.md)，本文聚焦架构与运行机制。

## 三、任务体系（YAML 声明式）

## 四、执行机制（一次任务运行）

`TaskRunner.run`（scheduler/runner.py）按序执行：

1. **交易日门控**：`trading_day_gated=true` 的任务遇非交易日直接记 SKIPPED run（`--force` 可跳过）；交易日判断只经 `TradingCalendar`（按需查库，长期运行不依赖启动内存快照）。
2. **depends_on 前置检查**：声明了上游的任务，任一上游当日（上海时区，尊重 `--date`）无 success/partial run 则记 SKIPPED 并告警；SKIPPED 不入失败口径——不重试、不放大熔断计数。
3. **多副本互斥**：PG advisory lock（`pg_try_advisory_lock(hashtextextended(task_code))`），上一实例运行中则本实例记 SKIPPED；锁的获取/释放与连接同生命周期，每次尝试新建连接、用完即弃。
4. **前置 running 行**：执行前先落 `collector_task_run`（running），终态回填——任何路径不留悬挂 running 记录；意外异常兜底置 failed，调度器启动时另有 reaper 清理被 kill 进程遗留的悬挂行。
5. **Executor 主链**（executor/executor.py）：`SourceSelector` 按健康分排序候选源 → 逐源 `fetch`（daemon 线程包裹 + 超时：全局 1800s / backfill 21600s / YAML per-source `timeout_seconds` 覆盖，防源端挂死拖垮任务；DB→DB 重算源显式调大超时，防「放弃线程」晚提交的僵尸写）→ 数据源库原生异常统一包 `SourceError` → `convert` → **先校验再聚合**（min_rows 等规则基于明细行数）→ `calc` → `store.upsert` 幂等落库（单事务）；成功回填 source_used/rows_written，soft issues 状态记 PARTIAL，源内 `last_warnings`/`last_affected_rows` 观测通道合入 run message。
6. **失败分轨**：`SourceError` 换下一候选源；`StoreError`（DB 写入失败）不换源，由 TaskRunner **整任务重试**——退避策略按任务配置（指数 30×2ⁿ 秒或 fixed 30s，`retry_max` 语义为重试次数，总尝试 = retry_max+1）；全部源失败抛 `AllSourcesFailed` 记 failed run 并触发终态告警。
7. **熔断**（executor/selector.py）：连续失败 3 次 open、冷却 600s 后半开、半开探针仅在无健康候选时兜底；熔断计数按「任务运行」计，重试不放大。健康分 = 100×成功率 − 时延惩罚（≤30）− 连败惩罚（≤40），YAML `source_ids` 声明顺序作平级 tie-break。

## 五、限速与并发

- **RateLimiter**（sources/ratelimit.py，进程内线程安全的最小间隔限速器，锁外 sleep）：`fina_indicator`/`daily_basic` 0.35s（≈171 次/分钟，上游限 200 次/分钟留安全余量）；ETF 目录逐只 enrich 0.3s（env `COLLECTOR_ETF_DETAIL_INTERVAL` 可调）。
- **页面直采源礼貌间隔**：新闻/公告/宏观/政策跨请求 0.3s（源内 `_polite`）。
- **并行拉取**：`StockFinancialSource` 用 `ThreadPoolExecutor(max_workers=4)` 全 A 逐股并发（executor.map 保持输入顺序），限速器在锁外等待、网络调用可重叠。
- **HTTP 缺省超时注入**（sources/http_guard.py）：进程级包装 requests.get/post 注入 90s 缺省超时，堵住 akshare 内部无超时调用（2026-10-15 审查 H1 修复）。
- **重试退避**：任务级指数退避（见 §四），取代旧的固定 30s。

## 六、交易日历与调度

- **启动序列**（`python -m collector.scheduler.jobs`，容器 CMD）：安装 http guard → alembic upgrade head → 刷新交易日历 + 陈旧检查（最新日期落后当天 >15 天打 warning 留痕）→ seed 任务 → 装配注册表与任务 → 清理悬挂 running 行（reaper）→ 计算从未成功任务（冷启动补跑，`next_run_time=now`）→ BlockingScheduler 启动长驻。
- **--once 模式**（定时窗口部署）：`python -m collector.scheduler.jobs --once [--tasks a,b]` 按 depends_on Kahn 拓扑排序跑一轮 + 尾部新鲜度巡检后即退，退出码供宿主机 cron/CI 判定；`make collector-once` 封装 `docker compose run --rm`（跑完即退，规避常驻 `restart: unless-stopped` 陷阱，见 README「定时窗口部署」节）。
- **日历自维护**：akshare `tool_trade_date_hist_sina` 每月 1 日 03:10 定期刷新（cron `10 3 1 * *`，upsert 幂等）。
- **新鲜度巡检**：交易日 17:30（cron `30 17 * * 1-5`）对 8 张规则表日终对账——6 张日频表查 `max(trading_day)` 落后即滞留，etf_basic/index_constituent 两张慢更表查 `max(updated_at)`（14 天/200 天阈值），滞留清单触发告警。
- **调度纪律**：每个 job 显式 `coalesce=True`、`max_instances=1`、`misfire_grace_time`（日级 3600s、日历刷新 86400s）；job 函数自兜底所有异常（异常逃出 job 会被 APScheduler 静默丢弃后续调度）。
- **时区**：镜像已装 `tzdata`（Dockerfile），`TZ=Asia/Shanghai` 生效。

## 七、数据源选型要点（明细见 05）

- **主备对（5 组）**：全 A 估值（akshare spot_em → tushare daily_basic 同构）、个股估值（tushare daily_basic → akshare spot_em 口径妥协备源）、新闻（东财 7×24 → 新浪 zhibo）、公告（巨潮 → 东财流）、宏观社融（socfin AFMI → M2，不冒充 AFMI——月度粒度每期仅一口径落库，降级留痕由 backend MacroHealthService 巡检判定）。其余任务单源（YAML 注明「备源后置」），靠任务级重试 + 熔断兜底。
- **页面直采源族**：新闻/公告/宏观/政策在 `fetch()` 内自含「HTTP 抓取 + 解析 + 增量截断 + 单条丢弃隔离」骨架基类，请求级重试 3 次后抛 SourceError 换源；增量截断策略按族不同（新闻 external_id 首见已存即停、公告整页无新增 + 3 天回看窗、宏观 indicator+period 集合、政策 external_id 集合）。
- **DB→DB 源**：`etf_tracking_error`、`industry_valuation_backfill` 在 fetch 内自行 UPDATE/重算、返回空帧走 writer 0 行路径（稳态 0 行属正常，validator 置 null）。
- **国债收益率曲线**：akshare `bond_china_yield`（中债信息网，全期限含 1Y/3Y）。`bond_zh_us_rate` 已下架 1Y/3Y 期限列，**勿回退**；单次区间上限约 1 年，按 180 天切块，日常增量以 DB `max(trading_day)` 为水位线，backfill 显式区间优先于水位线。
- **ERP 股息率**：`index_dailybasic` 不返回股息率，用 `make_index_dividend_fetch` 近似——`index_weight` 最新成分权重 × 成分股 `dv_ttm` 加权均值；积分不足/无数据回退 NULL 并记 last_warnings，保证不缺列不崩。

## 八、部署与运维

- **部署**：`collector/Dockerfile`（python:3.12-slim + tzdata，非 root，健康探针查进程存活）+ docker-compose `collector` 服务，`depends_on db/backend: service_healthy`（等 Flyway 建表）；`TUSHARE_TOKEN` 经环境变量透传（`.env` git-ignored）。
- **手工运维（Makefile）**：`make collect`（列任务与最近运行状态）、`make collect-run TASK=<task_code>`（手动触发一次，可 `--force` 跳过门控）、`make collect-backfill TASK=… START=… END=…`（区间回填）、`make collector-once`（--once 定时窗口一轮）、`make collect-test`（ruff + import-linter + pytest，覆盖率 ≥80%）。
- **告警链**（scheduler/alerts.py，全 opt-in，通道决策见 ADR-0013）：飞书群机器人（卡片 + HMAC 签名）> 通用 JSON webhook > SMTP 邮件降级，最外层 30 分钟同签名去重防风暴；触发点集中在任务终态失败、depends_on skip 与新鲜度巡检滞留；发送尽力而为，绝不影响任务执行语义。配置项见 README 环境变量表（`FEISHU_BOT_WEBHOOK` 等）。
- **执行历史**：`python -m collector.cli history <task_code>` 查 run 记录（状态/源/行数/错误）；`seed --dry-run` 校验任务定义。
- **可观测性**：每次运行双通道留痕——DB（collector_task_run：status/source_used/rows_written/error；collector_source_health：分数/时延/连败；collector_backfill_progress：回填分片进度）+ 日志（task_code、attempt、退避秒数）；日终新鲜度巡检对账兜底。已知缺口：无 Prometheus 类指标聚合与结构化日志（O4 决策暂缓），接入监控下游时再评估。

## 附：与 Java 后端行情链路的对比

| 维度 | Java 后端（ADR-0003） | collector（本文档） |
|---|---|---|
| 数据源降级 | 腾讯主源 + 东财/新浪兜底（同类型多供应商） | 五组主备对（全 A 估值/个股估值/新闻/公告/宏观社融）；其余任务单源，靠任务级重试 + 熔断 |
| 速率控制 | 令牌桶 5 req/s + TTL 缓存 | RateLimiter 最小间隔（tushare 0.35s、页面源 0.3s）+ 4 线程并行 + 指数退避 |
| 缓存 | TtlCache（行情热缓存） | 无缓存；映射/成分走 7 天/180 天 interval 任务天然低频 |
| 运行时段 | 在线实时（按请求） | 离线批量（行情族交易日 15:30–15:55；情报族日内高频/夜间档） |
| 定位 | 实时、低频量、面向在线查询 | 批量、日频~分钟频、面向离线快照与情报库 |
