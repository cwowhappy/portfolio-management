# 03 · 后端测试架构

> 后端四层测试体系的总览文档：四层模型、source set 划分、共享容器基座、覆盖率门禁与 ArchUnit 守护。
> 约束性条款（切片选型、BDD 准入等）见 [conventions/02-后端架构与代码规范.md](../conventions/02-后端架构与代码规范.md) 第七节；实施过程见 [features/plans/2026-08-30-后端四层测试体系建设.md](../../../features/plans/2026-08-30-后端四层测试体系建设.md)。

## 1. 四层测试模型

| 层 | 职责 | 边界 | Source Set | 命名 |
|---|---|---|---|---|
| 单元 | 证「逻辑对」：纯业务规则与编排 | 零 Spring/零真实 I/O，mock 只打端口接口 | `test` | `*Test` |
| 切片 | 证「接线对」：单层与框架的装配契约（绑定/校验/序列化/安全规则/异常映射） | `@WebMvcTest`/`@JsonTest` 部分上下文，无 Docker | `test` | `*SliceTest` |
| 集成 | 证「依赖对」：跨层与真实依赖协同（事务/约束/并发/迁移/装配/SSE 流） | Testcontainers 真实 PG，窄端到端 | `integrationTest` | `*IntegrationTest` |
| BDD | 证「流程对」：中文 Gherkin 锁定关键用户旅程 | Cucumber JVM + 真实 PG + 假 Model | `bdd` | `*Steps` + `*.feature` |

分工红线：**切片验接线、单测验逻辑、集成验真实依赖、BDD 只锁核心旅程不贪多**——同一行为不跨层重复断言。

source set 与依赖方向：

```
backend/src/
├── test/             单元 + 切片 + ArchUnit（禁 Docker，ArchUnit 强制）
├── integrationTest/  集成测试 ──┐
├── bdd/              Cucumber ──┤ 都依赖 testFixtures（test 不依赖）
└── testFixtures/     PostgresTestSupport（共享 PG 容器基座）─┘
```

`integrationTest`/`bdd` 经 Gradle JVM Test Suite 声明（`build.gradle` 的 `testing.suites`），依赖 `extendsFrom test`（复用 Mockito/AssertJ/ArchUnit）；Cucumber 依赖（7.34.7，经 `cucumber-bom` 管理）只进 bdd suite，不污染其他层。

## 2. 各层载体与示例

| 层 | 载体技术 | 运行命令 | 典型示例 |
|---|---|---|---|
| 单元 | JUnit 5 + Mockito + AssertJ | `make test-backend-unit`（= `./gradlew test`，含切片与 ArchUnit） | `application/portfolio/PortfolioApplicationServiceTest` |
| 切片 | `@WebMvcTest` + `spring-boot-starter-security-test`；`@JsonTest` + `Jackson2Tester`（Jackson 2 项目） | 同上 | `web/PortfolioControllerSliceTest`、`web/SecuritySliceTest`、`web/dto/DtoJsonContractTest` |
| 集成 | `@SpringBootTest`（需显式 `@AutoConfigureMockMvc`）/ `@DataJpaTest + @ServiceConnection + Replace.NONE`，Testcontainers PG | `make test-backend-integration` | `agui/AguiStreamIntegrationTest`、`agent/AgentConfigContextTest`、`auth/RegistrationConcurrencyIntegrationTest`、`migration/FlywayMigrationIntegrationTest`、`*RepositoryImplTest` |
| BDD | Cucumber JVM（cucumber-java/spring/junit-platform-engine）+ JUnit Platform Suite | `make test-backend-bdd`（= `./gradlew bdd`） | `bdd/CucumberRunnerTest` + `resources/features/*.feature` |

持久化测试的优先写法是 `@DataJpaTest + @ServiceConnection + Replace.NONE`（放 `integrationTest`，复用 testFixtures 单例容器，见 §3）；全量验证 `make test-backend`（= `./gradlew check`）串起三层 + 覆盖率门槛。

## 3. 共享基座 PostgresTestSupport

`testFixtures/java/com/portfolio/invest/support/PostgresTestSupport.java`：

- **JVM 级单例**：`static` 块启动 `postgres:16-alpine` 容器，shutdown hook 停掉。整个测试进程只启一次容器。
- 为什么不用 JUnit `@Container`：多个集成测试类共享同一个 Spring 上下文缓存时，`@DynamicPropertySource` 只解析一次；若按测试类启停容器，重启后端口变化，后续类会连到已停掉的旧端口。
- **双消费方式**：完整上下文测试继承基座（`@DynamicPropertySource` 注入数据源）；`@DataJpaTest` 切片经静态访问器 `postgres()` + `@ServiceConnection` 复用同一容器，不再启第二个。
- 基座自身不挂 `@SpringBootTest`/`@AutoConfigureMockMvc`——切片不需要完整上下文，这两个注解由各测试类按需自声明。
- Testcontainers 禁用 Ryuk（`TESTCONTAINERS_RYUK_DISABLED=true`）：兼容 Colima 等无法挂载 Docker socket 的本地运行时，容器回收由 shutdown hook 负责。

## 4. 覆盖率门禁

- **聚合统计**：`jacocoAggregatedReport` 把 `test`/`integrationTest`/`bdd` 三个任务的 exec 合并出一份报告（`build/reports/jacoco/jacocoAggregatedReport/`）；`jacocoTestCoverageVerification` 对合并结果卡 **BUNDLE 级指令 ≥80% + 分支 ≥80%** 双门槛。
- **挂 `check` 不挂 `test`**：门槛只由 `check` 触发。聚焦跑测试（`--tests X` 或单跑某个 suite）时三层 exec 不齐，门槛会误判，故只在全量 `check` 聚合；`test` 任务另挂单任务报告 `jacocoTestReport` 供聚焦时查看。
- 实测（2026-08-30，含分支补强）：聚合指令 98.6% / 分支 97.1%；web 包指令 97.9% / 分支 88.9%。

## 5. ArchUnit 守护

`src/test/java/com/portfolio/invest/architecture/` 三个测试类，19 条规则随 `test` 任务执行、违反即构建失败：

- `PackageConventionsTest`（13 条）：分包与依赖方向（web→application→domain 等白名单、无环、落位规则，详见 01 分包规范）；
- `CodingConventionsTest`（5 条）：编码约束（`@Transactional` 只在 application、domain/application 禁 `System.currentTimeMillis`/`getenv`、`@Entity` 只在 persistence、禁 Jackson 3 等）；
- `TestSourceSetConventionsTest`（1 条）：测试分层守护——`test` source set 禁依赖 Testcontainers（`@AnalyzeClasses` 默认排除测试类，故用 `ClassFileImporter` 直接分析 `build/classes/java/test`），守住「单元/切片无 Docker」边界。

## 6. BDD 层设计

- **入口**：`CucumberRunnerTest`（JUnit Platform Suite，`@IncludeEngines("cucumber")` + `@SelectClasspathResource("features")`）。
- **上下文**：`CucumberSpringConfig` 整套 BDD 共享一个 Spring 上下文（继承 `PostgresTestSupport`）；假 Model 用 `@TestBean` 定义级替换 `investModel`（`DEEPSEEK_API_KEY` 给占位值只为触发 `AgentConfig` 条件装配，全程不打真实 LLM）；三个行情客户端用 `@MockitoBean` 替换，各场景自 stub 主源故障/备源数据。注意：`spring-boot-starter-webmvc-test` 传递引入的 Jackson 3 会抢占 AG-UI 入参反序列化，已在 `build.gradle` 依赖级 exclude `spring-boot-starter-jackson`（见第 7 节），测试类路径与生产对齐。
- **steps**：复用 ApplicationService + MockMvc + 真实 PG，`ScenarioContext` 跨步骤传值，`MockResetHooks` 每场景复位 mock。
- **当前 5 个场景**（`src/bdd/resources/features/`，`# language: zh-CN`）：

| Feature | 旅程 |
|---|---|
| `auth_onboarding.feature` | 注册 → 待审核拒登 → 管理员审核 → 登录 → 流式对话 |
| `user_deactivation.feature` | 管理员停用用户即时生效（进行中的会话被踢出） |
| `portfolio_trading.feature` | 买入/卖出/现金分红/送股持仓全链路 |
| `market_fallback.feature` | 行情主源故障自动降级备源 |
| `valuation_cache.feature` | 估值同日缓存命中、不重算 |

- **已知补丁**：`src/bdd/java/io/cucumber/core/runner/Runner.java` 遮蔽 Cucumber 7.34.7 中文方言 Locale bug（上游 `localeForPickle` 用 `setLanguage("zh-CN")` 抛 `IllformedLocaleException`，改为 `Locale.forLanguageTag`；类路径遮蔽仅作用于 bdd source set，生产与 integrationTest 不受影响）。**上游修复后删除该类**。
