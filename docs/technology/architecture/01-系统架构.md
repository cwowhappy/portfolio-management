# 01 · 系统架构

> 系统整体架构设计：总体架构图、分层职责、请求链路、会话模型。
> 技术栈版本与工程目录结构见 [02-技术栈与工程结构.md](02-技术栈与工程结构.md)。

## 1. 总体架构

```
┌────────────────────────────────────────────────────────────────────────────┐
│                               浏览器 UI                                     │
│  对话（/，需登录）· 行情台（/market，公开）· 持仓/调配/日志/筛选/估值/行业       │
│  （/portfolio /allocation /journal /screener /valuation /industry）          │
│  登录/注册（/login /register）· 设置（/settings）· 管理（/admin）             │
└──────┬─────────────────────────────┬────────────────────────────┬───────────┘
       │ /api/copilotkit (AG-UI SSE) │ /api/market /api/auth       │ /api/admin /api/conversations
       │                             │ /api/portfolio /api/valuation│ /api/allocation /api/journal
       │                             │ /api/screening /api/agent …  │ /api/mcp /api/skills
┌──────▼─────────────────────────────▼────────────────────────────▼───────────┐
│            Next.js 15 前端（同源反代，透传 Cookie/Set-Cookie）                 │
│  /api/copilotkit → HttpAgent → POST /agui/run（转发会话 Cookie）              │
│  /api/{market|auth|admin|conversations|portfolio|…} → 后端对应路径            │
└──────┬─────────────────────────────────────────────────────────┬─────────────┘
       │ POST /agui/run                                          │ REST（会话/认证）
┌──────▼─────────────────────────────────────────────────────────▼─────────────┐
│        Spring Boot 4 + Spring Security 7（DDD 洋葱分层）                      │
│  web/        12 个 @RestController（Allocation/Auth/Conversation/Health/      │
│              Journal/Market/McpConfig/Portfolio/Screening/SkillConfig/        │
│              UserAdmin/Valuation）+ GlobalExceptionHandler                    │
│              + InvestAguiRuntimeContextResolver（AG-UI 请求解析登录用户）       │
│  application/ 12 子包用例编排：allocation/auth/cache/conversation/journal/     │
│              market/mcp/portfolio/screening/skill/useradmin/valuation         │
│  domain/     10 子包纯 POJO（零 Spring/JPA）：allocation/conversation/         │
│              journal/market/mcp/portfolio/screening/skill/user/valuation      │
│  infrastructure/ persistence(JPA+Flyway)/security/seed/market(客户端+缓存)/cache│
│  agent/      独立能力域：HarnessAgentFactory 按用户装配 HarnessAgent，          │
│              InvestTools 7 @Tool + 用户级 MCP 工具/技能（UserToolkitFactory）   │
└──────┬──────────────┬──────────────────────────────┬────────────────────────┘
       │ DeepSeek API │ PostgreSQL 16                │ 东方财富（主）/ 新浪 / 腾讯（兜底）
       │              │ （另被 Python collector 写入） │
```

- **前端**：同源反代，浏览器不直连后端，规避 CORS；所有反代透传 Cookie 头与 Set-Cookie（登录态落地）。
- **后端**：按「DDD 洋葱分层 + 独立能力域」组织（见 [ADR-0009](../decisions/0009-backend-ddd-layering.md)）；`agent` 保持独立能力域，其余业务域走 DDD 分层。
- **认证**：Spring Security 7 会话认证（`JSESSIONID` + 记住我）；`ActiveUserFilter` 每次受保护请求校验用户状态，停用/被拒即时失效（见 [ADR-0007](../decisions/0007-user-auth.md)）；`/agui/run` 经 `InvestAguiRuntimeContextResolver` 从会话解析用户并注入 Agent 运行上下文。
- **持久化**：PostgreSQL + Flyway 建表，V1–V11 共 26 张业务表（`app_user`/`persistent_logins`/`conversation`/`chat_message`、估值类 `valuation_snapshot`/`industry_valuation`/`index_valuation_history`/`shenwan_industry_mapping`/`treasury_yield_curve`/`index_constituent`/`stock_valuation_daily`/`stock_financial`、持仓类 `portfolio`/`holding_group`/`position`/`trade`/`dividend`/`cash_transaction`、调配与日志 `allocation_plan`/`allocation_plan_weight`/`journal_entry`、MCP 与技能 `mcp_provider`/`mcp_endpoint`/`mcp_user_config`/`skill_user_config`；V3 的 `treasury_yield` 已被 V4 `treasury_yield_curve` 取代，现无代码引用）；另有 collector 自管的运维表（`collector_task`/`collector_task_run`/`collector_source_health`/`trading_calendar`，见 [04-数据采集服务架构.md](04-数据采集服务架构.md)）。

## 2. 请求链路

**对话（AG-UI SSE）**

```
用户输入 → ThreadArea.send()
  → agent.addMessage() + copilotkit.runAgent({ agent })
  → CopilotKit 运行时 /api/copilotkit（useSingleEndpoint=false，REST 传输）
  → HttpAgent POST {BACKEND}/agui/run（转发会话 Cookie；反代把全量渲染历史
    裁剪为最新一条 user 消息——见第 3 节服务端记忆）
  → InvestAguiRuntimeContextResolver 解析登录用户 → CurrentUserHolder
  → AgentScope AG-UI starter（server-side-memory）：按（用户, threadId）取/建 HarnessAgent
  → HarnessAgent 装配（详见 [modules/01-Agent实现.md](../modules/01-Agent实现.md)）：
    循环调用 InvestTools 7 个 @Tool + 用户启用的 MCP 工具与内置技能
  → AG-UI SSE 事件流（TEXT_MESSAGE_* / REASONING_* / TOOL_CALL_* / RUN_*）
  → CopilotKit → useAgent 状态更新 → 逐字渲染
```

**行情（REST）**

```
页面 fetch /api/market/** → Next.js 反代 → 后端 /api/market/**
  → MarketDataService（缓存命中直接返回，未命中走限流 + 数据源 + 降级）
  → 返回 DTO（前端 zod 校验）
```

其余业务页面（持仓/调配/日志/筛选/估值/行业/管理/设置）同为 REST 反代链路，走各域 Controller → ApplicationService → Repository 端口实现。

## 3. 会话模型

- **领域实体** `Conversation`（`conversation` 表），`id` 复用 AG-UI 协议层 `threadId`；UI 转写消息存 `chat_message` 表（精简历史：仅 user/assistant 纯文本，`payload` JSONB 预留工具调用扩展）。
- **agent 记忆服务端化**（`agentscope.agui.server-side-memory=true`）：starter 的 `ThreadSessionManager` 按（用户, threadId）维护 agent 会话实例；`HarnessAgentFactory` 为用户构建 `HarnessAgent`，以 `JsonFileAgentStateStore`（`stateRoot` 可配）把会话历史落盘，并附带压缩（CompactionConfig）与节流落盘（MemoryConfig）。前端每轮**只发最新一条用户消息**——CopilotKit/HttpAgent 总是携带全量渲染历史，由 `/api/copilotkit` 反代边界裁剪后再转发 `/agui/run`；agent 历史由服务端 stateStore 恢复，不再整段重传。决策记录见 docs/technology/decisions/。
- **UI 转写持久化**沿用 ADR-0008 的「前端工作内存 + 服务端存储」模型：前端持有当前渲染消息，每轮回复完成后防抖 **PUT 全量纯文本消息**到 `/api/conversations/{id}/messages`，打开会话时 **GET 回灌**——该记录只服务列表与跨设备回显，不再作为 agent 上下文来源。
- **归属隔离**：会话读写按 `user_id` 过滤，非本人 404；多端同时编辑同一会话为后写覆盖。

详见 [ADR-0008 会话持久化](../decisions/0008-conversation-persistence.md)（取代 ADR-0004；其中 agent 上下文部分已由服务端记忆取代，转写存储仍有效）。
