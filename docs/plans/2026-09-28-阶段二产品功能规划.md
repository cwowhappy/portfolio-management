## 一、阶段定位与总体目标

**阶段一**（一期 + MVP + 二期 + 三期 + 平台增强，MS-00~19）交付的是「数据与记录」闭环：对话式投研问答、行情数据台、估值/筛选/持仓/配置/收益分析、决策记录与知识库、AI 工具与 MCP/Skill 平台能力。一句话：**答「数据在哪、赚了多少」**。

**阶段二**转向「信息消化与决策流程」：

1. **智能情报主线**：搭建以 AI Agent 为核心的**财务报告、宏观政策、财经新闻**的采集、分析框架与流程——让三路信源成为可查询、可推送、可复盘的数据资产。
2. **投资 SOP 主线**：把**新分析 → 制定投资策略 → 建仓与持仓 → 复盘**四阶段流程化——收集最佳实践构建 SOP v1，并用结构化数据 + Agent 引导把它变成系统内建的作业流程。

一句话：**答「信息怎么消化、决策怎么做」**。

## 二、复用的阶段一资产

| 阶段一资产 | 阶段二消费方式 |
|---|---|

| journal（备忘/复盘/时间线） | 研究项目、SOP 各阶段痕迹与 journal 备忘联动 |
| analytics（TWR/回撤/归因/净值序列） | 复盘环节数据自动带入（买卖点 vs 后续走势） |

| agent-testing（eval 设施） | LLM 结构化抽取的质量回归评估 |

## 三、架构决策（2026-09-28 已决）

**决策 #1（主线一分析形态）：结构化抽取优先，RAG 已弃用。**
采集内容经 LLM 按 JSON Schema 批量抽取（事件类型 / 涉及标的与行业 / 摘要 / 方向 / 关键数字 / 重要度），落 Postgres 结构化表，Agent 工具 + 定时简报消费。备选 B「RAG 优先」（embedding + 向量检索 + 文档问答）——**已否决并弃用（2026-09-28 用户裁决，见决策 #4）**。备选 C「Agent 在线实时搜」否决理由：无沉淀、不可复盘、不可推送，违背「框架和流程」目标，仅作对话内补充手段。

**决策 #2（主线二 SOP 形态）：结构化研究项目 + 内置 SOP Skill 双层。**
数据层新建 `domain/research` 域（研究项目四阶段状态机 + 策略文档 + 复盘记录），引导层四个内置 SKILL.md（每阶段一份最佳实践 checklist，按用户启停，Agent 引导收集要素 + 纪律检查消费 PrincipleRule），知识层 SOP v1 内容沉淀为 wiki 模板。备选 A「只做 wiki 静态文档」否决理由：被动、无流程沉淀。备选 D「全 Agent 黑盒自主流程」否决理由：不可控、不可测试。

**决策 #3（采集与分析的分工）：** 采集落 collector（复用调度/落库/告警）；分析为 LLM 批量结构化抽取（走既有 DeepSeek 通道）；存储 Postgres（Flyway 迁移）；触达 = Agent 工具 + 每日盘前摘要飞书推送 + 工作台页面。

**决策 #4（知识查询形态，2026-09-28 用户裁决）：弃用 RAG，已有知识以知识库 wiki 方式查询。**
阶段二不做 embedding / 向量检索 / 文档问答，后续批次也不预留。情报消费 = 结构化字段检索（`pg_trgm` 辅助）+ 盘前摘要推送；研究结论、SOP 知识、概念速查统一归 M13 wiki 组织与查询；PDF 原文不留存（仅存元数据 + 业绩要点抽取文本）。

## 五、里程碑详情

### MS-20 · 财经新闻采集与 AI 结构化 ⏳（0/5）

- **目标**：验证「采集 → LLM 结构化 → 落库 → 触达」最小闭环，让新闻成为可查询、可推送的资产。
- **交付范围**（M15-F01~F05）：
  - [ ] M15-F01 新闻采集任务（东财 7×24 为主源 + 新浪/腾讯降级，collector YAML 任务、幂等落库）
  - [ ] M15-F02 AI 结构化抽取流水线（JSON Schema：标的/行业标签、摘要、方向、关键数字、重要度评分；抽取质量 eval 回归）
  - [ ] M15-F03 新闻检索 Agent 工具（`search_news`，纳入提示词与工具卡）
  - [ ] M15-F04 每日盘前情报摘要（LLM 汇总昨夜今晨 → 飞书推送，DeepSeek 通道）
  - [ ] M15-F05 情报存储模型（Flyway 新表：原始条目 + 结构化结果，DDD 新域 `domain/intelligence`——domain 子包由 ArchUnit 层级通配自动覆盖、无需登记，同步 DDD 分包规范子包清单即可；域名已定稿 intelligence（需求规格决策 #28，原草案 research-intel 弃用））
- **前置**：**三源可得性探测报告**（东财 np/7×24、新浪、腾讯新闻接口的稳定性与字段漂移，沿用 MS-13 调研方式）——质量门槛⑤。
- **验收标准**：连续 5 个交易日采集落库正常；抽取结果抽验（标的/行业标签准确率人工抽检 ≥90% 量级）；`make test` 三端全绿 + smoke/e2e 过。
- **风险**：新闻源接口无官方授权（公开流），字段漂移需告警兜底（复用 collector 告警通道）。

### MS-21 · 公告与财报要点采集 ⏳（0/5）

- **目标**：财务报告与重大事项公告入库，业绩类公告关键数字结构化。
- **交付范围**：
  - [ ] M15-F06 公告采集（巨潮 hisAnnouncement 为主源 + 东财公告流降级；公告列表 + 定期报告元数据落库；PDF 原文不留存，仅存元数据 + 业绩要点抽取文本——决策 #4）
  - [ ] M15-F07 业绩类公告要点抽取（营收/归母净利/同比/分红方案等关键数字结构化）
  - [ ] M15-F08 公告分类标签（增减持/回购/定增/关联交易/业绩预告等重大事件类型）
  - [ ] M15-F09 公告检索 Agent 工具 + 定向订阅（按标的/持仓过滤）
  - [ ] M15-F10 新公告主动触达（订阅范围内重大公告飞书提醒）
- **前置**：MS-20。
- **验收标准**：业绩公告关键数字与原文抽验一致；公告类型分类准确率抽检达标；PDF 全文问答不做（决策 #4 弃 RAG）。
- **风险**：巨潮接口稳定性需探测（列入 MS-20 探测报告的巨潮专项）；定期报告 PDF 解析复杂度高，本里程碑仅做元数据 + 文本要点，不做全文。

### MS-24 · SOP 最佳实践沉淀与 Skill 化 ⏳（0/3）

- **目标**：SOP v1 内容定稿并 Skill 化，Agent 可按 SOP 引导用户走四阶段。**以内容工作为主，工程改动轻。**
- **交付范围**：
  - [ ] M16-F01 SOP 四阶段最佳实践 v1 定稿（内容研究与评审，范围见下）
  - [ ] M16-F02 四个内置 SOP SKILL.md（新分析 / 制定策略 / 建仓持仓 / 复盘，按用户启停，复用 Skill 系统）
  - [ ] M16-F03 SOP wiki 模板 seeding（四阶段模板/检查单入 M13 知识库，幂等 seeding）
- **SOP v1 最佳实践收集范围**：
  - 经典框架：格雷厄姆/巴菲特/芒格（能力圈、安全边际、护城河）、多尔西《股市真规则》分析 checklist、霍华德·马克斯（周期、第二层思维）、费雪《怎样选择成长股》、彼得·林奇六种公司分类。
  - 国内实践：段永平（商业模式优先、Stop Doing List）、唐朝估值三段式、张磊《价值》、李录。
  - 交易纪律：仓位管理（凯利简化、单票/行业上限）、买入前检查单、证伪/退出条件。

- **验收标准**：四阶段模板与检查单经用户评审定稿；四个 Skill 在对话中可按阶段引导并生成结构化草稿；wiki 模板可渲染可复用。
- **风险**：内容主观性强，**v1 必须用户参与评审**（每个阶段的「必须有 / 可选项」清单逐条确认）。

5. 涉及新外部数据源（新闻流/巨潮/宏观发布页）时，**里程碑启动前完成来源/稳定性/配额探测**（MS-20 探测报告为首个前置）。

### 8.2 技术可行性结论

- **collector 扩展可行**：插件机制为 `plugins.py` 新增 `Source` 子类 + YAML 任务，既有 18 任务模式直接复用（含限速/重试/告警设施）。
- **抽取与摘要运行位置**：推荐落 backend 定时任务（`SchedulingConfig` + 原则预警日终巡检同模式），复用 DeepSeek 通道、飞书客户端与 PG；collector 保持纯采集管道（待澄清 #14 定稿）。
- **SOP Skill 化可行**：MS-17 Skill 系统直接承载四个 SOP SKILL.md（按用户启停）。
- **全文检索**：以结构化字段过滤为主，`pg_trgm` 为 PG 内置扩展可直接启用；`zhparser` 需编译安装，列为可选、不作前提。
- **量级与成本**：新闻按交易日 300~800 条估算（年 15~25 万行），PG 单机无压力；DeepSeek 批量抽取日 input 百万 token 量级，日成本数元以内。
- **PDF 解析**：不再投入（决策 #4 弃 RAG）——定期报告仅消费元数据 + 业绩要点抽取文本，不留存原文。
